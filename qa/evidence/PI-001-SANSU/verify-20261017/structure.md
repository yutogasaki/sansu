# Sansuの生成・固有操作・復旧の地図

HUB-REORG-001を参照し、共通試行が終わる前の棚卸しとして記録した。[同じ詳細台帳](structure.json)に308 HTMLのsource/target/hashと操作要素数を保持する。操作要素数は動作の合格数ではない。全件の公開/内部用途判定は未確認。

| 段階 | 所在・責任 |
| --- | --- |
| 正本 | 仕様・共有TASKS/BLOCKED・flow根拠・docs/portal入力。移動/手書き二重管理をしない。 |
| 元7画面 | generate-agent-index/content。比較対象であり、新生成も関数を使う。旧画面の書出しと判定/承認処理は分ける。 |
| 統合生成 | standard-portal → integrated-portal → 固定integration → local library/固有図 → 固定reader/shell。 |
| 統合入口 | portal/index.html。現行候補はHOLD。hubはrepoの出力を直接参照。 |
| 固有操作 | 図鑑の32画像/比較/編集メモ/export、観察票のsave/import/export、3D教材のcanvas/操作/資源、依存図と同関係一覧を保持する。製品・公開資料へ内部外枠を無差別に適用しない。 |
| 旧URLと保存 | 未受入の元画面を保持。file/HTTP間で自動共有されない保存メモを、同一originのsave合格へ読み替えない。 |
| 復旧 | Gitの固定正本＋2復旧保管＋補足入力を合わせる。欠損6件と空生成依存により完全復元は未達。 |

共通側が外枠/固定ナビ/本文読取/検索/通常遷移を一式で所有し、repoは固有データ/図/比較/保存を結ぶ。共通版を待つ間に別ヘッダーや全面UIを作らず、固定vendorを直接改変しない。人向け検索のscript/style/反復nav除外と機械向け全件原文保持は、次の共通契約で照合する。

| 削除分類 | 今回の扱い |
| --- | --- |
| 現行必須 | 正本、固有入力/生成器、使用中vendor/lock、判定/検証/承認、製品と資源は保持。 |
| 再生成可能 | portalは生成物だが使用中。初回生成も未達であり、今回削除しない。 |
| 固定復旧 | 未受入の元7画面、履歴/承認、唯一資源、復旧保管は対象版を保ち保持。 |
| 削除可 | 新たな証明済み対象0。今回の削除0。過去の削除は当時の記録のまま。 |

削除候補を採用するには個別path・理由・hash・参照0・復元一致・通常生成で復活しない証拠を揃える。欠損を別版3Dで補わず、未確認を削除可へ分類しない。commit/push/公開なし。
