学習教材・問題種類・レベル・スキル監査

日付: 2026-10-01。対象: 現在のローカルcheckout。監査は読み取りと診断のみで、教材・保存データ・出題・解放の実装は変更していない。

結論

生成器の基本的な整合性は確認できたが、教材の意味と種類の網羅性には修正が必要。 とくに、英語で正しい理解を誤答にする選択肢、訳と例文の不一致、Lv8の足し算の範囲縮小を先に直す。算数の平均・除算・分数比較は正答が正しくても問題の型に偏りがあり、現在の成功をその概念全体の習得と解釈できない。

判定を分離する:

観点結果
ID・生成・入力契約・機械的な答え検査範囲でPASS。全乱数や全描画の証明ではない
英語の意味・正答の一意性要修正。C01/C02
数範囲・導入後の難度要修正。C03。その他の偏りはC04〜C06
概念の土台・順序・型の網羅改善が必要。C07〜C09。既知の未実装部分を含む
学年・検定相当の実証、子どもの理解未検証。機械検査で合格にしない

範囲と実施方法

  • 算数: 118教材、29レベル（Lv0〜28）、74既存単元、9planned単元。生成器・対応表・表示名・数範囲・表現・前提関係を全件照合。
  • 英語: 1,184項目、1,173種類の綴り、20レベル、49分類、1,184例文。ID・所属・重複・例文対応・かな/漢字の4択を全件検査。意味の整合性はデータを読み、具体的な疑義を個別確認した。全語義の専門家校閲完了とはしない。
  • 算数生成: 独力正解数なし/0/3/10/20/40/100 × 100 seed × 118教材 = 82,600問。47,600問の解析可能な四則式を別計算で検算。分数・帯分数・余りも数値として確認。
  • 追加: 比較・割合・平均・比・速さ・万/億の7教材を各10,000 seed、70,000問検算。別途、除算/平均/分数比較の分布を各10,000問確認。
  • 英語: 1,184項目 × かな/漢字 × 10 seed = 23,680問。4択の表示ラベル・IDの一意性と正解の存在を確認。意味が同じ選択肢は文字列比較では検知できないため別に再現。
  • 既存の関連テスト: 28ファイル・375件PASS。既存テストの合格と教材内容の妥当性を分けた。
  • 算数の具体図については生成契約・既存テスト・実装を確認。今回、新たな実機の画面比較や子どもの観察は行っていない。
  • 紙テスト、例文の凍結保存、SRSの最適性は今回の中心対象ではない。前回の学習アルゴリズム監査と区別する。

全件の所属・表示名・表現は棚卸し表。生成例・段階別の値・全英語項目と例文はinventory.json。入力ファイルのhashと監査中の不変確認はsource.json。共有checkoutには先行する変更が存在するため、HEADだけでは監査入力を表せない。

指摘

P1 = 誤答判定・誤学習・仕様上の範囲欠落を直接生む。P2 = 教材の偏り・概念や型の不足。P3 = 表示・説明・校正の改善。P2/P3はすべて現行仕様違反という意味ではない。

C01 / P1 / 英語の採用訳と例文の語義・品詞が一致しない

根拠: words.ts、examples.ts、回答前に例文を表示するEnglishExampleSentence.tsx、StudyLayoutとIslandProblemPrompt。

ID / Lv採用訳例文例文で表す意味
hard / 5かたいThis work is hard.難しい・大変な
apply / 15おうぼするI apply the new rule.規則を適用する
measure / 16たいさくWe measure the distance.距離を測る（動詞）

age / 13じだいTell me your age.年齢

語義の区別は出版社の辞書でも確認: hard、apply、present、measure・動詞、measure・名詞。表の例文は本リポジトリから採ったもので、辞書の例文の転載ではない。

修正方針: 原則として既存IDの採用語義を維持し、その語義を明確に表す例文へ変更する。語義自体を変更する場合は別の教材変更として仕様05・保存済み記録との関係を扱う。全件に品詞・語義を付け、例文がそれに一致するか校閲する。単語を含む・文が異なるという既存テストだけではこの不一致を検出できない。

atmosphere=たいき / The atmosphere is calm.など、文脈が弱く語義を確定しにくい例も校閲対象。これらを上表の確定した不一致と同じ件数に混ぜない。

C02 / P1 / 別ラベルでも同じ意味の選択肢が同時に出る

根拠: generator.tsの除外は表示ラベル一致・同じ綴り・ID。語義の同等性は扱っていない。

way_lv12、seed=8: 問題way、例文This is a good way.、選択肢「いち」「しんぽ」「やりかた」「ほうほう」。正解はID way_lv12だけで、method由来の「やりかた」は誤答になる。「方法/やり方」はこの文で区別できない。wayの方法の語義はOxfordのway、methodでも確認。

修正方針: 正解語義の許容訳・同義グループと誤答禁止ペアを教材データに保持する。ラベルだけを変える対応では解消しない。生成前に同義候補を除外し、クールダウン緩和でも維持する。まず上の実問題を回帰検査へ追加し、全語義の曖昧な組み合わせを校閲する。

C03 / P1 / Lv8の足し算が導入後に縮小し、仕様の数範囲を出さない

根拠: additionProgress.tsのLEVEL4_SEQUENCE/LEVEL4_POOLとselectAdditionPair。仕様04はadd_1d_1をa=1〜9、b=1〜3、和≤12と定義。

  • 導入は15組あり、後半は1+5、5+1、3+3など和6まで進む。
  • 正解数15以降は常にa+b<=5の10組へ戻る。プロフィールなしの検査でも同じ10組。
  • 8+3、9+2等の仕様上の範囲を出せない。add_1d_1_bridgeも同じ選択関数で縮小する。
  • 先にLv6のadd_5が1〜5同士・和10まで扱うため、Lv8は新しい範囲を学べる保証が弱い。

修正方針: bridgeとsymbolそれぞれの到達範囲を仕様に合わせ、導入終了後はその範囲へ拡張する。導入の直後に範囲が縮小しない境界検査と、仕様上の代表問題が生成可能な検査を置く。定着確認も「10種類の易しい問題ができた」ことと広い範囲の達成を分ける。

C04 / P2 / 平均の全問題が対称な並びで、平均計算をしなくても解ける

根拠: advanced.tsのaverage_basic。3個はavg-d,avg,avg+d、4個はavg-outer,avg-inner,avg+inner,avg+outer。10,000問すべて両端の平均だけで正答できた。3個なら中央の数を答えればよい。

間違った式ではないが、総和÷個数を理解していない状態でも現在の全問題を通過できる。対称な問題を導入として残しつつ、非対称・順番を混ぜた数列・異なる個数・整数/小数の答えを仕様化し、一般的な平均の型を別に確認する。

C05 / P2 / 2桁÷2桁の約71%が同じ数同士を割る問題

根拠: division.tsのdiv_2d2d_exact。除数10〜99を均等に選び、商は1〜floor(99/除数)。除数50〜99では必ず商1になる。

10,000問中7,094問（70.94%）が商1。答えは正しく仕様上有効だが、67÷67=1等に強く偏り、2桁除数を使う一般的な計算の練習が薄い。商1・商2〜9の型を分け、導入後の割合を制御する。無条件に商1を禁止する必要はない。

C06 / P2 / 分数比較には分子・分母が両方違う不等値の問題がない

根拠: advanced.tsのfrac_compareは同分母、同分子、等値の3モードだけ。10,000問でもそれぞれ3,333/3,336/3,331問、両方異なる不等値は0問。

Lv22で異分母の計算を扱った後のLv26「分数のくらべ方」でも、2/3と3/5のような比較を確認できない。現行の限定された3型は既に仕様32にも記述されており、今回見つかった計算バグではない。比較全体の達成と扱うなら、数量図/数直線や通分を使う一般型を追加し、型ごとの証拠を残す。

C07 / P2 / 基礎概念9単元が未実装で、41既存単元がそれを前提としている

根拠: mathCatalog.tsのplanned単元・prerequisites。仕様31が「通常出題の必須関門にしない」と明記する、既知の教材不足。

未実装: 10と1の位、100以上の位、小数の量と位、分数の量、等しい分数/約分/通分、帯分数の意味、等しい集まりと掛け算、等分除/包含除/余り、1あたりの量。

計算に図があることと、その概念を子どもが直接答えられることは異なる。特に分数Lv21は初回から約分した答えを求める。基礎を教わっていない子がアプリ単独で進む場合の橋渡しが足りない。

修正方針: 既存IDを移動して保存を壊す対応ではなく、各計算の直前に短い意味確認・説明・具体図の教材を加える。既に理解している子が一律に戻されない経路も作る。plannedをそのまま必須ロックへ変えると、教材がないのに先へ進めなくなるため先に教材を用意する。

C08 / P2 / 推奨される前提が後のレベルに置かれている

C09 / P2 / 「問題の型」が粗く、異なる技能を同じdefaultで数える

根拠: mathCatalog.ts、context.ts。現在、実問題から型を判定するのはsub_2d2dの繰下あり/なしで、他の多くはdefault。
