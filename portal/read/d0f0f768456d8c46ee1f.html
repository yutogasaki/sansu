Project Memory

Purpose

This file stores durable project memory only.

If the information would still matter after several unrelated tasks, it belongs here.

What Belongs Here

  • Source-of-truth relationships
  • Durable design or product constraints
  • Operational facts that are easy to forget and expensive to relearn
  • Long-lived exceptions to the normal rules

What Must Not Live Here

  • Temporary task notes
  • Daily progress
  • Open questions without a decision
  • Raw chat transcripts

Durable Memory

  • Island production method (2026-10-11): decision, canonical construction policy. Art authors terrain/place forms with floors, entrances and connection rules; player land choices, placement and maturity assemble the world. Art and gameplay read the same world definition. Establish one whole island before arrangement variants, growth and expansion. This supersedes the earlier single-family-first production order; current mechanics and save contracts remain valid until their own specifications are revised.
  • Island construction/art strategy (2026-10-10): decision, construction strategy. Build places from placement, maturity and real resident use. Compare identical materials in different arrangements, not only more objects or stronger lighting. Preserve the bright rounded initial appeal and Pokomoko identity. Immediate shape adaptation, timed maturity and contextual discoveries are separate mechanisms. The place contract and runtime ADR now implement six optional goals,15 arrangements and four relations in D1–D4. record4/schema5 uses the isolated placedIslands table; rendered current-revision use and first-history are distinct. Local runtime evidence does not certify native05 dense forests, deep bays/waterfalls, independent child/device observation or natural seven-day growth.
  • Single island runtime (2026-10-06): ADR. Growing is the only island home; retired Life/Home Journey/Nature Town flags cannot select another home. Preserve old stores, verified Life migration, learning and shared character meshes. Independent prototype UI is retired; do not recreate its dev commands.

6. Optional Explore Mode and Historical Rollout

> Current UI target (2026-09-21): For whole-app UX/UI work, the current PokoMoko app is Island-on: npm run dev → port 5198 → /#/island, verified by runtime flags and identity markers. The shared .app-container exposes Island/Nature Town flags on every route; Island and Nature Town roots add their route-specific identity. /explore is a preserved optional legacy game, not the Island home. Flag-off classic is explicit npm run dev:classic on port 5201. Nature Town is a separate preview (npm run dev:nature-town, port 5233, /#/nature-town) and must not be mistaken for either. The older exploration decisions below describe their historical mode/rollout; use screen-flow spec 12 and the verification matrix for current routing and audit targets.

  • The optional legacy Explore mode is an exploration-first math game: children solve math to open paths, choose where to go, discover things, and decide when to return. The separately adopted build-and-play mode is governed by section 7 below.
  • The intended world is a bright, wondrous underground setting, not a dark combat-oriented cave. Game tension may include short-term loss, rescue, and near-miss outcomes, but must not shame children or erase durable learning progress and confirmed discoveries.
  • The approved live-encounter visual direction is いびつ生態ポップ: one full-width scene, one actor, one subject, one math-powered world verb, the subject's unexpected return, and the actor's counter-pose. Pop comes from an extreme readable silhouette, a biased focal color, material collision, and a bodily fact told before progress. Calm means one clear cause and limited competing motion, not low saturation or an expressionless world. docs/product/14_ui_world_motion_spec.md is the exploration visual SSOT; docs/design/research-library-2026-07-19/benchmark-yoshi-fukashigi.md is measured evidence and records the IP boundary.
  • Historical Explore launch contract (2026-07, superseded): while Explore was the standalone MVP and Build-and-Play was off, / used replace navigation to /explore, including after onboarding. Island became the current app home on 2026-09-08. Today /explore is an optional mode selected from Island; this historical launch contract must not be used to infer the current app entry. The route-only change preserved /study, /battle, /settings, profiles, and learning data.
  • Exploration must preserve Sansu's original rapid problem-solving rhythm. One route decision starts a three-question section; ordinary correct answers advance with zero extra taps, ordinary discoveries never block input, and only a large discovery, return, or recoverable persistence error may interrupt the question stream. The target is 650ms from a correct answer to the next operable problem and 550ms from an incorrect answer to retry.
  • A fixed cold-open must not be preceded by route cards whose selected terrain or promise it cannot honor. Start the fixed opening with zero taps, then show the first meaningful route choice at the three-question boundary; every visible route choice must change the following node, action, or encounter in a way the child can recognize.
  • PWA version drift may reload /onboarding, /study, /explore, or /battle/play before the first pointer/key interaction. After interaction begins, only that same in-memory session remains update-protected; React Router navigation re-arms the next route without relying on hashchange. A result/reward/break screen stays visible until the child chooses replay, continue, cancel, or another destination; only that action may form the same-route boundary, and only after required persistence.
