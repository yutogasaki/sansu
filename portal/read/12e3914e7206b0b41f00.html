北極星（2026-09-29）

アプリ全体の北極星はCONSTITUTION §1の「育つ島」。ぽこもこと自分の島を育て、置き方で水・食べ物・人の流れが変わり、住人が増え、島が広がり、ときどきその場所だけの不思議が起きる。面白さの源は「くふう・にぎわい・ふしぎ」と土台の「愛着」。学習は材料（しずく）と、島の遊び方を変える道具をもたらす。人口は地区ごとに増やし、新しい動物の住人を追加してよい（ぽこもこの姿は変えない）。経緯はADR。

  • 旧Exploreでは、Study と共通の算数 planner が Due、weak、maintenance、表現フォロー、現在レベル、解放済み +1 レベルを選び、3問の連問区間へ供給する

  • 誤答は同じstep slotに留まり、1回目は同じProblem、2回目以降は支援assignmentを別attemptとして使う。支援assignmentもcheckpoint CASと完全なProblemを一緒に予約し、再読込時にfresh profileから再生成しない。支援問題を出しても次slotを消費・再計画せず、未回答Dueを回答済みにしない
  • 探索の学習対象回答は、planner が予約した実出題 skill と source を保存境界で照合できた場合だけ SRS 対象にする。近傍レベルへの表示 fallback や未対応入力の代替問題を、学習進捗へ混ぜない
  • 探索の1回答は、探索イベント、run 集計、既存回答ログ、MemoryState、プロフィール内の直近履歴・学習日・メインレベル回答窓を、同一の冪等 transaction で保存する
  • active探索runは、新規runを作る前に同一プロフィールのversion付きcheckpointを検索して自動復帰する。checkpointはroute、energy、finds、attempt境界、完全なpending Problem、opening experience ID、確認済みdiscovery cursorを保持し、入力途中の数字は保持しない。回答eventだけがcheckpointより1件先行した場合は、保存済みreceiptを同じpending gateへ1回だけ適用して復旧し、複数tailや照合不一致を推測で進めない
  • 予約済み連問区間はindexを増やさないrun行のoptional dataとして保存し、step、gate、node、Problem、assignment、計画時プロフィール境界を照合して再開する。旧active runが区間途中で区間dataを持たない場合は、完了済みstepを変更せず残りslotだけを一度予約する
  • 旧active runが既にpending full Problemを表示している場合は、そのProblemとassignmentを現在slotの正本として入力解禁前にsegmentへ取り込み、同じsnapshotで残りslotを予約する。現在問の回答によるunlockを次slotの再計画へ混ぜない
  • 各slotの完全なProblemを保存値の正本とし、fresh profileとseedからの再生成で置き換えない。保存値はsegment ID、絶対step、slot順、planner / generator versionも持ち、review capは既存assignmentと同じsegmentで計画済みのslotを含めて候補ごとに再判定する
  • Exploreで新しいbase segment slotまたはrepresentation retryを予約するときは、すべてのplanner sourceを計画時 mathMaxUnlocked 内へ制限し、生成済みProblemをrapid-loop適格性で判定する。適格条件は単一のnumber入力、正規化済み非負数、答え入力3操作以内かつ決定込み4操作以内、筆算 / algorithm 面でなく、application / number-advanced の高認知負荷familyでないこととする
  • 不適格なDue等はassignment化せず、別identityのrapid-safe game-only-fallback / affectsSrs = false で不足slotだけを埋める。除外した学習候補をfallbackへ偽装せず、logs、MemoryState、recentAttempts、Due状態、プロフィール回答窓を変更しない
  • rapid-loop適格性は未保存の新規予約時だけ適用する。保存済みsegment / assignment / retryと、旧runから現在slotへ採用したfull Problemは新規則で再評価・差替えせず、旧runで同時に新規生成する残りslotだけ現行規則を通す
  • ランの最初の3問は、学習問題の意味を変えず、解く → 即世界反応を2回積み重ね、3問目に同じ身体規則から読めるオチへ到達するcold-openとする。1・2問目は追加0タップ・submitから650ms以内に次問を操作可能にし、誤答はsubmitから550ms以内に同じ問題へ戻す
  • 1ラン8問の体験順は Q1〜3 cold-open → Q3後の道選択 → Q4〜6 主調査の手掛かり → Q7 大発見1回 → Q8 持ち帰り → 帰還要約 → 再出発 とする。cold-openは主調査ページへ特徴を付与せず、通常標本とレア標本は希少度だけを理由に操作を止めない。明示的に止める報酬は意味づけされた大発見だけとし、8問完了時は「基地へ もちかえる」を唯一の主操作にする
  • delivery / feature-flag ID snap-root-v1 のcold-open visual candidate dig-pop-carry-bloom-v3 は、後続と同じ黄色い葉帽子のポッコ、シアンの空、黄土の地面、コーラルの根生物、同じ横cameraを保ち、commit済み正解数だけを ready → dig-one → dig-two → popped へ写す。相棒は根生物の身体や葉ではなく中央の同じ土だけを掘る。一つの土塊が飛ぶ、根生物が持ち上がって両足が見える、全身でぽんと抜ける、という三段変化の最後に、相棒が安全に尻もちをつき、柔らかい土塊が葉帽子へ載る。1・2問目の途中発見はtoastを出さず、3問目も説明モーダルや追加CTAを挟まない。先読みが期限に間に合わない場合、正解後は通常plannerへ戻し、誤答後は先読みをabortして同じ問題を操作可能にする。blocking discoveryを越えて次問を先読みしない。旧v2のruntime視覚点とthroughput点はv3へ継承しない
  • production defaultは snap-root-v1 とする。classic-v1 は旧マキモドンから後続の別rendererへ切り替わる実機FAILのためrollback先として使わない。旧 ready → tug → tumble → landed、編み根、nest-squash | nest-tip、一本葉を引くBloom版、水やり版、dig-pop-painted-v1、dig-pop-painted-v2、root-pull-v1 / root-pull-v2 は非採用のままとする。default変更を dig-pop-carry-bloom-v3 や後続v5のformal visual承認、Gate B通過、過去候補の点数継承とみなさない。保存済みactive runのopening IDは途中で差し替えず、新規runから現行defaultを使う
  • 絵主導のcold-openは、視覚的磁力、無文字の因果理解と安全、runtime整合 を別々の非補償ゲートとして判定し、総合点へ平均しない。視覚的磁力は承認済み絵本調benchmark 52 / 60以上かつ6軸すべて8 / 10以上、無文字テストは未説明の5人中4人以上が同じ主動詞とpayoffを説明し4人以上が続きを望み、危険解釈0件を必須とする。runtimeは1・2問目の正解から次問入力までP95 650ms以内、誤答から再入力までP95 550ms以内、追加0タップ、answer leak 0件、旧高速学習と同一固定問題で同等以上のthroughput、およびmobile / tablet・入力・reduced motion・asset・PWA検証の通過を必須とする。三ゲートすべてを実runtimeで通るまで最終visual承認を出さない。現在defaultがmandatory gateを実機で明確にFAILした場合は、既知FAILをrollback先に残さず、最小の同一lineage候補へcontainmentし、その未通過gateをHOLDとして明記する
  • Gate Cの同一問題比較にはDEV限定fixture cold-open-fixed-ten-v1 を使う。Studyは非記録session、Exploreは8問の実runを帰還・summary・再出発した後に別runで2問を解き、Exploreの全回答を game-only-fallback / affectsSrs = false とする。10反復all-correctの未丸め中央値で Explore回答数/分 ÷ Study回答数/分 >= 1.000 を必須とする。Q4 / Q8誤答はStudyが訂正表示から明示Nextで次問へ進み、Exploreが同じ問題へ戻るため、相互のthroughput合否へ混ぜず回復時間・正答率・操作中断の別証拠にする。このfixtureは通常plannerの同一skill上限を意図的に外す表示throughput検証であり、planner / SRS真正性は既存の実planner 3問grayboxで別に確認する
  • 全問足し算の固定10問はroot-tangleの引き算遭遇を偽装せず、Q7では3手掛かりをつなぐ中立の調査ページpayoffだけを開く。Explore中断は Q3後の道選択 / Q7大発見 / Q8後に持ち帰る / 帰還要約から再出発 の4件へ固定し、Q1〜2、Q4〜6、Q8〜10はblocking表示0件とする。root固有の動作・観察provenanceは、実plannerが対応引き算を割り当てるroot-tangle E2Eで別に検証する

1.5 モチベーション（再プレイしたくなる探索）

  • 岩を開く手触り、発見、分岐、帰還判断を反復の動機にする

  • 未発見の手掛かりは同時に1件だけ示し、チェックリスト消化ではなく「次は何が起きる？」を残す
  • 複数の性質がつながったときだけ短い「大発見」のピークを作り、通常発見との山と谷を明確にする
  • 「谷」は低彩度で無表情な待機画面を意味しない。通常遭遇にも、対象固有の極端な輪郭、相棒との視線・重心の関係、一つの読める因果を置き、静止時点だけでも触りたくなる状態を保つ
  • 「山」は全要素を同時に派手にすることではない。色、縮尺、表情、素材、密度、動勢のうち、その発見に必要な2〜3軸だけを強める
  • Golden Discovery Page の最初の縦切りでは、通常発見で3つの手掛かりを集めた後、receipt確定済みのQ7 finaleだけが最終特徴「花のまんなかに 四滴」を開く。通常調査は、四滴を葉帽子で運ぶ、一つのでこぼこで安全に尻もちをつく、五枚花が開く、四滴が花の中心へ収まってポッコが帽子を片目にかぶったまま笑う、という一続きの因果にする。対応引き算なら root-tangle 固有の動作と観察provenanceを付け、非対応skillなら問題の意味を変えず中立のページpayoffにする。4件目という順番、正答数、希少度だけでは大発見にしない
  • 現行MVPの調査特徴はrun内の一時進捗であり、rootを選ばず帰還した未完成ページが次runへ持ち越されるとは表現しない。run横断の特徴永続化はMVP-2bで扱う
  • ランごとに予測可能だが読み切れない変化を入れる
  • 学習上は子どもを責めず、ゲーム上は短期的で回復可能な失敗を許可する
  • 図鑑登録済みの重要発見、学習履歴、恒久進行は失敗で没収しない
  • 「見つけた」と「身についた」を分離し、発見表示だけで習熟認定しない。習熟はMVP-2以降も学習ログとSRSを正とする
  • 外部ランキング、課金圧力、未達ノルマは導入しない
  • 音は任意でOFFにできる

  • 二桁以上の掛け算・割り算の筆算は、位をそろえた途中式と現在の一手を表示する。掛け算の部分積、割り算の商・かける・ひく・おろすを分け、途中段の完了を一問の正解として扱わない。新規の割り算短縮版では商の各桁（あまりありは最後のあまり）だけを入力し、かける・ひく・おろすは計算結果として表示する。詳細と保存済み問題の互換性は 06_screen_specs.md「多桁の筆算」を正とする。
  • 初期設定の非同期読込が、表示済みの同じ問題に入力した数字や処理中の回答を消さない。保存済みの筆算設定など入力形式に必要な初期設定は、入力を有効にする前に確定する。新しい問題への移行や、子どもが明示した形式変更に必要なリセットは区別する。

  • モバイル端末でも全要素が収まるよう、動的リサイズやフレックス配置を行う。
  • 島の学習中は景色を非表示にし、問題・筆算・解答操作を優先する。全テンキー、訂正、決定、支援操作はスクロールなしで押せる位置に保つ。高さが足りない問題・筆算履歴・お手本だけを個別にスクロールでき、島の成長は「しまへ」で戻った時に見せる。

  • 地図と問題を同時に複雑表示せず、常に主操作を1つにする
  • Island有効時の / は /island へ replace 転送する。旧Exploreへ自動では入らない
  • /explore は全画面の任意モードとして維持し、既存の /study・/battle・設定系ルートも独立して維持する

4.1 プロフィール切り替え

  • 端末内に複数プロフィールを保持

4.3 回答方式（UI切替）

次の問題へ進む操作は、表示中の問題に対して一度だけ有効とする。誤答・スキップ画面が消える途中の操作で、未回答の次問を飛ばさない。

Study・島の算数は、02の自動採点に従い、整数・小数・分数・商と余りの各欄を桁ごとのマスで示し、最後のマスが埋まった瞬間に正誤を問わず採点する。教材による1桁入力の手動/自動の混在をなくす。筆算も現在段の必要マスが埋まると採点する。通常練習はテンポを優先し、マス数と小数点位置を学習上の足場として提示する。正答一致や入力停止時間では確定しない。桁数・小数点位置そのものの独力判断を測る証拠とはしない。

確定が必要なときは、入力がそろうと同じ位置のEnterボタンが明るい面と二重枠で主操作になる。最初は周囲の光だけをゆっくり2回動かし、その端末で一度手動確定を使った後は静止した強調だけにする。説明文を追加せず、自動採点時のEnterは薄い非操作状態とする。筆算ではEnterと画面上の左右キーを空き領域に置き換え、数字キーの位置を動かさない。保存失敗時の再送は例外として有効にする。動きを減らす設定では最初から静止表示とする。

筆算の誤答は06の多桁の筆算に従って部分訂正する。行全体の採点後、正しく入力した数字を残して誤ったマスだけを空け、次の空欄へ自動移動する。誤答・支援の履歴は維持し、段の途中に演出用の固定待ち時間を追加しない。

4.5.1 問題の定義（Problem）

  • 1問（Problem）: 1回の解答入力（または一連の入力完了）で完結する最小単位。
  • 計算の途中経過や、位ごとの分割入力は、それ全体で「1問」とみなす。

4.6 算数：複数入力（あまり・分数・帯分数）の入力仕様（専用パッド）

算数は原則「数字入力（0-9テンキー + 決定）」だが、入力欄が2つ以上になる回答形式では、

迷わない入力のため 回答形式に合わせた専用パッドと マス（1桁セル）を用いる。

用語

  • マス：数字1桁分の入力セル（[□]）
  • フィールド：マスのまとまり（商/余り、分子/分母 など）
  • フォーカス：現在入力対象のマス（視覚的に明確）
  • 専用パッド：0-9、←、C、OK、フィールド切替 など

共通ルール（必須）

  • フォーカスは常に視覚的に分かる（太枠／淡い背景／カーソル点滅 等）
  • 数字入力で 次のマスへ自動遷移する
  • 自動遷移に加え、専用パッドに 手動切替ボタン（←/→）を併設する
  • マス数は 問題が決まった時点で自動決定する（原則：正解の桁数から算出）
  • 削除（←）は直感的であること

A) マス数の自動決定（推奨：正解の桁数から算出）

  • あまりあり割り算（商＋余り）
  • 商：Q = 桁数(商)
  • 余り：R = max(1, 桁数(余り))（余り=0でも1マス）
  • 例：150 ÷ 4 = [□][□] あまり [□]
  • 分数（分子＋分母）
  • 分子：N = max(1, 桁数(分子))
  • 分母：D = max(1, 桁数(分母))
  • 帯分数（整数＋分子＋分母）
  • 整数：W = max(1, 桁数(整数))
  • 分子：N = max(1, 桁数(分子))
  • 分母：D = max(1, 桁数(分母))

B) フォーカスと自動遷移

  • 初期フォーカス：先頭フィールドの先頭マス
  • フィールド内最終マスまで埋まったら次フィールドへ自動移動
  • 最終フィールド最終マスまで埋まったらOK待ち

C) 手動切替（専用パッド必須）

  • 直ジャンプ切替を用意（例：商へ/余りへ、分子へ/分母へ…）
  • 各フィールドをタップしてフォーカス移動できる（推奨）

D) 削除（← / C）

  • ←：現在マスが埋まっていれば空にする。空なら1つ前へ戻って空にする
  • C：全マスを空にし、フォーカスを先頭へ戻す

E) OK（決定）

  • 未入力マスがある場合：不足マスを強調して進めない
  • 全マスが埋まっている場合：組み立てて判定

F) 出題上限（推奨）

  • 商：最大3桁／余り：最大2桁
  • 分子/分母：最大3桁（レベル別に調整）

4.7 スキップの扱い

  • UI: 問題カードを左スワイプ、またはPCならスキップボタン/キー。
  • 制限: 1問につき1回だけ 可能（答えを見て次へ進む）。
  • 評価: 不正解（Incorrect） として扱う。
  • 学習への影響:
  • strength = 1（リセット）
  • nextReview = 今日（直近で再出題されやすくする）
  • ガード: 同一項目のスキップが 連続3回 起きた場合は、当日は出題停止（翌日に回す）。

5.2 段階的解放

しあげテストによる進級（2026-10-01）

  • 普段の学習では現在のメイン範囲を練習する。過去7日以内の現在範囲の非復習・独力回答の直近20問で17問以上正解し、現在範囲のcoverageも揃うと、しあげテストへ挑戦できる。算数は既存単元・variantごとの同じ表現での代表難度3問、英語は異なる語70%以上。算数Lv11の既存coverageも維持する。詳細と初期値の位置づけは29。
  • しあげテストは現在範囲の20問。初回の独力正解20問すべてでクリアし、隣接する次範囲の解放・有効化・メイン移行を同じ保存処理で行う。訂正正解・ヒント・スキップは独力正解に数えない。確認用の定期テストと紙テストの点数は進級に使わない。
  • 受験は任意。準備ができても通常練習を続けられる。未クリアでレベルや取得済みの物を下げず、練習・再挑戦を選べる。日をあけた復習は進級後も続ける。
  • 既存プロフィールのレベル・解放・有効設定・学習履歴を保持し、過去へ遡ってテストを要求しない。既に解放済みで保護者が無効にした次範囲は開かない。最高レベルでは進級テストを出さない。
  • 2026-10-02: メインレベルの選び直しでも上位が無効になるため、無効にした人や操作を保存値だけで断定しない。保護者の学習範囲変更から、変更内容の確認後に解放済み・無効の隣接次範囲だけを再開できる。現在レベル・解放上限・履歴・しあげ資格はそのままとする。選択済みのメインを再度押して上位を無効にする操作は置かない。表示と再開の契約は06・29に従う。
  • テストの問題集合・所有者・元レベルを独立して保存する。開始と完了時に最新のプロフィールと資格を再確認し、古い問題集合・二重完了・別の所有者から進級しない。詳細は 29_learning_progression_spec.md。

  • 解放 (unlocked) されていないレベルは有効 (enabled) にできない
  • メインレベルは常に unlocked=true かつ enabled=true
  • すべてOFFになった場合は、メインレベルを自動でONに戻す

5.3 出題ロジック（ブロック生成フロー）

島のmixモードは仕様28の教科切り替えに従い、固定交互をやめる。3〜6問の予約ごとに、新しい内容の短い継続・有効な復習の必要量・次の一区間への本人の希望を使う。以下の10問ブロックは通常Studyの契約とする。

基本方針

  • 10問 = 1ブロック として出題
  • ロジックは科目ごとに完全に分離する
  • 出し過ぎ防止（共通ガード）: 1ブロック内で同一 wordId / skillId は最大2回まで。
  • 対象範囲の候補数 × 2 がブロック問題数に満たず上限を守れない場合は、出題不能や先頭IDへの集中を避け、出題回数が最少のIDから選んで偏りを最小化する。

ブロック決定フロー

  • 英語の復習チェック（最優先）
  • 条件：英語の「要復習」単語が存在 AND 直近40問中の復習比率 < 50%
  • 判定：YESなら 「英語復習ブロック」 を生成
  • 通常ブロック生成
  • 算数か英語かを決定（直近40問のバランスを見て不足している方、差がなければランダム）
  • 決定した科目のロジックで「通常ブロック」を生成

5.3.3 復習出題時の補助表示（Visual Feedback）

  • 復習スキルや以前間違えた問題が出題される際、問題表示直後に一瞬だけ 補助ラベルを表示する。
  • 目的: 「なぜ簡単な問題が出るのか」への納得感を与える。
  • 仕様:
  • 文言: 🔁「まえに やったところ」「もういちど やってみよ」
  • 挙動: 0.5秒フェードなどでさりげなく表示し、消える。
  • 頻度: 毎回ではなく、久しぶりの出題や正答率低下時などに限定してもよい。

通常・+1・自動の表現フォローでは、解放・当日停止・表示対応の条件を満たす active または未学習の候補を先に使い、卒業済み候補を混ぜない。同じ範囲にその候補が1つも残らない場合だけ、範囲内の独力の定着練習を通常枠で続ける。これは最終レベルや既習範囲への戻りで出題停止／別レベルへの置換を避ける例外で、回答は通常学習として記録する。1%の維持確認抽選は別枠として isMaintenanceCheck を保持する。明示的な誤答直後の支援は必要な表現へ戻せる。

B-1) 算数ブロックの中身（教材としての組み方）

算数は英語と違い、同じ skillId を繰り返すだけでは伸びにくい。

通常ブロックの中で、新しい内容 橋渡し 復習 手順理解 を混ぜる。

要素目安役割備考
新規 / 現在レベル40〜60%いま進めたい本体現在の mainLevel と +1 レベル上限の範囲
橋渡し / 別表現20〜30%絵・表・数直線・逆向きで理解を支えるBridge, Reverse, Strategy 系
復習 / weak / Due10〜30%忘却防止と穴埋めただし 1セッション全体で 60% 上限
手順確認0〜20%筆算や途中の考え方を確認Algorithm の途中手順系

補足:

  • ここでいう「橋渡し」は、同じ答え領域を別表現で見る問題を指す。
  • 手順確認 は毎回必須ではないが、筆算系・誤答多発時は優先する。
  • 同一 block 内で、同じ skill family だけに偏りすぎないようにする。

B-2) ミニレッスン束（算数専用）

算数では、必要に応じて 3問を1束 とみなす。

問役割例
1問目Concrete / Bridge絵、数直線、表、位取り
2問目Symbol / Reverse式、穴埋め、対応づけ
3問目Mental / Algorithm暗算、筆算、途中手順

生成ルール:

  • 1ブロックに最大2束まで入れてよい。
  • 新スキルの初回導入時は、可能なら1束を優先する。
  • weak な skillId がある場合も、単純再出題より束を優先してよい。
  • 束内では同じ概念を扱うが、同じ見た目の問題を連打しない。

B-3) 失敗時の戻し先（算数専用）

算数の復習は「同じ問題をもう一度」ではなく、つまずいた種類に応じて戻し先を変える。

失敗パターン優先して戻す先
記号問題で崩れたBridge 系（絵、表、数直線、位取り）
比較で崩れた数直線、位取り、表
割合・比・速さで崩れた対応表、テープ図、逆向き問題
暗算で崩れたStrategy 系（10づくり、分ける、近い九九）
筆算で崩れた途中手順系（くり上がり位置、借り先、部分積、商の位置）
余りで崩れたConcrete / Bridge 系（配る、何こずつ）

戻し方:

  • 直後の1問を representation_retry にしてよい。
  • 同一セッション中に同じ失敗が続く場合は、mini_lesson_review を1束入れてよい。
  • Due より軽い失敗でも、理解不足が明確なら別表現への寄り道を許可する。

B-4) 算数専用の再出題ガード

  • 同じ skillId をそのまま連続で出すのは原則避ける。
  • ただし ミニレッスン束 の中では、同じ概念 family の連続出題を許可する。
  • calc_error_check などの誤答診断問題は、元問題の直後または2問以内に出すと効果が高い。
  • representation_retry は、元問題と答えの難度を大きく変えすぎない。

5.6 初期レベル設定ロジック（Start Level Logic）

初回起動時にユーザーに最適なレベルを提供するためのロジック。

A) 算数：到達目安と学年による初期設定

1. 基準レベル（Base Level）

  • 学年ごとに「基準となる算数レベルID」を内部定義する（補遺C参照）。
  • 例：小学2年生 → Lv.X（足し算筆算付近）

2. 補正（Adjustment）

  • 初回質問「どこまでやった？」の従来5択は、学年基準に補遺Cの補正を加え、選んだ範囲の末尾で上限を設ける。
  • わり算・小数・分数・割合/平均/比・速さは、学年にかかわらず補遺Cの範囲末尾を使う。小2でも先取りした範囲を選択でき、小6の九九選択だけで小数を既習扱いにしない。

3. スタートレベル適用（Impose）

  • 補正後のレベルを mathStartLevel とする。
  • 解放ロジック:
  • Level 1 〜 mathStartLevel まではすべて unlocked=true とする。
  • mathStartLevel の1つ上を mainLevel（現在の学習対象）とする。
  • maxUnlockedLevel も mainLevel と同じにする。
  • 「簡単すぎて退屈」という離脱要因を防ぐため、既知の範囲はスキップさせる（ただしいつでも戻れる）。

C) 安全装置（Safety Net: 内部仕様）

自己申告は過大評価になりやすいため、初期設定直後の一定期間 は以下の比率で下位レベルを混在させる（UIでの説明は行わない）。

  • 混入比率（目安）
  • mathStartLevel : 90%
  • -1 Level : 5%
  • -2 Level : 5%
  • 解除: 正答率が安定して高い状態が続けば、自然にメインレベルのみに収束させる（通常の苦手判定ロジックに委ねる）。

B) 英語：簡易推定

  • 英語は算数ほど細かく刻まない。
  • 学年（中学生判定など）と「経験有無」のクロスで、初期単語レベル（Lv.1 or Lv.5 or Lv.10程度）を決定する。
  • 基本は Lv.1 からの積み上げを推奨するが、経験者のために多少のスキップを許容する。

6. テスト・復習機能（定期テスト・にがて復習）

※ 詳細は 06_screen_specs.md を参照のこと。

6.1 概要

従来の「ちからチェック」「特別ちからチェック」「紙テスト」は、名称を「定期テスト」に統一し、役割ベースで再編する。

測定（テスト） と 準備（にがて復習） を明確に分離する。

機能目的問題数位置づけ
にがて復習準備10問テスト前の練習。思い出すことが目的。
定期テスト測定20問正式な確認。アプリ（オンライン）でも紙（オフライン）でも同一内容。

6.2 にがて復習（新設）

  • 位置づけ: 定期テスト前に行う準備用の復習モード。
  • 目的: 理解度測定ではなく、「一度触った」「思い出した」状態を作ること。
  • 問題数: 10問固定。
  • 出題範囲: 定期テストと同一（現在のメインレベルに属するスキル集合）。
  • 優先順位: weak（苦手） > strength低 > テスト範囲内の重要スキル。
  • 算数・英語とも、範囲外のDue／maintenance／表現フォローを混入しない。当日の3連続スキップによる停止を守り、対象不足を別レベルで埋めない。
  • 自動テストが受験待ちなら保存済みテストのレベルを優先する。候補が少ないときは最少出題の項目から10問を組む。全候補が当日停止なら出題せず記録へ戻る。途中で3回目の連続スキップに達した項目は残りの予約から外し、その回の復習を短縮して終了する。
  • 評価: 点数・合否なし。時間計測なし。スキップ可。
  • データ影響: weak 判定・復習優先度の更新は行う。

6.3 定期テスト（アプリ内・PDF）

位置づけ: 学校の定期テストに近い正式な測定。

目的: 子ども・保護者が「できているか」を納得できる確認手段。

問題数: 20問固定。

出題内容: 範囲内から偏りなく均等またはランダムに出題（weak 等の重み付けはしない）。

実施方法:

  • オンライン（アプリ内）: 時間計測あり、正誤結果確認あり。
  • オフライン（PDF出力）: 家庭での印刷用。オンラインと 同一テスト内容 を出力。

結果表示: 実施後に 点数（正解数/20・スコア）と所要時間 を表示する。

家庭用印刷（2026-09-07改善）:

  • 設定のテスト欄から20問をプレビューし、ブラウザーの印刷／PDF保存を使う。問題のみ・解答のみ・両方を選べ、A4で問題途中を分断しない。
  • 算数の図・空欄・複数回答の意味と英語の4択を保持する。数える問題を「りんご3こ」のような答え入り説明へ置換しない。
  • 採点待ちは教科ごとに1件。完全な問題集合をプロフィール所有のsnapshotとして保存し、レベル変更やアプリ受験の後でも同じ内容を再印刷できる。旧データでsnapshotがない場合は内容を推測して再印刷せず、点数入力または明示的な取り消しを案内する。
  • 作成／再印刷だけではSRS・Due・進級・回答数を変更しない。採点は最新プロフィールに対して1回だけ記録し、別の設定・学習結果を上書きしない。取り消しは紙の採点待ちだけを外し、学習履歴を変更しない。
  • 自動出現中のテストを紙で作成した場合は auto として保存する。採点時に同一の問題snapshotがまだ自動受験待ちなら、その待ちを解消して7日のクールダウンへ移る。別の新しいテストの待ちは解除しない。採点した現在の問題集合は次回作成で更新できるように解放する。

7. データ構造（ローカル保存）

7.1 方針

  • 完全ローカル（Local Only）: 全データは端末内 IndexedDB に保存。
  • アカウント不要: ログイン機能は持たない。
  • 同期なし: 複数端末間の同期は行わない（将来検討）。
  • バックアップ/復元は扱わない: 仕様上の機能対象外とする。
  • 探索学習接続: run に予約した planner assignment を持つ回答だけ、既存プロフィール・学習ログ・SRSへ原子的に反映する。未予約 fallback は探索イベントだけを保存する。
  • 探索正式導入: 探索ラン、発見、イベント、設定は UserProfile へ大量追加せず、Dexie version 5以降の専用テーブルへ分離する。
  • 移行安全性: 既存プロフィールと学習ログを破壊する移行を禁止し、詳細は 13_data_storage_migration_spec.md に従う。
  • 学習記憶の正本: skill / word 単位のSRS状態は memoryMath / memoryVocab を正本とする。UserProfile.mathSkills / vocabWords は互換用ミラーであり、プロフィール取得時に正本テーブルの同一IDで上書きして問題生成へ渡す。
  • 回答保存の原子性: 探索の1回答では exploreRunEvents、run集計、logs、SRS MemoryState、プロフィール内の直近履歴・連続日数・メインレベル回答窓を同一Dexieトランザクションで保存する。保存できない場合は問題を進めず、同じ回答・同じattempt keyから再試行できるようにする。
  • weak移行: isWeak はMemoryStateへIN/OUTヒステリシス状態として逐次保存する。旧行は最初の参照時に全履歴から一度だけ復元し、回答書き込みと競合しないトランザクションで正本へ反映する。
  • 削除: プロフィール削除時は、そのIDのプロフィール、回答ログ、算数・英語MemoryStateを同一トランザクションで削除し、同IDのいきもの状態・図鑑も端末保存から除く。「全データをリセット」は全プロフィールへ適用する。

7.1.1 初期化（プロフィール作成時）

  • 2.4「初回起動時の初期化」に従う。
  • schemaVersion はアップデート時に段階移行できるように保持する。

7.1.3 ログ保存方針（Logging Policy）

  • Problem（個々の問題）: Studyでは都度生成して教材リストとして永続保存しない。Exploreのactive runに限り、checkpoint / immutable segment / retryの正本としてrun行へ一時永続し、完了済みrun外の再利用問題集にはしない。
  • SkillStats（累積統計）: memoryMath / memoryVocab で永続保持する。
  • AttemptLog（全回答履歴）: logs に保存し、SRS・統計・旧weak状態の復元に使う。
  • RecentAttempt（直近履歴）: UserProfile.recentAttempts に 直近300件 をリングバッファで保持し、出題クールダウンや直近判定に使う。
  • Islandの前向きな観測（2026-09-08採用、次段階の実装契約）: 既存のIsland学習操作eventへ、具体的な予約問題・筆算途中段/全体完了・操作直前の保存済み支援・実際に観測できたDOM表示と要求受理時刻を任意情報として添える。正誤・scopeは保存側の実slotと採点から作り、観測値を採点/SRSの正本にしない。旧行・他経路・未観測はunknownで、独力や定着を推定しない。新table/schema、汎用AttemptLog、SRS・Due・日次・streak・進級・報酬の計算を変えず、観測時計を既存計算へ渡さない。同一要求の再送は最初のaction/観測snapshotを保持し、実保存例外の原子rollbackを維持する。詳細と検証境界は 島仕様の観測契約 に従う。

  • 更新識別子 version はコミットの revision と分離し、同じコミット・異なる公開設定の再ビルドも識別するためbuildごとに一意とする。version.json とアプリに埋め込む版は同じ値を使う。オンライン復帰・安全なcheckpointで新しい版を自動適用し、利用者による更新確認やキャッシュ削除を要求しない。
  • 起動中のPWAは、起動時、復帰時、再接続時、フォーカス時、SPA内の画面遷移時、および表示中は最大60秒間隔で新しいbuildとService Workerを確認し、手動キャッシュ削除なしで新しいbuildへ移る。オフライン中に確認できなかった更新は、次の再接続・復帰・フォーカス・画面遷移のいずれかで再確認する。
  • Service Workerの通信が遅れても版確認を止めない。版確認は10秒で打ち切り、次の確認契機で再試行する。通常のSW更新では、新しいService Workerがページを制御してから再読込する。
  • 版の差だけが残った場合は、オンラインかつ表示中に更新用URLのHTMLを取得できることを確認し、安全なcheckpointでネットワークから再読込する。更新用URLは古いapp shellへのnavigation fallbackから除外し、復旧のために既存Service Workerやoffline cacheを削除しない。同じ版への復旧再読込はタブ内で1回に制限し、不整合な配信による連続reloadを防ぐ。
  • /onboarding、/study、/explore、/park、/island、/battle/play はpointer/key操作後の同一進行中セッションだけ更新reloadから保護する。各画面の初回表示から最初の操作までは更新を適用できる。
  • 更新を進行中セッションで検出した場合は即時reloadせず、保護対象外の画面へ移る、別の保護対象セッションを開く、または同一画面の結果・休憩を確認して「もう一回」「続ける」「cancel」を選んだ安全なcheckpointで一度だけreloadする。結果・報酬画面が表示されただけではreloadしない。React RouterのSPA遷移はnative hashchange に依存せず観測する。
  • 安全なcheckpointは、そのrun・テスト・プロフィール更新など中断できない保存が完了した後にだけ公開する。reload後はcheckpointの行き先または同一画面を保ち、子どもに終えた操作を繰り返させない。
  • 回答、テスト結果、探索runなどのcritical persistenceが1件でも進行中なら、保護対象外または別routeへ移っても更新reloadを解禁しない。必要な保存がすべてsettleした後に更新判定を再開する。
  • 島がまだ表示できない読み込み・失敗画面は、操作済みの島遊びとして更新を保留しない。読み取りとWorker計算は中断して修正版を読み込める。実際の書き込みは引き続きcritical persistenceで守り、島が表示された、または別の画面へ移ったら通常のセッション保護へ戻す。具体の同期・再試行は52 §18.2に従う。
  • 読み込みの更新例外は島の待機中に限定し、画面移動先の学習と新しいcheckpointへ持ち越さない。Growingの命令・模様替え・贈り物・写真・所有者削除は呼び出し元によらず保存transactionで更新を保護し、完了/失敗後に解放する。
  • 島の描画初期化やGPU contextの喪失は進行率で覆い隠さず、保存を保持した軽い設定の再試行・最新版の取得・学習の入口を表示する。描画待機中の更新も、実保存の保護を優先する。
  • 既に軽量設定の端末でも再試行はさらに低い描画解像度と標準のGPU選択で行う。失敗した描画資源を解放し、保護者が展開できる詳細に失敗段階・例外・アプリ版を表示する。診断のために学習記録を収集・送信しない。
  • 育つ島の軽量/復旧描画は低解像度で先に開き、前景の安定した描画を確認して段階的に鮮明にする。継続的な遅延では画質を戻し、増画質後の描画障害では安全側へ自動復旧する。同じ画面で失敗した高画質を繰り返さず、保存や学習を巻き戻さない。
  • PWA更新処理はIndexedDB、localStorage、ユーザーデータ用cacheを削除しない。回復処理で削除できるのはアプリが管理するService Worker cacheだけとする。

とアプリに埋め込む版は同じ値を使う。オンライン復帰・安全なcheckpointで新しい版を自動適用し、利用者による更新確認やキャッシュ削除を要求しない。\n- 起動中のPWAは、起動時、復帰時、再接続時、フォーカス時、SPA内の画面遷移時、および表示中は最大60秒間隔で新しいbuildとService Workerを確認し、手動キャッシュ削除なしで新しいbuildへ移る。オフライン中に確認できなかった更新は、次の再接続・復帰・フォーカス・画面遷移のいずれかで再確認する。\n- Service Workerの通信が遅れても版確認を止めない。版確認は10秒で打ち切り、次の確認契機で再試行する。通常のSW更新では、新しいService Workerがページを制御してから再読込する。\n- 版の差だけが残った場合は、オンラインかつ表示中に更新用URLのHTMLを取得できることを確認し、安全なcheckpointでネットワークから再読込する。更新用URLは古いapp shellへのnavigation fallbackから除外し、復旧のために既存Service Workerやoffline cacheを削除しない。同じ版への復旧再読込はタブ内で1回に制限し、不整合な配信による連続reloadを防ぐ。\n- `/onboarding`、`/study`、`/explore`、`/park`、`/island`、`/battle/play` はpointer/key操作後の同一進行中セッションだけ更新reloadから保護する。各画面の初回表示から最初の操作までは更新を適用できる。\n- 更新を進行中セッションで検出した場合は即時reloadせず、保護対象外の画面へ移る、別の保護対象セッションを開く、または同一画面の結果・休憩を確認して「もう一回」「続ける」「cancel」を選んだ安全なcheckpointで一度だけreloadする。結果・報酬画面が表示されただけではreloadしない。React RouterのSPA遷移はnative `hashchange`
