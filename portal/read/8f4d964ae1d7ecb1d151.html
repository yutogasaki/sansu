育つ場所の目標と組み合わせ

本体統合 v1 / 2026-10-10 / place-goals-design-v1。効く柱はくふう・にぎわい・ふしぎ・愛着。弱める柱はない。

利用者「いい感じ。これをもとに、目標や組み合わせとか。ゴール戦略や仕組みに落として」を受け、全島実3D native-05を美術の到達方向に採用する。これは固定配置、15軒の上限、模型の巨大GLBをそのまま本体へ載せる決定ではない。自分の配置からこの豊かさが育つ仕組みを設計する。

目標・配置の設計ショーケース · 設計カタログ · 実3Dで見る

1. 正本と今回決めること

本書は52 §0.5に接続する本体の規則。目標、場所の適応/成熟/利用、組み合わせ、実装境界を定義する。数値と配置例の正本はJSON、規則の意味は本書とする。個数は最小成立条件の試作初期値で、最大所有数でも購入レシピでもない。6目標・15配置・4関係を本体へ統合した。空間、表示、行動、受領を同じ派生結果で結び、実画面・保存/更新の受入を別々に記録する。

既存の学習完了・しずく・まち時間・しぜん時間・価格・解放・個体ID・建築時styleを引き継ぐ。既存A1〜A6/S1〜S5も保持する。新しい道具の購入、素材採集、住人への依頼、道路を一本ずつ引く作業はこの設計に加えない。

2. ゴールの戦略

> 育てたい場所を見つける → 同じ材料の置き方を試す → つながりが育つ → その場所で遊ぶ → 次の地区へ広げる。

ゴールは任意。目標帳で好きな一つを選べるが、選んでいなくても条件がそろえば場所は育つ。順番や全達成で遊びを制限しない。目標変更は無料で、仕込みや時間を失わない。

目標到達する大きな姿選択と遊びの見返り
P01 木陰の庭根と樹冠がつながる、入口のある小さな庭早い段階から、同じ苗を置き直して木陰を変え、ぽこもこと座る
P02 大樹の住まい木の家を包む幹の空洞、枝の回廊、青紫/翡翠の葉列・塊・中庭で構造が変わり、入口から入って回廊へ歩く
P03 青い泉の庭鉱石を源に水面/岸がつながる庭。斜面なら段泉水の入口・曲げ方・出口を変え、実通水と花・岸の利用を見る
P04 入り江の集会所家とあそびばを包む、色を透かす殻の共同屋根庭の向きと家の並びを選び、元の住人と遊び場を使う
P05 花の屋根の庭複数の茎が支える、花のアーチ/屋根/中庭同じ株と好きな色で形を変え、花弁の下の席に座る
P06 めぐれる島異なる場所を道・岸・木陰でつないだ、自分の全島自分で選んだ3系列以上をつなぐ。森の2目標だけで3系列とは数えない

P01とP05は少ない所有物から変化を見せる入口。P02は既存の大木と家の成長が景色になる長期目標。P03/P04は水辺や新しい土地で配置の工夫を広げる。P06は全島の目安で、クリアや人口/地区の上限にはしない。模型にある全地区を全部同じ順番で作る必要はない。

目標の主な報酬は形が育つことと、その場所を使えること。無料の再配置、触る返事、住人を運ぶ遊びが続く。完成による通貨倍率・学習の抽選券・維持費は追加しない。あゆみには育った事実を残し、本人が写真を撮って見せられる。

3. 「組み合わせ」の三層

材料の関係

既存の苗、木の家、花、水ばち、みずみち、ベンチ、あそびばが入力。合体は、個体を消す処理ではなく、同じ個体から共有の形を作る処理とする。持ち物一覧と現物選択から各品へ戻れ、移動/収納は既存の操作を使う。

同じ材料の置き方

配置主に変わること例
列長い境目と経路を育てる枝の道、花のアーチ、岸沿いの共同屋根
塊密度のある大きな屋根と内部を育てる大樹の住まい、花弁の屋根
中央を空ける入れる庭と、その周りの囲いを育てる木陰の中庭、花の庭、開いた殻の集会所
水を曲げる/段へつなぐ水源・通水・岸と歩く場所を育てる曲がる水庭、段泉、海へ開く水庭

JSONの15配置例は、各目標の中では同じ種類と個数で比較する。P01の2本は列/角/樹冠の端のくぼみで、4本の大樹や花の本格的な中庭の成立とは区別する。中庭の中心は歩ける余白とし、席で唯一の中央セルを塞がない。配置例は規則の説明図で、実ゲームの成長前/途中を撮影したものではない。完成3Dの絵も、一つの成熟例として別に明示する。

育った場所どうしの関係

関係連続する景色実際の働き
森＋泉根の足元から青い流れと岸が続く実際の木陰/水の届く植物、岸の席を使う
泉＋花水の縁に花弁と低い岸が続く現行の湿りと開花。交配や珍しい色の保証は加えない
森＋集落枝の回廊と共同の足元が家へ続く実住人が自分の家から木陰へ歩く
花＋集落花弁の屋根から共同の庭が続く既存の遊びを、その庭で繰り返す

異なる系列の関係は、入口間の最短歩行経路が初期値3セル以内かつ同じ到達領域で成立する。水/木陰を使う関係はその影響も必要。近いだけ、見た目だけの接続では成立にしない。入居枠・ごはん・あそび点・げんきは元の個体から1回だけ数える。

4. 場所が育つ共通規則

4.1 接続と形の判定

  • 現在の本人の、土地へ配置済みの品/種だけを読む。収納品、別人の島、未受領の贈り物は入力にしない。
  • 木/花の基本接続は辺で接するセル、または通れる1セルを隔てた直線。斜めだけで接続しない。間の家/塀/ベンチで経路が塞がれる場合はつながらない。水は現行の水源/通水の辺接続を使う。
  • 列は分岐のない細長い領域、塊は隣接2×2を含む領域、中庭は中央の歩ける余白を囲み、外へ通れる入口を残す領域とする。複数該当時は入れる中庭→塊→列→自由形の順。斜め4点だけの囲いは候補でも、経路がなければ中庭ではない。
  • 家・席・あそびばは、主要領域から初期値2セル以内で実際に到達できるものを組み込む。同じ役割の品を複数領域へ割り当てる場合は最短経路、同点なら安定ID順で一つに決める。P01/P02が同じ木のまとまりを表す場合は同じ席を使い、別系列へ二重割当しない。割当後に入口・足元・対象を再計算する。
  • 正式な空間判定で読めない地形/空洞/橋は、完成形として表示しない。部分的な木陰や水庭はそれまでの状態で使える。

各購入物の足元は所有セル内に保つ。樹冠/屋根は通路の上へ広がってよいが、物理的な幹/壁/水面が占有を増やす場合は、同じ計算でプレビュー・確定可否・通行を更新する。取得済み土地、玄関、橋の入口を囲い込まない。元の8軒やぽこもこを模型に合わせて勝手に移動しない。

広い領域は一つの超巨大な模型へしない。入口・席・家のまとまりで節を作り、回廊や岸でつなぐ。元の物を削除せず、密度/尺度/屋根の向きを変えて地区が育ち続ける。

4.2 成長と時計

層進み方保持すること
配置による接続/形確定した配置を再計算無料。接続前に予告し、元の物を消費しない
植物の成熟現行しぜん時計花の開花、木の成熟/大木を再利用。別の「場所の待ち時間」を足さない
家/あそびばの建築現行まち時計と既存の条件段階・builtAt・styleを保持。周りが変わったから普通の家を木の家へ自動改造しない
現在の利用到達、元の役割、実際の住人/ぽこもこの行動架空の人口や利用を足さない
目標の達成履歴一度成立した節目後で分離しても履歴を消さない。現在の形/機能は現在の配置で再判定する

P02の初期値は4本成熟、うち2本が大木、木の家がこや以上。大木の既存7日を使い、30日のぬしの木は任意のさらなる変化にする。長期目標のために学習で実時間を早送りさせない。ほかの場所を育てたり、今の庭で遊んでいる間にも自然は育つ。

P03の平地は曲がった池/岸、斜面は段泉として成立する。段差のない場所へ滝だけを描かない。 新しい高さは取得済み座標を保持する共有の地形計算を用い、通水の方向、階段/橋、住人の接地、配置hitを一致させる。現行の水源と最大8セルの通水は引き継ぐ。本体v1は初期6×5の床を保ち、拡張地区の床を共有 placeTerrain.ts から導く。既存の辺接続・8セル通水は保持し、供給済み水路に実下降がある場合のみ段泉にする。地形は供給距離や入居効果を増やさない。元の平地/水源の供給を奪わず、下流の水ばちを接続したから無限の距離へ水を伸ばす処理はしない。

4.3 分ける・しまう・やり直す

一本を移すと根/樹冠のつながりと形を再計算する。木の年齢、家の段階、元の持ち主/ID/価格、取得した品と達成履歴を保持する。つなぎ直しても追加購入や成長のやり直しは不要。

供給や到達を失った場合、今の水/木陰/利用だけが変わる。枯死、退去、目標失敗、記録の没収はない。元の席/家は現在の条件で使い続ける。回廊や殻が変わる際は、そこで行動中の住人を有効な入口側へ戻してから構造を閉じる。見えない床で歩かせない。

5. 子どもに見える一周

  • 任意の「あそびかた/目標」から到達する場所を見る。現在の持ち物でできる候補を先に見せる。目標はいつでも変えられる。
  • 置く位置を変えると、根が寄る向き、連なる岸、残る入口、将来の屋根が現物に重なる。一つの変更で何が変わるか見える。
  • 確定すると足元がつながる。まだ若い植物でも庭や席を使え、配置を試す遊びを待機だけにしない。
  • 通常の学習で材料/まち時間が届き、しぜん時間で植物が育つ。「あと何問」「住人が困るから学ぼう」は使わない。出題/採点/支援/復習の正本は変えない。
  • 帰島時に変化した場所を短く見せる。新しい必須確認画面を増やさず、既存のひらく/あゆみへ合流する。開けずに遊んでも変化や記録を失わない。
  • ぽこもこをその席/遊び場へ運ぶ、元の家へ入る、水に触れる。その場所の意味が行動で読める。
  • 次の目標は、隣に泉を作る、花で庭を囲む、別方向へ土地を広げる、など今の景色から予告する。全系列を集める義務にはしない。

初回はP01またはP05の一つだけを任意に案内し、桟橋/無料家/学習の既存導線を重ねた説明で塞がない。常設ナビと「まなぶ」の入口は維持する。

6. 実装へ渡す仕組み

現行には個体の状態、環境、占有/到達、通水、自然時計がある。新しい場所の計算を各Threeモデルへ埋めず、その状態から純粋に導く。

本人の配置・成熟・家の段階・取得済み土地
  → sharedEnvironment / sharedTerrain / safeAccess
  → derivePlaces → DerivedPlace[]
  → deriveRelations → PlaceRelation[]
  → 同じ結果を、配置予告・描画・住人の行動・目標判定で読む

DerivedPlaceは ruleId, memberIds, anchorId, variant, stage, footprint, entrances, walkSurface, water/shadeRefs, useTargets, revision を持つ。anchorは家/あそびばを優先し、なければ安定ID順。領域全体のIDは再計算してよいが、所有物のIDへ置き換えない。

保存するのは本人の選んだ目標、goalIdごとの達成履歴、実表示した節目の原本/対象ID/版。現在の領域mesh、材質、メッシュIDをゲームの所有として保存しない。P01〜P06は新しいIDであり、既存A1〜A6を上書きしない。合体/分離後に達成を再発行して通貨や学習時間を増やす経路は作らない。

新しい純粋モジュールの想定は places.ts（役割/接続/形）、placeRelations.ts（異なる場所）、placeGoals.ts（任意目標/履歴）。表現は placeGeometry.ts と共有地形、住人の行動へ接続する。これらを本体へ追加した。Workerの命令/同期で達成を更新し、本人の前景rendererから実表示・実利用の受領を送る。保存4/schema5の placedIslands を正本とし、旧tableを保持・隔離する。保存契約13と実装ADRに従う。

7. 作る順序と完成条件

段階作る一周閉じる条件
D1P01：2本を離す→寄せる→成熟→席を使う→分ける実取得/配置で庭が変わり、木の年齢/所有を保持。木陰と行動が同じ計算
D2P02/P05：同じ材料で列/塊/中庭→入口と回廊/花の屋根を使う3配置が輪郭で違い、空洞/床/支えが実3D。普通の家/顔/布を保持
D3P03/P04：水→岸→段/殻→実際の席/遊び場水/床高/経路/接地/hitが一致。既存の水供給/家/入居/橋を保持
D4P06/C01〜C04：複数の場所→自然な利用→次の地区元の庭を保ち、異なる系列を歩いてつなぐ。通常取得と保存/更新後にも成立

各段階で自分の通常の品を使った自然な一周を検証する。模型や注入した完成状態を自然な取得/成長の証拠にしない。実装を分けても、全景はnative-05の尺度・素材・色の差と照合し、白い小物の列へ戻さない。

必須の規則ケースは、同じ材料の3配置、斜めだけ/遮断/島外、成熟境界、複数領域への席の割当、合流/分離/収納/再接続、通水断絶と8セル境界、床高と経路、元のstyle/所有、複数回の完了と本人分離。動作中の変更、offline再読込、旧保存、同時更新失敗と再試行、学習予約へ戻る経路を対象別に検証する。

視覚は採用方向の実モデルと最新の本体画面を並べる。理解/安全は作者以外が配置の原因と使い方を説明なしで読めるかを観察する。runtimeは同版の形・環境・行動・保存・性能の整合を確認する。三つの判定は独立。今回の利用者の美術方向への好評価を、本体や子どもの一周の合格へ広げない。
