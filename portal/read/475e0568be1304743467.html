今の島に自然と町の仕組みを取り込む

2026-09-29 次期設計の確定範囲

水源・時計の導入単位を具体化。北岸外の固定水源、既存水ばち/所有座標の保持、二つの保存時計と景色の時刻、cutover/旧再演/復旧の一括導入順を記録。仕様51の時計切替は未実装。単一財布・学習倍率・完全バックアップとともに次候補で検証する。以下の古い「次にすること」の来訪/入居は既に実装済みであり、新たな未着手項目へ数えない。

2026-09-29 一括実装

main 4002e67b から本番へ反映済み。公開URLの390/768幅で初回学習・購入・招待・庭と家・実SW offline・同じ学習の再開を確認。実機/参加者確認は別。

新しい島はぽこもこ1人から、花のそばのベンチ/植物のそばの水ばちへの実呼出、または実配達と食事3回で招待資格を得る。本人の操作でうさぎ/カワウソと暮らす。1人の間はぽこもこが運ぶ。既存3住人は無条件保持。土地は入居や食料でロックせず既存12/24/48へ接続。保存21と旧writer拒否を実装。 検証・main・公開状態。以下の棚卸し/過去記録と区別する。

  • 更新日: 2026-09-29
  • Review By: 2026-10-06
  • 状態: 同じ島で食料の最初の一周、水ばち・木陰・つながる「みずみち」と土の時間変化を実装し、幻想の庭とともに本番へ統合。来訪・入居と土地入口は追加実装。実機確認、固定地形水源、次期時計は後続。
  • 正本: 統合方針
  • 目的: 同じ島・同じ住人で、配置を変えると育ち方や食べ物の届き方が変わり、住人と土地が増える遊びへ進める。

今どこまで進んだか

作業状態
現行の島と試作の違いを整理する整理済み。絵・画面・座標・時間・学習報酬・保存が別だった
方針を一本にする親仕様と統合方針に反映。今の島を本体にし、町の仕組みを取り込む
別の町を仕上げるタスクを退避する旧S1の記録をarchiveへ移動。コード・データ・検証結果は削除していない
育つ→運ぶ→食べる仕組みを同じ島へつなぐ最初の一周を実装。鉢の収穫物を同じ住人が食卓へ運び、在庫があると食べる。配置と通路で結果が変わる
水と木陰で育ち方を変える現行の水ばち・育った木の位置を鉢ごとに読み、収穫までの時間を変える。移動後も途中の成長と在庫は保持
みずみちをつなぐ水ばちから最大8マスの水路が通水。切断・再接続で遠くの鉢の条件が変わり、在庫は保持
土が湿り、乾く所有地の土がLifeの実時間で水分目標に近づく。切断・再接続後も現在の水分を保持して変わる。鉢の育ちと地面の淡い色、持ち物の説明へ接続。新しい土地は基本水分から始まる。固定地形水源は未接続
保存と学習を接続する食料と土は現行Lifeの保存・時計と同じ再生に接続し、それぞれの切替境界を追加。通常学習のwriterと旧Nature Town DB・通貨は変更していない。旧版→版20・実獲得・学習往復・offline・互換復旧を両幅で確認
統合後の画面・動作を確認する純粋計算・保存再開・3Dモデルの自動テストと、食料の画面記録で収穫→運搬→食事→再読込を確認。水路の画面記録で通水→切断→再接続を確認。土の画面記録でスマホ・タブレット幅の接続→時間経過→切断→乾燥→再接続を確認。実機・利用者確認と、物流を含む実経過の長期観察は残る。旧試作の46/47項目は統合後の完成率ではない

次にすること

最初の実装単位「同じ島の一画で、植物を育て、住人が収穫物を運び、食卓に届ける」と、水ばち・木陰・水路・土の時間変化から鉢への影響はローカル実装済み。更新とオフラインの学習・所有保持は検証済み。次は実機で一周を確認し、供給から住人と土地の増加をつなぐ。

  • 本番相当の更新・オフラインで、鉢→住人のかご→食卓→学習往復と経路不通からの復旧を確認する。
  • 固定地形水源を現行の島へどう置くか決める。現在の水源は所有した水ばちのみ。
  • 供給の継続から来訪・入居・土地拡張をつなぐ。小さな一周だけで全体完了としない。

完了条件

  • 通常の島から別画風の町へ移動せず、同じ場所・住人・家で遊べる。
  • 実際の育成・在庫・配送・共同食・入居・土地拡張がつながる。
  • 学習履歴、途中の問題、作品、購入済みの物、住人と土地を保つ。
  • スマホとタブレットで配置→変化→学習→再開を確認。無音・動き抑制でも状態が分かる。
  • 検証結果を「絵の魅力」「子どもの理解と安全」「動作と保存」に分け、未確認を明記する。

Verification

変更後の確認：

  • 食料の収穫・配送・食事、道の不通、配置変更時の在庫保全、保存境界と再読込、実際の3D住人のかごを自動テストする。
  • npm run verify:core と島の関連画面テストを実行し、失敗の原因を分けて記録する。
  • 実機phone/tablet、学習往復、オフライン更新、絵の魅力、子どもの無説明理解を別々に確認する。未確認を完成率へ加えない。
