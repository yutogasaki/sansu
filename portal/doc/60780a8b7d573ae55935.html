0. 結論

18章の分析（何が楽しくないか）は維持する。変えるのは設計の順序とメカニクスの出所の2点である。

項目これまでこれから
設計順序ゲームを決め、それに載る問題を選ぶ問題を前提に固定し、それを収容できるゲームを選ぶ
メカニクスの出所Sansu固有の操作文法を発明する実績ある構造の操作文法と報酬構造だけを借用する
検証の主対象「この遊びは面白いか」「借りた遊びに算数が壊れずに載るか」

採用候補の中心は次の一文である。

> これから解く問題そのものを、リスクとリターンのある賭けとして自分で選ぶ。

仮称を 「かけ探検」、candidate id を core-wager-v1 とする。§7の人力テストと§8のゲートを通るまで最終コアとして採用しない。

1. 前提（問題の実態）

正本は 02_math_skills.md と 04_math_problems.md。

項目実態
範囲未就学児〜小6、118スキル / 29レベル
内容公文型の計算（四則、位取り、小数、分数、割合・比・速さ）。図形・文章題・グラフは扱わない
入力テンキー single 75 / 選択式 choice 31 / 筆算など multi 12
1問の長さ数秒。同一runでも問題ごとに大きく変動する
出題主体共通plannerとSRS。子どもは出題内容を選べない
誤答の扱い学習上の誤答をゲーム失敗の原因にしない（18章 §5.6）

2. 前提から導かれるゲーム側の必須条件

No条件理由
1可変長・可変レイテンシの二値イベント列を燃料にできる2秒で解ける問題と20秒かかる問題が同一run内に混在する
2注意チャネルは1本として設計する繰り上がりを計算している子は、同時に画面の連鎖を見て判断できない。リアルタイム同時進行は成立しない
3判断は問題と問題の間に置く条件2の帰結。ターン制であることが必須になる
4118スキル全部に載る載らないメカニクスを中心に据えると、必ず「そのゲームに合う問題」を選ぶことになる
5誤答は学習成果を没収しない18章 §5.6 と 15章の学習安全境界

条件4が、これまでの候補を落とす基準になる。18章 §11 の候補C（number-suika）は同章自身が「加法しか載らない。引き算、掛け算、割り算、筆算、割合・平均・比・速さ、非数量skillは載らない」と明記している。候補A（chain-shot）も、18章 §5.3 の MathActionContract を全スキル分は書けないため、同じ壁に当たる。

メカニクスの被覆率が100%でない限り、問題編成をメカニクスに合わせて曲げる圧力が必ず発生する。

3. 全118スキルに共通する統合軸

3.1 軸の棚卸し

軸全118スキルが持つかゲームへの変換
難易度持つ（plannerが既にレベル・スキル・履歴として保持）難しい問題を選ぶ＝ハイリスク・ハイリターンの賭け
速さ持つ（解答時間は全スキルで計測できる）倍率・コンボ
数量の意味（和・差・積・商・位取り・分割）持たない（スキルごとに異なる）契約を書けるスキルでのみ世界作用へ翻訳できる

したがって、算数を通行料にしない内在的統合を全スキルで成立させるなら、翻訳すべきは答えの中身ではなく、問題の難しさと自分の速さである。

3.2 統合の2層構造

18章 §5.3 の MathActionContract は廃止しない。コアから外して追加レイヤへ降ろす。

共通レイヤ（全118スキル / 必須）
  難易度 → 賭けの大きさ
  速さ   → 倍率

深いレイヤ（契約が書けるスキルのみ / 任意）
  operand と result → 世界作用の大きさと種類

契約のないskillは18章 §5.3 のとおり中立presentationへfail-closedするが、その場合でも共通レイヤは動くため、体験が欠落しない。これが現行案との最大の違いである。

3.3 内在的統合としての正直な評価

Habgood & Ainsworth の言う intrinsic integration は「学習内容そのものがコアメカニクスの中で表現されている」ことを指す。難易度と速さを賭けるのは、学習内容そのものではなく学習の困難さと習熟度を賭けている。したがってこれは完全な内在的統合ではなく、中間である。

  • 通行料版（正解でゲージが貯まるだけ）より上
  • 数量が直接メカニクスになる版（候補C）より下
  • ただし候補Cは被覆20〜30%であり、残り70〜80%のスキルでは通行料版に退化する

平均すれば中間案の方が高い、というのが採用理由である。全スキルで深い統合を得る方法は現時点で存在しない。

4. 借用方針

4.1 3層に分けて層ごとに借りる

層時間借り元候補借りるもの
A 瞬間の反応0〜1秒Balatroの得点積み上げ演出 / パズドラのダメージ表示 / マリオのコイン正解1件に対する即時フィードバックの形
B run内の判断30〜120秒Slay the Spireの道選択 / Balatroのブラインド選択とスキップ / Vampire Survivorsのレベルアップ3択 / Plants vs. Zombiesの波間配置選択肢の提示形式と報酬構造
C run間の持ち越し日をまたぐHadesの永続強化 / ポケモンの図鑑と手持ち / どうぶつの森の蓄積再訪動機の作り方

面白さの本体はB層にある。Vampire SurvivorsもBalatroも、1回の入力自体はほぼ無であるにもかかわらず強い再プレイ動機を持つ。理由はビルドと選択であって操作の手触りではない。

算数ドリルは「単発操作が単調で反復が多い」という点で、これらと同じ形をしている。 テンキー入力である限り、操作の手触り自体を面白さの主軸にすることはできない。A層は650ms / 550ms制約に収まる軽い演出で足り、発明する必要はない。

4.2 借りるもの / 借りないもの

18章 §3.2 を維持する。

  • 借りる: 操作文法、選択肢の構造、報酬構造、run単位の設計
  • 借りない: キャラクター、固有名、アート、造形、音、画面構図、固有システム名

5. 組み合わせ候補の比較

  • 採用候補は案2を軸に、案1のB層（3択ビルド）と案5のC層（基地が育つ）を接続したハイブリッドとする。

6. 採用候補「かけ探検」の骨子

6.1 1 runの形

1. plannerが「いま出してよい」assignmentの集合を予約する
2. その集合から3つの札を作って提示する
     例: かんたん3問（小報酬） / ふつう2問（中報酬） / むずかしい1問（大報酬）
3. 子どもが1枚選ぶ
4. 選んだ札の問題を黙々と解く（判断を挟まない。注意チャネル1本）
5. 結果を見る（速さが倍率になる）
6. 数手ごとに3択のビルド強化が入る
7. run終了時に1つ持ち帰り、基地が変わる

判断は 3 と 6 だけに置く。4の最中には何も判断させない。これが条件2・3への回答である。

6.2 plannerとの境界

18章 §5.3 は「対象選択でcategory、source、難度、問題値を変えない」と定めている。本案はこの制約を意図的に破るため、境界を書き直す。

  • plannerは単一のassignmentではなく、すべて出題妥当な候補集合を予約する。
  • 子どもが選べるのは、その集合の内側だけである。どれを選んでもSRS、Due、weak、解放guardの正当性は壊れない。
  • 難易度を子どもが選べる以上、苦手・Due項目の回避が起こりうる。少なくとも1枚には必ずDueまたはweakを含める。「かんたん」札にもDueを混ぜ、回避できる逃げ道を作らない。
  • 演出都合で問題を差し替えない点は18章 §5.3 のまま維持する。

正式決定は 11_learning_integration_spec.md で行う。

6.3 誤答と失敗

  • 誤答はenergyを減らさず、run終了へも近づけない。同じ問題へ戻す（誤答後550ms目標）。
  • ゲーム上の失敗は「むずかしい札を選んで時間内に終わらなかった」など、自分の賭けの結果からのみ発生する。
  • 失敗しても、確定済みの学習成果、図鑑、bank済みの持ち帰りは失わない。賭けるのは未確定のrun報酬だけである。

6.4 速さの扱い

  • 速さは倍率にする。ただし急かす演出はしない。カウントダウン、赤い警告、失敗音は使わない。
  • 遅くても報酬は0にならない。倍率が1倍に留まるだけとする。
  • reduced motion / sound off でも倍率が読めること。

6.5 持ち越し

18章 §6.3 の「runから2つ以上残す」を維持する。持ち帰るのは、次runの札の内容か倍率か基地の状態を実際に変えるものに限る。

7. 絞り込み手順

7.1 実装済みのラボ（2026-07-26）

案2の実画面を dev専用ルート /#/__dev/wager に実装した。candidate は core-wager-v1。

要素実装内容
札の選択やさしい3問 / ふつう2問 / むずかしい1問。それぞれ baseLevel −1 / 0 / +1 のレベル帯から実問題を引く
出題既存の算数ジェネレータから実問題を生成し、既存TenKeyで解く。planner / SRS へは接続しない（G1の課題）
速さ3秒以内×3、6秒以内×2、それ以外×1。カウントダウンなし、遅くても0点にしない
誤答減点なし、run終了なし、同じ問題へ戻す。その問題の倍率が1に固定されるだけ
ビルド各ラウンド後に道具の3択
目標と持ち越し4ラウンドで目標点。届いた run のあとだけ次の目標が上がる（ante）。届かなくても道具を1つ持ち帰る

目標点は ante 1 が 300、以降 +80。この 300 は「1問ずつ時間をかけて正解する子（倍率1倍）でも、むずかしい札を選び続ければ360で届く」下限として置いた。学習の遅さがクリア不能に直結しないことを、src/domain/explore/__tests__/wagerRun.test.ts の不変条件として固定している。

ラボは試験器が動く証拠であり、楽しさのPASSではない。判定は §7.3 の観察で行う。

7.2 実プレイで判明した設計の穴

目標点に届いた後も残りラウンドを消化させるため、先に目標を超えると最後の1〜2ラウンドが無意味になる。18章 §5.7 の「帰る / 続ける」がこの穴に対する既存の答えであり、目標到達時点で「ここで帰る / 賭けを続けて上乗せする」を出す形へ変える必要がある。未着手。

7.3 観察（実装ゼロでも回せる）

ラボが使えない場面では紙でも回せる。/study は既に動作しているため、B層は人力で代替できる。

項目内容
準備紙の札3枚（かんたん3問 / ふつう2問 / むずかしい1問）と、報酬を書いたメモ
進行子どもは /study で実際に問題を解く。大人が横で札を出し、結果を口頭で伝える
所要1案あたり5分
比較案2（賭け型）を最初に回す。落ちた場合のみ案1（サバイバー型）を回す

観察項目（アンケートで代替しない）:

  • 札を選ぶとき、迷うか。即座に一番簡単な札へ固定されないか。
  • 「次はむずかしい方をやる」という発話が出るか。
  • 終了後、こちらから誘わずにもう一度やろうとするか。
  • 失敗した後に再挑戦するか。
  • 誤答を「自分が悪い」と受け取っていないか。

停止条件:

  • 3回連続で最も簡単な札しか選ばない → 報酬設計を直す。それでも変わらなければ案2を落とす。
  • 自発的な2run目が起きない → 案を落とす。演出で救済しない。

紙で落ちた案にコードは書かない。

8. 検証ゲートの改訂

18章 §11 のG0〜G2を置き換えるのではなく、借用方針に合わせてG0の役割を縮小する。

9. デザイン先行定義の扱い

18章 §9.3 は「grayboxの楽しさゲートを通るまで画像生成を始めない」と定めている。この規則は自分でメカニクスを発明する場合には正しいが、実績ある構造を借用する場合は前提が変わる。

  • 借り元が既に再プレイ動機を証明しているため、「この遊びは面白いか」の不確実性は下がる。
  • 残る不確実性は「算数が壊れずに載るか」だけであり、これはG1で判定できる。
  • したがって、§7の人力テストを通過した時点で、網羅的なデザイン定義に着手してよい。

順序:

借り元の決定（本文書）
→ §7 の人力テスト（実装ゼロ）
→ 網羅的なデザイン定義（世界観、キャラ規約、UI規約、モーション規約、色・タイポ）
→ G1 実算数接続
→ 作り込み
→ G2 と three-gate visual監査

網羅定義の対象は 07_ui_design_guideline.md、14_ui_world_motion_spec.md、design-system/MASTER.md に接続する。完成frameの量産ではなく、規約と部品の定義を先に置く。

plannerは単一のassignmentではなく、**すべて出題妥当な候補集合**を予約する。\n- 子どもが選べるのは、その集合の内側だけである。どれを選んでもSRS、Due、weak、解放guardの正当性は壊れない。\n- ゲーム上の失敗は「むずかしい札を選んで時間内に終わらなかった」など、**自分の賭けの結果**からのみ発生する。\n- 失敗しても、確定済みの学習成果、図鑑、bank済みの持ち帰りは失わない。賭けるのは未確定のrun報酬だけである。\n\n### 6.4 速さの扱い\n\n- 速さは倍率にする。ただし**急かす演出はしない**。カウントダウン、赤い警告、失敗音は使わない。\n- 遅くても報酬は0にならない。倍率が1倍に留まるだけとする。\n- reduced motion / sound off でも倍率が読めること。\n\n### 6.5 持ち越し\n\n18章 §6.3 の「runから2つ以上残す」を維持する。持ち帰るのは、次runの札の内容か倍率か基地の状態を実際に変えるものに限る。\n\n## 7. 絞り込み手順\n\n### 7.1
