2026-10-01: 教材の意味・種類・導入の整合性を適用する。既存ID・所属と保存済み予約を維持し、語義/例文、問題の範囲・型、追加の基礎導入を修正する。新規文脈はcurriculum-v2とし、旧文脈は保存版のまま検証する。

親仕様は 01_app_spec.md。単元と証拠の共通契約は 31_learning_units_spec.md、既存の生成規則は 03_english_skills.md、教材本文は 05_english_words.md に従う。

今回の対応範囲

既存1,184項目をそれぞれ「表示された英語の綴りから訳語を選ぶ」単元へ対応させる。1,184単元は語義別の証拠を保存する粒度であり、子どもに提示する授業やメニューの数ではない。20レベルを校正済みの習熟段階とみなさず、既存の出題・進度・保護者設定を維持する。

項目契約
カタログ版新規は共通の curriculum-v2（v1保存を保持）
単元IDvocab.recognition. + 既存教材ID
対応全1,184項目から各1単元へ1対1
系統vocabulary-recognition
表現・問題の型recognition / default
前提・推奨前提今回は双方空配列。語彙の出現順から前提関係を推定しない
提供状況全単元 existing
表示ラベルsurface ?? id と既存かな訳

同じ綴りの11組も、保存IDごとに別単元とする。異なる綴りは1,173。同義properlyの再登場を除く語義識別子は1,183。orangeとorange_lv2、同義の再登場であるproperlyとproperly_lv18も統合せず、過去の正解・Due・強度を別項目へコピーしない。訳語4択から聞く・話す・綴る・文脈で使う能力の達成を作らない。新規問題の文脈や独力・支援の証拠は仕様31に従う。

既存の分類と棚卸しAPI

既存のcategoryは49種類で、「食べ物」などのテーマと「形容詞」などの品詞が混在する。カタログはこの分類を保持するが、品詞解析、授業の区切り、難度推定には使わない。

src/domain/learning/englishCatalog.ts は ENGLISH_LEARNING_UNITS と ENGLISH_ITEM_MAPPINGS を公開する。getEnglishCatalogInventory() はレポート向けに次を返す。

  • itemCount / unitCount / distinctSpellingCount / distinctSenseCount / legacyCategoryCount
  • legacyLevels: レベル番号順の { level, itemCount }
  • legacyCategories: 元教材の初出順の { category, itemCount }

各数値は教材から集計する。レベル別件数は1〜20の順に 60, 59, 60, 60, 60, 60, 60, 59, 60, 60, 60, 60, 60, 60, 60, 59, 60, 60, 60, 47。分類は既存教材の在庫情報として報告し、単元の適切さや習得率の証明にはしない。

教材の校訂

既存かな訳の2点の訂正に加え、教材整合性の契約に従って採用語義に合わせた20例文と同義の誤答選択肢を修正する。

教材ID旧かな校訂後既存漢字訳
positiveぜんむきなまえむきな前向きな
localちもとのじもとの地元の

ID、レベル、漢字訳、既存記録は変えない。全教材の語義・品詞・自然さの校閲を完了したとはみなさない。

入門の小単元へ進む条件

2026-09-09: 回答を求めない任意の短文リスニングは英語仕様03・第7節に採用し、10文の初版を実装した。以下は能動的な小単元の後続候補であり、短文を聞くだけの体験の前提条件ではない。既存の1,184認識単元へ聴取の達成を加えない。

幼児〜小3向けの音声・絵による入門は後続段階。現カタログは訳語選択の教材であり、承認済みの音声カリキュラムではない。

試作順小単元の候補必要な内容と確認
1身近なものの音を聞いて絵を選ぶ対象語・語義、発音音声、誤解のない絵、選択肢の適切さを校閲。日本語を読まなくても操作できる
2身近な短い指示を聞いて動かす指示表現と絵・動作を用意し、単語の意味理解と指示全体の理解を区別
3慣れた語の音と文字を結ぶ同じ語義について音声と綴りを接続し、訳語4択とは別の証拠を保存

既存のEnglishWordは校閲済み音声や絵の教材参照を持たない。追加単元には音声・画像の権利、正しい発音と意味の対応、オフライン配信、音声再生失敗時の復帰を確認する必要がある。通常利用へ入れる前に、端末ごとの再生、翌日・1週間後の理解、再び遊びたいかを確かめる。発話・綴り入力を追加するときも個別に内容と評価方法を設計し、既存の4択実績から達成扱いにしない。

検証

englishCatalog.test.ts で全件の対応・ID一意性・旧レベル保持・同綴り項目の分離・認識以外の推定がないこと・棚卸し件数を確認する。english/generator.test.ts の全項目走査で、かな校訂後も4択の表示ラベルが重複しないことを確認する。
