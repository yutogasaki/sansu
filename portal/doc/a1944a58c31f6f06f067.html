1. 基本方針

1.1 コンセプト

公文式のように「計算力」に特化

  • 四則演算、分数、小数の計算スキルを段階的に習得
  • 四則・小数・分数の計算領域を扱う。公文A〜Fの全教材への適合認定ではない
  • 幼児の数量・形・空間・比較と、割合・平均・比・速さの限定した問題を含む。面積・角度・図形全般・グラフなど学校算数全体は対象としない
  • 「考える」より「手が動く」トレーニング

1.2 対象範囲

項目内容
対象学年未就学児〜小学6年
スキル数旧118スキル（29レベルに分類）+基礎導入9教材（所属は別）
出題形式数字入力（テンキー）・選択式

1.3 学び方の戦略

同じ計算内容でも、表現を行き来する力 と 解き方を選ぶ力 を育てる。

通常のメイン／メイン+1出題は、解放上限・明示的なレベル無効設定・当日停止・同一区間の上限を守り、直近出題の偏りを避けた候補から、未学習、記憶強度の低いスキルを優先する。Dueと表現フォローの優先順位は維持する。レベル配列を持たない旧プロフィールは解放上限内を対象とし、既存ID・所属は変更しない。学習曲線の共通契約は 29_learning_progression_spec.md を参照。

段階役割典型表現身につけたいこと
Concrete具体物で理解する絵、物、まとまり数の意味、増える・減る実感
Bridge具体物と式をつなぐ絵 + 式目で見た変化を式に写す
Symbol記号だけで処理する8 + 7 =抽象的に計算する
Strategy考え方を選ぶ10をつくる、差で考える、分ける複数の解法を使い分ける
Mental頭の中で処理する暗算、途中式なし速さと見通し
Algorithm手順で処理する筆算、標準アルゴリズム正確さと位の整列
Reverse逆から考える引き算を足し算で考える、割り算を掛け算で考える関係理解と柔軟性

方針:

  • 初学では Concrete と Bridge を厚くする。
  • 定着期では Symbol と Strategy を増やす。
  • 桁数が増えたら Mental と Algorithm を分けて育てる。
  • 同じ答えに複数の解き方がある内容は、別スキルとして分けてもよい。

1.6 Lv13-18 教材改善プラン

現状の Lv13-18 は、九九暗記 -> 数字だけの掛け算 -> 数字だけの割り算 へ進む比率が高い。

教材としては、同じ意味を別表現で往復する段階 と 暗算/手順を分ける段階 を足したほうが伸びやすい。

前提:

  • 既存の mul_99_*, mul_2d1d, div_99_rev, div_rem_q1 などは残す。
  • 追加スキルは、既存レベルの前後に差し込むか、補助レベルとして併置する。
  • 1問ごとのランダム性より、導入 -> 変換 -> 定着 の小さな束を意識する。

  • mul_group_intro: 1問の中で「同じ数ずつ」を複数グループで見せる。
  • mul_skip_count: 数列と集まりの両方を使い、2,4,6,8 と 2 × 4 をつなぐ。
  • mul_array_intro: 行と列の向きを変えても同じ数になる経験を入れる。
  • mul_formula_match: 絵 -> 式 と 式 -> 絵 の両方向を含む。
  • mul_2d1d_mental_split: 20 × 3 と 4 × 3 に分ける型を固定する。
  • mul_2d1d_algorithm: 途中の位と部分積が見える UI を前提にする。

  • div_measure_intro: 「2こずつ取ると何回」で、等分と区別して出す。
  • div_inverse_intro: 掛け算の空欄補充と割り算を同じ答えで往復させる。

1.7 共通で足したい出題タイプ

スキル追加と同じくらい、問い方の種類 を増やすことが教材として重要。

出題タイプ例ねらい入れたい領域

  • 3問目は Mental または Algorithm

1.9 筆算と復習の改善プラン

  • 暗算で失敗した -> 位取りを見せる
  • 筆算で失敗した -> 途中手順を問う
  • 比較で失敗した -> 数直線や表へ戻す
  • 割合で失敗した -> 表スキルへ戻す

ミニレッスン復習の例:

  • frac_compare で失敗したら frac_number_line
  • 次に frac_equiv_visual
  • 最後に frac_compare へ戻す

この構成にすると、単なる再挑戦ではなく「理解が足りなかった場所」まで戻せる。

注:

  • representation_retry や mini_lesson_review の発火条件・混入比率は 01_app_spec.md の 5.4-5.5 を参照する。

5.2 テンキーUI

自動採点と確定キー

  • 対象はStudy（復習・テストを含む）、島、遊園地。旧探索・対戦は独立した操作契約を維持する。
  • 整数・小数・分数・帯分数・商/余りは、正規の答えの各欄に対応する桁マスを最初から表示する。1桁でも複数桁でも最後の数字で正誤を問わず即時採点する。各欄が埋まると次の未入力欄へ移る。小数点の位置は空マスで示し、. キーで入力する。数字だけでは小数点を自動補完しない。Enterや入力停止待ちは通常回答に不要。
  • マス数・小数点位置の提示はテンポを優先した意図的な学習上の足場とする。値の一致を確定条件にしない。正規の分数表記（約分済み指定を含む）のマスで回答する。採点・SRS・支援後の独力扱いは既存経路を維持するが、桁数や小数点位置そのものを独力で選んだ証拠にはしない。その判断を直接測る問題は選択式などの別形式にし、通常のマス入力へ手動確定を混ぜない。
  • 筆算は、現在段の必要セルがすべて埋まった最後の入力で自動採点する。途中段の正解は次の段へ進むだけで、一問完了・報酬・独力正解として数えない。
  • 割り算の新規短縮版は、商の各桁を入力すると、その桁のかける・ひく・おろす行を計算結果として表示する。あまりありは最後のあまりだけを入力する。計算結果の表示は正解数字の補完ではなく、次の商を考えるための確定済みの途中式であり、商の途中の0も入力対象に含める。
  • 筆算の誤答が採点・保存されたら、現在の行の入力をすべて空欄に戻し、小数点を含めて左から入れ直す。確定済みの前の行と位合わせ用の補助0は保持する。現在行が再びすべて埋まった時点で採点する。入力途中の桁単位採点や正解数字の補完はしない。訂正後の完了も従来の誤答後の学習証拠として扱い、独力扱いへ戻さない。
  • 数字の値は埋めない。マス数だけを導出し、入力途中の正誤判定・タイマー採点は行わない。Backspaceは小数点も含め、最後に入力した1文字を消す。自動移動後の空欄では直前に入力した欄へ戻して消す。欄を任意順に埋めた場合は末尾から先頭へ巡回し、未入力欄へ移る。自動移動直後の / は空の欄を飛ばさない。矢印・欄の選択・消去は次の数字入力より先に反映し、入力中の訂正を維持する。既存フィールド長ではなく表示マスと同じ長さで完了を判定する。
  • 正答一致や入力停止タイマーを自動確定条件にしない。表示マスの充足だけで確定する。採点/SRS/支援の計算は既存の経路を使う。
  • タッチと物理キーで同じ動作とし、保存中・お手本中・押し続け・同一イベント内の連打からの二重回答を止める。誤答は従来の訂正経路を使える。保存失敗では下書きを残し、決定キーによる再送を可能にする。島の3列テンキーは通常の自動回答中（送信直後・保存中を含む）に「こたえる」行を追加せず、問題とキーの配置を保つ。再送用の行は保存失敗で同じ下書きが再び操作可能になった場合だけ表示する。
  • キー配置を動かさず、自動採点時の決定は薄い非操作状態、手動確定の入力がそろったときは明るい面と二重枠を表示する。未操作の間だけ周囲の光を1.2秒周期で2回動かす。一度の手動確定で案内の動きを終了し、端末のlocalStorageに専用の表示設定1項目として記憶する。再起動後も静止表示を維持する。読み書きが拒否された場合は起動中だけ記憶し、解答を止めない。プロフィール/学習記録へ保存しない。reduced motionは静止した枠と面だけを使う。
  • 筆算の自動採点中は、決定と画面上の左右キーをボタンのない同じ大きさの空き領域にする。数字、戻す、現在段の消去を維持し、マスの直接タップと物理矢印で訂正位置を選べる。保存失敗後は同じ位置へ再送用の決定を出す。

interface MathSkill {

  | "counting"      // 数の基礎

  | "subtraction"   // 引き算
  | "multiplication"// 掛け算
  | "division"      // 割り算

  | "numpad"        // 整数テンキー

  | "remainder"     // 商・余りパッド

  | "concrete"
  | "bridge"
  | "symbol"
  | "strategy"
  | "mental"
  | "algorithm"
  | "reverse";
