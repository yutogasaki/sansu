2026-07-24 — PWA update pickup hardening

  • Reduced visible-session update polling from five minutes to a maximum of 60 seconds and made every React Router navigation trigger a fresh Service Worker and version.json check.
  • Preserved the existing child-safe boundary: an update may reload before interaction, but an active onboarding, Study, Explore, or Battle session and any critical persistence continue to defer it until the next safe checkpoint.
  • Extended the production-preview regression with a Service Worker-enabled browser context that proves a real version.json drift detected on SPA navigation resets only app-managed caches, preserves the destination, and reloads exactly once.
  • Updated the parent PWA contract and release runbook. No schema, learning, host-header, durable-memory, or ADR change was needed.

  • npm run docs:check, npm run lint, npm run typecheck: PASS
  • npm run test:run: PASS (91 files / 844 tests)
  • npm run build: PASS (PWA generation and asset budget included)
  • npm run e2e:smoke: PASS (31/31)
  • npm run e2e:pwa-update: PASS (four update handoff/recovery scenarios, including Service Worker-controlled version drift)
  • PWA precache: PASS (85 files, 9.87 MiB / 12 MiB)
  • iOS relaunch timing and a real hosted two-build deployment remain release-device checks because offline or OS-suspended clients cannot update until the next online resume

2026-07-23 — PWA update handoff

  • Reworked update protection around the current protected-route session instead of a once-per-app interaction flag: /onboarding, /study, /explore, and /battle/play can accept a new build before their first interaction, then protect in-memory progress after interaction.
  • Re-armed the pre-interaction update window from React Router location keys rather than native hashchange, kept pointer/key tracking alive across SPA route changes, and preserved single-shot reload at the next safe route.
  • Added explicit same-route boundaries on Explore replay, Battle cancel/replay, and Study continue. Result, reward, and break screens remain visible until the child chooses the next action; periodic-test result UI appears only after its completion/profile persistence resolves, while replay/continue remains the first protected interaction of the next active session.
  • Added production-preview regressions for safe Router handoff, direct interacted Explore → Study protected Router handoff with delayed recovery, and interacted Battle cancel on the same URL; duplicate update signals must still produce one reload.
  • Added a global critical-persistence hold around Study answer/test writes and Explore run/attempt writes, so a route change cannot release a deferred update while IndexedDB work is still in flight. The protected Router E2E now holds persistence across the handoff and proves reload waits for release.
  • Made the canonical appData profile and legacy profiles mirror update in one Dexie transaction, applied session progression/results against the latest owned profile snapshot, and kept failed fixed-session completion retryable without duplicating a periodic-test result. Explore persistence continuations now stop UI timers, sounds, and navigation when their component or run is no longer current.
  • Kept the existing version-drift recovery, Service Worker cache boundary, URL marker behavior, IndexedDB/localStorage safety, and host no-cache rules unchanged.
  • Updated the parent PWA contract, release runbook, and durable memory; no schema, learning, hosting, or ADR change was needed.

Verification:

  • npm run verify:core: PASS (76 files / 695 tests; docs, lint, typecheck, production build, PWA generation, and asset checks included)
  • npm run e2e:smoke: PASS
  • npm run e2e:pwa-update: PASS (safe and protected Router handoffs, persistence-held delayed recovery, same-route Battle checkpoint, duplicate-signal single reload)
  • Real Chromium Service Worker update: PASS for build pickup and hashed-bundle replacement; the automated production-preview gate now owns route/checkpoint ordering, while the full real two-build matrix and iOS relaunch remain release-device checks
  • PWA precache: PASS (82 entries, 8.25 MiB / 12 MiB); iOS relaunch timing remains a release-device manual check

2026-07-19 — Explore Attempt Identity foundation

  • Added a pure { profileId, runId, gateId, attemptNumber } identity with one-based validation and a versioned stable idempotency key.
  • Made the generated Problem.categoryId after assistance or fallback the authoritative skill at the future learning-record boundary.
  • Fixed the next-loop contract: current nearby exploration problems remain affectsSrs = false, gameplay advances only after a saved receipt, and save failures retry the same Problem and identity.

Verification:

  • Exploration domain: PASS (8 files / 83 tests)
  • npm run docs:check, npm run lint, npm run typecheck: PASS

2026-07-19 — Explore persistence receipts

  • Added Dexie version 5 with profile-scoped exploration runs, run events, and discoveries while preserving representative version 4 profile, log, memory, and AppData rows unchanged.
  • Added atomic startExploreRun and idempotent commitExploreAttempt operations. A versioned AttemptIdentity key returns the original saved receipt on sequential or two-connection concurrent resend without double-counting run totals.
  • Kept current nearby exploration problems at affectsSrs = false; answer commits do not write existing logs, SRS memory, weak state, unlock state, or learning-profile progress.
  • Added rollback, ownership, conflicting resend, profile isolation, and profile-deletion coverage with fake IndexedDB. Independent review found no P0/P1 issues.

Verification:

  • npm run verify:core: PASS (56 files / 522 tests; docs, lint, typecheck, production build, and asset checks included)
  • Persistence repository: PASS (15 migration, atomicity, idempotency, concurrency, rollback, and deletion tests)

2026-07-19 — Explore receipt-driven gameplay and run lifecycle

  • Bound each in-memory run to its successfully persisted profile/run start, then replaced raw correct/incorrect/return reducer actions with validated answer and terminal receipts.
  • Added the saved answer result to receipts and rejected mismatched profile, run, gate, one-based attempt number, actual problem skill, result, stable key, or affectsSrs claims. Duplicate receipts no longer double-progress gameplay.
  • Froze Problem, answer, result, and AttemptIdentity across retries; disabled same-tick click/Enter duplication; and advanced feedback, energy, attempts, discoveries, and problem refresh only after commit success.
  • Added child-safe inline recovery that keeps the exact problem, entered answer, attempt count, and energy after a write failure. Start failure can be retried or safely exited without leaving a run.
  • Added idempotent finishExploreRun / run_ended persistence for returned, rescued, and abandoned endings. Return/rescue reaches summary only after finish success, active exit waits for abandoned, and a new start transaction converges each profile to one active run.
  • Preserved the final-discovery story: a last-light correct answer remains active through DiscoveryReveal and is saved as rescued only after the child continues. Return failure keeps status and confirmed finds unadvanced until retry succeeds.
  • Kept current nearby exploration problems at affectsSrs = false; existing logs, SRS memory, weak state, unlock state, and learning progress remain unchanged.

  • Reducer / persistence repository: PASS (24 + 19 tests)
  • npm run e2e:smoke: PASS (19/19, including start failure exit, abandoned exit, open-attempt return guard, rapid double submit, frozen-identity retry, last-light rescue ordering, return-finish retry, and existing Research/encounter regressions)
  • Independent receipt integration audit: no P0/P1 findings

2026-07-18 — Exploration direction, /explore MVP, and app-wide consistency

  • Reframed the product around a replayable, child-safe math exploration game while preserving the existing learning-system source of truth.

  • Added a pure in-memory exploration domain with a deterministic 15-node map and eight-action route depth, visible route tendencies, an unavoidable bridge event, meaningful bridge costs/reward tendencies, four discovery families, voluntary return, and energy-depletion rescue.

  • Made profile deletion remove its owned logs and SRS rows atomically, and made the full-reset action remove every stored profile.
  • Bounded fraction/advanced random generation under constant RNG, repaired invalid zero/equivalent fraction subtraction cases, and expanded regression coverage.
  • Protected in-memory onboarding/study/exploration/battle progress from forced PWA reloads, repaired stale active-profile pointers, and brought the smoke suite fixtures/navigation back in sync with current screens.
