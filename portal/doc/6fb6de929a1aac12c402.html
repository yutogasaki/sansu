Purpose

タスク・リポジトリの概要・ドキュメントをブラウザで確認するためのローカル閲覧用ページ。

アプリの機能・学習・保存・配布仕様は変更しないため、プロダクト仕様の変更は不要。

入口

通常入口は共通概要。共通ナビは概要／計画／仕事／知識・仕様／役割・手順／運用。以下の旧入口は専門索引として保持する。内部資料のため公開配布へコピーしない。

  • リポジトリ概要
  • 現在のタスク
  • 仕様と実装のマップ
  • ドキュメント索引

HTMLはファイルを直接ブラウザで開ける。サーバーや外部通信は不要。

タスクは「詳細を読む」で元のMarkdown本文を確認できる。各カードのタイトルは正本へのリンク。

ページ内検索でタイトル・パス・説明を絞り込める。タスクは詳細本文も検索対象。

「仕様と実装」では今の島の主な機能を、今できること・次にすること・方針・実装・動作確認・実機／利用者確認で示す。上部の件数は掲載項目の内訳であり、アプリ全体の完成率ではない。状態は生成器内の一覧で明示し、詳細と受入判定はリンク先の仕様・共有タスクを正とする。仕様書は docs/product/README.md の位置づけをもとに、現在のルール／採用済み／開発用・次期案／旧モードに分ける。旧モードと制作・検証の履歴は折りたたんで今の島と分ける。目次から各区分へ移動でき、検索で旧モードが見つかると履歴欄が開く。

主な進捗欄には通常起動の島の機能だけを載せる。家から店へのDEV試作は別枠に置き、今の島の家とは混同しない。「今の島にはない」は、別の試作に計算があっても通常の島では遊べないことを示す。

素材欄は assets/、public/assets/、src/assets/ 内の画像・3D・音声・動画・PDFをフォルダ単位で集計する。島の候補は代表画像を一覧に示し、フォルダを開くと画像4点、さらに開くと残りのファイル名と容量を確認できる。PNG・JPEG・WebPにはヘッダーから取得した縦横のピクセル数も表示する。docs/design/ の制作・検証生成物は日付順のフォルダごとの件数と合計容量、容量上位3件を表示する。画像を選ぶと元画像を開ける。生成HTMLも一覧に載せる。容量はローカルファイルの実容量であり、転送時の圧縮容量や公開状態ではない。ビルド出力 dist/ は一覧に含めない。指定ディレクトリ内に一時ファイルを置くと集計対象になるため、再生成前に除く。

更新

正本のMarkdownを編集したら、リポジトリのルートで実行する。

npm run agent:index
npm run agent:index:check
npm run docs:check

生成HTMLを直接編集しない。生成器は tools/generate-agent-index.mjs。

更新漏れチェックは元の文書から再計算したHTMLと比較し、不一致なら失敗する。

Source of truth

2026-09-29の整理では実行キューを4担当へ集約。v3・家のDEV試作・横断索引は参照として保持し、実行件数に含めない。学習v8と性能の残件は機能マップにも表示する。公開照合と実機・利用者確認を実装済みと混同しない。

実行中の一覧は .agents/tasks/TASKS.md、詳細はそこから参照する docs/tasks/active/*.md。

保留は .agents/tasks/BLOCKED.md、計画は docs/tasks/backlog.md、完了履歴の入口は .agents/tasks/DONE.md。

履歴や古い詳細ファイルの存在から現在のタスク状態を推測しない。

HTMLは生成時点のスナップショットであり、公開・検証完了の判定には使わない。機能の状態が変わったら、共有タスクと仕様を更新し、生成器の機能マップも照合してから再生成する。

今回の限定検証

検証契約に範囲・依存・修正上限を定義する。node tools/check-internal-portal.mjs で共通ナビ・旧アンカー・リンクと依存の異常系を確認。既存の verify:core が必須、4幅のbrowserと独立レビューはローカルで別取得する。原証拠は /tmp/sansu-common-portal-application/。再生成のみで検証済みやユーザー受入としない。

永続ローカル証拠

今回の原証拠を gitignored output/internal-portal-evidence/sansu-common-portal-application/ へ内容不変で保全。通常概要の「今回の検証証拠」からローカル閲覧できる。原文の /tmp/ は取得時の記録として残し、保存先 archive-manifest.json の対応で解決する。node output/internal-portal-evidence/sansu-common-portal-application/validate-archive.mjs は保存先だけを検査する。別checkoutで保存先が無ければ未取得表示、公開配布へコピーしない。証拠導線追加後は別候補となるため、旧正式PASSは旧13成果とrunの歴史的結果として保持し、現候補へ再受入せず転記しない。
