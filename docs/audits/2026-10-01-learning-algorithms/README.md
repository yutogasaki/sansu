## 優先所見

P1は現在の進級・学習証拠の信頼性を損なうため先に対応するもの。P2は配分・回復・定着の改善。実装不整合と製品方針の不足を区別する。

### A1 — P1 / 実装不整合：筆算ONの仕上げで独力証拠が失われる

[生成後の表示処理](../../../src/hooks/useStudySession.ts)はfinish/periodicの予約を保持して[筆算表現の確定](../../../src/domain/math/studyPresentation.ts)をスキップする。一方、画面は親設定から筆算を開き、[studyLearningEvidence](../../../src/domain/learning/attemptContext.ts)は予約のsymbolと実表示algorithmが違えば証拠を返さない。finishの回答保存は証拠なしをfalseとして保存する。

D1で `add_2d2d_c` は input=number、筆算=true、evidenceなしを再現。正しい最終回答でも進級用独力正解として数えられない。現在Lv16の `div_2d1d_exact` 等にも同じ構造がある。前回20問UI診断は筆算OFFだったため未検出だった。

修正方向：**新しく予約する時点**で実表示・入力方式・証拠を一緒に確定する。旧予約への後付け認定はしない。筆算ON/OFFの20問を実入力で完了し、20独力正解と保存結果を照合する回帰を追加する。

### A2 — P1 / 実装不整合：分数の整数表示で通常の独力記録も失われる

[integerFractionProblem](../../../src/domain/math/fractionInput.ts)は例えば `1/2 + 1/2` の答え `['1','1']` を単一の `1` 入力へ変える。[Study](../../../src/pages/Study.tsx)は変更後のproblemで証拠を作るが、learningContextは元の分数内容のまま。内容一致検査で証拠なしになる。通常Studyの独力数・SRSの成功と仕上げの正解数に影響する。

D2で生成した整数になる分数を正しく入力した場合の証拠欠損を再現。島の答え復元関数を使う経路と同一ではないので、全モードで必ず起きるとはしない。

修正方向：表示と回答の変換を元予約へ正確に対応づけ、元の全問証拠として扱う。保存済み問題は変更しない。整数になる答え/ならない答え、正誤、通常/仕上げを組み合わせて検査する。

### A3 — P1 / 評価設計の不足：20問が一つの導入問題に固定される

[testSet](../../../src/domain/test/testSet.ts)は練習用生成器へ開始時のprofileを渡す。問題ごとの独力数はセット内で変わらず、導入列の同じ位置を何度も生成する。型IDの均等配分だけでは、別の式や代表的な難度を保証できない。

D3：現在Lv9、bridge/symbol各10独力正解、資格窓20/20という整合するfixtureで、仕上げ20問はすべて `1 + 7 =`。繰り上がりは一問もない。各型を10回練習した事実だけで、繰り上がりを含む現在範囲をクリア可能になる。Math.random固定は型の並びの再現用で、これら二つの導入列の式は独力数10から決まる。

修正方向：仕上げ専用の内容設計を持つ。必要な概念・数の範囲・繰り上がり等の型を指定し、意味のある別問を確保する。同式の再抽選だけでは型漏れを直せない。20問満点は維持する。

### A4 — P1 / 製品方針の不足：直近正解数と範囲coverageが分離していない

[finishEligibility](../../../src/domain/finishTest.ts)は直近20boolean中17trueを使い、Lv11以外の必須型、異なる問題、英語の異なる語の数を検査しない。D5は語彙記憶0件・資格窓20trueでもreadyを返す。これはフィールド間の整合を検査しないことの診断であり、通常利用で記憶0件になる経路を証明したものではない。語彙は各レベル47〜60項目なので、20問は全体の部分標本にとどまる。

前の回答の「以前の70%」は**旧メイン+1への昇格条件**だった。現在範囲の仕上げに70%を戻すことが自動的に正解とはしない。新しいcoverage方針を定義する必要がある。

修正方向：算数は必要な概念/型、英語は異なる語の独力確認を資格として別に持つ。Lv11の全表現を強制しない設計を参考にし、不要な学習量を増やさない。閾値は製品判断として明示し実利用で測る。

### A5 — P1 / 回復設計の不足：仕上げの誤りが次の練習に渡らない

[finish回答処理](../../../src/hooks/useStudySession.ts)は通常writerを通さず、問題index→初回正誤だけを[finish予約](../../../src/domain/finishTestRepository.ts)へ保存する。完了後は予約を消し、履歴は合計点を残す。失敗した型を通常の弱点/再確認へ渡す専用処理がない。資格窓も維持される。

D11：19/20未クリアでもlogs=0、memory=0、contacts=0、main維持。直後に空の新しい予約を取れる。未クリア後の即再挑戦は現仕様どおりだが、学び直さず再抽選を続ける経路になる。

修正方向：通常練習のraw実績を捏造せず、テストの誤りを専用の再確認義務として残す。短い別問練習を提案してから再挑戦へつなぐ。満点条件の変更とは分ける。

### A6 — P2 / 接触記録の不足：仕上げ・確認テストが遅延確認の時計に入らない

[SRS](../../../src/domain/algorithms/srs.ts)は最新通常回答と任意時間制限チャレンジのcontactから24h経過を確認する。[仕上げ](../../../src/domain/finishTestRepository.ts)はcontactを更新しない。確認テストも通常writerを通さず、item接触を残さない。Lv11の[単元投影](../../../src/domain/learning/pilotRepository.ts)もテスト履歴を読む構造ではない。

D10は直前1hに接触を渡すとstrength3のまま、渡さなければ4になることを確認。D11はfinishがcontactを書かないことを確認。両者から、テスト直後の通常成功を「24h空けた想起」と扱い得ると判断する。テストは習得点に加算しなくても接触は記録すべきである。

修正方向：全評価モードの表示/回答接触を独力証拠とは別に記録する。同概念・表現をまたぐLv11の遅延時計にも接続する。未知/保存失敗は未知のまま扱う。

### A7 — P2 / 通常Studyの配分不整合：英語Dueが算数を押し続ける

[shouldForceVocabReviewBlock](../../../src/hooks/blockGenerators.ts)は英語Dueが一つでもあり英語直近復習率が50%未満なら英語ブロックを強制する。[通常Study](../../../src/hooks/useStudySession.ts)はmixの教科判定より先にこれを採用する。通常英語のDue一つなら10問中復習は基本一問なので、50%を達成できない。ここで数えるDueはenabled/当日停止の適格性で事前filterされていないため、解けないDueにも引かれる。

D6：直近40問が全て英語、復習率10%、Due1でも強制英語=true。Dueが残る限り算数への切替が遅れるという結論は教科分岐とのコード照合による。現在の島は[subjectSelection](../../../src/domain/island/subjectSelection.ts)に2区間連続の切替guardがあり、この問題を島の自動選択へ一般化しない。

修正方向：適格Due数を使い、実際の問題配分上限と教科配分条件を一致させる。少量Due/大量Due/無効Due/当日停止を長いmix旅程で検査する。

### A8 — P2 / 指標設計の不足：弱点解除は独力ではなくraw正解

[weak更新](../../../src/domain/learningAttemptWriter.ts)と[旧履歴復元](../../../src/domain/learningRepository.ts)は結果correctだけを数える。訂正後の正解も弱点解除に使える。D7は以前weak=trueからraw correct10でfalseを再現。assistedの証拠がweak関数へ渡らないことをコードでも確認した。

SRSのneedsRelearningは別に残るため、この解除がそのまま習得認定になるとはしない。だがweak表示・weak枠の優先順位が、本当に独力で回復したかとずれる。

修正方向：参加/正解経験の指標と、独力による弱点回復を分ける。旧ログのunknownを一括誤答へ変換しない。支援だけの連続成功で回復扱いしない経路を検査する。

### A9 — P2 / 難度移行の方針不足：表現followupがraw正解で進む

[getMathFollowupPlan](../../../src/domain/math/followups.ts)はrecentAttemptsのcorrectだけで次表現を選ぶ。recentAttemptsには独力/訂正を区別する情報がない。D8はbridgeのraw correctからmentalのprogression候補を再現する。数の導入幅は独力正解数なので、この経路と数値難度の管理が別基準になっている。

別表現を見せること自体は習得認定ではなく、支援後に少し挑戦させる意図も成立する。どの条件で補助を外すかが仕様として不明確な点を設計課題とする。

修正方向：初回独力/支援成功/誤答を表現選択に渡し、支援後の短い再確認と独力成功後の発展を区別する。

### A10 — P2 / 時間の方針不足：古い資格でも同じready

finishEligibilityは日時を参照しない。D4で2020年のupdatedAtでも20trueならready。受験まで何日空いたか、直近失敗後に資格が十分新しいかを判別する証拠がない。SRSのDueは別にあるので「復習が全く出ない」という問題ではない。

修正方向：長い不在後は短い再確認を提案するか、復習を挟んでから仕上げへ案内する。古い資格・クリア済み権利を罰として一括取消ししない。当日クリアと長期定着も分けて表示する。

## 問題と混同しない確認済みの土台

- 新しい通常writerは証拠を明示し、文脈のない旧raw正解から独力数を推定しない。部分筆算の正解を全問成功へ加算しない。
- SRSは期限到来、直近回答/独力成功から24h以上を要求。同日・期限前練習で将来の期限を後ろへ送らない。
- 誤答・支援の再学習を卒業statusと分離し、卒業済みでもDueへ戻せる。解除は間隔を空けた独力成功、最大strength2から再確認する。
- Lv11は必要な型と3別問を要求。同概念の直近接触を参照し、図の直後の式を遅延確認へ変換しない。全方法の一律強制はしない。
- 新規の島/Park予約はseedとprofile/revisionを固定し、支援履歴も再開する。保存・正式回答・報酬の境界は原子的で再送防止がある。
- 島は支援を開いたことだけで架空の正誤ログを作らず、別問での独力確認を残す。未完了の旧予約は進級後にも書き換えない。
- 保護者の有効範囲、当日の連続3スキップ停止、通常のmain/+1上限、英語のDue重複防止は関連検査で確認。

## 既知の限界・実測が必要な事項

1. 通常Studyの未完の誤答/筆算途中操作は永続証拠が限定される。中断後まで独力履歴を完全に追跡できないことは仕様31に明記されている。今回新たに発見した完全保存の回帰とは数えない。
2. 候補不足時に同じスキルがDue枠とmain枠へ入ることはある。D9はLv28の1スキルでこれを確認。復習率だけで概念の反復量を表せない。型ID上限と概念上限を一律に厳しくすると少ない範囲で出題不能になるため、設計判断が必要。
3. 正解の桁数・小数点・筆算途中の固定値を見せる教材は、支援を開いていなくても手掛かりを含む。「アプリ内支援なし」と「補助なしで何でも解ける」を同一にしない。
4. 4択の認識は発話・綴り・文章理解の証拠にならない。例文と語義IDを分けた現仕様は妥当だが、誤答選択肢の意味的妥当性や語彙難度は教師等の教材レビューが残る。
5. 17/20、20問満点、3別問、復習1/3/7/14/30日、weak閾値、main/+1の配分は設計値。実際の翌日/1週後の正答率、挑戦到達までの問題数、未クリア後の離脱/再挑戦率を測っていない。乱数で同じ問題の再抽選を繰り返す合格率と習得率を混同しない。

時間を空けた学習、想起練習、具体と抽象の接続には[IES学習ガイド](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)の支持がある。子どもの既知の内容に合わせる進度観察と発達に沿う内容には[IES幼児算数ガイド](https://ies.ed.gov/ncee/wwc/PracticeGuide/18)を参照した。いずれもこの製品の閾値や全問満点条件の最適性を証明するものではない。

## 対応順と受入証拠

1. **A1/A2**：全問の表示と独力証拠を一致。筆算ON/OFF、整数になる分数、既存予約再開の実入力で正しい回答を認定する。
2. **A3/A4**：仕上げの内容設計と練習coverage。Lv9の繰り上がり、Lv11の7単元、英語の未確認語などを漏らさず代表的な別問で測る。
3. **A5/A6**：失敗した型の短い再確認と全評価接触を接続。テスト後1hの正解を24h遅延確認にしない。
4. **A7/A8/A9/A10**：長期mix旅程、支援後の回復、表現移行、不在後の再確認を改善。過去の権利と保護者範囲を維持する。
5. 子どもの実利用で、到達問題数・翌日/1週後の独力正解・未クリア後の再挑戦と自発的な学習選択を測る。

この監査ではアプリを修正・配布していない。コード/隔離診断/関連既存テストの結果であり、実ブラウザの全経路、実SW、実機、子どもの定着・意欲の合格証拠にはしない。
