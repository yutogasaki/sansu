## 指摘

### B1 — 高：装飾で土地を使い切り、成長が恒久的に詰まりやすい

根拠：`commands.ts:33` の土地拡張は5回まで。最大18×8＝144マス。住人の家は最終段階でも2人で、畑・遊び・飾り・道も同じ土地を使う。土地を超える成長先がない。

同じ12件/日で、各学習後に花を1つ先に置く手順では、住人が30日23人→90日26人→180日26人→365日26人。土地144マス、家14個、Lv7で停止した。育成優先でも90日51人→180日67人→365日67人で停止。これは各手順の結果であり、26/67をエンジンの絶対人口上限とは呼ばない。手で花を収納し配置を変えれば回復する余地はある。しかし有限土地という最終上限自体は残る。

90日比較は追加の3つのseedでも育成優先51人、装飾優先26人だった。装飾優先手順は仕込みの奇数行・偶数行を固定し、収納をしないため、子ども全般の平均進行とは一般化しない。少なくとも、合法的に飾り続けるだけで成長余地を失う経路はある。

憲法§1/§4は、小さな固定上限で繁栄を止めず地区を広げる。仕様52の有限5段階と、その先の成長契約を整合させる必要がある。

最小の次手：拡張後の地区を増やす契約を先に定める。満杯時には、無料の収納・移設による回復先を子どもが見つけられる導線を確認する。装飾を減らすことだけを成長の条件にしない。

### B2 — 高：小さな出来事が学習連動の抽選機会になっている

根拠：`town.ts:89–96` は学習で増えたまち時間の夜明けごとに `dayMoment` を呼ぶ。`moments.ts` は日ごとの確率0.6、まれなお客の候補確率0.3。実際に見せるのは最後の夜明けの結果のみ。

咲いた花6個で同じ60完了を与えた診断では、まとめてひらくと出来事1件、6完了ずつ10回ひらくと9件。まち時間はどちらも240時間、乱数seedも同じ。抽選結果そのものは決定的で開き直しによる再抽選ではないが、学習量で日ごとの抽選機会が増え、戻る頻度でも見られる数が変わる。

仕様52§11.2には沿うが、憲法§1.2「学習の量で、運を引く回数を増やさない」と整合しない。

次手：出会いの抽選機会を学習の完了数と切り離す契約を決める。未表示の出来事を保持するかも併せて定め、学習画面と島を往復するほど得をする動機を作らない。

### B3 — 中：しずく収入に対して、使い道と進行が追い付かない

根拠：しずくは完了数に比例する一方、来訪間隔は住人数で延び、土地・家の密度が進行を制限する。家4・畑4に対し、住人が増えるほど次の入居まで多くのしずくが貯まる。食料・維持費による通貨消費はなく、これは罰を避ける良い契約でもある。

12件/日では90日総収入2,160に対して残高1,664、約77%が未使用。365日には残高8,040。装飾優先でも8,204。各手順で消費先が尽きた結果であり、全利用者の貯蓄率とはしない。

影響：価格を見て選ぶ意味が薄れ、学習後に残高だけが増える。B1の停止が原因でもあるため、単純な値上げでは回復しない。

次手：先に成長先を用意し、その後に任意の地区づくり・外観・作品づくりなど使いたくなる消費先を検証する。報酬2を減らす、維持費を足す、既得権を削る対応は採らない。

### B4 — 中：まとめ学習では仕込めず、同じ学習量が成長へ変換されにくい

日12件と週84件の比較：7日目8人対1人、90日目51人対22人。週84件は週頭にまとめて付与するため90日時点では1,092件で、日12件の1,080件より少し多い。それでも成長が遅い。

根拠：`openTown` は貯めた時間を全部消費してから次の購入・仕込みを行う。週1回の訪問手順では、最初の無料家しかない状態で最初の336時間が過ぎる。その後に置いた家は次の週まで建たない。比較には仕込み頻度の差を含み、時計の分割だけの不変性テストではない。

仕様52§10の「しこんだ物以上には進まない」「残りはのんびりした日」と整合する設計上のトレードオフ。ただし子どもには同じ学習量なのに無駄になった感覚を与える可能性がある。

次手：まとめて学ぶ場合に、学習前の仕込みが分かるか、島へ戻ってから次の仕込みを続けたくなるかを実参加者で確かめる。学習回数を増やす案内で補わない。時間の保存・消費規則を変える場合は仕様変更として扱う。

### B5 — 中：到達できない完成済みの家でも入居・近くの遊具の評価が成立する

根拠：`community.ts` の `housing` と `town.ts:52` の `chooseHome` は、完成済みの家が歩いて行けるか確認しない。`comfort` は遊具・好みを距離だけで数える。食料には経路確認があるため条件が非対称。

完成済み空き家の手前を柵で完全に分断した診断で、到達判定falseの家に夜明けで1人入居した。診断は明示状態fixtureであり実UIの操作旅程ではないが、建築後に柵を置く・家を移す合法操作で同種の状態は作れる。家の移動・柵による分断を経たUI再現は未確認。

影響：道を戻す工夫をしなくても人数とげんきが増え、実際に行ける暮らしと数値がずれる。仕様52§16の「家を動かすとき通れなければ確定前に知らせる」も併せて確認する必要がある。

次手：新規入居の家候補と利用可能な遊びの経路条件を明示する。既存住人を追い出したり、取得済み段階・解放を戻したりしない。

### B6 — 低：同一同期バッチ内の重複完了を二重加算する

根拠：`island.ts` の `ingestCompletions` は、入力全体を `fresh` にした後で既知集合へ追加する。同じIDを同じバッチへ2件入れると、4しずく・8時間になる。別の同期への再送は防がれる。

現在の `terminalFacts` はMapでIDを重複排除するため、通常の公開入力で発生する経路は確認していない。経済の純粋関数が契約を単独で守らない防御不足であり、現状の利用者が報酬を増やせるとは主張しない。

次手：関数内で入力IDを一度ずつ数え、同一バッチ・別バッチの両方で確認する。

## 残した良い契約と検証限界

- 独力/SRSと参加報酬を分離し、支援を受けた子のしずくを減らさない。筆算途中の成功は終端完了として数えない。
- 序盤無料、完成前返却、無料移設、学習しない日も植物が育つ、取得済みの住人・段階・解放が戻らない。
- 現行Lifeの経済v3は6完了/24時間で最大速度1、未学習も0.5で止まらない。Growing Islandは花6時間・木18時間を自然時計で育て、しずくの購入倍率とは別。Lifeのいぶき減衰・ひかり有限発行を新エンジンの現行経済として混同しない。
- Growingの初週8人、月25人、3か月51人という既存の目安は再現した。これは育成優先手順の確認であり、B1〜B6を相殺しない。
- 視覚の魅力、無説明理解/安全は今回未評価。runtimeは対象の純粋計算・保存関連既存テストのPASSのみで、公開版・実端末・PWA・実回答旅程の合格とはしない。
