# 学習教材・問題種類・レベル・スキル監査

日付: 2026-10-01。対象: 現在のローカルcheckout。監査は読み取りと診断のみで、教材・保存データ・出題・解放の実装は変更していない。

## 結論

**生成器の基本的な整合性は確認できたが、教材の意味と種類の網羅性には修正が必要。** とくに、英語で正しい理解を誤答にする選択肢、訳と例文の不一致、Lv8の足し算の範囲縮小を先に直す。算数の平均・除算・分数比較は正答が正しくても問題の型に偏りがあり、現在の成功をその概念全体の習得と解釈できない。

判定を分離する:

| 観点 | 結果 |
|---|---|
| ID・生成・入力契約・機械的な答え | 検査範囲でPASS。全乱数や全描画の証明ではない |
| 英語の意味・正答の一意性 | 要修正。C01/C02 |
| 数範囲・導入後の難度 | 要修正。C03。その他の偏りはC04〜C06 |
| 概念の土台・順序・型の網羅 | 改善が必要。C07〜C09。既知の未実装部分を含む |
| 学年・検定相当の実証、子どもの理解 | 未検証。機械検査で合格にしない |

## 範囲と実施方法

- 算数: 118教材、29レベル（Lv0〜28）、74既存単元、9planned単元。生成器・対応表・表示名・数範囲・表現・前提関係を全件照合。
- 英語: 1,184項目、1,173種類の綴り、20レベル、49分類、1,184例文。ID・所属・重複・例文対応・かな/漢字の4択を全件検査。意味の整合性はデータを読み、具体的な疑義を個別確認した。全語義の専門家校閲完了とはしない。
- 算数生成: 独力正解数なし/0/3/10/20/40/100 × 100 seed × 118教材 = **82,600問**。47,600問の解析可能な四則式を別計算で検算。分数・帯分数・余りも数値として確認。
- 追加: 比較・割合・平均・比・速さ・万/億の7教材を各10,000 seed、**70,000問**検算。別途、除算/平均/分数比較の分布を各10,000問確認。
- 英語: 1,184項目 × かな/漢字 × 10 seed = **23,680問**。4択の表示ラベル・IDの一意性と正解の存在を確認。意味が同じ選択肢は文字列比較では検知できないため別に再現。
- 既存の関連テスト: **28ファイル・375件PASS**。既存テストの合格と教材内容の妥当性を分けた。
- 算数の具体図については生成契約・既存テスト・実装を確認。今回、新たな実機の画面比較や子どもの観察は行っていない。
- 紙テスト、例文の凍結保存、SRSの最適性は今回の中心対象ではない。前回の[学習アルゴリズム監査](../2026-10-01-learning-algorithms/README.md)と区別する。

全件の所属・表示名・表現は[棚卸し表](inventory.md)。生成例・段階別の値・全英語項目と例文は[inventory.json](inventory.json)。入力ファイルのhashと監査中の不変確認は[source.json](source.json)。共有checkoutには先行する変更が存在するため、HEADだけでは監査入力を表せない。

## 指摘

P1 = 誤答判定・誤学習・仕様上の範囲欠落を直接生む。P2 = 教材の偏り・概念や型の不足。P3 = 表示・説明・校正の改善。P2/P3はすべて現行仕様違反という意味ではない。

### C01 / P1 / 英語の採用訳と例文の語義・品詞が一致しない

根拠: [words.ts](../../../src/domain/english/words.ts)、[examples.ts](../../../src/domain/english/examples.ts)、回答前に例文を表示する[EnglishExampleSentence.tsx](../../../src/components/domain/EnglishExampleSentence.tsx)、StudyLayoutとIslandProblemPrompt。

| ID / Lv | 採用訳 | 例文 | 例文で表す意味 |
|---|---|---|---|
| hard / 5 | かたい | This work is hard. | 難しい・大変な |
| apply / 15 | おうぼする | I apply the new rule. | 規則を適用する |
| measure / 16 | たいさく | We measure the distance. | 距離を測る（動詞） |
| present / 13 | げんざい | This present is for you. | 贈り物 |
| age / 13 | じだい | Tell me your age. | 年齢 |
| heart / 8 | こころ | My heart beats fast. | 心臓 |
| sound / 9 | きこえる | I like this sound. | 音（名詞） |
| free / 9 | ひま | This seat is free. | 空いている席 |
| step / 12 | だんかい | Take one step forward. | 一歩 |
| sense / 15 | かんかく | I sense a change. | 感じ取る（動詞） |
| potential / 20 | せんざいてきな | This idea has potential. | 可能性・潜在能力（名詞） |
| cold / 1 | さむい | The water is cold. | 水が冷たい |
| back / 7 | うしろに | Please come back soon. | 戻って来る |

`hard`ではseed=2で「かたい」「むずかしい」が同時に出て、例文に沿った「むずかしい」を選んでも不正解になる。[probes.json](probes.json)に問題と選択肢を保存。

語義の区別は出版社の辞書でも確認: [hard](https://www.oxfordlearnersdictionaries.com/definition/english/hard_1)、[apply](https://www.oxfordlearnersdictionaries.com/definition/english/apply)、[present](https://www.oxfordlearnersdictionaries.com/definition/english/present_2)、[measure・動詞](https://www.oxfordlearnersdictionaries.com/definition/english/measure_1)、[measure・名詞](https://www.oxfordlearnersdictionaries.com/definition/english/measure_2)。表の例文は本リポジトリから採ったもので、辞書の例文の転載ではない。

修正方針: 原則として既存IDの採用語義を維持し、その語義を明確に表す例文へ変更する。語義自体を変更する場合は別の教材変更として仕様05・保存済み記録との関係を扱う。全件に品詞・語義を付け、例文がそれに一致するか校閲する。単語を含む・文が異なるという既存テストだけではこの不一致を検出できない。

`atmosphere=たいき / The atmosphere is calm.`など、文脈が弱く語義を確定しにくい例も校閲対象。これらを上表の確定した不一致と同じ件数に混ぜない。

### C02 / P1 / 別ラベルでも同じ意味の選択肢が同時に出る

根拠: [generator.ts](../../../src/domain/english/generator.ts)の除外は表示ラベル一致・同じ綴り・ID。語義の同等性は扱っていない。

`way_lv12`、seed=8: 問題`way`、例文`This is a good way.`、選択肢「いち」「しんぽ」「やりかた」「ほうほう」。正解はID `way_lv12`だけで、`method`由来の「やりかた」は誤答になる。「方法/やり方」はこの文で区別できない。`way`の方法の語義は[Oxfordのway](https://www.oxfordlearnersdictionaries.com/definition/english/way_1)、[method](https://www.oxfordlearnersdictionaries.com/definition/english/method)でも確認。

修正方針: 正解語義の許容訳・同義グループと誤答禁止ペアを教材データに保持する。ラベルだけを変える対応では解消しない。生成前に同義候補を除外し、クールダウン緩和でも維持する。まず上の実問題を回帰検査へ追加し、全語義の曖昧な組み合わせを校閲する。

### C03 / P1 / Lv8の足し算が導入後に縮小し、仕様の数範囲を出さない

根拠: [additionProgress.ts](../../../src/domain/math/additionProgress.ts)の`LEVEL4_SEQUENCE`/`LEVEL4_POOL`と`selectAdditionPair`。[仕様04](../../product/04_math_problems.md)は`add_1d_1`をa=1〜9、b=1〜3、和≤12と定義。

- 導入は15組あり、後半は`1+5`、`5+1`、`3+3`など和6まで進む。
- 正解数15以降は常に`a+b<=5`の10組へ戻る。プロフィールなしの検査でも同じ10組。
- `8+3`、`9+2`等の仕様上の範囲を出せない。`add_1d_1_bridge`も同じ選択関数で縮小する。
- 先にLv6の`add_5`が1〜5同士・和10まで扱うため、Lv8は新しい範囲を学べる保証が弱い。

修正方針: bridgeとsymbolそれぞれの到達範囲を仕様に合わせ、導入終了後はその範囲へ拡張する。導入の直後に範囲が縮小しない境界検査と、仕様上の代表問題が生成可能な検査を置く。定着確認も「10種類の易しい問題ができた」ことと広い範囲の達成を分ける。

### C04 / P2 / 平均の全問題が対称な並びで、平均計算をしなくても解ける

根拠: [advanced.ts](../../../src/domain/math/generators/advanced.ts)の`average_basic`。3個は`avg-d,avg,avg+d`、4個は`avg-outer,avg-inner,avg+inner,avg+outer`。**10,000問すべて両端の平均だけで正答**できた。3個なら中央の数を答えればよい。

間違った式ではないが、総和÷個数を理解していない状態でも現在の全問題を通過できる。対称な問題を導入として残しつつ、非対称・順番を混ぜた数列・異なる個数・整数/小数の答えを仕様化し、一般的な平均の型を別に確認する。

### C05 / P2 / 2桁÷2桁の約71%が同じ数同士を割る問題

根拠: [division.ts](../../../src/domain/math/generators/division.ts)の`div_2d2d_exact`。除数10〜99を均等に選び、商は1〜floor(99/除数)。除数50〜99では必ず商1になる。

10,000問中**7,094問（70.94%）が商1**。答えは正しく仕様上有効だが、`67÷67=1`等に強く偏り、2桁除数を使う一般的な計算の練習が薄い。商1・商2〜9の型を分け、導入後の割合を制御する。無条件に商1を禁止する必要はない。

### C06 / P2 / 分数比較には分子・分母が両方違う不等値の問題がない

根拠: [advanced.ts](../../../src/domain/math/generators/advanced.ts)の`frac_compare`は同分母、同分子、等値の3モードだけ。10,000問でもそれぞれ3,333/3,336/3,331問、**両方異なる不等値は0問**。

Lv22で異分母の計算を扱った後のLv26「分数のくらべ方」でも、`2/3`と`3/5`のような比較を確認できない。現行の限定された3型は既に仕様32にも記述されており、今回見つかった計算バグではない。比較全体の達成と扱うなら、数量図/数直線や通分を使う一般型を追加し、型ごとの証拠を残す。

### C07 / P2 / 基礎概念9単元が未実装で、41既存単元がそれを前提としている

根拠: [mathCatalog.ts](../../../src/domain/learning/mathCatalog.ts)のplanned単元・prerequisites。[仕様31](../../product/31_learning_units_spec.md)が「通常出題の必須関門にしない」と明記する、**既知の教材不足**。

未実装: 10と1の位、100以上の位、小数の量と位、分数の量、等しい分数/約分/通分、帯分数の意味、等しい集まりと掛け算、等分除/包含除/余り、1あたりの量。

計算に図があることと、その概念を子どもが直接答えられることは異なる。特に分数Lv21は初回から約分した答えを求める。基礎を教わっていない子がアプリ単独で進む場合の橋渡しが足りない。

修正方針: 既存IDを移動して保存を壊す対応ではなく、各計算の直前に短い意味確認・説明・具体図の教材を加える。既に理解している子が一律に戻されない経路も作る。plannedをそのまま必須ロックへ変えると、教材がないのに先へ進めなくなるため先に教材を用意する。

### C08 / P2 / 推奨される前提が後のレベルに置かれている

根拠: [mathCatalog.ts](../../../src/domain/learning/mathCatalog.ts)と[curriculum.ts](../../../src/domain/math/curriculum.ts)。検出した関係は8件。

| 先に出る内容 | 推奨前提が出る位置 |
|---|---|
| 小数の足し算/引き算 Lv19、整数との掛け算/割り算 Lv20 | 小数比較 Lv25 |
| 小数同士の掛け算/割り算 Lv20 | 10倍/100倍/10分の1 Lv24 |
| 同分母分数の足し算/引き算 Lv21 | 分数比較 Lv26 |

前提表は実際の解放に使われないため、循環検査はPASSでも学習順の不整合は残る。これは「必ず先に比較を合格しないと計算不可」という主張ではない。カタログが推奨する内容を事前に経験できないことが問題。

修正方針: 保存済みレベルを維持したまま、事前の確認教材・不足概念へのフォローを接続する。単なるレベル番号変更ではなく、通常経路で必要な土台に触れられるかを検証する。

### C09 / P2 / 「問題の型」が粗く、異なる技能を同じdefaultで数える

根拠: [mathCatalog.ts](../../../src/domain/learning/mathCatalog.ts)、[context.ts](../../../src/domain/learning/context.ts)。現在、実問題から型を判定するのは`sub_2d2d`の繰下あり/なしで、他の多くは`default`。

例: 九九の各段とランダムが同一単元/default、百分率の2方向、速さの距離/速さ/時間の3方向、10倍/100倍/10分の1、万/億、分数比較の3型。これらは必要な操作が異なるが、どの型ができたかを区別していない。

[finishCoverage.ts](../../../src/domain/finishCoverage.ts)はカタログの単元/型を使うため、問題内容が異なる3問でも同じ方向に偏れば、別方向が確認済みとはいえない。例としてLv28の距離だけ3問解けても、時間を求められる証拠にはならない。

修正方針: 出題内容から決まる操作・方向・繰上位置等をvariantとして記録し、必要な型の代表問題を生成できるようにする。既存default記録を後から特定型の達成へ格上げしない。全方法を一律必須にすることとは分ける。

### C10 / P3 / スキル名が実際に問う行為より広い

根拠: [labels.ts](../../../src/domain/math/labels.ts)、[counting.ts](../../../src/domain/math/generators/counting.ts)、[advanced.ts](../../../src/domain/math/generators/advanced.ts)。

| 表示名 | 実際の問題 | 改善案 |
|---|---|---|
| 50まで数える / 100まで数える | ある数の次の数を1個答える | つぎのかず（50/100まで） |
| ちいさいじゅん | 最小の数を選ぶ | いちばんちいさいかず |
| 10倍・100倍 | ÷10も含む | 10倍・100倍・10分の1 |
| 1桁−1桁（繰り下がり） | 主範囲は11〜18から1桁を引く | 10をまたぐひきざん |

概念カタログには一部正しい説明が既にあるが、子どもや保護者が見る表示とずれている。名称を直し、順序づけ・大量の実物の計数など未測定の技能をできたように見せない。安定IDは維持する。

### C11 / P3 / レベルを校正済み難度や別技能の数として扱えない

算数Lv11は19教材だが、意味上は7単元。Lv8/9は2教材、Lv28は1教材。表現違いの多さと概念の多さを同じ「スキル数」で比較すると、レベル間の負担や進歩が読みにくい。19教材をすべて別概念として提示するより、7単元の内訳とできた型を示す方が実際の学びに合う。

英語は47〜60項目ずつ配置され、[仕様03](../../product/03_english_skills.md)自身が難度を学習者データで校正していないと明記。全項目のposは未設定で、49分類はテーマと品詞の混在。例えば`shape/tool`はLv18、`and/but/or`はLv11にあり、単純に後の番号ほど難しいとみなせない。これらの配置だけで児童にとっての難度逆転を実証したとはしない。

`properly`はLv15/Lv18で同じ「てきせつに」。これは[仕様05](../../product/05_english_words.md)に明記された意図的な再登場で、11重複綴りすべてが11の新しい語義というわけではない。違う例文でも同義項目を独立の新技能として過大に数えない。

修正方針: 学習の進度、概念、表現、数範囲、語義を表示と集計で区別する。教材の所属番号から学年相当/検定相当の到達を断言せず、誤答・独力正解・保持・学習時間の実データで校正する。音声/発話/綴りの達成を訳語4択から推定しない現在の区別は維持する。

### C12 / P3 / 教材の範囲説明が実際の収録内容と一致しない

[仕様02](../../product/02_math_skills.md)は「図形・文章題・グラフは扱わない」とする一方、形認識・空間関係・長さ/高さ/重さ、平均・比・割合・文章形式の速さを収録している。収録が悪いのではなく、説明が広すぎる。

修正方針: 「計算を中心に、幼児の数量・形・空間の基礎と、割合・平均・速さの限定した問題を含む」等へ実際の範囲を整理する。面積・角度・図形全般・グラフ等の未収録を、計算中心という現行の製品方針を無視して不具合には数えない。公文A〜Fや学校算数全体を網羅したという適合認定も今回していない。

## 修正の推奨順序

1. C01/C02: 既存語義を守って例文を校訂し、意味が同じ誤答候補を除外。子どもの正しい理解を誤答にしない。
2. C03: 足し算の導入後の縮小と仕様上の数範囲欠落を修正。
3. C04〜C06/C09: 問題分布と必要な型を一緒に設計し、仕上げでも型ごとの代表問題を確認。
4. C07/C08: 未実装の基礎を短い教材として実装し、既存の保存レベルを維持して接続。
5. C10〜C12: 表示名・進捗の単位・範囲説明を修正し、難度校正を別の実証作業として進める。

今回は監査依頼なので、以上の変更は提案であり未実装。前回のアルゴリズム修正や既存の別作業の差分を今回の成果として数えない。
