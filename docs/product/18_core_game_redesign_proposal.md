## 0. 結論

現行探索は、絵や停止回数だけを直しても「もう一回遊びたいゲーム」にはならない。

作り直すべき中心は、次の一文である。

> **気配のある場所を自分で狙い、算数を数量の一打へ変え、地形といきもののクセを連鎖させ、次の遊び方を一つ持ち帰る。**

先行仮説の仮称を **「ふしぎ連鎖探検」** とする。G0〜G2と非補償ゲートを通るまでは、最終コアとして採用しない。

これは参考作品のキャラクター、造形、図鑑画面、動作を模倣する案ではない。Sansu固有の中心は、**算数で作った数量変化が、横舞台の物理連鎖と次の判断へ直結すること**に置く。

実装順も変える。完成絵、図鑑ページ、長期コンテンツを先に量産せず、まず色付きの形だけで30秒遊べるかを確かめる。絵なしで面白くない仕組みを、かわいい絵で救済しない。

## 1. Sansuにおける「楽しい」の定義

### 1.1 瞬間の楽しさ

一回の操作が楽しいとは、次の連鎖が短時間で成立することである。

```text
自分で狙う
→ 算数で作用を作る
→ 触れた瞬間に大きく反応する
→ 大半は予測どおり、少しだけ意外な連鎖が起こる
→ 次に何を試すかが生まれる
```

必要条件は次の5つ。

| 条件 | 子どもの実感 | Sansuで必要な実装 |
|---|---|---|
| 意図 | 「ここを狙った」 | 舞台上の対象を直接選ぶ |
| 手応え | 「自分で当てた」 | 入力直後の構え、接触、変形、余韻 |
| 理解 | 「だからこうなった」 | 同じ舞台、同じ物体、連続した因果 |
| 意外性 | 「えっ、そこまで行くの」 | 予告された性質から一段だけ外れる連鎖 |
| 再行動 | 「次はあっち」 | 結果が次の選択肢を実際に変える |

正解音、コンボ数字、粒子、画像差し替えだけでは、この5条件を満たさない。

### 1.2 また遊びたい理由

継続したい気持ちは、ログイン報酬や低確率の景品ではなく、次の4つから作る。

| 継続動機 | 内容 |
|---|---|
| 未知 | 次は別の対象、クセ、組み合わせを試したい |
| 上達 | 世界の規則を覚え、連鎖を上手く作れる |
| 愛着 | ポッコと持ち帰ったいきものが前回を覚えている |
| 影響 | 発見したクセが次のrunの遊び方を変える |

図鑑の空欄を埋めるだけでは弱い。持ち帰った発見が、次回の動詞、予告、連鎖、行ける場所のいずれかを増やすことを必須にする。

### 1.3 掛け算で評価する

このゲームの楽しさは、点数の足し算ではなく次の掛け算として扱う。

```text
楽しさ
= 行為の快感
× 因果の理解
× 自分で決めた感覚
× 次を想像できる余白
```

どれかがほぼ0なら、他の軸が高くても採用しない。技術PASS、処理速度、絵のかわいさは、楽しさの代替にならない。

## 2. 現行探索が楽しくない根因

現行は高速に動く。しかし、実装上は探索ゲームより **固定8問のreceipt pipeline** に近い。

### 2.1 一本道を画像で探索に見せている

現在は本来別であるべき4つの値が、実質的に同じ `steps` へ結合している。

```text
正解数
= 現在nodeの深さ
= temporary findの件数
= reward / presentationの段階
```

この結合を残したままUIだけを変更すると、「一問正解するたびに一歩進み、一件配られ、次の固定絵になる」構造が必ず再発する。

- `src/domain/explore/runStructure.ts` はQ1〜3、Q4〜6、Q7、Q8の役割を固定する。
- `src/domain/explore/learningSegment.ts` は `3 / 3 / 2` の区間を固定する。
- `src/domain/explore/generator.ts` は選択直後の深度で道を合流させ、終盤を単一点へ収束させる。
- `src/domain/explore/rewards.ts` は、選んだ道にかかわらずQ4〜6で同じ手掛かり、Q7で同じfinaleを付与する。
- `src/domain/explore/rapidLoop.ts` は区間内の行き先を自動選択し、橋も実質同じプランへ進める。

そのため、子どもが選ぶ道は、問題、作用、次の作戦、finaleを変えない。選択は見た目のラベルに留まる。

### 2.2 算数が世界アクションになっていない

正解は `completedSteps` を進め、決められた次のframeを表示する。問題値、演算、狙った対象、持ち帰った発見は反応の規則へ入らない。

体験は次の形になる。

```text
数字を入力する
→ 正解する
→ 別の絵になる
→ 次の数字を入力する
```

これは速いドリルとしては成立するが、「掘った」「当てた」「連鎖させた」という操作感にはならない。

### 2.3 リソースが判断を作らない

- 正解でも不正解でもenergyが減る。
- all-correctでも固定消費が大半を占める。
- energyを貯める、使う、帰路へ残す判断がない。
- comboは表示だけで、作用、報酬、確率、分岐へ接続しない。
- 救助でも任意帰還でも持ち帰り結果がほぼ同じなので、欲張るリスクがない。

現在のenergyは戦略資源ではなく、ほぼ「あと何回間違えられるか」の表示になっている。

### 2.4 運、失敗、継続が化粧差に留まる

- seedで標本名や見た目は変わるが、作戦は変わらない。
- 誤答はenergyとcomboの数字を変え、同じ問題へ戻すだけで、面白い別展開を作らない。
- run終了後の発見を次のrunや基地が利用しない。
- teaserは次回生成条件へ渡らず、約束した場所へつながらない。

したがって、同じ正答列から別の物語が生まれない。

### 2.5 「止まる回数」より「止まる価値」がない

現行benchmarkは中断を `Q3 route / Q7 discovery close / Q8 return / replay` の4件へ固定する。しかし、

- Q3の道はすぐ合流する。
- Q7は毎回同じ役割のmodalである。
- Q8と帰還summaryは終了操作を分割している。

新しい判断、驚き、損得がない停止なので、どれも邪魔に感じる。単にmodalを消すだけではなく、**止まるなら、その操作自体を遊びにする**必要がある。

### 2.6 現在の証拠が示す限界

[Stumble Bloom v5監査](../design/audits/2026-07-24-stumble-bloom-v5-ea10f29/README.md)では、ExploreはStudyより高い問題処理量を保った一方、視覚的磁力は43 / 60、無文字理解はHOLDだった。

これは「遅すぎてつまらない」だけではないことを示す。処理速度が速くても、操作の著者性、選択の結果、連鎖、次回への影響がなければ、爽快なゲームにはならない。

## 3. ベンチマークから借りる原則、借りない表現

### 3.1 借りる原則

- [Yoshi and the Mysterious Book](https://www.nintendo.com/en-gb/Games/Nintendo-Switch-2-games/Yoshi-and-the-Mysterious-Book-2915259.html): 対象へ複数の行為を試し、固有の性質を知り、その発見が次の探索手段になる。
- [Kirby and the Forgotten Land 開発者インタビュー](https://www.nintendo.com/en-gb/News/2022/March/Ask-the-Developer-Vol-4-Kirby-and-the-Forgotten-Land-2187039.html): プレイヤーの意図を寛大に成功へつなぎ、接触結果を気持ちよく返す。
- [Super Mario Bros. Wonder 開発者インタビュー](https://www.nintendo.com/au/news-and-articles/ask-the-developer-vol-11-super-mario-bros-wonder-chapter-1/): 別画面へ転送せず、いまいる舞台そのものを目の前で変える。
- [Hades公式FAQ](https://www.supergiantgames.com/blog/hades-faq/): 各runの条件と選択を組み合わせ、失敗しても知識、関係、次の手段を増やす。

学習ゲームとしては、算数を遊びの通行料にした版より、中心メカニクスへ統合した版の方が、学習成果と自由選択時のプレイ時間の双方で優れたという[Habgood & Ainsworthの研究](https://tecfa.unige.ch/tecfa/teaching/BSEP/articles/Habgood_Ainsworth_2011.pdf)を重く見る。

また、自律性、有能感、関係性が楽しさと将来のプレイ意向を予測するという[Ryan, Rigby, Przybylskiの研究](https://selfdeterminationtheory.org/wp-content/uploads/2020/10/2006_RyanRigbyPrzybylski_MandE.pdf)、学習の正誤とは別のゲーム部分へ不確実性を置くと関与が高まるという[Howard-Jones & Demetriouの研究](https://research-information.bris.ac.uk/en/publications/uncertainty-and-engagement-with-learning-games/)も設計根拠にする。

### 3.2 借りない表現

- 既存IPのキャラクター、輪郭、身体比率、動き、鳴き声
- 飛び出す本、図鑑ページ、工作物の具体的なレイアウト
- 既存作品固有の「食べる・卵を投げる」などの動詞セット
- コース、バッジ、神の力などの固有システム
- cinematic fantasy painting、金色発光、奥行きの強い巨大背景

Sansuは **地形へ数量の作用を打ち込み、いきもののクセで連鎖を変えるゲーム** として独自性を作る。

## 4. コアループ候補の比較

既存の成功例から借りるのは、検証済みの操作文法と報酬構造である。キャラクター、固有名詞、画面構図、音、造形は借りない。

| 候補 | 参照するメカニクス | 30秒の中心操作 | 瞬間の手触り | 算数統合 | 主な弱点 |
|---|---|---|---:|---:|---|
| A: ねらい撃ち連鎖 | Peggleの一打と連鎖 / Hadesのrun差分と持ち越し / New Pokémon Snapの反応観察 | 予告を見てsafe / wild / recoveryの対象を撃ち、2〜4手で出口と持ち帰りを作る | 高 | 高 | genericな正解弾へ退化しやすい |
| B: 数のうつわ | DragonBox Numbersの合成・分解 / Suika Gameの容器圧 / Little Alchemy 2のrecipe発見 | 数量cluster同士を合成し、必要なら分解して、2〜4手で目標量か回復経路を作る | 中〜高 | 最高 | 管理UIや単純な最短手順へ退化しやすい |
| C: かずのスイカ | Suika Gameの落下位置入力と容器圧 / 2048の同種合体 / Hadesのrun間持ち越し | 落とす位置だけを選び、和が目標量以下なら合体、ちょうど目標量なら解放、超えたら積み上がる。整数・小数・分数を同一規則で扱う | 高 | 高 | 加法しか表現できず、筆算と応用計算が載らない |

**2026-07-26追記**: この表の3候補は、[19章 §2](./19_problem_first_core_design.md) の必須条件4（118スキル全部に載る）で再評価した。候補Cは被覆20〜30%のためコア候補から外し、Concrete / Bridge帯の副メニュー候補として保持する。候補AもMathActionContractを全スキル分書けないため同じ制約を受ける。現在の採用候補は19章 §5 の案2（賭け型）を軸としたハイブリッドであり、以下の表は比較履歴として残す。

G0では、AとBを同じ「2択×3タップ」へ正規化しない。Aは舞台上の対象を狙うゲーム、Bは物体同士を操作するゲームとして、別々の状態機械と終了条件を持たせる。

比較時に揃えるのは、完成絵なし、約30秒、同じ端末、同じseed、音初期OFF、提示順のcounterbalance、2〜4回のworld actionという外枠だけである。操作文法と反応時間は、各ゲームの仮説に忠実にする。

G0で自発的再試行、別戦略、因果説明、回復後の再試行が上回った一案だけをG1へ進める。連鎖採掘を先に書いたことを採用根拠にしない。

## 5. 先行仮説「ふしぎ連鎖探検」

### 5.1 コアファンタジー

> ポッコと「どこを動かすか」を決め、自分の計算を一打へ変え、地形といきものの変な性質をつないで、予想外の道を開く。

### 5.2 一回のbeat

```text
0. 裏側で予約する
   plannerが次のProblem / assignmentを先に固定する。対象選択でcategory、source、難度、問題値を変えない。

1. 見る
   揺れる土、変な音、眠そうないきものなど、結果傾向を予告する。

2. 狙う
   予約済みProblemを変更せず成立する対象だけを、横舞台上へ二つ提示する。カード画面ではなく対象を直接タップする。

3. 解く
   plannerが選んだ実問題を、既存TenKeyで解く。

4. 一打
   receipt確定と同時に、数量の作用が狙った対象へ届く。

5. 連鎖
   地形の性質、同行するいきもののクセ、run条件が一つずつ反応する。

6. 次を決める
   開いた道、残った気配、持ち帰り候補が次の判断になる。
```

問題と反応の間に「正解」「つぎへ」「図鑑を閉じる」を挟まない。反応中にも次問を操作できる。大きな連鎖だけ短い余韻を持たせるが、別modalへ切り替えない。

反応中に次問を操作できるのは、同じ対象へ続く予約済みfollow-upだけとする。新しい対象選択が必要な境界では、次問を先に表示して選択を無効化しない。

### 5.3 算数を一打の意味へする

正解を汎用ゲージへ貯めるだけでは、算数は通行料のままである。対応できる問題では、演算の意味を作用へ変換する。

| 数学的な関係 | 世界の作用例 |
|---|---|
| 足し算 | 二つの流れ、塊、力を合わせる |
| 引き算 | 覆い、詰まり、重なりを取り除く |
| かけ算 | 同じ作用をまとまりで反復する |
| わり算 | 力や対象を同じ数ずつ分ける |
| 位取り | ばらを束ねる、束をほどく |
| 分数・小数 | 一つを分ける、容器の一部を満たす |

数量表現は、既存problemが持つ正規のvisual scaffoldを使う。背景美術の個数、長さ、ゲージを勝手に正答ヒントへしない。

各encounterは、次の `MathActionContract` を宣言する。

```text
compatibleSkillFamilies
worldBefore(operands)
worldOperation
worldAfter(result)
strategicConsequence(result)
answerLeakGuard
```

- operandを変えると、作用前の世界状態が変わる。
- resultを変えると、作用後の世界状態と次の連鎖可能性が変わる。
- 子どもが「この数の関係だったから、世界がこうなった」と説明できる。
- 式を無関係な仮ボタンへ置換すると、このmechanicは成立しない。

plannerがProblem / assignmentを先に予約し、そのProblemを変えずに成立するencounterと二つのgame targetだけを提示する。対象選択はcategory、source、難度、operandへ影響しない。演出のために問題を差し替えない。

最初のgrayboxは管理された足し算・引き算profileに限定する。全118 skillへ薄い汎用演出を急いで広げず、意味のある動詞を段階的に追加する。契約のないskillは新coreへ入れず、既存の中立presentationへfail-closedし、coverage missを記録する。対象学年のrapid-safe assignmentを十分に覆うまでproduction defaultにしない。

### 5.4 いきものの「クセ」を収集する

いきものは鑑賞報酬ではなく、次の連鎖へ一つだけ作用する。

| クセ | 次のrunで起こすこと |
|---|---|
| はねる | 一打を隣の対象へ一度だけ跳ね返す |
| のぞく | 未知の対象の傾向を一つ見せる |
| くっつく | 隣接した小さな発見も一緒に運ぶ |
| わける | 一つの作用を二方向へ弱く分ける |

強いものを集めるだけの装備ランキングにしない。それぞれに得意と不得意を置き、別の連鎖を試したくなる横並びの道具にする。

初回は自動で前回の相棒を連れて再出発する。編成画面で毎回止めない。基地で触れば任意に交代できる。

### 5.5 予測できる運

運は、正解か不正解か、学習進行、問題難度を決めない。**状況を作り、解決はプレイヤーに渡す。**

- 地形やいきものに「やわらかい」「中で動く」「くっつきそう」などの予告を置く。
- 選んだ対象から結果の種類はおおよそ予想できる。
- 連鎖先、姿勢、出てくる小発見に少量のrun-seed差を入れる。
- run seedを保存し、reloadで結果をすり替えない。
- レア抽選より「見えた条件を組み合わせたら新しい反応が起きた」を優先する。

ガチャ、連続ログイン、期間限定、損失不安、希少度の煽りは使わない。

### 5.6 失敗を出来事へ変える

誤答をrun終了へ近づけるenergy減算は第一案から外す。**学習上の誤答をゲーム失敗の原因にしない。**

誤答時:

- 対象とworld stateを進めず、道具や対象を短くwobbleさせ、具体的なヒントを返す。
- 同じ問題へ550ms以内を目標に戻す。
- 開いた道、未確定ボーナス、登録済み発見、学習進行は失わない。
- 失敗frameのまま止めず、再入力が主操作であり続ける。

身体ギャグは誤答のたびに出さない。一つのrunで最大1回、主にプレイヤーが選んだ未知側の結果や大連鎖の余韻から起こす。

ゲーム上の失敗とリスクは、予告を見て未知側を選ぶ、帰る前にもう一つ狙う、安定したクセか未知のクセを連れていく、といった意思決定から作る。

失敗は「減点」ではなく、「欲張ったらポッコが土まみれになって別の穴へ落ちた」のようなrun固有の話へする。

### 5.7 遠征制約と「帰る / 続ける」

誤答とは独立した、有限の `worldTurns` と持ち帰り枠1つを置く。

- G0では最低2beat、最大4beatとし、world actionを一つ解決すると1turn使う。
- 誤答、ヒント、再試行はturnを使わない。
- 最初の大きな発見後、観察記録は確定するが、次runへ連れていける「クセ」は未確定の持ち帰り枠へ入る。
- 帰れば、そのクセをbankして次runへ持ち越せる。
- 続ければ、残りturnでクセを組み合わせたり別の発見へ交換できるが、予告されたdetour結果では未bankのクセを持ち帰れないことがある。
- 既にbank済みの発見、過去の図鑑、学習成果は失わない。

これにより「続ける」が常に優越しない。賭けるのは未確定のrun bonusだけで、子どもの学習成果ではない。

G0の2〜4beatは検証用境界であり、最終run長ではない。G2で自発的再プレイと疲労を見て調整する。

### 5.8 爽快感の波形

爽快感は派手な最終画像ではなく、次の身体的な波形で作る。

```text
構える
→ 接触する
→ ひび・圧縮・傾きが蓄積する
→ 連鎖が走る
→ 大きく解放される
→ 物体と身体が遅れて落ち着く
```

一打ごとに同じ正解SEを鳴らすだけにしない。各動詞は `onset / impact / settle` の3音を持つ。音なしでも接触、変形、余韻が読めるようにする。

一打目だけでも、もう一度押したくなる接触を持たせる。最後の大オチが、それ以前の操作の弱さを補償してはならない。

通常時は大きな色面と静かな余白を保ち、連鎖の瞬間だけ動く。全面粒子、金色発光、カメラズーム、別世界への切替で強さを偽装しない。

## 6. 一つのrunの構造

最終設計を固定8問に合わせない。学習予約は裏側でsegmentを使ってよいが、子どもに見せる終了条件は出来事から決める。

### 6.1 目標リズム

```text
0〜20秒
  気配を見る → 最初の対象を狙う → 小さな連鎖

20〜60秒
  性質が分かる → 安全 / 未知を選ぶ → クセを利用する

60〜120秒
  二つの規則がつながる → 大きな解放と身体オチ

120秒前後
  一つ持ち帰る / 見えている次の気配をもう少し追う
```

時間は仮説であり、grayboxで調整する。重要なのは、Q番号で必ず同じ出来事を出さないこと。

### 6.2 止めてよい場所

- 舞台上の対象を選ぶ操作
- 一つ持ち帰るか、見えている気配を追うかの判断
- run終了後の任意の命名
- 回復不能な保存エラー

これらも別画面へ移さず、できる限り対象を直接触る行為にする。

通常発見、コンボ、保存成功、図鑑記録、次問準備は止めない。大発見は同じ舞台の変形として起こし、summaryは帰還後にまとめる。

戦略的な「持ち帰る / 続ける」は、現在のimmutable learning segmentを完了した境界だけに出す。未回答assignmentを消化させるための追加画面は出さない。

左上の退出は問題境界から常に使える。途中退出時は未回答・未commitの予約を未消化のままactive runから外し、SRS、Due、weak、正答集計を変更しない。既存のconfirmed observationは守るが、まだbankしていないtraitは持ち帰り済みにしない。

### 6.3 runから残すもの

各runは必ず次のうち二つ以上を残す。

1. 新しいいきもののクセ
2. 既知のクセと地形の新しい組み合わせ
3. 基地の小さな変化
4. ポッコが覚える一つの出来事
5. 次回に実際に生成される気配

「また会えるかも」と表示した対象は次回seedまたはquest条件へ渡し、実在しない予告をしない。

## 7. 具体的な90秒例

```text
1. 横舞台に、やわらかい土と、内側で何かが跳ねる土が見える。
2. 子どもは跳ねる方を直接タップする。
3. 足し算を解く。二つの力が合流し、ポッコの一打として土へ届く。
4. 土がへこみ、中の丸いいきものが一度だけ隣の岩へ跳ね返る。
5. 次の問題中も岩はぐらぐらし続ける。
6. 正解すると岩が割れ、水の流れといきものの「はねる」クセが連鎖する。
7. 子どもが未知側を選んだ結果、水がポッコの葉帽子へ入り、遅れて帽子が裏返り、ポッコが安全に尻もちをつく。
8. 開いた道の奥に安定した帰路と、まだ動く未知の土が同時に見える。
9. 子どもは一つ持ち帰るか、もう一度未知を狙う。
10. 持ち帰った場合、「はねる」クセが次runの一打を一度だけ隣へつなぐ。
```

この例で重要なのは、花や水や尻もち自体ではない。

- 最初の狙いが結果を変える。
- 算数の作用が接触へ変わる。
- いきものの性質が連鎖を作る。
- 身体ギャグが物理結果から生まれる。
- 持ち帰りが次回の操作を変える。

という一本の因果である。

## 8. 長期構造

### 8.1 図鑑

図鑑は完成画像の棚ではなく、子どもが発見した規則の記録にする。

- 自分で付けた名前
- 見つけた場所
- 発見したクセ
- まだ試していない地形・道具との組み合わせ
- そのrunで起きた短い出来事

空欄を大量に並べて作業感を出さない。未発見は「次に試せる一つか二つ」だけ具体的に見せる。

### 8.2 基地

基地はメニューではなく、持ち帰ったものが動く小さな遊び場にする。

- いきものが発見したクセで環境へ反応する。
- ポッコが前回の身体ギャグを一度だけ再演する。
- 次の気配が基地の端に実物として現れる。
- 主CTAは、その気配へ直接触れて再出発すること。

保護者向け情報、編成、設定を主導線へ混ぜない。

### 8.3 継続の倫理

続ける理由は、好奇心、上達、愛着、自己表現に置く。

- daily streakを失わせない。
- 期間限定報酬で急かさない。
- ランダム景品を課金や広告へ接続しない。
- 休んだことを責めない。
- 既に登録した発見を没収しない。

## 9. 視覚・音の役割

アートはコアループを成立させる一部だが、コアループの代用品ではない。

### 9.1 画面構図

- 横向きの舞台構図
- 一画面に一つの主対象、一人のポッコ、一つの読める作用
- 55〜65%の静かな大色面
- 3色相族程度の明快な色面
- 大きく単純な形と、接触部だけの素材差
- 同じcamera、地面、対象を変形させ、別画像へワープしない
- 問題・TenKeyは下部dockへまとめ、世界の接触点を隠さない

### 9.2 キャラクター

かわいさは装飾ではなく「触ったらどうなるか見たい」という予感を作る。

- 64pxでも読める固有silhouette
- 一体につき一つの身体規則
- 待機、成功、失敗、連鎖で同じ規則を変奏する
- 一runに一つの身体ギャグ
- 痛み、拘束、切断、能力への嘲笑へ読める形を避ける

### 9.3 制作方式

完成frameの全面差し替えより、固定舞台、役者、作用物、接触差分をlayer化する。code-native motionと少数の手描き素材を組み合わせ、連鎖の状態を実際のgame stateから描く。

grayboxの楽しさゲートを通るまで画像生成を始めない。

## 10. 学習・データ安全の境界

### 10.1 残す

- Study共通planner、SRS、Due、weak、解放guard
- rapid-safe適格性
- immutable segment予約を使った学習plan
- `AttemptIdentity`、receipt、atomic transaction
- seeded deterministic generation
- checkpoint、CAS、crash resume
- prefetch、TenKey、正解後650ms / 誤答後550ms目標
- confirmed学習・発見を能力罰で没収しない原則
- reduced motion、sound off、offline、PWA更新契約

これらは堅牢な基盤であり、楽しさ不足の原因ではない。

### 10.2 作り直す

- Q番号から報酬を決める固定 `3 / 3 / 2` の体験規則
- 選択直後に合流するmap
- `steps` だけから決まるpresentation stage
- 作用しないcombo
- 誤答回数表示になっているenergy
- run内だけで消える発見
- 次回生成へ渡らないteaser
- 固定Q7 blocking modal
- 全面raster差し替えによる疑似的な世界反応

### 10.3 新しく分離するdomain

巨大な `Explore.tsx` へ直接足さず、少なくとも次をpure domainとして分ける。

```text
EncounterState
WorldTarget
WorldAction
CreatureTrait
ReactionChain
RiskChoice
CarryOverEffect
RunStoryBeat
```

学習receiptは `WorldAction` を一回発火する入力であり、game stateはその後の連鎖を決定論的に解決する。

新game stateでは少なくとも、`learningAnswerCount`、`worldTurn`、`actionCharge`、`rewardCount` を別々に持つ。学習集計の不変条件とゲーム集計の不変条件も分離する。

traitのbankはrun終了と同じ冪等transactionへ含め、`runId / bankDecisionId` の重複retryで二重登録しない。bank保存が失敗した場合はactive runと選択を維持し、成功したふりをしてsummaryへ進まない。

legacy runと発見は読み取り互換を維持する。新coreを理由に既存データを消さない。

## 11. Graybox検証

### 11.0 Gateの事前固定

G0〜G2を始める前に、日付付きdecision recordへ次を固定する。

- 対象年齢、人数、募集条件
- current Exploreなどの比較baseline
- 提示順のcounterbalance
- 自発的再run、後日再訪、因果説明、概念理解、遅延正答の最低条件
- accuracyと学習転移の非劣性境界
- 観察手順、除外条件、安全停止条件

人数や閾値を結果を見てから変えない。事前条件がない結果はdiagnosticに留め、formalなG0 / G1 / G2通過やproduction昇格の根拠にしない。

### G0: 算数なし30秒whitebox

**2026-07-26追記**: G0の役割は [19章 §8](./19_problem_first_core_design.md) で縮小した。実績ある構造を借用する方針では、面白さの発明検証をwhiteboxで行う必要がないため、絞り込みは19章 §7 の人力テスト（実装ゼロ、1案5分）で行い、G1を主ゲートとする。以下の記述と `/#/__dev/g0`、`/#/__dev/g0-v2`、`/#/__dev/suika` の実装は比較履歴として凍結する。§11.0 の事前固定は19章にもそのまま適用する。

完成絵を使わず、色付きの形、数量cluster、地面、短い任意音だけで次の2案を比較する。

1. `chain-shot`: 予告の異なる三つの対象から一つを狙い、連鎖量を見て次手を選ぶ。wildの直後はrecoveryが実際に結果を変え、2〜4手で出口を開くか明るいdetourへ着地する。runで得た一つのtraitはリプレイ時の連鎖を変える。
2. `number-vessel`: 一つの数量clusterを選び、別clusterへ直接合わせる。選択中のclusterは分解できる。通常の合成後だけ予告済みclusterが入り、容器圧が上がる。overflowは即終了にせず一度回復でき、2〜4手で目標量、recipe、または安全なspillへ着地する。

2026-07-26に候補Cを追加した。

3. `number-suika`: 落とす位置だけを選ぶ。触れた2つの量の和が目標量以下なら合体して和になり、ちょうど目標量なら弾けて消え、超えたら合体しない。容器があふれるまで続き、run終了時に3択のおまもりを一つ持ち帰る。

候補Cは操作文法を新規設計せず、既に広く遊ばれている落下・合体パズルの文法をそのまま借り、合体結果だけを算数へ置き換える方針を取る。借りるのは入力と報酬構造だけで、果物、キャラクター、固有名、画面構図、音、造形は借りない。route は `/#/__dev/suika`、candidate は `g0-number-suika-v1` とし、A/Bとは別routeに置く。

候補Cの量は最初から有理数で持ち、整数（目標10、玉1〜5）、小数（目標1、玉0.1〜0.5）、分数（目標1、玉1/2・1/3・1/4・1/6）を同一規則の別profileとして扱う。整数専用として作ってから小数・分数を後付けしない。玉の大きさと色は目標量に対する割合で決まるため、整数の5、小数の0.5、分数の1/2は同じ大きさ・同じ色になる。異分母の足し算は、通分手順を教える前に物理として起こる。

この文法が扱えるのは目標量への加法だけである。引き算、掛け算、割り算、筆算、割合・平均・比・速さ、非数量skillは載らない。[02_math_skills.md](./02_math_skills.md) の7段階でいえばConcrete / Bridge / Strategyに効き、Algorithmには効かない。全118 skillを新coreへ載せる前提を置かず、契約のないskillは §5.3 のとおり既存の中立presentationへfail-closedする。

実装と実ブラウザ証拠は [G0 Number Suika Audit](../design/audits/2026-07-26-g0-number-suika/README.md) を正とする。同auditは試験器が動く証拠であり、楽しさのPASSではない。

Aの入力は舞台上の対象タップ、Bの入力はsource clusterからdestination clusterへの二段階の直接操作、Cの入力は落下位置の指定とする。Bの二段階選択は確認modalではなく、pointer、keyboard、assistive technologyで同じ物体間操作を成立させる代替文法である。

反応中の次入力はqueueしない。世界状態、対象の意味、clusterの位置が反応後に変わるため、結果を見る前の先行入力を受理すると意思決定の検証にならない。

2026-07-25時点の4案・同一3入力版は、development専用 `/#/__dev/g0` の
`g0-direct-stage-v1` として比較履歴に残す。既存の
[G0 Core Loop Lab Audit](../design/audits/2026-07-25-g0-core-loop-lab/README.md)
は上書きしない。

A/Bの異種ループ版は別route `/#/__dev/g0-v2`、別candidate
`g0-mechanic-remix-v2` とする。事前条件は
[G0 Mechanic Remix Experiment Contract](../design/audits/2026-07-25-g0-mechanic-remix-v2/experiment-contract.md)
を正とする。v1とv2は入力数も操作文法も異なるため、完走時間やタップ数を直接比較しない。いずれも試験器が動く証拠であり、楽しさのPASSやproduction採用の証拠ではない。

初期の停止条件:

- 自分からもう一度を選ぶ子が4 / 5未満
- 「何を狙って、どうなったか」を説明できる子が4 / 5未満
- 失敗後に再試行する子が4 / 5未満
- 危険、痛そう、責められたという解釈が1件以上

未達なら、絵を直さず動詞か規則を変える。

### G1: 実算数graybox

G0を通った一案だけへ、実planner、実receiptと、skillに適合する実回答入力を接続する。候補Aまたは直接操作に適合しないskillでは実TenKeyを使う。

- current Exploreと同じ非記録DEV問題列を使い、入れ替えるのは参加者ごとの「current / grayboxを先に遊ぶ順序」だけにする。問題順、assignment、operandは変えない。
- 正解後P95 650ms以内、誤答後P95 550ms以内。
- 通常beatの強制停止0件。
- answer leak 0件。
- 4 / 5以上が自分の選択と結果の違いを説明できる。
- 4 / 5以上がoperand、operation、resultとworld reactionの関係を説明できる。
- 4 / 5以上が明示的に「終わってよい」と伝えられた後も別の選択を試す。
- Study共通planner、SRS、receiptに差分を作らない。

これとは別に、実plannerが足し算・引き算を予約する管理profileで、概念説明、正答率、同問再試行、短い遅延確認を測る。契約のないskillは中立presentationへfail-closedし、別skillへ差し替えない。

問題数/分は守るが、主要な楽しさ指標にしない。算数を仮ボタンへ置換しても同じ判断・結果が成立する場合は不採用とする。

候補BがG1へ進む場合、compatibleなConcrete / Bridge skillでは合成・分解そのものを回答入力としてreceiptへ接続する。TenKeyを合成前の通行料として置くだけの版は不採用とする。直接操作がanswer leakになるskillは中立TenKeyへfail-closedし、plannerが予約したcategory、operand、operationをrecipe都合で差し替えない。この接続をproductionへ入れる前に、11の学習統合仕様で正式決定する。

### G2: 7日間の継続graybox

3体、各2種類のクセだけを仮実装し、複数日で確認する。

- 初日に自発的な2run目が起きるか。
- 次回に自分で同じゲームを選ぶか。
- 「次はあの場所を狙う」「あのクセを連れていく」という意図が出るか。
- 安全側だけに選択が固定されないか。
- 標本名ではなく、自分のrunの出来事を覚えているか。
- 学習上の誤答を能力の失敗として受け取っていないか。

アンケートの「楽しかった」だけで合格にしない。行動、発話、再選択を証拠にする。

G2と学習安全性の正式判定は、11.0で固定した人数、baseline、最低条件をすべて満たした場合だけPASSとする。未設定、途中変更、対象不足はHOLDとする。

## 12. 実装の順序と停止線

1. この提案をdecision queueへ置き、現行productionをcontainmentとして維持する。
2. `g0-direct-stage-v1` を比較履歴として凍結し、新しい完成絵を作らず、操作文法の異なるA/BのG0 v2 whiteboxを別routeへ作る。
3. 子どもの行動で一案を選び、G1へ実算数を接続する。
4. G1通過後だけ、最小の相棒・地形・一体のいきものを制作する。
5. G2で持ち帰りと次回作用を検証する。
6. three-gate visual監査、学習安全、runtime、PWAを別々に通す。
7. G2の継続性、学習安全性、three-gate visual / silent / runtimeをすべて通過した後にだけ [10_exploration_game_spec.md](./10_exploration_game_spec.md)、[11_learning_integration_spec.md](./11_learning_integration_spec.md)、[12_screen_flow_spec.md](./12_screen_flow_spec.md)、[14_ui_world_motion_spec.md](./14_ui_world_motion_spec.md)、[15_mvp_rollout_verification_spec.md](./15_mvp_rollout_verification_spec.md) を正式更新し、production defaultを切り替える。

G0またはG1で楽しさが成立しなければ、現行art assetを流用してproductionへ急がない。

## 13. 採用しない近道

- Q7 modalだけを消して完成とする。
- 画像をさらに豪華、明るい、かわいくして完成とする。
- コンボ数字、紙吹雪、振動、効果音だけを追加する。
- ルートカードの文言だけを変える。
- レア標本確率を上げて運と呼ぶ。
- energyを増やして失敗を軽くする。
- 8問の固定sceneを別テーマへ差し替える。
- 参考IPのキャラクター、工作素材、図鑑UIへ寄せる。

これらは局所改善として価値があっても、`意思 → 操作 → 結果 → 次の作戦` が欠けたままならコア問題を解決しない。

## 14. 現時点の仮説判定

現段階で確定するのは、production採用ではなく検証順だけである。

- G0比較前に、現行の固定8問reward graphへ追加のart・演出投資を続ける: **NO**
- 現行reward graphを最終ゲームの一部として残す: **未決定**
- 学習、保存、resume、PWA基盤を捨てて全面新規にする: **NO**
- 学習基盤の上へ、Aのねらい撃ち連鎖とBの数の合成・分解をG0で比較する: **2026-07-26に終了**（[19章 §5](./19_problem_first_core_design.md) の候補比較へ引き継ぐ）
- 連鎖採掘を最終コアとして正式採用する: **NO**（19章 §5 で案2軸のハイブリッドへ変更）
- Yoshi系の見た目や図鑑体験へさらに寄せる: **NO**
- 絵より先にG0 / G1で「操作自体が楽しい」を証明する: **YES**（ただし借用方針では19章 §7 の人力テストとG1で証明する）

最初の完成物は美しい画面ではなく、子どもが説明なしで対象を狙い、反応を見て笑い、自分から別の狙い方を試す30秒のgrayboxである。正式採用はG2、学習安全性、three-gate通過後に別判断する。
