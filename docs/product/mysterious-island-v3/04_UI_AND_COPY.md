# 画面・言葉・情報の開示

v3.0-rc1／新規提案。完成見本・レシピを見せず、操作と現在状態は分かるようにする。

## 1. 画面構造

島全体を小窓へ追いやらず、通常は暮らしを近くで見られる画角、配置時は空間全体が分かる画角を使う。既存の家、布製ぽこもこ、うさぎ、カワウソのidentityを維持する。

常設は小さな残高、必要な操作入口、既存の下部ナビ。通貨や未発見の進捗バーを画面の主役にしない。メニューを閉じると島の現在の姿へ戻る。

| 画面／状態 | 主な内容 | 行ってはいけないこと |
|---|---|---|
| しま | 自分の配置・住人の暮らし、つくる／もちもの／ようす | 「今日はこの景色を完成させよう」 |
| つくる | 公開済みの物単体、価格、購入時の育ち、実物見本 | 合成後の完成見本、未発見の効果の説明 |
| もちもの | 実際の個体、現在の育ち・外観、無料の移設・収納 | 普段の模様替えに売却を要求する |
| 配置 | 薄い仮表示、利用位置と安全な通路、ここに置く／やめる | 仮表示の段階で魔法や発見を確定する |
| みてみる | 今の条件で住人利用・対象の普通の反応を試す | 過去の成功例へ自動的に置き換える |
| 島のようす | 現在の成長・住人の活動・短い説明 | できていない条件を全て学習不足として見せる |
| きろく | 表示された場面・本人が残した思い出 | 未発見の「？？？」を全件並べる、完了率を競わせる |
| まなぶ | 既存の適切な課題・支援・区切り | 島イベントの割込み、毎問の必須回収 |

## 2. 子ども向けの文例

| 場面 | 採用する表現例 | 採用しない表現 |
|---|---|---|
| 学習から戻った | 「まなんだぶん、しずくがふえたよ」 | 「花畑クエストを進めよう」 |
| 物を選ぶ | 「ちいさなベンチ。どこに置こうかな？」 | 「花3本のそばなら特別な行動が解放」 |
| 不足 | 「あと4しずく」 | 「あと2問で魔法が起きる」 |
| 模様替え | 「こっちに置いてみる？」 | 「おすすめの正解配置にする」 |
| 通路が塞がる | 「ここだと、とおれないよ」 | 「間違い。置き直そう」 |
| 成長待ち | 「まだ、つぼみだね」 | 「勉強が足りないから咲きません」 |
| 住人が忙しい | 「いまは、ほかのことをしているよ」 | 無言で実験が失敗したように見せる |
| 任意の探索ヒント | 「少し、場所を変えてみる？」 | 「水鉢を灯りから4マス以内へ」 |
| 場面の記録 | 「花のそばで、ベンチにすわっていたよ」 | 「花とベンチの法則を理解しました」 |
| 魔法のあと | 「いまの、のこす？」 | 「魔法発動成功！レア獲得率アップ」 |
| 久しぶり | 「おかえり。お花が咲いているよ」 | 「7日サボったのでボーナス消滅」 |
| 終了 | 「また、つづきからあそべるよ」 | 「あと少しでレアが出るからやめないで」 |

文字が読めない場合にも、動いた物、顔の向き、元の状態との差が分かる表現を優先する。幼児向けの言葉を保護者向けの説明文へ無理に適用しない。

## 3. 「隠す」と「隠さない」

隠すのは未経験の結果と完全な条件。購入価格、所有か収納か、種か開花済みか、通れない場所、忙しい住人、実装されているかは隠さない。

未成熟3株がまとまったら前段階の土の変化を見せる。花壇と同じ完成の縁・タイトルを出さない。芽を買ったのに、開花済みの商品を買えたかのような見本にしない。

子どもが自分で考えた目標は自由。「お花をいっぱいにしたい」と本人が言うことを止めない。ゲームが特定の完成形を割り当てない、という意味である。

## 4. 現在状態の比較と、記録の再演

「みてみる」は現物の検証。対象と現在の配置を薄く強調し、普通の反応を先に見せる。離した相手を裏で近いことにしない。過去の思い出から再演するときは枠と「おもいで」の表示で区別し、現在の島へ書き戻さない。

比較中に別の場所の大きな動作を割り込ませない。音のない状態でも、注視点・対象・変化が読み取れるようにする。音や点滅だけを手がかりにしない。

## 5. ヒントの設計

最初に教えるのは操作のみ。「つくる」「置く」「移す」「見る」「戻る」が分かればよい。花壇の条件をチュートリアル課題にしない。

本人が「なにかあるかな？」を開いた場合、一度に一つ、所有物の範囲で試せる抽象的な提案をする。「近づけたり、離したりしてみる？」のような言い方を使う。何分操作しなかった、という理由だけで連続ヒントを出さない。

「何も分からない」が続く場合は、説明をさらに隠すのではなく、単体反応・現在状態・操作の見つけやすさを直す。保護者から手順の説明を受けたことを悪い行為として扱わない。

## 6. アクセシビリティ・小画面

既存の390×844、768×1024の縦画面を主要確認対象とする。大きさだけでなく、メニューを開いたまま閉じる・学ぶ・置くへ届くことを確認する。短い高さの画面でも下部ナビを隠さない。

主な操作領域は44px以上を既存の設計目安として継承。ドラッグだけでなくマス選択・ボタン操作を用意する。色だけで可否を伝えない。影・小鳥・花等の観察対象が小さい場合は拡大した観察面から同じ操作を提供する。

動きを減らす場合、葉の大きな移動を「上へ並ぶ葉の静止像」へ、影の挨拶を「本体と違う姿の影」へ置き換える。揺れを止めた結果、魔法の差が完全に消えないことを確認する。

## 7. 画面チェックでの禁止パターン

レシピの一覧、発見前の具体的魔法名を全部並べる画面、毎回の「発見完了」モーダル、常設の「まだ○個」、学習回数による魔法メーター、配置ミスによる赤い成績評価、再演へ通貨を要求する画面は作らない。

スタイルは既存の不思議な島を継承し、青い海、明るい地面、主役の家と布の質感を土台にする。新しい世界観の参考画像は今回生成・承認していない。元資料に入っていない3D資産の視覚品質を確認済みと扱わない。
