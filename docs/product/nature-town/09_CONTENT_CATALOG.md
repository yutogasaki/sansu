# 09. 初期要素・場面・追加の契約

## 1. S1の要素

| 要素 | 作用と状態 | 配置を変える意味 |
|---|---|---|
| 川・水辺 | 固定の水源、移動の障害 | 水分と橋の接続の両方に影響 |
| 木 | 日陰、占有、好まれる休憩候補 | 人が休む場所と畑の光の両方が変わる |
| 花 | 訪問パッチ、観察先 | 虫の来やすさと住人の行き先が変わる |
| 畑 | 成長、収穫在庫、配送元 | 育ちやすさと運びやすさを同時に考える |
| 道 | 移動時間、経路の選択、通行量 | 近道、迂回、地区間の接続になる |
| 橋 | 水面の接続 | それまで遠い／届かない土地へ行ける |
| 共同食の拠点 | 在庫、受渡し、供給範囲 | 遠い家・畑への届き方が変わる |
| 家 | 入居枠、所属拠点 | 家を増やすだけでは住めず、供給と経路が必要 |
| ベンチ | 定員、滞在、共有反応 | 通り道が滞在する場所に変わる場合がある |
| 水路 | 接続された水源の影響範囲 | 乾いた場所へ畑を移す選択が生まれる |
| 台車 | 連続した道で積載4個 | 遠方の収穫を運ぶ経路が再評価される |
| 小さな虫 | 条件付き訪問、滞在 | 花・水分・天候・住人の観察がつながる |

天候は晴れ・曇り・雨の共有条件。住人の見た目の色違いは、別のシステム要素として数えない。

## 2. 住人の個体例

既存モデルのぽこもこ・うさぎ・カワウソを優先する。以下の性格は挙動の試作用であり、既存キャラの正式な設定や名前を上書きしない。

| 例 | 外見の再利用候補 | 好み | 見える行動差 |
|---|---|---|---|
| R1 | ぽこもこ | 木陰、静かな場所 | 配送後に混んでいない木陰へ寄る |
| R2 | うさぎ | 人のいる場所、遠出 | 別地区の利用できる席も候補にする |
| R3 | カワウソ | 水辺、自然観察 | 水辺の花や訪問群へ目を向ける |
| R4 | ぽこもこ系の別個体 | 食卓、近場 | 拠点付近に滞在しやすい |
| R5 | うさぎ系の別個体 | 静かな花畑 | R2と同じ種でも別の場所を選ぶ |
| R6 | カワウソ系の別個体 | にぎやかな場所 | R3と違い、複数人の集まりへ寄る |

固有の大きな脚本は初版に必要ない。気づく→近づく→物を見る／置く→相手へ反応→次へ、という共有動作を使う。後続の入居者はこれらの見た目と好みを組み合わせるが、既存個体のIDと記憶は維持する。

## 3. 環境4例

水辺の近くは育成条件が整いやすいが、川によって経路が限定される。乾いた広場は歩きやすく拠点を置けるが、畑の水分を工夫する余地がある。木陰のまとまりは住人の休憩先になり、畑には光の制約になる。川向こうの地区は近くに見えても、橋と供給経路をつながなければ同じ生活圏にならない。

これらは土地の種類を増やすための名前ではなく、同じ畑・道・木を置いたときに異なる結果を生む条件である。

## 4. 眺める場面12例

1. かごが満ち、住人が2個を持ち上げ、拠点へ置き、食卓の量が変わる。
2. 台車に4個載せ、以前なら2往復した道を一往復で届ける。
3. 道をつないだ次の配送から、住人が新しい経路を選ぶ。
4. 遠回りする住人を見て短い道を足すと、通行の集中が変わる。
5. 木を増やした場所で休憩が増え、隣の畑の成長が少し遅くなる。
6. 水路がつながり、乾いた土と植物の形が時間をかけて変わる。
7. 花を増やした場所へ、ある回には虫が来て、別の回には来ない。
8. 訪問群を見に住人が近づき、近くのベンチへ落ち着く。
9. 二人が同じ場所へ滞在し、短い共有反応をして別々の行き先へ戻る。
10. 食料の余裕と家がある町に入居候補が来て、迎えると新しい家へ向かう。
11. 人口が増え、以前余っていた食卓の量が減り、運ぶ頻度の見直しが必要になる。
12. 北の地区を開き、旧地区の畑から新しい拠点へ荷物が運ばれる。

以上は発生し得る場面であり、固定順の12ミッションではない。場面7の当選を、ムービー再生で必ず起こしてはいけない。

## 5. 試して違いが出る6組

| 比較 | 変えるもの | 維持するもの | 見るもの |
|---|---|---|---|
| A | 畑の水源からの距離 | 天候・日陰・運搬条件 | 成長と収穫の時刻 |
| B | 木の位置 | 畑・水・道 | 植物の光と住人の休憩先 |
| C | 近道の有無 | 畑在庫・目的拠点・住人 | 配送時間と交通の偏り |
| D | 台車／手運び | 同じ収穫4個・連続道路 | 一往復量と必要往復数 |
| E | 花の密度 | 天候・水分・評価回数 | 多数回での訪問傾向。1回の当否だけで判定しない |
| F | 一極の拠点／分散拠点 | 住人・畑・土地 | 供給範囲と地区間の輸送 |

比較表は開発者用。子どもに条件統制の手順を毎回提出させるものではない。

## 6. 追加コンテンツの契約例：渡し船【S2以降】

目的は、既存の川・家・畑・輸送経路を再評価させること。新しい船の動画を一回見るだけの追加にしない。

定義データ：両岸の停留所、船のID、定員、貨物量、運行経路、出発条件、所要tick。状態：どちらの岸にいるか、乗客と荷物、予約、次の出発。共有動作：歩く、待つ、乗る、座る、積む、降ろす。専用美術：船体、停留所、乗降と航行。

道・台車・拠点は同じ移動グラフへ接続する。陸路より遅くても短い距離をつなぐなどの選択を作る。定員超過、停留所移動、航行中の保存、反対岸の削除、台車ごとの乗船、複数住人の順番を仕様化してから導入する。

受入条件は物量保存、乗客の所在が一意、到着後の経路再開、閉じ込め防止、seedと中断の再現。船の追加だけで学習の取得単位や幸運率を変えない。

## 7. 拡張の審査

新しい要素には、既存システムへ届く作用、見える違い、選択上の利点と制約、失敗時の回復、保存、再現テストを要求する。「最低10個と反応する」といった根拠のない数量ノルマは置かない。

一つの意味のある相互作用を丁寧に作る方が、見分けられない十個の演出分岐より重要。追加後に既存の町を試し直したくならなければ、主要解放としては弱いと評価する。
