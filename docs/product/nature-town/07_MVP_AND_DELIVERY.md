# 07. 実装段階と納品条件

## 1. 全体像を小さく切り出す

最初の試作S1は、3人から始まり、複数の家と供給を整え、最大9人の試験範囲まで増やせる。初期1チャンクから3チャンクまで連続して広がる。人口と土地のどちらか一方だけを増やしたデモでは不足。

この上限は検証用。将来の世界を9人・3区画に固定する設計にしない。最初から全生態系や電力を作る必要もない。

## 2. S0：コアと接続確認

描画を豪華にする前に、入力・固定tick・経路・在庫・seed・保存・学習アダプターを分離する。`fixtures/starter_world.json` を読み込める初期生成器を作り、02と03の数式・予約・受渡しの検査を通す。

S0の完了は技術上の区切りにすぎず、ゲーム完成ではない。乱数テストの通過を面白さの証明にしない。

## 3. S1：必須の縦切り

次の一周をプレイ可能にする。

```text
畑・水辺・木・道を変える
→ 育ち方・収穫・運ぶ時間が変わる
→ 食料が拠点へ届く／届きにくくなる
→ 住人の滞在と、入居を迎える余裕が変わる
→ 人口が増えると需要と移動が変わる
→ 道を伸ばして隣の地形へ広がる
→ 遠い地区の畑・拠点・住人をどうつなぐか試す
```

その上に、花・水分・天候で起こりやすさの変わる虫の訪問、住人の短い共有反応を載せる。学習で水路または台車を開き、**既存の場所をやり直す理由**が生まれることまで確認する。

S1必須要素：道、橋、家、共同食の拠点、畑、木、花、ベンチ、水路、台車、川、天候3種、虫の訪問、既存外見に対応する住人、入居候補、2方向の土地拡張、プロフィール別保存、学習境界。

## 4. S1の納品物

動くアプリに加え、仕様対応表、設定ファイル、既存との接続表、起動手順、操作説明、受入結果、既知の不具合を出す。保存の破損・二重報酬・物量の複製など重大な問題が残る場合は、利用可能な範囲を明示する。

テスト用seedと初期状態を添付し、成功場面だけの動画ではなく、条件変更前後、条件不成立、運で来ないケース、中断・再起動も見せる。仮の学習ボタンなら、そのことを画面と報告の両方で明示する。

## 5. S2以降：条件付きで追加するもの

S1で「配置をもう一度試したくなる」「人口と土地の成長に意味がある」が確認できた後に拡張する。

| 追加候補 | 既存に生まれる新しい意味 | 追加前に必要な確認 |
|---|---|---|
| 土壌・複数作物 | 同じ水・日陰で得意な土地が分かれる | 実在知識との区別、単なる相性暗記にしない |
| 生き物の複数役割 | 植物・住人・環境の別の関係が生まれる | 条件、個体数、誤学習、過剰増殖の管理 |
| 渡し船 | 川の両岸が別の供給圏からつながる | 定員・待ち・荷物・途中編集 |
| 加工・市場 | 食料・輸送・人の集まりが別の循環になる | 自動増築の許可、資源保存、単一の最適解化 |
| 風・エネルギー | 場所と時間が施設選択に影響する | 常時給電義務や停電の罰へしない |
| 芸術・祭り | 集まる場所や住人の組合せが文化へなる | 専用イベントの大量制作だけに依存しない |

追加量ではなく、既存システムが再び試したくなるかで判断する。S1で遊びが成立しない場合に、全候補を追加して埋め合わせない。

## 6. 禁止する短絡

「植物＋水なら繁栄+10」「家を置くと住人を即生成」「新しい道具で新しい動画を再生」「乱数で成功／失敗だけ分ける」「人口も拡張も後回し」「コードの巨大な条件分岐へ全イベントを直書き」は、この仕様の実装とみなさない。

コンテンツ定義だけ完成して実際の輸送や反応が動かない場合も未完成。逆に、未提供の何十種ものコンテンツがないと面白くならない作りも避ける。
