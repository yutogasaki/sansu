# 08. 受入条件

## 0. この資料の検査と、実装後の検査を分ける

同梱の `tools/check_spec.py` は、設定、初期配置、参照数式、乱数サンプル等の**資料検査**である。以下のゲーム受入条件を実行したものではない。ここにチェック項目があることと、実装が通過したことを混同しない。

実装AIは各IDに PASS／FAIL／NOT_RUN、実行環境、入力seed、実行方法、証拠を記録する。目視評価を自動テストの件数へ混ぜない。

## A. 因果・物量・移動

| ID | 条件・操作 | 合格条件 |
|---|---|---|
| SIM-01 | 同一の畑を水分の高低だけ変えた条件で実行 | 参照式通りに成長差が出る。他の要因を勝手に変更しない |
| SIM-02 | 水路を接続／途中で切断 | 接続した下流のみ水分目標が変わり、切断後は緩やかに戻る |
| SIM-03 | 上り・循環・長すぎる水路 | 上りへ通水せず、ループ増殖せず、最大距離を守る |
| SIM-04 | 同じ畑の近くに木を移す | 日陰の変化が成長に作用し、休憩候補にも作用する |
| SIM-05 | 成熟した畑の在庫が満杯 | 収穫で上限超過しない。収納・再配置で再取得しない |
| SIM-06 | 収穫→積載→運搬→納品→共同食 | 食料総量が収穫・初期投入・食事消費以外で増減しない |
| SIM-07 | 同じ食料を2人が取りに行く | 二重予約・二重取得・負数在庫がない |
| SIM-08 | 台車あり／なし、道が連続／途中欠落 | 一回の実積載量と往復数が仕様に沿って変わる |
| SIM-09 | 短い混雑路と少し長い空いた道 | コストに応じて迂回する場合がある。全員停止しない |
| SIM-10 | 道を消す・橋を消す・輸送先を動かす | 所持品を保護し、安全に再計画。水面や宙に残らない |
| SIM-11 | 拠点が満杯／配送予約後に条件変化 | 受入上限を超えず、予約と荷物を整合させる |
| SIM-12 | 家と拠点を切り離す→再接続 | 供給範囲が変わり、復旧する。住人への苦痛・没収なし |

食料保存の不変式：`畑在庫 + 拠点在庫 + 運搬中 + 収納中 = 初期食料 + 累積収穫 - 累積共同食消費`。予約は所有量に加算しない。世界初期化以外で初期食料を再付与しない。

## B. 繁栄・人口・広がり

| ID | 条件・操作 | 合格条件 |
|---|---|---|
| GROW-01 | 家だけ大量に配置 | 自動で住人を生成せず、供給条件と抽選と受入れが別 |
| GROW-02 | 空き家、十分な供給・備蓄・履歴 | 初期式の入居抽選が始まる。常住人口は受入れまで不変 |
| GROW-03 | 候補カードを連打・保存後に再表示 | 一人だけ受入れ。ID・枠・候補を二重消費しない |
| GROW-04 | 条件悪化・しばらく中断した候補 | 候補が無期限で保持され、基礎権利も失わない |
| GROW-05 | 人口を増やして同じ供給を使う | 食料要求が増え、配置変更の理由が発生する |
| GROW-06 | 道を境界へ接続し、開拓する | 隣チャンクが同じ世界につながり、座標・旧物・旧住人を保つ |
| GROW-07 | 道の未接続、水面だけを触る、拡張連打 | 不正な開拓や重複生成がない |
| GROW-08 | 遠い地区へ家・拠点・畑を作る | 旧拠点の在庫が勝手に全域共有されず、輸送が意味を持つ |
| GROW-09 | 人口を増やさず自然を整備 | 訪問・道具解放・土地拡張を人口条件で閉ざさない |
| GROW-10 | S1上限に到達／将来設定を増加 | 試作上限を明示。追加チャンク・IDに耐える構造を確認 |
| GROW-11 | 十分な備蓄があり、在庫満杯で配送が少ない | 供給余地の式が備蓄を考慮し、配送件数だけで入居を閉ざさない |

GROW-02の単体テストは乱数を注入して当選・非当選を両方検査する。一般のプレイで「このtickに必ず入居」が起きることは要求しない。

## C. 運・再現性

| ID | 条件・操作 | 合格条件 |
|---|---|---|
| RNG-01 | 同じseed・初期状態・同tickのコマンド列 | 最終状態とドメインイベントが一致 |
| RNG-02 | 30／60fps、カメラ位置、音、演出設定を変更 | 同じ論理tickまでの結果が一致 |
| RNG-03 | セーブ／ロード、画面の開閉、プロフィール切替 | 抽選を引き直さず、評価回数と候補を維持 |
| RNG-04 | 花の低条件／高条件、他条件同じで2000試行 | 高条件の確率が数式上高く、標本でも方向と誤差範囲が整合 |
| RNG-05 | 物を大量に置く・同セルをなぞり直す | タップ数や物数分の追加抽選をしない |
| RNG-06 | レア訪問を一切発生させない | 土地・人口候補・学習・全基本道具が機能する |
| RNG-07 | 長い不発、天候変化、定員超過 | 仕様の頻度・上限を守り、普通の遊びが止まらない |
| RNG-08 | 学習量・正答率・所要時間だけを変える | 同じ世界条件なら訪問率が変わらない |

RNG-04は単一seedの成功を証拠にしない。サンプル数、期待確率、標本割合、二項標準誤差または信頼区間を併記する。分布検査を通っても、子どもが因果を読めることは別の目視検証である。

## F. 人が遊んで確認すること

ここは自動検査・仮想ユーザーで代替しない。最初は対象年齢の少人数で形成的な観察を行い、統計的な教育効果の証明と呼ばない。

**魅力**：動作を止めずに眺める、配送や来訪に気づく、元の場所を覚えている。  
**理解**：配置を変えて結果を比べる、原因を一つに断定せず再試行する、何が変わったか指差しでも示せる。  
**成長**：人口と土地が増えた意味を感じる、別地区へ広がる理由がある。  
**学習**：新道具への期待から学習を始める場面があるか、支援や終了を自然に選べるか。  
**終了**：途中でやめても不安や損失感を煽られない。

評価のためにノートや口頭説明を必須にしない。観察者が必要以上に「次は水路を置いて」と誘導した場面は、自発的な試行と分ける。

## G. 判断と見直し

重大なデータ欠落・二重付与・住人の消失・再現性破綻は0件が公開前条件。体験の合否は別に判断する。

子どもが家具を一度並べるだけなら、相互作用の見え方と結果の差を見直す。訪問抽選だけ待つなら、確率以外の基本動作が弱い。学習を障害としか捉えないなら、解放の価値と練習の負担を分けて検証する。解決策を「必要問題数を増やす」に固定しない。
