# 05. 操作・見せ方・発見

## 1. 画面の骨格

既存のキャラクター美術と世界表現を再利用候補とし、全面的な新アートはこの実装の必須にしない。仮アートで確認した操作感を、最終的な視認性の合格と混同しない。

主画面は世界。下部に「せかい」「どうぐ」「れんしゅう」の3入口を置く。補助は全景、住人を探す、一時停止／2倍速、取り消し。記録は目立たないサブ入口でよく、閲覧必須にしない。

スマホ390×844相当とタブレット768×1024相当を確認する。タップ領域は原則44 CSS px以上を試作基準とし、読みやすさを実機で確認する。操作部品と地形のドラッグを混同しない。色だけ・音だけの情報を作らない。

## 2. 主要操作

| 操作 | 基本の手順 | 成功が分かる表示 | 困った場合 |
|---|---|---|---|
| 置く | どうぐ→選ぶ→場所を触る→確定 | 占有範囲と入口、配置のプレビュー | 重なり・範囲外を形と短文で表示 |
| 移す | 物を触る→動かす→確定 | 同じ物が選択状態で移動 | 在庫・住人・予約を保護して変更 |
| 道・水路 | 始点→なぞる→確定 | 全経路と接続状態 | 部分だけ黙って施工せず、無効箇所を提示 |
| 住人を見る | 個体を触る | 名前、今していること、行き先 | 地図から家・本人へ戻れる |
| 全景 | 全景ボタン／縮小 | 地区と道が連続して見える | 初期の家へ戻るボタン |
| 学習 | れんしゅう→開始 | 世界停止と学習画面 | 途中終了、入力保持、再開 |

配置ブラシは同じセルに何度重なっても一回の変更。画面外へ指が抜けても勝手に大量配置しない。パン、ズーム、選択、配置は入力状態機械で分ける。

## 3. 子どもが因果を追える表示

結果だけでなく途中を見せる。畑のかごに実際の食料が入り、住人が持ち、道を通り、拠点へ降ろし、その後に食卓が変わる。新入居はこの供給の上に起こる。

通常画面に全数値は出さない。触った物には「水がとどいている」「ここから運んでいる」「道がつながっていない」など、現在の確定状態を表示する。複数要因で変わる訪問について「この花のおかげで来た」と断定しない。

比較を助ける任意の表示は「しめり」「日かげ」「人の通り道」。一度に一種類だけ重ね、閉じれば普通の景色に戻る。記録や研究モードを開かなければ違いが分からない設計にしない。

## 4. 発見記録は補助

書かせるノート、問いへの回答、仮説の入力、正解の確認は必須にしない。S1の記録は短い自動アルバムで十分。

記録するのは、実際に起きた新入居、地区接続、初回の新道具利用、初めて見た訪問の見た目など。通常の毎収穫は通知しない。直近50件を上限とし、初期の姿と地区・入居の重要な節目は別の記録として保つ。フルの統計ログとは分離する。

表示例：「北の花ばたけに、小さな虫が来た」「新しい道を通って、食べ物が届いた」。前者は訪問時の場所を示す観察、後者は実際の配送経路を追えた場合のみ表示する。

表示しない例：「花が原因だと分かった」「3回再現したので法則を習得した」「条件を全部解明した」。自動でユーザーの理解を認定しない。

## 5. 出来事を見逃しても損をしない

重要な出来事が画面外で起きても、勝手にカメラを奪わない。小さな通知から任意に見に行ける。入力中、学習中、設定中に割り込まない。入居候補や解放権利を数秒で消さない。

短い訪問を画面外で見逃しても、能力・土地・報酬を失わない。記録には出来事を残せるが、「実際には見ていないのに見た」と学習成果へ換算しない。演出の再生を後から行う場合は「さっきのようす」と明示する。

## 6. 最初の体験の台本ではなく、初期条件

初期の3人、畑、共同食の拠点、水辺、木、花、道を配置し、畑は成長途中から始める。最初から道があり、何も学習しなくても輸送を見ることができる。

次に触りやすい物はベンチと、少し遠回りした道。どちらも動かせるが、必須ミッションは出さない。川の向こうと北の土地は薄く見えている。学習で使える道具の案内は常時点滅させない。

最初の30秒は歩行・土・植物の変化、数分では収穫と配送、しばらく遊ぶと配置変更・供給の差、継続すると新住人・新地区を見られることを目標にする。ただし、訪問抽選の時刻を台本で固定して達成した扱いにしない。

## 7. 終わりやすさ

学習・世界どちらからでも中断できる。作品保存の状態を見せ、保存できていなければ静かに明示する。終了時に「今やめると損」「あと少しで必ず来る」「住人が待っている」を出さない。

動きを減らす設定ではカメラ移動・跳ね・通知演出を弱めるが、世界の状態や抽選を変えない。音なしでも配送完了、道の不通、解放、入居が分かる。
