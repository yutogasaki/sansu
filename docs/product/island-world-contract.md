## 一つのデータを使う範囲

編集可能な3Dと本体は `WorldDefinition` を共有する。地区の形、置ける地点、床の三角形、通れる接続、水面、接続口をこの定義に持つ。全体のboundsはカメラと検索の範囲に使い、所有判定には使わない。床が描かれていても、配置地点として取得していなければ置けない。

| 要素 | 契約 |
|---|---|
| 地区 | 安定ID、形の原本ID、局所論理座標、固定の世界原点、90度単位の向き。追加地区の取得で既存地区の原点や形を変えない |
| 床 | 地区ごとの安定ID、ground/deck/waterの区別、論理座標と実3D位置を持つ頂点、三角形のindex。waterは足場にしない |
| 配置地点 | 安定ID、地区内の整数セル、取得可否、原本床上の固定anchorと現在の支持床を分ける。水域になっても取得権と所有IDを消さない。新しい配置には現在の乾いた支持床が必要 |
| 水庭の造成範囲 | DEVの美術地区が明示する、原本groundのfloorIdsと地区内の論理envelope。配置点の集合とは別で、指定床と範囲が実際に重なる部分だけを造成できる。配置・取得・通行・通水の権利を追加しない |
| 歩行点 | 狭い岸や坂では配置地点より細かな、安定IDを持つ床上の点を使う。配置権は持たない。歩行点の間も実際の足の帯を支える床が必要 |
| 接続 | 地点ID間の明示した辺。歩行・場所の結合・通水の可否を別々に持つ。同じ整数座標で隣り合っていても辺がなければ接続しない |
| 地区の接続口 | 安定IDと地点ID。別地区の接続は取得後の明示した辺に限る。海を越える辺には実際のdeck床が必要 |
| 世界座標とhit | 実際の三角形上で往復する。水域、未取得地点、床外を近い所有セルへ丸めて配置可能にしない |

頂点・地点・辺のIDは同じ定義内で重複しない。未知の床、未定義の接続先、壊れたindex、有限でない位置、床のない地点を受け入れない。世界定義の読込は所有・時計・学習を進めない。

## 既存島の互換地区

現行の取得済み矩形を、全セルを保持する一つの互換地区へ読むアダプターを用意する。これは読込時の派生データであり、本人recordを書き換えない。初期6×5、東西南・岬・繰り返し拡張、橋の足場を保持する。旧セル、所有ID、成熟、屋根色、style、時計、住人、学習履歴はそのまま使う。

linearとcurved-owned-v1の既存表示を区別し、その表示で使っている実床の三角形を共通定義へ写す。既存の土地をnative05の岸へ押し込んだり、水へ変えたりしない。採用美術から作る新しい地区は別の定義として制作する。

## 制作と保存の境界

M0では定義の評価、実床の描画、hitと補間、明示グラフの経路、旧土地保持を実装する。M1では採用native05の床を原本から読み、一つの全島をこの契約で描き、同じ地点と接続から所有物・配置・歩行を動かす。模型だけでM1完了にしない。

世界定義は本人の所有記録と分ける。頂点配列やmeshをGrowing保存4へ追加しない。M1の制作中の島は明示した診断入力で扱い、通常の本人保存へ取り込まない。永続化する地区の取得と選択は、M4の形・接続・価格を仕様52へ確定し、M5の新writer/復旧境界を仕様13へ確定してから切り替える。

歩行用に美術の地形を家の整数マスへ膨らませない。配置できない細い岸は、実床のある歩行点と明示した歩行辺で結ぶ。結合・通水の辺は配置地点どうしの規則として分け、細かな歩行点を理由に材料の結合距離や通水8セルを増やさない。歩行点上へ家を置くことも認めない。

## M0の通過条件

- 旧取得セルの集合、配置可否、位置、床高、橋の足場を保持する。
- 同じ世界定義の点を実3D床へ置き、rayによるhitから元の地点を得る。床高は実三角形と一致する。
- 入り江の欠けた地点と水域は所有判定で落ちる。bounds内であることを理由に補わない。
- 辺を外すと歩行・結合・通水を個別に止める。見えている床だけで隣の地区へ到達可能にしない。
- 地区追加で元の地点と実床の位置を動かさず、定義の入力を変更しない。

技術上のM0通過を美術の合格へ読み替えない。全島・近景の比較、配置差、成長と編集、拡張、実保存と更新、独立理解/実機の未実施条件は別に残す。

## M1の実装境界

共通世界は純粋計算へ明示して渡す。所有状態にmeshや関数を追加せず、全域の一時変数から世界を切り替えない。省略した場合は旧土地の規則を維持する。制作中の全島は本体の `GrowingWorld` と同じ配置command・場所計算・住人の経路を使い、本人のIndexedDBへ保存しない。

配置は整数の取得地点だけを認める。歩行は細かな地点と実際の接続を使い、家・木・家具の支持部分と住人の足幅を避ける。閉じた所有地点の利用には、同じグラフ上の実際の入口を使う。細分した辺の本数を結合・通水・利用距離として数えず、論理座標上の距離で現行のセル数を保つ。細かな歩行点を配置権へ読み替えない。

原本の岸と支持側面は共通床と同じ変換で描く。入り江を矩形や外周の近似で埋めない。原本の家・住人・泉を固定背景へ置かず、所有物の形は所有IDと成熟から描く。制作中のUIは診断であることを明示し、取得・学習・保存の実績として扱わない。

元の[編集できる全島診断](../design/2026-10-11-authored-island-runtime/README.md)はgroundを共有する。[水底の基盤](../design/2026-10-11-authored-water-world/README.md)に続き、[水庭b6](../design/2026-10-11-authored-water-garden/README.md)では原本由来の非対称の輪郭・厚い岸・鉱石洞と木橋を、固定anchorと同じ世界へ構成した。実deck、乾いた両岸、全足幅の支持を確認し、27所有物へ接近できる。73取得権と原本GLBは保持する。原位置の三段構図と同一とは扱わず、全島の美術・大樹の回廊・森の面は未完。[床照会と道の改善](../design/2026-10-11-authored-world-performance/README.md)と岸検索の出力一致による軽量化は、水・支持の境界を緩めない。browser previewの12〜13秒の待ちを保持し、M1を完了しない。

## M1の水と支持の組立て契約

以下はDEVの美術地区に限る制作契約であり、本人の旧土地を水へ変更する移行ではない。

- 地区は任意の `anchorFloors` を持てる。これは取得地点を証明する原本床で、描画・足場・hit・boundsへ入れない。active `floors` と原本床は別のID空間。`anchorPoint` がある地点の `floorId` は原本床を参照し、その論理セルで補間した点と一致しなければ読込を拒否する。有限な点を任意に足すだけでは取得権を作れない。anchorなしの既存定義は今までどおり実床を必須にする。
- compiled siteの `point` は固定anchor、`support` は現在の乾いたground/deck上の点または未支持。`owns` と取得地点一覧は権利を示す。`walkSites` とwalk辺は現在の支持を示す。水へなった取得地点は保持するが、新配置と歩行には使わない。deckが水面より上に実在するときだけ再び支持できる。新配置は原本の配置検査と同じ半幅0.46の支持点と高差0.28以下を確認し、中心が乾いていても占有footprintへ内部の水が入れば拒否する。水上のdeckはその交差部分を実際に支持するときだけ認める。
- `anchorAt` は固定位置、`sampleFloorAt(cell, floorId)` は指定したactive ground/deck/waterそのものを照会する。通常の `floorAt` / `logicalAt` / `siteAt` は水面下の地面を足場にせず、近い権利へhitを吸着させない。原本の外海と高さの分類は固定原本を読み、内部の池を海岸として扱わない。
- 垂直の岸や流れは地区の `surfaces` に持つ。kindはbank/flow、実3D頂点・index・色・roughness/metalness/opacityを検証して変換し、歩行・配置・hitから除外する。これは底やdeckの代わりにならない。
- 世界の安定IDと原本SHAは保持し、派生した幾何の `revision` を別に持つ。描画cacheはrevisionを含める。所有recordへrevisionやmeshを保存しない。

組立ては「不変な原本＋現在の所有セル/材料/成熟/明示した通水辺 → 水の形の計画 → 切った地面・水底・水面・岸・流れ・必要な実deck → 現在の入口/道/場所」の順で一度行う。最終のgrown判定を水の有無へ戻して循環させない。原本で通れたwalk辺でも足幅の帯が切れたら除外する。compilerは壊れた明示walk辺を引き続き拒否する。join/waterの権利・8セルの範囲は増やさない。

三つの水ばちを採用原本の三段の中心へ無条件に移して描かない。現行の丘の取得地点では、原位置の下段に通水接続がない。各所有anchorを保ち、現在の配置に合わせて輪郭と岸を設計する。形を広げる場合も取得地区・場所の範囲・別の所有物・玄関と実道を確認する。原位置の三段と同一とは認定せず、全景比較で美術を再評価する。

移動・収納・分離は毎回原本から組み直し、失った材料の水底/流れを残さない。予告用のfuture worldは確定したworldと分け、取消で原本/確定世界を変更しない。確定後は描画・hit・配置・住人・場所が同じrevisionを読む。水で未支持となるownerの利用入口は、現在の岸/deck上の接近点から選ぶ。

通過条件は、取得権保持、水への新配置/歩行拒否、deck支持のみの渡り、異なる三水面と接続、所有物の接近、収納/分離の復元、予告取消/確定の一致。技術通過だけで美術の完成やM1完了にしない。

## M1の水庭美術を作る境界

採用native05の水庭の輪郭・岸の断面・鉱石の形と材質を制作の原本にする。水ばちの固定anchorを中心に、通水する方向の幅と横へ広がる幅を別々に適応させ、元の位置を保ちながら一つの水庭を構成する。輪郭の境界だけでなく内部も、取得地区・別の所有物の支持・玄関と乾いた接近路に交差しないことを確認する。原本から対応を説明できない半径の変更や、固定背景として泉全体を重ねる方式にはしない。

家を置くための0.46支持/高差検査から抽出した配置地点を、地形の造成範囲へ代用しない。明示した造成scopeには、地区・原本床のID・論理envelopeを持たせる。範囲内に原本の実groundがある部分だけ切り、海・別地区・未指定床へ広げない。未指定の地区は従来の配置地点近傍に限る。今回の全島診断は丘の範囲だけを明示し、73配置権・固定anchor・明示したjoin/water辺を保つ。新しい土地購入の範囲や規則には流用しない。

広い池の利用入口は、実輪郭の外側で足幅が支持される既存walk地点を同じworldへ対応させる。固定の中心距離だけで岸を推定せず、現在の水・床・高さと同じgraphで到達を確認する。この入口対応から配置権や新しいwalk辺を作らない。

水庭の造成で原本の通路を切る場合は、水路と岸を実際に渡すdeck床と接地した橋を同じworldへ構成する。橋は現在の材料・成熟・通水接続から派生し、別の所有物・土地・報酬として数えない。両端の乾いた岸、全足幅、床高の連続と橋の支持を検査し、原本にあるwalk辺のうち現在の実床が支持するものだけを使う。支持のない辺を復活させたり、水面下の底を通路にしたりしない。固定anchor・配置権・join/water辺を保ち、水ばちの中心・玄関・鉱石の基部に橋を重ねない。分離・収納では不要な橋も消え、予告と確定は同じ橋の計算を読む。

岸は実際の水底と地面を結ぶ断面として同じworldのsurfaceへ持つ。鉱石/岩の基部は実水底へ置き、足場や配置権を追加しない水域の内側に収める。元の所有物の派生形として扱い、新しい所有物や利用実績を増やさない。水面の色・反射と波紋も同じ実水面へ描く。原本の全三段の構図と同一かは、採用原本と全景/近景を比べて別に評価する。

若い姿と成熟の文法、実共有deck・森林・三配置・拡張は引き続き制作する。この輪郭/岸の制作をM1や全島美術の完了へ読み替えない。本人保存・通常土地購入・学習・時計・配布の境界は変更しない。
