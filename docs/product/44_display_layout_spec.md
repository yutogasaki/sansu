# 目的別の画面レイアウト

2026-09-09、ユーザーが[12アプリとKeepGoingの比較提案](../design/research/2026-09-09-layout-strategy/strategy.md)を実装するよう指示。親仕様01、UI仕様07、[ナビ仕様43](43_island_navigation_spec.md)の下で、画面ごとの面積と操作配置を定める。

## 主役と共通部分

共通にするのは生成りの面、濃い藍の文字、青い主操作、読みやすい文字と44px以上の操作領域。全画面に同じ島・大きいヘッダー・カード列を置かない。3Dの物・住民identity・素材・採点の意味色は維持する。画面を広げた結果ではなく、住民、問題、選ぶ品の実際の見やすさを検証する。

| 画面の役割 | 配置 |
| --- | --- |
| 島・暮らし | ヘッダーと下部ナビ以外を世界へ渡す。育成状況は一つの短い帯。島のメニューと眺め操作は明示的な入口から開く |
| 学習 | タブを閉じ、問題と答えを近づける。3択は内容の大きさでまとめ、数値・筆算は必要な作業領域と固定入力を保つ |
| 持ち物・選択 | 一覧の前に大きな島を繰り返さない。品・名前・状態を主役にし、戻る操作に縮まない幅を確保する |
| 配置・編集 | 実景と道具。スマホは上下、十分に広い画面は左右。取消と確定の入口を見つけやすい上端へ置く |
| 思い出 | 作品や比較実景を先に見せ、分類・地区・時点を簡潔な操作にまとめる。写真一枚表示の集中状態を維持 |
| 設定・記録 | 無地の明るい読書面とまとまった項目。設定は広い画面でカテゴリと詳細を併置。全データリセットは保護者詳細のデータ管理へ |

## 島の入口と面積

通常ナビは「しま／いえ／まなぶ／きろく／設定」の位置を維持し、高さ約60px＋safe area、44px以上のタップ領域と文字を保つ。開始操作と現在地の選択状態を同じ強い塗りで二重表示しない。

ホームの任意機能は「しまのメニュー」を開いて一覧する。「あそぶ」「ととのえる」「おもいで」にまとめ、旧おくりもの・未解放条件・家・アルバム・ほかの遊びを含む全既存入口を残す。メニューは表示中の島とは別の操作面にし、閉じる手段とフォーカス復帰を備える。学習中は操作できない。メニュー内からの通常機能選択後はメニューを閉じる。

カメラの回転・拡縮・リセットは「ながめ」から開く。眺めを変えた時は、島の左下にも44px以上の文字付き「もとの ながめ」を表示し、メニューを開かず戻せる。ジェスチャーを唯一の操作方法にしない。世界の実際の表示範囲にカメラを合わせ、固定の過剰な高さで主要入口を画面外へ押し出さない。縦長phoneの通常ホームでは、庭のbase fitを1.3倍の近景にする。これは手動ズームとして扱わず、住民の共同動作に合わせた自動画角を維持する。「しまぜんぶ」は従来の全景へ戻る。横画面・比較・写真・学習・家・配置の専用構図と、3D形状・保存契約は維持する。

小型画面では最小限の現在地・育成状況・入口を残し、追加の説明・目標・複数機能をメニューへ収める。広い画面では道具を横へ展開する。端末回転は画面遷移・保存・下書き破棄を発生させない。

## 学習と退出

スマホ・iPadの縦横とも、全テンキーを常時表示した残りの問題枠の実際の幅・高さに合わせ、問題文と教材図を一緒に最大2倍まで拡大する。元の読みやすい寸法より縮小せず、長文は既存の内部スクロールを維持する。回転・ヒント表示で枠が変われば再計算し、右の入力・選択肢の位置は保つ。

学習の表情は[デザイン憲章](design-charter.md)の操作面の原則に従う。外周には共通の大きく静止した水玉を見せ、生成りの解答面を広く残す。進行帯は淡いラベンダー、入力の台座は共通の青系でまとめ、背景・問題・操作の階層をつくる。問題文・教材図形・数字キーには模様を入れない。ヒントは文字とアイコンで見つけやすくし、既存の進行・正誤表示に新しいカウントや常時演出を足さない。短い画面では装飾より全入力と支援の到達性を優先する。

学習台には680pxの高さ上限を設けず、ヘッダーと外周余白以外の高さを使う。数値問題は短い式でも残りの問題領域を使い、iPadでは幅も広げる。短い画面では利用可能な高さに縮み、問題・お手本の内部スクロールと固定入力を維持する。短い式は無地の淡い面に大きく示し、解答欄・テンキーへ視線が続くまとまりをつくる。台座の外縁だけに縫い目と柔らかな陰影を使い、キーは模様のない明るい押し面にする。台座を押す演出や新しい待ち時間は追加しない。

進行帯は台座に縫い付けたタグとして整え、採用済みのアプリアイコンを小さなワッペンとして左端に添える。装飾に新しい操作や読み上げを持たせない。文章題は空白・文の区切りを折り返し候補とし、数字と単位（例:「7 じかん」「420 km」）をひとまとまりで読む。画面より長い語句は横溢れを避ける。表示だけを整え、保存された問題文・分数表示・正答を変更しない。

「しま」やトップを開いても自動学習を始めない。中央「まなぶ」は現在の問題・下書きを開き、閉じると開始元へ戻る。通常タブ選択で先頭へ戻すことと、集中状態からの復帰は別操作とする。予約・SRS・採点・支援・0追加操作の連問・PWA保護は変更しない。

問題の入力種類を表示のために区別する。選択問題の大きい上下の空白を縮め、横画面の3択は1段にしてヒントと問題の領域を確保する。テンキー789/456/123/0、入力契約に応じた削除・確定、ヒント・わからないは画面内に確保。長い問題だけを内部スクロールできる。

背景で発見を保存している間も、島・記録・アルバムの閲覧を止めない。新しい学習の開始だけは保存完了を待つ。履歴やURLから学習へ入った場合も、保存中に開始処理を失わず、完了後に同じ予約を開く。

配置の取消は選択元、保存成功は島、失敗は再試行できる編集中の状態を維持する。他の編集の試用・所有・装備・保存結果をこの仕様で統合しない。試用/確定の状態がある既存機能をレイアウト目的で自動確定しない。

## 記録と設定

記録の概要とカレンダーは常設する。詳細を開く操作は、成長・苦手・復習・進み具合・テスト履歴・保護者向け情報の既存内容を表示し、同じ場所で閉じられるようにする。UIのない旧セクション表示設定が詳細を空にすることを解消する。記録データそのものや既存の保存済み設定キーを削除しない。

0回答ではゼロの数値の繰り返しより、ここに残る記録と学習の入口を伝える。学習済みの内容・既存の復習/テスト経路は保持する。設定カテゴリのURLとフォームの保存を維持し、広い画面のカテゴリ/詳細化によるフォーム二重マウントを起こさない。

## 検証

390×844、768×1024、1024×640/768で初期の島・学習・一覧・編集・設定・記録を確認。短い360×640も入口と退出の到達性を確認する。成熟した島の絵と操作が隠れないことは別状態として確認する。

全入口とその戻り先、下書き、配置取消/保存、写真閲覧、文字の折り返し、音off、reduced motion、実PWA更新/オフラインを検証する。docs/lint/typecheck/unit/buildとナビ・学習・PWAの該当既存ハーネスを実行し、変更に適応したQAと以前の版の証拠を区別する。

実画面の魅力、説明なしの理解・安全、runtime整合を独立に報告する。子どもの独立観察がない場合は未評価を明記し、CSSの面積比率や自動テストの合格だけで最高品質と認定しない。
