# 家の学習チャレンジ

2026-09-09、家を入口とする任意の学習チャレンジと時間制限種目の具体化をユーザーが指示。本書は初版の実装契約。初版を実装した。検証の範囲と未充足は末尾に記録し、公開承認を意味しない。親仕様は[01](01_app_spec.md)、展示は[42](42_island_learning_keepsakes_spec.md)、戻り先は[43](43_island_navigation_spec.md)。

## 目的と初版の範囲

家で次の記念を見る→自分で挑む→結果を知る→家に飾る→もう一度挑む。中央の「まなぶ」は従来どおり一操作で通常学習を開始・再開し、選択画面を挟まない。

初版は算数「10までの たしざん・1ぷん」1種目。種目IDは `addition-within-10-60s`、ルール版は1。時間なし10問、九九、英語、配達・釣りは後続とし、未実装ボタンを並べない。以前の会話の「10問中8問」には効力を持たせない。後続種目は別の出題・採点契約を定義してから追加する。

## 家から開始する

- 家のoverviewにトロフィーの絵、種目名、自己ベスト（未挑戦時は「はじめての ちょうせん」）、獲得条件と「ちょうせん」を直接表示する。棚や一覧を先に開かせない。
- 開始前の説明は「1ぷんで なんもん できるかな」「1ぷん おえると きねんが もらえるよ」。背景化で記録対象外になることは詳細に記載し、通常開始に確認ダイアログを追加しない。
- 開始ボタンで資格確認・問題準備・挑戦予約の保存を終え、3・2・1の後に入力可能な第1問を表示して計時する。準備失敗時は家に留まり再試行できる。問題・答えはカウントダウン中に見せない。
- 保護者の算数範囲に `add_1d_1` が含まれ、現行の解放条件を満たし、同スキルが当日停止でなく、通常学習で同スキルの初回独力正解を少なくとも1件確認できる本人が対象。確認できない旧記録から資格を推定しない。未対象は「たしざんを れんしゅうすると ちょうせんできるよ」と通常の「まなぶ」を案内する。新しいレベル制限は作らない。
- チャレンジ中は下部タブを隠す。「とじる」・ブラウザ戻るは中断して家の元の位置へ戻る。結果画面の「もういちど」は準備から新しい挑戦を開始する。「いえへ」で家に戻る。通常学習の問題・入力下書き・予約は変更しない。

## 出題と公平さ

- 整数 `1 <= a <= 9`、`1 <= b <= 9`、`a+b <= 10` の式 `a + b =`。0、繰り上がり、文章題、絵の補助、筆算を含めない。数字キーと物理キーボードを同じ採点経路へ接続する。
- 正解は整数の和と一致する入力。空入力は送信不可。整数として正規化した先頭0は許容し、小数・負数は受け付けない。自動桁数確定を使わず「こたえる」/Enterで確定する。
- 通常generatorの進度依存抽選はそのまま流用しない。共通の問題形式・採点を再利用し、上記の全45個の順序付き組を専用sourceで生成する。
- 10問を1ブロックとし、和2〜5から3問、6〜8から4問、9〜10から3問を抽選して混ぜる。各層をseed付きshuffle bagで使い切ってから再利用する。直前と同じ組または左右反転の組は候補交換で避ける。これ以外の適応的な難易度変更はしない。
- 開始時にseed・source版・問題snapshotを確定する。先頭300問を準備し、枯渇時は残り時間中に同じ規則で追加する。追加が入力表示を遅らせた回は技術中断とし記録対象外にする。全問・層の比率・境界の重複をテストする。
- 別seedの部分列の難しさが完全に同一とは主張しない。順位や他者比較は設けない。自己ベストは本人×種目×ルール版×入力形式で比較し、出題や採点・計時規則変更時は版を上げる。端末間の入力速度差は能力差と扱わない。

## 採点と時間

- 状態は `preparing → countdown → running → finalizing → result`。中断は `interrupted`。1問につき最初の確定回答だけを採点し、正解は+1、誤答は0。減点、残り時間の減少、連続正解倍率はない。
- 誤答はその場で入力欄の近くに正しい式を短く表示し、正解・誤答とも300msで次問へ移る。その間の入力は受け付けず、次問へ持ち越さない。タイマーは動く。演出を追加してこの間隔を伸ばさない。reduced motionでも同じ間隔で静止表示する。
- 「わからない」も0点で正しい式を300ms表示して次へ進む。誤答とスキップは別集計。ヒントや訂正による追加得点は設けない。解き方を確認したい場合は挑戦を閉じて通常学習へ戻れる。
- 第1問の表示・入力準備完了を起点に単調時計で60,000msを測る。setIntervalの呼出回数や端末の日付変更で時間を決めない。残り表示は秒単位の切上げと静かなバー。最後の秒の赤点滅、警報音は使わない。
- 入力handler冒頭の採時が開始から60,000ms未満なら採点対象、60,000ms以上なら対象外。期限前に受理した回答は採点・保存が期限を越えても含む。入力連打には問題IDと受付済みフラグを使い、同じ問題を二重採点しない。
- 60秒で入力を止め、結果を一度だけ確定する。期限前の最終回答を含めた正解・誤答・スキップ数を保存する。時間切れで残った未回答問題は誤答に数えない。
- 表示・通常フィードバック中も実時間を使う。毎問のDB保存を待って問題送りを遅らせず、イベントを順序付きで退避する。保存失敗や問題表示の技術的な中断は参考記録へ変更し、ベストを更新しない。演出や裏側の3D観察処理は学習を妨げないよう停止する。

## 中断と記録の有効性

- `visibilitychange(hidden)`、`pagehide`、再読み込み、明示終了、プロフィール切替、所有者/設定/保存競合、保存失敗でその回の正式記録資格を失う。以後回復しても戻さない。focus喪失だけでは中断しない。
- 背景化で即時に入力と時計を止める。復帰時は「ひとやすみしたよ」と参考結果、「もういちど」「いえへ」を出す。初版は途中再開を実装せず、残り時間を持ち越さない。これは前の会話での一時停止案を具体化した終了契約。
- reload時に未確定予約を見つけたら中断扱いにする。既に確定済みの結果は同じ結果として再表示でき、再授賞や再加算をしない。履歴の進む操作や直リンクではタイマーを自動開始しない。
- 参考結果は「ここまで ○もん」と理由を表示し、保存できた範囲を明示する。ベスト・完走回数・賞には加算しない。完全に保存できなかった入力数を復元したと主張しない。
- 開始前/結果確定時に本人と資格を照合する。他プロフィールに結果を移さない。通常学習との同時実行、同一プロフィールの複数タブでの同時挑戦を禁止し、既存の予約は破壊しない。

## 結果と賞

| 事実 | 結果と報酬 |
|---|---|
| 初めて正式に60秒を完走（0正解も含む） | 「1ぷんに ちょうせん」の賞状を1点取得 |
| 正式記録で初めて10問以上正解 | 「10までの たしざん・1ぷん」のトロフィーを1点取得 |
| 自己ベストを超える | 「じぶんの きろくを こうしん」。既存トロフィーの詳細のベストを更新、品は増やさない |
| 同点/前回未満 | 今回の正解数とこれまでのベスト。賞の剥奪や不合格表示なし |
| 中断・参考結果 | 授賞・正式ベスト更新なし |

10問は製品の初期目標値で、習得の基準や実証済みの適切な難度ではない。対象児の試用で到達性を確認し、変更はルール版を分ける。初回10問以上なら賞状とトロフィーを1回の授賞にまとめる。自己ベスト初回登録を「更新」とは呼ばない。

獲得前は絵と条件で予告し、家に実物を置かない。授賞は保存成功後だけ、2秒以内でスキップ可能。取得と展示は分け、「いえに かざる」で無料展示し、「あとで」でも所有は残る。記録更新だけで展示を強制変更しない。

旧16品の所有・展示・名称・回数条件を保持する。初版は挑戦の賞状1点とトロフィー1点を追加し、家に追加2枠を設け計18品を同時展示可能とする。既存品を押し出さず、棚と室内の実画面で見切れを確認する。今後種目を増やす際は棚の容量を改めて設計し、無制限に縮小しない。

詳細は種目、ルール版、初回取得日、初回獲得時の正解数、現在ベストを区別する。旧版の賞を保持し、新版へベストを移さない。古い写真の画素や取得日の書換えはしない。

## 学習データへの境界

初版は挑戦専用記録。SRS、Due、weak、独力正解カウンタ、主レベル、解放、単元readiness、通常テスト履歴、completedSets、島の成長、ほし・資源を更新しない。挑戦の速さを習得に換算しない。通常の学習日数や連続日数にも加算せず、結果は家の挑戦記録に表示する。

ただし挑戦で直前に同じ概念へ触れた事実を無視し、直後の通常回答を「日を空けた確認」と認定してはいけない。表示した問題の単元と接触日時を専用記録へ残し、31/34の遅延確認の経過時間判定では通常学習と挑戦の最新接触の大きい方を使う。Due期限は延期せず、次の通常出題を妨げない。接触保存が不確実なら該当単元の遅延確認資格を保留し、成功へ推定しない。これは初版に必須の学習整合接続である。

## 保存と互換性

- 挑戦のversion付き専用保存領域を設け、IslandRecordの通常更新から分離する。挑戦ID、profileId、種目/ルール/source版、seed、予約問題、受付順イベント、状態、中断理由、結果、接触、receiptを保持する。表・index・DB版の具体変更は実装前にmigration noteへ記載し、既存storeへ場当たり的に詰め込まない。
- イベントは挑戦ID×問題番号で重複排除。結果・ベスト・完走数・獲得資格を同一transactionで確定し、結果receiptの再送は同じ結果を返す。未知結果は同IDで照会/再試行し、新しい挑戦へ置き換えて加算しない。
- 最新20回の結果詳細と参照中の未確定1回を保持する。初回賞の根拠・ベスト根拠・獲得品・累計正式完走数・単元別最新接触は別の要約として保持し、履歴整理で失わない。完了した古い予約・イベントの整理は結果確定後だけ行う。
- 展示選択は42の既存選択と新しい挑戦品の選択を区別して保持し、旧version1の16品正規化で新しい品を消さない。所有資格は保存済み結果由来で検証し、改変されたUI指定だけで付与しない。
- プロフィール削除時は専用保存領域も削除する。切替時は入力/タイマー/未保存イベントを別人へ引き継がない。データなしの旧プロフィールは挑戦未実施として受理する。
- PWAは挑戦中と保存未確定中に更新reloadを保留する。結果確定/中断保存後をcheckpointとする。通常学習の既存holdも保持する。オフラインでも準備・完走・授賞可能。旧DBへdowngradeせず、対応buildで機能入口だけを無効化できる配信flagを設け、無効化で所有品を消さない。

## 実装の順序と受入条件

1. 専用出題source・採点reducer・単調時計境界と資格判定を純粋関数で作る。
2. 保存境界・再送・プロフィール所有検査・遅延確認の接触参照・migrationを接続する。
3. 家overviewの入口、入力、結果、再挑戦、授賞と既存の展示をつなぐ。
4. flag付き固定buildで以下を検証してから公開対象にする。コードの合格だけで体験を合格にしない。

| 検証 | 必須ケース |
|---|---|
| 出題/資格 | 全45組、10問ごとの3/4/3構成、bag再利用、同組/反転の連続なし、固定seed再現、設定/解放/当日停止/未知ログ |
| 採点/時計 | 59,999ms採用・60,000ms不採用、期限前受理後の遅延保存、連打、空/先頭0、誤答/スキップ0点、フィードバック中の入力無視、端末時刻変更 |
| 中断 | countdown中の退出、背景化、reload、進む/戻る、表示障害、保存失敗、同時タブ、プロフィール切替後に別人へ加算なし |
| 保存/賞 | 0/9/10/11正解、初回の2賞、同点、ベスト更新、同一receipt再送、未知結果、旧16品保持、履歴整理、profile削除 |
| 学習整合 | 通常予約/入力保持、SRS等の非加算、挑戦直後の偽の遅延確認拒否、通常Due期限保持、接触保存不明の保留 |
| 実UI | phone 390×844、tablet 768×1024と横向き、家から一操作開始、数字キーの収容、完走→展示→再読込、もういちど、音off/reduced motion |
| 配信 | core、smoke、島の該当E2E、PWA更新/島offline、通常連問の固定10問benchmark。schema変更時は二build移行・保有データ保持を追加 |

実画面の証拠はtarget・build revision・flag・candidate ID付きで入口→挑戦→結果→家の展示のcontact sheetを残す。視覚的魅力、無説明理解/安全、runtime整合を別判定する。子どもの自発的再挑戦、制限時間への反応、10問目標の到達性は未検証と明示し、独立観察で確認する。今回の仕様更新は `npm run docs:check` と参照/矛盾の読み合わせを検証範囲とする。
