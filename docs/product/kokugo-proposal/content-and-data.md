# 国語の教材と保存契約案

[包括仕様案](README.md)の一部。ここでの型・table名は設計案。DB migration、現行enum変更、端末データの書換えを実施する指示ではない。

## 教材の最小パッケージ

| 情報 | 必須項目 |
|---|---|
| 識別 | packageId/version/hash、curriculumVersion、unitId、abilityId、targetId、itemId、passageId/version、採点器version |
| 意味 | 主評価、必須/推奨前提、条件coverage、genre、内容family、答えの露出group、語彙/文字負荷、年齢の入口目安 |
| 表示 | 正文、段落/文/語句の安定ID、問い、選択肢ID、意味に沿うページ境界、ルビ区間、読みの対象、画像/音声/alt |
| 採点 | 有限正答集合または許容範囲、別解、正答根拠、各誤答理由、採点不能の扱い、規格化の許容条件 |
| 支援 | 注目点/別例/お手本、各支援が露出するtarget/answerGroup、本文読み上げ/ルビが評価に与える影響 |
| 予約 | 順序制約、選択肢shuffle可否、先に見せる導入、同じ本文の設問組、完了可能な最小単位、再利用の方針 |
| 出所 | 作者/出典、権利状態、音声/画像/字体の利用条件、校閲者とrevision、停止/差替理由 |
| 供給 | 導入/練習/別教材確認/後日確認の候補集合、人の観察活動、offline assets manifest |

版を変えても同じ答えの露出群は引き継ぐ。表記修正だけで未提示の別作品として再計上しない。意味を変えた改稿では旧/新の対応と独立性を人が確認し、旧問の回答を新問へ変換しない。

一つの設問は一つの主評価を持つ。複数条件の設問は各条件を付けるが、漢字・語彙・読解を同時に習得と加算しない。教材IDの数、作品数、単元数、評価target数は別に集計する。

## 制作と校閲

状態は `draft → editorialReview → approved → packaged → suspended/retired`。作者の草案と独立した校閲を通った教材だけを出題候補にする。自動検査と人の確認を同じapprovedフラグにまとめない。

1. 原作本文と目的を作る。島だけでなく、日常・自然・科学・文化・物語を用意する。子どもの個人情報や家庭事情を答えとして要求しない。
2. 前提語・漢字・ルビを点検する。読解なのに未習漢字の解読が主な難しさになる場合は補助するか別入口へ回す。
3. 作者以外の校閲者が実際に解き、自然な日本語・別解・根拠・誤答・絵/音の識別を確認する。語順や心情は特に複数解釈を点検する。
4. 露出groupと内容familyを編集する。同じ話の言い換えを別確認にしない。機械の意味類似度のみでこの対応を確定しない。
5. 練習・確認・後日用の候補が条件coverageを満たすか、該当本人の既接触を考慮した候補供給を検査する。確認不足でも練習として出せる範囲を明記する。
6. 音声は読み、アクセント、間、助詞、同音、速度、音量、クリッピングを人が実聴する。絵は色・大きさ・構図の偏りで答えを漏らさないか確認する。
7. 生徒/保護者の許諾を得た小さな試用で指示理解・操作・別解・負担を確認する。試用がない段階は技術検証だけの状態として扱う。

生成AIは草案や別解探しの補助に使えても、その出力を無校閲で本番出題/採点しない。くもん本文・既存文学作品・第三者の挿絵を当然に取り込まない。原作または個別の利用条件を確認した素材だけを配布する。

### 採点器の規則

- 選択/構成はchoiceIdやtokenIdの意味を判定する。画面上の正解位置を判定の正本にしない。複数の自然な語順が成立するなら全正答か部分順序の制約を持つ。
- 抜き出しは固定本文のspan ID/境界で判定。本文の一部が正解という形式では、句読点を含むか/除くかを問題ごとに宣言する。
- 短答は原文を保持し、Unicode表記の規格化/外側空白などを採点器版ごとに定義する。拗音・促音・送り仮名・漢字かなの相互置換を勝手に同値化しない。字形/表記そのものが対象なら該当変換はしない。
- 「雨だから」などの意味短答は正答リストだけでは全誤答を判定できない。初期は範囲選択/構成で閉じた解答空間にするか、リスト外をunscorableとする。単語が含まれるだけの作文採点はしない。
- 心情問題は本文から根拠を説明できる範囲に限定。自由な感想・価値観・本人の気持ちを正誤にしない。
- 内容/採点の誤りが判明した教材は新規予約を止め、未完は保留できる。過去の事実は消さず `contentInvalidated` 注記を加え、将来の推薦の根拠から除外する。教材不備を本人の誤答や降格として再集計しない。過去の島報酬は回収しない。

## 保存の責務

既存の学習DBへ加算する専用store群を候補とする。採用時に実schema番号、index、旧writerの挙動、transaction範囲をコードと照合して決める。DB全体の置換や自動合算はしない。

| 保存候補 | 主キー・責務 |
|---|---|
| kokugoCourses | profileId。選択入口、範囲、activePlanId、pending変更。申告と証拠を分離 |
| kokugoOwners | profileId。active/deleting、writer互換世代、owner revision |
| kokugoPlans | planId。本人、教材/採点版snapshot、slots、本文/設問順、choice順、status、revision |
| kokugoDrafts | profileId/assignmentId。入力、IME確定済みの下書き、本文位置、view、draft revision。競合入力の退避を含む |
| kokugoEvents | eventId。提示/接触/初答/訂正/支援/完了/延期/読書/活動/人の観察。append-onlyの事実 |
| kokugoContacts | profileId/接触対象。最新revision/日時、露出group、presentationId、欠測状態。eventsから追跡可能 |
| kokugoProgress | profileId/評価キー。確認履歴、coverage、期限、最近の困難、保留理由、集計version |
| kokugoWorks | profileId/workId。自由表現の下書き/見直し版、自己終了、人の観察。初期に録音/画像は保存しない |
| kokugoOutbox | profileId/completionId。source version、元の完了日時、報酬配送とack状態 |

### 予約と状態

`reserved → active → suspended → active → completed`。途中のslotをskippedで終えることはできるが、予約全体を全正解にしない。素材/版が利用不能なら `blockedContent` と理由を保持する。終了済みへの再送は元receiptを返す。

slotはassignmentId、対象版、回答revision、presentation snapshot、draft、初答、支援、読上げ/ルビ履歴、結果、completionIdを持つ。新しい予約は同じ本人のactiveを原子的に切り替える。suspendedは残し、明示再開できる。一つの答えを別assignmentへ転記しない。

下書きは入力確定後の変更を短いdebounce（候補300ms）で保存し、退出/本人切替/明示保存ではflushする。保存中/失敗/保存済みを区別し、OS強制終了直前の未保存入力まで保証しない。IME変換中の文字を提出済み回答へ変換しない。保存済みrevisionを表示/再開の基準にする。

### 書込みと競合の不変条件

1. 予約保存後にだけ問題を表示する。予約だけでは接触を記録しない。実提示は接触書込みを伴い、観測/保存が不確実なら確認資格を保留する。
2. 回答はowner/profile/plan/assignment/教材版/revisionを照合する。初答原文・正誤/採点不能・支援/音声・接触再照合・進捗・完了・outboxを必要な同一学習DB transactionで確定する。画面の表示だけで完了扱いにしない。
3. 同一answer operation IDとcompletion IDは再送しても一度。複数タブはIDBのrevision比較で古い更新を拒否する。BroadcastChannelだけで正しさを保証しない。
4. 初答と訂正を別eventにする。支援表示を実際に保存する前に答えを見せた場合は欠測として資格を落とし、支援なしと偽らない。
5. 本人切替は元本人の保存を終えてから行う。非同期処理にはownerとpresentation tokenを持たせ、古い音声/採点完了を新本人へ適用しない。
6. 別DBの島への報酬はoutboxで少なくとも一度配送し、receiverで本人+completionIdを重複排除する。初回受信時の島への帰属を固定し、永続化後にackする。途中で島を変えても再加算しない。
7. 本人の削除開始はsource/receiverの削除境界を立て、pending配送で復活させない。旧データ削除・旧writer・export/import/resetを国語追加後も検証する。

## 報酬と記録を混ぜない

[現行経済](../growing-island-balance.md)の「有効な一問完了＝2しずく＋まち2時間」を、短い自動採点課題の初期接続案でも保持する。独力完了/お手本を経た支援完了は同額で、支援を損にしない。本文ページ・ヒント・訂正回数・区間終了には加算しない。

複数欄の一設問は一完了。本文1つに校閲済み設問3つなら各設問一完了であり、後から報酬のため設問を分割しない。スキップ、おためし、導入、読書、素材失敗、未解決の採点不能は有効完了を作らない。採点不能からお手本を経て支援完了した場合は、その新しい完了だけを一度配送できる。

自由表現/音読/紙の書字は初期は活動記録として扱い、学習正解数・独力coverage・通貨へ自動算入しない。読書も無報酬の任意活動とする。これらが短問より不利になる恐れ、長文の実時間当たり報酬の偏りは未解決の経済論点。長文・表現を本体へ配布する前に実時間/負担/選択を測り、同じ完了基準の維持か別契約かを判断する。未決の倍率や経過時間ボーナスを実装しない。

「回答問題数」「支援完了」「活動」「読書」「確認済み能力」を別集計にする。読書のページ数や作文の文字数を国語の習得率へ変換しない。国語のトロフィー/賞状・既存の連続正解演出への接続は、対象形式と完了種別を定めた後に別途承認する。

## オフラインと更新

approvedな教材・音声・画像・フォント・採点器を版付きmanifestで配布し、予約作成前に必要素材の利用可能性を検査する。通常練習中のオンライン生成は不要。端末音声だけを必須刺激の唯一の供給源にせず、固定音声を優先する。

保存済み予約の旧版素材は参照が残る間保持する。安全に旧版を表示できなければ保留し、別の活動へ案内する。緊急停止した問題を旧cacheがあるだけで出し続けないよう、配布版の停止manifestとwriter互換世代を検査する。offlineで新しい停止情報を取得できない限界も受入記録に残す。

PWA更新では旧/新二つの実build、未完予約、下書き、接触資格、receipt、別タブを含めて検証する。破損回復のためにDBを削除する手順を通常案内にしない。国語を無効化するrollbackでも新しい保存を読めるbuildを用意し、旧版writerへ無条件に戻さない。

## プライバシー

初期は端末内保存。子どもの記述を公開・外部送信・クラウド同期しない。保護者が同じ端末で作品を見る場合も本人の活動記録と人の観察の出所を分ける。外部共有・録音・写真・AI添削を加えるときは、目的、同意、保存期間、削除、通信、受信先を別仕様で決める。

教材不具合の報告では、既定で個人の作文や名前を送信しない。診断は教材ID/版/失敗種別を中心にし、本人識別や回答本文が必要なら明示的な送信範囲を示す。
