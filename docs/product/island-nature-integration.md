# 今の島に、自然と町の仕組みを取り込む

採用日: 2026-09-22。ユーザーの「今のとマージしてすすめたい。違う絵でやっていて分からない」という指示に基づく統合方針。

## 結論

作るアプリは「ぽこもこと不思議な島」ひとつ。**今の島を土台に、Nature Townで試した自然・運搬・住人が増える仕組みを取り込む。** 別の町の絵や別ホームを並行して仕上げない。

これは統合の採用であり、全機能の移植完了ではない。現在の画面・保存形式を説明するときは[暮らす島](48_island_life_spec.md)、作業の現在地は[統合タスク](../tasks/active/2026-09-22-island-nature-integration.md)を参照する。

## Nature Townは、そもそも何のためだったか

「家具を置いて眺める」だけでなく、**置く場所を変えると、水や食べ物の届き方が変わり、住人が集まり、町が広がる**遊びを確かめるための試作だった。学習は基礎練習、島では配置を変えて試す楽しさを持たせる。

仕組みを壊さず試すために、別の地図画面と保存場所を作った。しかし、そのまま別の絵・別の開発目標で進めたため、今の島との関係が分からなくなった。別保存は安全対策として必要でも、別作品として育て続ける理由にはしない。

## 何を残し、何を取り込むか

| 対象 | 今あるもの | 統合の扱い |
|---|---|---|
| 絵・キャラクター・家 | 今の島の3D表現、ぽこもこ・うさぎ・カワウソ、家と室内 | **今のものを残す。** 改善版の美術も同じ島の担当へまとめる。町専用の別画風を作らない |
| 草・木・家具の素材 | 今の島の素材、光、影、奥行き | 新しい畑・水路・食卓にも引き継ぐ。平面の格子地図を通常の遊び画面へ移さない |
| 植物 | 今の島にも時間による成長と配置関係がある | 水・日陰・育ち方の計算を追加する。既存の花の成長段階や獲得済みの状態を巻き戻さない |
| 水 | 今の水鉢は住人の利用・観察対象 | 水分が土地へ届く仕組みは別の追加機能。水鉢を置いただけで水路完成とは扱わない |
| 運搬 | 今の島にも本・園芸道具の運搬がある | 同じ住人・同じ動きの上に収穫物の在庫と配送を追加する。運搬の絵だけで物流完成とは扱わない |
| 食べ物と暮らし | Nature Townに収穫・供給・共同食がある | 実際に育った物を運び、同じ島で食べる一周を移す。装飾の食卓を増やすだけにはしない |
| 住人と土地 | 両方に住人・土地の仕組みがあるが条件が違う | 供給→来訪→入居→土地拡張を段階導入。今いる住人や開いた土地は失わせない |
| 学習 | 今の通常問題・ヒント・復習・報酬 | 入力と学習記録を継続。町側の「区間ごとの解放単位」をそのまま第二の財布にしない。解放条件は移植時に対応表を作る |
| 保存 | 島用と町の試作用が別に存在する | 両方を保持する。丸ごと上書き・自動合算・過去報酬の二重付与は禁止。変換規則と復旧方法を確認するまでデータは混ぜない |

見た目の継承は「現行の島の素材・人物・家・カメラの連続性」。継承しないものは「別の町ホーム、格子地図の表示方式、町専用の人物デザイン、別の学習入口」。細かな最新候補は島の美術担当で決め、試作の合格を別候補へ流用しない。

## 作る順番と、終わったと判断する条件

| 順 | 作るもの | 終わったと判断する条件 |
|---|---|---|
| 1 | 仕様と作業の一本化 | 別作品を仕上げる指示が残らず、今の島に何を取り込むかを1枚で読める |
| 2 | 同じ島で「育つ→運ぶ→食べる」 | 現行3Dの一画に配置した物について、同じ収穫物が育ち、住人に運ばれ、食卓へ届く。配置を変えると結果も変わる |
| 3 | 学習・保存との接続 | 同じ学習へ戻れる。取得済みの物・途中の問題・住人・土地を再起動後も保持し、二重報酬が出ない |
| 4 | 住人と土地の拡張 | 供給が続くと来訪・入居・土地拡張へつながる。初期人数や上限を試作値のまま固定しない |
| 5 | 一連の画面と実機で確認 | 島→家→学習→島に別の絵が混じらない。スマホ・タブレット、音なし・動き抑制、更新・オフラインを確認し、子どもの理解は別に観察する |

2〜4を実装する際は、既存座標・時間・在庫・解放・保存の違いを解消してから接続する。[技術的な対応表](nature-town/IMPLEMENTATION_GAP.md)に根拠を残す。試作の計算をそのまま画面へ二重起動しない。

## 旧資料の扱い

- Nature Townの計算・テストは再利用する資産。削除しない。
- 独立した町の画面を磨く作業は終了し、旧S1タスクを退避する。未合格の項目を合格には変えない。
- 過去の検証結果は、その時の試作だけの証拠。統合後の島の合格・完成率には足さない。
- 旧画面は現時点で開発用の比較資料として残る。通常起動は今の島のまま。この文書の更新だけで、画面撤去・データ移行・公開まで済んだとは扱わない。
- この方針は、2026-09-16の「独立試作として進める」という開発方針に優先する。旧資料に残る独立試作の起動・保存条件は、その旧試作を再現するときだけの契約。
