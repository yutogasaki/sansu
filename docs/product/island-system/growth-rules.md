# v0.4 成長・購入統合・旧記録の詳細規則

2026-10-19。[育成仕様v0.4](growth-proposal.md)の採用規則。[ADR](../../adr/2026-10-19-island-growth-v04.md)に基づき実装する。**採用と検証/公開の合格は別。** [current-map](current-map.md)は実装前のsnapshot。

## 新規購入と旧個体

| 入口 | 新しく取得するもの | 続けて使うもの |
|---|---|---|
| 住む | home 40、初回無料の現行特例 | 全ての旧家、住人、容量、屋根、style |
| 食べる | farm 40、6まち時間、食2/実給水3 | 旧鉢30/食1、旧パン70/食3、旧市場120/食4。元価格で保持 |
| 自然 | 木20、花10、水源20、水路10 | 旧wild、所有する木/花/水。自生は下記 |
| 遊ぶ | ベンチ/ブランコ/滑り台/トランポリン/音楽等の直接選ぶ品 | 旧play/festivalの個体と動作 |
| 記念 | 購入不可。W1〜W4のふしぎ種 | 旧在庫、現物、独力習得の13kindの記念品 |

新規購入終了は **wild/play/market/festival/鉢/パンの6品**。通常の購入種は7系統から家/畑の2系統へ、ふしぎ種を合わせた種全体は3系統へ絞る。新規めじるし17種から鉢/パンを除いた15種を継続する。水源と水路のように同じ概念に複数の道具があるため、「5概念＝商品5個」ではない。

既存の種は元のkindと時計で完成できる。既存個体は移動/収納/再配置/利用できる。建築途中を取り消す場合は保存された元取得額を返し、新価格へ換算しない。完成済みを新しい畑へ変換したり返金したりしない。

継続商品の旧解放とA/B資格は和集合。終了商品は旧解放済みでも追加購入を終了する。旧解放記録は保持するが、追加購入機会は減る。旧店の姿や広場の固有体験を新しく選べないことも、**簡素化に伴う採否のトレードオフ**として扱う。所有保護と購入機会の維持を同義にしない。

店を40の畑の選択外観へしない。旧70/120の店と同じ姿で異なる容量を新設せず、店の自動生成から架空の食料も発行しない。畑の作物の環境差は既存規則を使う。向き指定、新祭りイベント、新通貨は追加しない。

## 自然の広がり

現行の[nature.ts](../../../src/domain/growingIsland/nature.ts)は成熟したwildだけを親にする。購入終了後も始点が残るように、次期では木/花の実個体を親へ追加する。

| 入力/段階 | 候補規則 |
|---|---|
| 木の親 | 配置済みsapling、成長量18以上。支払の有無で分けない |
| 花の親 | 配置済みflower、成長量6以上。購入/贈り物/交配の由来を保持 |
| wildの親 | 旧種/自生の個体、配置済み、建築完了、成長量6以上 |
| 時計 | 自然時間の12時間境界。各境界の判定開始時に親一覧を固定 |
| 試行 | 親1個につき最大1株、50%。島のseed・親ID・境界番号で再現可能 |
| 生成先 | 親の隣の実接続先。土地内の空地、湿り0.35以上。既存の玄関/ぽこもこの家/所有物/床/通行を保護 |
| 競合 | 親を安定ID順に処理し、各生成後の空地を再評価。同じセルへ二重生成しない |
| 上限 | 土地セル数×40%の切捨て。既存と同じく収納中を含むwildの総数で上限を判定 |
| 子の保存 | wild、origin=spread、paid=0、成長量0。子は同じ境界の親一覧へ追加しない |
| 子の成長 | 既存の自然成熟に従い、後の境界では親になれる |
| 換金/交配 | 子は購入花/交配花の所有IDへ昇格せず、交配用の花や食料や換金在庫を発行しない |
| 空地なし/乾燥/上限 | 生成しない。元の植物を失わず、後から罰や未払いを課さない |
| 片づけ | 自生は現行の摘む/置き換える操作で除ける。自然が土地を恒久占有しない |

木の成熟18自然時間、開花6自然時間は成長量の閾値。湿りによる既存の速度補正を使う。木が成熟してから7日で大樹、30日で神木になる年齢と混同しない。自然の追いつきは現行の1回168時間上限を保持する。

初期から咲いた花も自然の親にはなれる。一方、W3は島開始後の未成熟→成熟の保存された遷移が必要なので、初期開花からW3を発行しない。

親一覧・抽選結果・配置先・生成ID・最終処理境界を同じ保存結果へ結び、再読込/別タブ/島切替で同じ境界を再抽選しない。これは新版の保存要件であり、実装が完成したという主張ではない。

**速度は現行と同じとは呼ばない。** 親が増え、さらに自生も親になるので、試行数は増える。早いIDが空地を先取りする偏りもあり得る。上限は総数を抑えるが分布の魅力や使いやすさを保証しない。乾いた島の木1本から必ず草が広がる約束をせず、湿りと空地が必要であることを見て試せるようにする。背景の草地は所有物の増殖と区別する。

## 場所と大型の判定

成熟済みの木陰・花庭は、同じ接続領域へ若い株を追加しても未成熟へ戻さない。成熟した部分領域を現在の接続・到達から導出し、若い株は元の場所で個別に育てる。通常床の木陰に若木が混じる間は元の個体の姿と接地した根を使い、利用段階だけを保つために大きな樹冠を追加して近くの種を隠さない。通常床の大型部品は、庭全体の完全一致ではなく、対応する成熟済みの支持株群ごとに導出する。追加株で既存の支持・床・入口が失われなければ、その部品を保つ。複数の部品では支持株を重複させず、未対応の株を屋根の中心・半径・回廊へ混ぜない。支持株の収納や実通路の閉塞は再評価し、所有・成熟・履歴を保ったまま通常形へ戻す。authored worldの大型部品は既存の専用支持契約を維持し、通常床用の部分部品を無断で移植しない。

入力は現在の島/規則版、元個体ID、位置、成長量/木年齢/家段階、実土地/床/通水、入口、他物の占有、利用者の全身形状。派生場所を独立の購入物や新所有権にしない。

1. 配置済みの同系列の所有物を列挙する。収納物は現在の形から除く。
2. 辺接続、または通れる1セルの直線的な隙間で接続グラフを作る。斜めだけ/塞がれた隙間は接続しない。
3. 各成分を下表の中庭→塊→列→自由形の優先で分類する。
4. 元個体の成熟と対応する有限部品の能力表を照合する。若い部分の姿を成熟済みにしない。
5. 実支持、床、入口、全身通行、頭上、他物の非干渉を共通worldで検査する。
6. 条件に適合する部品だけを使う。未対応/不合格なら現在の成熟した通常形を使う。
7. 描画と同じ結果で実利用を計算する。移動/収納/分離時は利用者の安全な退出を先に確保して再計算する。

### 形の分類と見返り

| 形 | 分類規則 | 成長と利用 |
|---|---|---|
| 単体 | 所有物1個 | 木陰、花床、水辺。少量でも返事がある |
| 中庭 | 現行同様、主材4個以上で、到達する内側セルを四象限から囲む | 大型では追加で連続する空床2セル以上と外部入口を確認。内側へ入り集まる |
| 塊 | 主材が隣接した2×2を含む | 厚い樹冠/花のまとまり。床と頭上が通る場合だけ天蓋下へ入れる |
| 列 | 主材が全て同じxまたは同じz | 成熟木2本以上を木陰の道の試作初期値とする。花は開花した連続株で花道 |
| 自由形 | 上記以外 | 個体と周囲の通常景観をつなぐ。曲がる配置を無断で直線用部品へ押し込まない |

中庭の四象限判定は[現行places.ts](../../../src/domain/growingIsland/places.ts)の近似分類を継承する。囲いがあることだけで入口や床の成立を認定しない。「成熟木2本」「空床2セル」は**未実測の試作初期値**であり、どの寸法でも安全な建築レシピではない。

| 系列 | 少量からの通常形 | 建築的な大型が成立する追加条件 | 不成立時 |
|---|---|---|---|
| 木 | 列=地上の木陰の道、塊=厚い木陰、中庭=内側の庭 | 部品が要求する木年齢/支持/実床。大樹用部品は成熟直後でなく既存の大樹年齢を要求 | 現在の年齢に合う独立した木陰/樹冠 |
| 花 | 開花に応じた花道/花床/庭 | 成熟した茎の支持と入口/頭上が合う有限部品でアーチ/天蓋 | 通常の花床と花のまとまり |
| 水 | 実水源から8セル以内の通水と連続する岸 | 段泉は供給された実下降床、支持、乾いた歩行経路 | 平地の水庭。切断すると通水した範囲だけ |
| 家 | 既存の玄関位置と実経路から共有の庭 | 複数の玄関が同じ到達する庭へ接続し、支持と安全な共有床を持つ屋根部品 | 個々の家の周囲。元の屋根/styleは保持 |

木陰の道と、枝の上を歩く空中回廊は別の成果。中空幹/空中回廊/大型花天蓋を任意配置で必ず生成するとは約束しない。対応部品がない配置にも通常の景観と遊びはある。

### 共通の安全契約

- 支持は元所有セルまたは既に許可された支持領域。既得の土地・他物・玄関・橋の入口を侵食しない。
- 見える通路は実歩行床と入口を持つ。派生床は共通worldへ導出し、取得土地/新たな配置権/住居容量を増やさない。
- 耳/帽子を含む利用者の全身bboxに、部品能力表で測定したマージンを足して通行を検査する。マージン値未測定の部品は大型として有効化しない。
- 同じ形/床/入口の結果を配置予告・確定・足・影・水・住人が読む。見た目だけで通行可能にしない。
- 年齢/ID/所有/家段階/入居/履歴は形の分解で失わない。経路を切ると現在の供給/利用だけ再計算する。

## Wの旧枠と例外復旧

枠は島別W1〜W4、旧Lv3/5/7/9へ一対一対応。新版の節目は[育成仕様案](growth-proposal.md#ふしぎ種の四つの記念枠)を使う。旧枠の対応と新節目の達成理由は別記録。

旧snapshotと元規則版を変更せず残し、既存の所有物/在庫を移行根拠のために消費しない。在庫0を未受領の証拠にしない。旧個体だけから元の発行枠を推測しない。

| 状態 | 根拠/意味 | 許される遷移 |
|---|---|---|
| legacy-confirmed | 元規則版と一貫した最高げんきの保存契約で旧発行を確認 | 旧由来の受領済みとして終端。新条件で再付与しない |
| available | 旧未発行を確認、または新島の未受領枠 | 新条件成立でgrantedへ |
| pending | 元規則版/発行根拠が欠落または矛盾 | 追加証拠で確定状態へ、または保護者の復元でrestoredへ |
| granted | 新条件とreceiptと付与を原子的に保存済み | 終端。再処理しても追加なし |
| restored | pending枠に例外復旧を原子的に保存済み | 終端。再復元/新条件の付与なし |

保護者向け「この島の記念を復元」はpendingの対象島/枠だけに使える。一度の保存transactionで枠receipt、ふしぎ種在庫、例外復元理由、元snapshot参照を保存する。並行操作は同じ島/枠の一意性で一度に制限する。子どもへ証明や初期化を求めない。

4枠上限は**新版の付与/復旧資格**の上限。旧発行を証明できない例外では、既存現物と重複する可能性があり、現物総数4個や二重発行ゼロを保証しない。復元後に旧現物が見つかってもどちらも没収せず、由来を残す。

復元品は換金不可/他島移送不可。植えた後も由来を維持し、建築途中の取消は返金0・同じ由来の在庫へ戻す。再植えから新receipt/新在庫を発行しない。完成済みは既存の収納/再配置として扱う。元価格を持つ旧品の取消契約と混同しない。

在庫は由来別に扱える保存が必要。旧合計在庫を根拠なく復元由来とみなさず、在庫→種→完成品→収納まで一貫して保持する。保存schema/transaction/旧writer拒否/復旧版は実装検証が必要であり、文書で完了した扱いにしない。

## ここで決めたことと残る証拠

購入統合先、自生の親/抽選/上限、形の有限判定/戻り先、Wの状態と例外復旧は候補として決めた。未定の一般巨大生成器や新祭りを必要条件に残さない。

残る証拠は、自然の30日分布と競合、美術部品の能力/実寸/安全、全食施設と配置を含む経済、旧保存fixtureでの移行/並行/更新/復旧、子どもの原因理解と自発的な再訪。[仮計算](../../design/2026-10-19-island-system-spec/pace-analysis.md)だけでこれらを合格にしない。

共有庭（P04）は育った家2軒以上が同じ到達経路につながると成立する。庭の実床・空き床から1点を決定的に選び、既存のぽこもこ/住人がそこまで歩き700ms以上滞在した描画だけを実利用とする。新しい住人・床・屋根を生成せず、移動/収納で庭が変わったら旧行動を中止する。過去の利用履歴は保持する。

保存はrecord5/Dexie10。cultivatedIslands/cultivatedArchives/cultivatedMoments/cultivatedGiftsを新版の正本とし、旧系の元snapshotを保持する。旧家の段階開始と建築時刻が両方欠ける場合は、移行時の現在町時刻を新たな起点にし、過去の成長を捏造しない。既存の有限大型プロファイルは場所JSONのP02/P05を使い、適合しない形を通常の庭として表す。

## 子どもに示す育ち方

新版の「そだつ場所」の名前・不足条件・材料図・説明は現在の規則から示す。P01は木、P03は水源、P05は花1個から、P04は育った家2軒の共有庭として案内する。席・木の家style・終了した遊び場種を新版の必須材料にしない。P02の大型は有限配置と大木の条件を伝え、どの配置でも幹の部屋や屋根が生まれるとは案内しない。旧カタログの配置図は旧規則の保存/診断用として保持し、新版の購入レシピと混ぜない。
