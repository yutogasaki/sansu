# 学習単元と習得証拠

> 2026-09-08追補: 過去/現在の確認とLv11の通常選択・coverage接続は[34](34_learning_reinforcement_spec.md)で採用。単元の対応表と証拠形式は本仕様、通常進行への適用は34を正本とする。

親仕様は [01_app_spec.md](01_app_spec.md)。2026-09-08のスキル・レベル境界を含む再設計案と「すすめて」に対応する。

## 今回の導入範囲

算数118スキルと英語1,184項目に版付きの単元対応表を追加し、算数Lv11の19スキルを7単元として比較評価する。概念、表現・方法、問題の型、開始目安、習得証拠を分ける。算数の必須前提と推奨順序を明記する。未実装の基礎概念はplannedとし、通常出題の必須関門にしない。

既存のID・所属レベル・保護者設定を保持する。出題・SRS・解放・昇格は[仕様29](29_learning_progression_spec.md)を[学習強化34](34_learning_reinforcement_spec.md)で更新し、Lv11の単元coverageを新しい進行へ適用する。新しい子ども向け設定や操作を加えない。英語の音声・絵の入門は後続段階とし、今回は既存語義の対応と明白なかな訳の校訂を行う。

## 単元境界

- 別の前提や誤り方を持つ内容を単元とする。同じ概念の具体図、式、暗算、筆算、逆向きの確認は表現・方法別に記録する。
- Lv11は2桁+1桁（繰上なし/あり）、2桁−1桁（繰下なし/あり）、2桁+2桁（繰上なし/あり）、2桁−2桁の7単元。最後は繰下なし/ありを実問題の型で区別する。
- 数量、数列、数の読み、分類、空間、測定を別系統とする。色名や日本語の読みを算術全体の前提にしない。
- 小数・分数は位取り・量の意味・比較との関係を記述する。同一旧ID内の型が異なる場合、旧IDを丸ごと別レベルへ移さない。
- 英語は既存の各語義について、綴りが表示された訳語選択の対応を作る。categoryは教材の旧分類であり、品詞・習得レベル・最適な授業単元の証明ではない。聞く・話す・書くの達成を推定しない。

## 新規問題と回答の証拠

- 新しく生成する問題にカタログ版、教科、教材ID、単元、表現、問題の型、内容の識別子を付ける。追加処理は乱数を消費しない。
- 保存済み予約に文脈がない場合は補完しない。予約済みの問題・答え・筆算座標・版はそのまま再開する。
- 全問の採点時に、保存された文脈と独力/支援あり/不明を既存回答ログのoptional fieldへ保存する。従来ログを作らない島・遊園地の支援完了は既存イベントに証拠を保持し、SRS用の回答を追加しない。支援開始・筆算途中の誤りは別のbarrierとしてイベントへ記録し、全問正解にせず当該単元の再確認へつなぐ。訂正を含む従来の実回答記録と、進行に使う独力証拠を分ける。
- 旧ログ・紙テスト合計点・島の演出観測・初期retiredから新単元の達成を作らない。情報不足はunknownとする。
- 証拠は既存回答と同じtransactionで保存する。再送は既存receiptに従い、二重計上しない。DB indexやschema versionを増やさず、34の独力カウンタ・進行窓をoptional fieldで保持する。

## Lv11の確認

独力で異なる問題を解ける状態と、日を空けた再確認を分けて集計する。同じ問題の直後の訂正・支援後の回答・同日連答だけで定着を認定しない。

readinessは必要な表現・型ごとに異なる3問の独力正解を初期設計値とする。無補助の式または問題全体を完了した筆算の、同じ表現で必要な型をすべて確認する。図・暗算指示・補助付き戦略は別欄に保持し、それだけでreadinessを満たしたことにしない。筆算・暗算・図の結果を別欄に残し、一つの方式の正解で他方式の達成を作らない。2桁−2桁は繰下なし/ありをそれぞれ確認する。

遅延確認の実績は同じ単元の直近接触から24時間以上空いた独力正解とする。復習段階を上げて次の期限を設定するには、対象の現在の確認期限への到達も必要。04:00境界を跨いだだけでは認定しない。最新の誤答・支援あり・スキップの後は対象の表現×型で独力確認を再収集し、他方式を含む過去の遅延確認実績は残す。現在の確認期限と再確認の必要性は別欄に持つ。計算結果だけでは支援の有無を判断できない旧記録も、以後の新しい証拠で再確認する。必要な証拠が不足する場合は不合格ではなく未確認とする。前提の未確認は単元の実績と別に表示する。

この3問・24時間は製品の設計値であり、研究で最適と証明された値ではない。通常進行への適用条件は34を参照する。比較レポートで足し算のみ、偏った反復、支援、混合、後日、旧記録の各ケースを再現する。

## 検証と次段階

対応の詳細は[算数の全118スキル](32_math_unit_catalog.md)と[英語の全1,184項目](33_english_unit_catalog.md)に保持する。`npm run learning:report`で`output/learning-units/report.html`と`report.json`を生成する。HTMLは教材・単元・旧レベルで検索でき、7つの合成シナリオを比較する。実プロフィールの診断は`readMathLevel11Pilot(database, profileId, asOf)`を明示的に呼ぶ読み取り専用APIとする。Lv11関連の新規予約・進行条件が成立する境界で読み取り、他レベルの通常回答で単元の全履歴を読み直さない。

全IDの対応漏れ・重複・レベル改変、参照切れ・前提循環、未知の版・不一致文脈、支援と独力の混同、問題内容の反復、保存失敗と再送、旧予約の再開を検証する。型の指定がない生成では同じseedの問題内容が追加文脈を除いて一致することを確かめる。

次に位取りの直接確認と英語の音声・絵の一単元を試す。保護者範囲・未実装前提を迂回せず、実利用で翌日/1週後の独力正解、別形式への対応、自発的再遊びを確認する。全面の段階数や合格値はこの評価に沿って改訂する。

根拠は[IESの幼児算数ガイド](https://ies.ed.gov/ncee/wwc/PracticeGuide/18)、[学習・指導ガイド](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)、[文部科学省の外国語解説](https://www.mext.go.jp/content/20220614-mxt_kyoiku02-100002607_11.pdf)。具体的な単元割当・閾値・実装順はこの製品の設計判断である。

## 収集範囲の境界

通常Study、島、遊園地および34で接続するExploreの新規問題が対象。通常Studyで予約の表現と実際の筆算切替が異なる場合は新しい証拠を認定しない。旧予約へ文脈を後付けしない。通常Studyの未完了の途中操作には新しい永続イベントを増やさず、対応する全問ログで支援・訂正を記録するため、中断直後の状態まで完全に評価できるとはしない。Lv11のreadinessは34の新しい昇格・解放の追加条件とする。
