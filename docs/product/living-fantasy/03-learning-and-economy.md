# 03 学習・経済・品揃え

[包括仕様51へ](../51_living_fantasy_island_spec.md)。次期の規則版は `fantasy-economy-v1` / `fantasy-growth-v1`。以下は実装用の初期値で、現行の経済へ遡及適用しない。

## E-01 学習の正本

[算数](../02_math_skills.md)、[英語](../03_english_skills.md)、[学習進行](../29_learning_progression_spec.md)、[単元](../31_learning_units_spec.md)、[支援・定着](../34_learning_reinforcement_spec.md)を引き継ぐ。出題の選択、採点、支援、独力判定、復習期限は島の状態を参照して変更しない。

| 学習の状態 | しずく | 学習記録 |
|---|---|---|
| 通常plannerの有効な問題完了 | 1件2しずく | 既存の結果と独力・支援情報をそのまま保存 |
| 支援を使って同じ問題を完了 | 1件2しずく | 参加として扱い、独力習得とはしない |
| 誤答・途中離脱・お手本を見ただけ | 0 | 既存の途中・支援状態を保持。減点・没収なし |
| 同じ完了receiptの再送・再読込 | 追加0 | 同じ事実を二重登録しない |
| 既に完了した問題の閲覧・再演 | 0 | 新しい通常予約の完了とは区別 |
| 既存の任意チャレンジ・紙テスト・旧モード | 島への新規加算なし | それぞれの既存契約を保持。自動合算しない |

自然に再出題された同じ内容でも、別の正規plan-slotの完了であれば別件。`profileId + planId + slotId + terminalVersion` により同一事実を識別し、フレーム数や正解音の回数から報酬を出さない。

学習writerは正規結果を先に確定する。島への加算失敗で完了した回答をやり直させない。学習事実から再同期できるようにし、島側に保存済みIDの一意性を持たせる。教科混合・途中再開・連続学習の契約を変えず、購入や成長の受取面を学習区間へ挿入しない。

## E-02 財布と価格

> 2026-09-29: この節の一部は北極星と食い違うため無効。[51冒頭の整合表](../51_living_fantasy_island_spec.md#北極星との整合2026-09-29)を正とする。

次期の島はしずくのみを表示する。学習完了以外では新規のしずくを発行しない。住人の利用、収穫、発見、写真、連続日数、長時間放置に通貨を付けない。現金購入・広告・ガチャ・消費型成長促進なし。

残高は非負の安全な整数。上限は `Number.MAX_SAFE_INTEGER` で、超える取引は破損扱いとして停止する。通常プレイ用の獲得日次上限は設けないが、稼ぐための追加問題・残り何問の催促・通貨倍率は出さない。

新規10品は全て最初から一覧で見られ、学習成績・通算問数・住人数の追加解放条件を付けない。初回の先頭には花・木・ベンチ・水ばちを並べ、他の物は同じ一覧の続きに置く。「売り切れ」や未実装品のカウントダウンを出さない。旧5品は「もっている もの」に残り、将来の再販売は別版で定める。

上限は**島へ同時に配置する30個**とし、収納を含む所有数のゲーム上限は設けない。初期無料物も配置中は数える。これにより30個買った後でも、古い物を収納して新しい庭を試せる。新規購入は実際に置く場所と空き枠を確保してから確定し、上限時に収納へ無条件で買い溜めさせない。

所有一覧は同種をまとめ、各個体の成長・見た目を選べる。1ページ24個の遅延表示を初期値とし、収納中は描画・成長・住人の候補判定に参加させない。所有データも端末容量を使うため、容量不足のときは取引を失敗として戻し、バックアップ等の復旧を案内する。「無制限の端末容量」を約束しない。収納1,000個＋配置30個でも主要操作の予算を守ることを検査する。

旧保存で配置数が30を超えていたら全配置を保持し、数を増やす新規配置だけを止める。移動・回転・収納は可能。30個以下になった後は新上限へ従う。上限を理由に自動移動・削除しない。

土地の価格は1回目12、2回目24、3回目48しずく。住人数・食料供給・連続利用日は条件にしない。本人が広げる方向と見え方を確認して購入する。土地は恒久権利、取り消し・再販売なし。全発見を初期土地で試せるため、拡張を遊びの通行料にしない。

## E-03 取引

見積には本人・商品・規則版・価格・配置・world revisionを含む。確定時に現状態で検証し、残高減算、所有ID生成、配置、receiptを原子的に保存する。価格や地面が変わったら同意なく別条件で購入せず、最新プレビューへ戻す。

同じintent IDは一度だけ反映する。通信のない端末内取引でも二重タップ、複数タブ、commit通知欠落を想定する。取り消したプレビューのintentを後から確定させない。移行時のしずくとひかりの扱いは[06章](06-data-and-migration.md)だけで定義する。

## E-04 成長時計と環境

成長時計は[04章](04-discovery-and-memory.md)で定義する受理済みの経過時間。カレンダー日付、景色の昼夜、FPS、最近の学習数は成長速度に含めない。配置されている間だけ成長し、収納中は進めない。移動・回転で蓄積成長を失わない。

水の影響 `W` は、水ばちまたは通水水路のセルからの距離 `d` に対して `clamp((4-d)/3, 0, 1)`。木陰 `S` は成熟した所有木からの距離に対して `clamp((3-d)/2, 0, 1)`。それぞれ最も強い一つを使い、重ね置きによる加算をしない。背景の枝は編集域へ実際の育成用の影を落とさず、所有木の木陰と混同させない。距離は02章と同じ。

土の水分 `m` は0〜1、初期値0.20、目標値 `T=clamp(0.20+0.50W+0.08S,0,1)`。配置が同じ区間の経過 `h` 時間について `m(h)=T+(m(0)-T)*2^(-h/3)`。水路の切断表示は即時、土は徐々に変わる。新しい土地の水分だけ0.20で追加する。

湿りの正規化 `M=clamp((m-0.20)/0.50,0,1)`。1実時間に増える有効成長時間は次のとおり。

| 植物 | 速度 | 段階・収穫 |
|---|---|---|
| 花 | `1+0.25M` | 0〜2未満:芽、2〜6未満:つぼみ、6以上:開花 |
| 木 | `1+0.15M` | 0〜6未満:苗、6〜18未満:若木、18以上:成熟 |
| ハーブの鉢 | `(1+0.25M)*(1-0.20S)` | 有効2時間ごとに1個。収穫周期の前半は芽、後半は葉、在庫ありは実のある姿 |

花と木は成熟で成長蓄積を上限へ固定する。鉢は在庫3個で育成停止し、満杯になった余剰経過は貯めない。1個取り出した後は残った周期内の進捗から再開する。植物は乾いた場所でも育ち、枯れず、育った段階は戻らない。鉢の陰は少しゆっくり育つが、生存条件にはしない。

配置変更、木の成熟、通水切断、収納、収穫上限到達の時刻で積分区間を分ける。変更後の速度を過去全体へ掛けない。式の区分を解析的に扱うか、結果が規定許容誤差内で一致する決定的計算を使う。通常再生とoffline catch-upの成長差は有効時間1秒以内、収穫個数・段階・在庫は完全一致を必須とする。

子ども向けには「めが でた」「つぼみが ふくらんだ」「土が しっとり」「木かげで ゆっくり」など現在の理由を示す。正確な残り時間のカウントダウンは常設しない。詳細には「あと 数時間くらい」を表示できるが、環境変更で予測が変わることを含める。

## E-05 初回・数日・長期のバランス

最初の有効3完了で6しずく。水ばち＋花、木＋花、ベンチ＋花、鉢など複数の意味ある選択が成立する。標準6完了なら12しずくで灯り＋水ばち、鉢＋ブランコなども選べる。初期の花とベンチだけでも住人が使い、最初の友達を招ける。

花の成熟は標準6時間、最も湿った場合約4.8時間。木は標準18時間、最も湿った場合約15.7時間。成熟の待ち時間中は移動・水のつながり・住人・水面と灯りの反応を試せる。待つだけの画面を作らず、時間を進めるための起動放置を要求しない。

1日6完了を仮定すれば12しずく、7回で84しずくだが、これは価格の比較例であって日課や達成ノルマではない。長期の主目的は配置・写真・再会・異なる場所作り。v1の品数が有限なことを明示し、無限成長、何か月もの新規内容を約束しない。

値を調整するときは、初回の選択肢数、既存残高で買える物、成熟済み段階、既存receipt、土地権利への影響を確認する。取得済み成果を巻き戻す調整は禁止。学習を増やす指標だけを最適化せず、同じ材料で遊び直せるかと学習への戻りやすさを併せて判定する。
