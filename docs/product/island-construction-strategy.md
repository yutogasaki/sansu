# 島構築方針 — 美術で設計した場所を、配置から育てる

制作方針 v6 / 2026-10-11。[決定の理由](../adr/2026-10-11-authored-place-world-policy.md) · [美術戦略](island-art-strategy.md) · [拡張戦略](island-expansion-art-strategy.md)。本書が体験・世界の作り方・制作順の正本。現行の遊びは[52](52_growing_island_game_spec.md)、保存は[13](13_data_storage_migration_spec.md)が正本で、新しい世界への切替は未実装。

> **美術で地形と場所の作り方を設計し、子どもの土地選択・配置・成熟から、その子の島を組み立てる。**

美術模型を作った後で別の簡易モデルへ置き換える制作を終える。地形、森、水庭、集落、入口、歩ける床を同時に設計し、その同じ世界の定義を本体で使う。まず一つの島全体で成立させ、配置差と成長を通してから、大規模な拡張へ進む。

## 1. 新しい中心

子どもが決めるのは、どちらへ土地を広げ、何をどこへ置き、どんな場所を育てるか。島が行うのは、つながる根・樹冠・岸・道・共有空間の組立てと、住人が使える場所への接続である。

目標は「自分の置き方が、そこで暮らせる景色になる」。小さい島でも一つのかわいい景色として成立し、成熟すると空間と尺度が変わり、拡張すると別の景色を訪ねられる。人口・地区に完成上限を設けない。くふう・にぎわい・ふしぎ・愛着の四つの柱を維持する。

## 2. 何が詰まっているか

2026-10-11の[自由造形の全島](../design/2026-10-11-island-landscape-art/README.md)と[本体の拡張候補](../design/2026-10-11-expanding-island-runtime/README.md)は、世界を作る方法が異なる。前者は自由な美術anchor、後者は矩形の取得セルを連続変形した床と個別配置を使う。部品の材質を引き継いでも、地形・密度・入口・集落の構成を引き継げていない。

| 今の方法 | 届かない理由 | 変える責任 |
| --- | --- | --- |
| 全景は自由に造形し、後から保存セルへ対応させる | きれいな場所に、本体で成立する床・配置・経路がない | 美術と遊びが同じ世界を作ることを、最初の成果物にする |
| 地面を曲げ、個々の所有物を描く | 大きな森、囲われた集落、下る水庭の構成を決める処理が足りない | 地形と場所ごとの組立て規則を作る |
| 全取得セルを矩形boundsの内部として扱う | 新しい土地の購入が、同じ台地の追加へ偏る | 次期は地区ごとの実床・取得範囲・接続を扱う |
| 8／16／32軒を先に増やす | 小さい島の弱い構成が拡大される | 一つの全島の品質を成立させてから拡張する |

現在の連続写像は旧床・足・hitを揃える実装として保持する。ただし、これを調整し続けるだけで完成美術を作れるという前提は置かない。技術検査のPASSと全島美術のHOLDは両立する。

## 3. 選ぶ制作方式

**作家が設計した地形・場所の形を、配置に応じて組み立てる方式を選ぶ。** 自動化する範囲と、美術で決める範囲を具体的に分ける。

| 決める人・処理 | 決めるもの |
| --- | --- |
| 美術 | 岸・丘・低地の形、木陰の回廊・中庭・樹冠の塊、段泉、共同屋根。それぞれの入口、支持構造、床、若い姿、許容する変形 |
| 子ども | 土地を広げる方向と候補、材料・家の配置、残す余白、移動・分離・再接続 |
| 本体 | 地形と配置から使える形を選び、向き・長さ・継ぎ目を調整する。成熟と実際の到達・通水・利用を反映する |

採用native-05を造形の基準にし、回廊・中庭・樹冠など、接続できる形の系列へ作り直す。伸ばせる部分、元の幹に接続する部分、入口を空ける部分を設計する。完成モデルを切り出した部品の並べ方だけに、空間の成立を任せない。

形の種類は、色違い・大きさ違いだけで増やさない。列・塊・中央を空けた配置が別の空間になるように、美術部品と接続規則を一緒に制作する。任意の配置を一つの完成模型へ自動整列しない。共同形が成立しない配置にも、かわいい単独の姿を用意する。

この方式には、接続形と成長段階を先に作る制作費がかかる。その代わり、全景の品質をその都度プリミティブから再発明せず、配置による違いを扱える。子どもに地形彫刻や建築CADの操作は要求しない。

参考の役割は[32枚の参考と構造監査](../design/2026-10-10-island-design-strategy/index.html#foundation)へ残す。借りる対象は配置・周辺環境から大きな形と暮らしが生まれる原理。Sansuの材料・造形・安全の規則は本書と各仕様で決める。

## 4. 「合体」を三つに分けて設計する

| 仕組み | 変わる瞬間 | 見える変化 |
| --- | --- | --- |
| 接続と形の適応 | 隣へ置く、動かす、分ける | 根・枝・岸・花の縁・足元がつながる。確定前に予告する |
| 場所の成熟 | 元の材料や家の育成が進む | 樹冠・屋根・水庭・使える空間が育つ。既存時計を使う |
| 関係からの発見 | 異なる役割の場所がつながる | 木陰と暮らし、水と花などから、その場所固有の形や利用が生まれる |

個体の取得・成熟・styleは残し、現在の場所の形を配置から導く。分離で成熟や住人の権利を下げず、再接続で報酬を二重取得しない。個数だけで同じ最高形へ収束させない。詳細の現行条件は[育つ場所v1](island-place-goals.md)を使い、変更は52へ先に反映する。

## 5. 五つの層を一緒に作る

| 層 | 組み立てるもの | 全島での役割 |
| --- | --- | --- |
| 土地 | 岸、丘、低地、地区の接続 | 輪郭・高さ・入り江の大形 |
| 水と余白 | 実水源、水路、歩ける帯、入口 | 流れと見通し、地区の間の抜け |
| 植物の場所 | 元の幹・株、つながる樹冠・根・花の縁 | 点から面へ育つ森と庭 |
| 集落と暮らし | 元の家、玄関、共有の足元、席と遊び | 大きな自然の下に読める小さな生活 |
| 固有の不思議 | 空洞幹、下降する鉱石泉、色を透かす共同屋根 | 地区ごとに成立の異なる主景 |

この五層を別々の完成工程にしない。森の場所を設計するなら、幹と樹冠に加えて地面・入口・通路・隣の家まで一体で作る。地区間は、道・岸・低地の接続部を使って結ぶ。

## 6. 土地の形を根本から扱う

M0の具体契約は[共通世界定義](island-world-contract.md)で定める。取得する配置地点と、狭い岸に沿う細かな歩行点を分け、両方を同じ実床へ接地する。歩行点から材料の結合距離や通水範囲を増やさない。

**次期の土地は、追加列／行を全景の設計単位にせず、形と接続を持つ地区として扱う。** 岸の低地、森へ続く丘の肩、泉から下る斜面など、広げた先で作れる場所の違いを見せる。土地の候補には実際の取得範囲、通れる入口、価格を一緒に示す。完成した森や集落を購入する方式にはしない。

地区には安定したID、局所座標、取得できる配置領域、床高、水域、他地区との接続口を持たせる。配置点と、その点同士の接続を明示し、隣接・通水・歩行はその接続を読む。boundsは検索用の包絡として使えても、その内部がすべて所有地であるとは扱わない。購入済みの地区を、次の拡張で再生成しない。地区が増えても元の家・庭の場所を維持する。

これは次期の世界表現の設計方針で、保存形式や取得規則の切替ではない。52の土地・通水・通行と13の互換契約を先に定める。旧保存は全既得セルと所有物を含む互換地区として読み、既得の床を海に消したり、家を勝手に移動したりしない。新しい岸・段差の選択は新規取得部分から導入する。

## 7. 場所の成長文法

| 系列 | 置き方と環境 | 育つ形 | 美術と遊びが共有するもの |
| --- | --- | --- | --- |
| 木 | 列、塊、中央を空ける | 横へ続く木陰、厚い樹冠、内側に入れる中庭 | 元の幹、根と支持、入口、通れる床、木陰の範囲 |
| 水 | 実水源と水路、地形の高低 | 低地の水庭、斜面を下る段泉 | 水源、通水範囲、水面高、岸、乾いた道。平地に見た目だけの滝を作らない |
| 花 | 色のまとまり、縁、中央の余白 | 花の面、囲われた庭、元の茎が支える天蓋 | 元の株、成熟、支持、入口、席と通路 |
| 家・食卓・遊び | 木陰や水庭のそば、向かい合う空き地 | 森の集落、水辺の集落、庭を囲む暮らし | 個々の家と玄関、実経路、到達できる利用先 |

本数・戸数を増やさなくても形が変わることを、島全体で比較する。根や共有屋根は所有物から派生した形で、追加の所有物として数えない。成熟した森を背景用の木の量産で偽らない。低い草・地面の細部は環境装飾として区別する。

## 8. 幻想性を構築の結果にする

[採用native-05](../design/2026-10-10-island-final-3d/README.md)の、明るく丸い3Dと昼にも色を持つ素材を基準にする。青紫・翡翠の大きな葉と琥珀の幹、鉱石を源とする青い水、色を透かす殻は、異なる場所の構造として使う。

全景では岸と丘、森の面、家の群れ、主景の大きさの差を作る。主景のそばに密度を寄せ、水・岸・通路に余白を残す。小さい家と住人は同じ世界尺度で保つ。回転した近景でも、幹の内側、枝の下、屋根の中が実在し、支持と入口が読めるようにする。

樹冠を大きくする場合も玄関や実actorの頭を覆わない。素材と空間が違う主景を地区に置き、同じ巨木を等間隔で複製しない。昼の形と素材が届いてから、夕の光や短い反応を調整する。

## 9. 島を作りたい気持ちの流れ

| 時点 | 景色の見返り | 次に選べること |
| --- | --- | --- |
| 少ない材料 | 一つの小さな庭として成立する | 近くへ寄せるか、余白を残すか |
| 同じ滞在で置き直す | 接続の向きと空間が変わる | 回廊・樹冠・中庭の違いを試す |
| 成熟する | 前に置いた場所の尺度と使われ方が育つ | 暮らしを添える、隣に別の場所を作る |
| 土地を広げる | 岸・高さ・隣接関係の違う場所がつながる | 森を続ける、水庭を分ける、花の丘へつなぐ |
| 長く続ける | 元の庭を覚えたまま、訪ねる先が増える | 好きな一角を編集し、別の組み合わせを育てる |

島の大きくなり方は、土地の候補と配置の組合せから分岐する。「湾型・森型・丘型」を初めに固定する方式にはしない。同じ戸数でも違う島になることを比較する。8／16／32は診断例で、解放条件や上限にしない。

自然とまちの既存時計、無償の置き直し、任意の目標を使う。場所の不足を学習ノルマ・維持費・枯れ・退去へ置き換えない。自発的な学習と再訪への効果は、許可を得た実利用で別に観察する。

## 10. 操作の再設計

配置予告は品一つと、その操作で変わる場所の輪郭・残る入口・道を同時に見せる。予告と確定は同じ計算を使う。取消しで元に戻り、保存しない。

共同形を触っても元の自分の品を選べるようにする。大きな樹冠に隠れた品は、小さな選択肢から移動・収納へ進める。まず個体の移動・分離・再接続を成立させ、場所の一括移動や地形編集を先に増やさない。

自動の道や地面の継ぎ目は、本人が置いた家・木・玄関を勝手に移動しない。配置の巧拙を点数化せず、共同形が成立しない場合も遊べる。学習へはいつでも既存の入口から進める。

## 11. 実装の基盤

**美術表示・本体・配置予告が、一つの世界定義を読む。** 以下は次工程で確定する契約の構成で、現行APIや新しいDB schemaを実装済みと扱わない。

```text
実所有ID・配置・成熟・取得地区
        ＋ 美術で設計した地形／場所の形と接続規則
        ↓
一つの世界定義
  地形と岸／配置できる床／水域／個体の位置と支持
  場所の輪郭と成熟／入口／歩行接続／利用先
        ├─ 全島3Dと近景
        ├─ 配置hit・予告・個体の選択
        └─ 通水・移動・住人の実利用・目標判定
```

共有する世界には、安定IDを持つ配置点、その隣接、実際の床面、地区間の接続、各場所の入口と利用先を含める。床面から接地と配置hitを求め、その上を通れる接続から実経路を作る。カメラは実地形と主景の範囲を読む。

制作時に、見える地形と配置領域・入口・経路を一緒に編集・出力する。本体はその結果を読み、別の床や代替プリミティブで美術を再制作しない。通常の配置操作で表せない自由anchorを、ゲームへの到達証拠には使わない。

地形・元の所有物・派生した場所の責任は分けるが、同じ世界revisionで合成する。レンダラー独自の隣接判定や、見た目だけ通れる橋は作らない。既存の所有・成熟・目標・履歴の純粋計算と学習を保持し、世界の床・配置・到達を読む境界から接続する。

変更した周辺と接続成分を再計算し、地区単位の共通材質・読み込み・表示品質を扱う。バッチ化しても元の選択IDを保持する。編集用全島GLBの複製をそのまま配信する方式にはしない。実機予算は既存性能仕様と計測で確定する。

## 12. 作る順序を変える

以前の「完成模型→別の本体へ対応」「木の一系列→水と地形」「先に16／32軒を増やす」という工程を置き換える。**最初の実制作は、地形・場所・生活を含む一つの島全体。** 美術と遊びを別の世界として完成させない。

| 順 | 成果物 | 次へ進む条件 |
| --- | --- | --- |
| M0・契約 | 一つの世界定義と、52の土地・床・通水・到達に必要な次期差分。旧保存の保護境界も記す | 美術で作る岸・丘・入口を同じ配置／歩行で表せる。描画だけの例外が要らない |
| M1・全島一例 | 入り江・丘・森・水庭・小さな集落を含む編集可能な実3D。家8軒程度を診断例にし、所有IDを同じ定義へ対応。全景と近景を本体rendererで見る | 採用原本と全景を比較でき、同じモデルを選択・配置・歩行で使える。単体の巨木や独立viewerだけでは完了しない |
| M2・配置差 | 同じ材料・家数・成熟の全島を、列／塊／中庭など三つの配置で組み直す | 輪郭・密度・通路・暮らしが変わり、複数の魅力がある。美術だけの手直しで一例を成立させない |
| M3・成長 | M2と同じ形・床から、単独→若い接続→成熟→実利用→分離→再接続を作る | 少ない材料でも一景になる。成熟の理由が見え、元の所有・時計・入口・利用と一致する |
| M4・拡張 | 初期の中心を残し、岸の低地／森の肩／花の丘への拡張を比較。16／32とその先を診断する | 元の地区を変えず、別の場所とその間の関係が増える。大きくすると単調になる場合は、地区の組立てを直す |
| M5・統合 | 13の保存互換、通常取得・学習・offline・更新・復旧、実機・理解／安全を同じ配布候補で検証 | 美術、無説明理解／安全、runtimeを別々に受け入れる。未実施のゲートを技術PASSで埋めない |

M1の島は診断用であることを明示し、模型の家や住人を本人の保存へ取り込まない。移動や分離が一例の構図を壊すなら、その場で世界の表現や場所の規則を見直す。既存のD1〜D4は再利用するが、この新工程を通過した証拠にしない。

## 13. 判断に使う比較

1. **全島**：採用native-05と、同じ世界尺度・対応する全景／近景で比較する。岸と起伏、森の面、家のまとまり、主景と余白が一緒に成立するか。
2. **同じ材料、違う配置**：数を足さず、複数の空間が育つか。元の個体を探して触れるか。
3. **同じ配置、違う成熟**：巨大物を後付けするだけでなく、元の幹・株・水・暮らしから連続して育つか。
4. **同じ場所、編集して戻す**：接地・道・所有・成熟・住人・履歴を保つか。
5. **拡張前後**：中心の場所と尺度を保ち、別の景色が増えるか。島タイプの固定や一つの最適形へ誘導していないか。

全景が届かなければ、機能数や試験数を増やす前に地形・場所の表現を修正する。自由な美術anchorでしか成立しない形は、共有する契約へ戻して作り直す。小物・発光・戸数を増やす改修へ逃がさない。

実画面の記録はapp target、build、delivery flag、候補ID、所有と診断の区別を持つ。作者の美術比較、説明を受けていない観察者の理解／安全、対象buildのruntime検査を分ける。

## 14. 保持するものと変更するもの

| 保持するもの | 再設計するもの |
| --- | --- |
| 本人の所有ID、品・家の成熟と装い、住人、取得土地、履歴・写真 | 土地を全景へ組み立てる表現と、新規地区の形・接続 |
| 学習の出題・採点・SRS・同予約への復帰、既存時計 | 地形・配置・通行と美術が共有する世界定義 |
| 無償の置き直し、不在の無罰、人口と地区の継続成長 | 接続形・地面・共有空間・成長を一体にした場所の制作 |
| ぽこもこの顔・頭身・耳・布・色、同じ家の尺度 | 全景の密度、見通し、地区間の継ぎ目、カメラの寄り先 |

既存の家や土地の位置を勝手に再配置しない。旧保存の互換を、美術の簡略化を永久に固定する理由にも、既得権を削る理由にも使わない。次期の取得単位や規則を変更するときは、52と13の契約・検証を先に揃える。

## 15. 正本と完了の境界
