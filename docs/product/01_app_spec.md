## 島をメインにする公開導線（2026-09-08）

2026-09-09、外部12アプリとKeepGoingの比較後にユーザーが実装を指示。島・学習・一覧・編集・思い出・管理ごとに主役と面積を分ける。ホームの任意機能は必要時に開くメニューへまとめ、島と問題そのものの見やすさを優先する。44px以上の操作領域、全入口、学習と保存を保つ。表示配分は[仕様44](44_display_layout_spec.md)、戻り先は[仕様43](43_island_navigation_spec.md)に従う。 スマホ・iPadの縦横とも全テンキーを常時表示し、残りの幅・高さを問題に渡して収まる範囲で拡大する。入力の位置と可読性を維持する。

トップ訪問では問題を開始しない。Island無効かつBuildPlay有効時は遊園地の作品画面、両方無効時は探検基地を開く。旧探索runが残っていてもトップから自動再開しない。この2026-09-09の方針は、以前の探索を直接起動する記述に優先する。

Island有効時は「ふしぎな しま」をホームとする。プロフィールありの `/` は旧探索の途中runがあっても `/island` へ進む。下部ナビは「しま／いえ／まなぶ／きろく／設定」とし、中央の「まなぶ」で学習を開始・再開する。島への移動だけでは未完了の問題を開かない。「いえ」は家の先頭を開き、アルバムへ進める。設定は下部タブから開く。通常画面はタブを残し、学習・配置等の集中画面は隠す。「とじる」で開始前の画面とタブを復元する。詳細は[タブと戻り先43](43_island_navigation_spec.md)。通常練習の `/study` と `/study?session=normal` も明示的な島の学習へ接続する。明示した復習・苦手・テスト・開発用学習は既存の対象範囲と保存契約を保つ。

設定・きろく・ほかの遊びの一覧は、島のクリーム色の地、濃い青の線、青と黄色の操作面、同じ島の印を共有する。ポッコのアプリアイコンや旧探索の空色〜金色グラデーションを共通画面の顔にしない。遊園地・旧探索・2人遊びは島の「ほかの あそび」（`/battle`）から明示的に選び、遊園地には保存中を除き「しまへ もどる」を常設する。旧作品・途中学習・探索runは保持し、選んだ遊びから再開できる。明示的な `/park` などへの直接アクセスと操作中のPWA更新保護は維持する。Island無効時もトップからの自動学習開始は行わない。

## 学び始めやすさと報酬の強弱（2026-09-08採用）

回答の判別と手応えは[28仕様の音・回答表示](28_mystic_island_spec.md#音と回答の判別2026-09-08)に従う。島の正解・再入力を記号と文字で区別し、短い実音源を入力・保存済みの結果に結ぶ。英単語の手動・自動読み上げを島でも利用できるようにする。

島ホームは景色と操作を中心にし、住民紹介・成長予告・自動保存の常設説明を置かない。操作後の反応と必要時の案内は残す。詳細は[28仕様](28_mystic_island_spec.md)のホームの説明量に従う。

島を眺める時は1本指で上下左右へ移動、2本指をひねって回転、2本指の開閉・ホイール・ボタンで拡大縮小でき、元の眺めへ一操作で戻せる。2本指操作は指の下の地面を保ち、眺めを変えた後は島の隅に文字付きの戻すボタンを出す。家具の配置、学習、成長比較、明示的な発見の再演では既存の操作と固定画角を優先する。詳しくは[30仕様の眺め操作](30_living_island_growth_spec.md#島の眺め操作)に従う。

Islandの初回は「まなぶ」から必要な設定を終えると、そのまま最初の問題を開く。新しい島で最初に予約する区間だけ3問にし、各問の小さな反応と最初の自動成長で短い達成を体験する。初回も受取・配置を挟まず次問へ続ける。既に保存した予約問題は変更せず、旧予約のおくりものと未受取権は保持する。

その後は通常6問／複雑な区間3問の保存・編成単位を維持し、区切りをまたいでも追加0操作・正解から次問入力P95 650ms以内で続ける。新予約は対象の居場所を自動で育て、家具の受取権を毎区間増やさない。誤答から再入力P95 550ms以内、SRS・支援・独力確認の意味は維持する。次区間の予約だけが失敗した場合は、保存済みの最終回答と成長（旧予約は報酬）を保ち、次の問題を開く再試行を示す。再送・別タブ・プロフィール変更・PWA更新で重複保存や誤った問題への入力を起こさない。

集中している間の静かな成長と、戻った島で分かる蓄積はForestを参考にする。初回の短い成長間隔は本アプリの設計判断である。遊びは観察・試行による発見、住民との暮らし、配置による反応、同じ物への愛着を育てる。学習への移動や解答中断を増やす条件にしない。成長・旧予約の互換性は[30仕様](30_living_island_growth_spec.md)、基礎の学習契約は[28仕様](28_mystic_island_spec.md)に従う。

### 1.2 探索と学習（メイン機能）

- 通常起動と初回設定完了後は `/` を経由して `/explore` の探索ランを直接開く
- 探索は「問題を解く速さ」を主リズムにする。道を一度選んだ後の2〜3問は、通常発見や保存表示で止めず追加操作なしで連続出題する
- `/study` は復習、定期テスト、英語、開発確認の独立ルートとして維持する
- `/battle` は探索から退出した後の「探検基地」とし、相棒と次の未発見を予告する即再出発の主CTAを最上段、既存2人ゲームを下位導線に置く。価値ゲート未通過のcold-open actorや固有名を基地の恒久的な顔として固定しない。`/settings`、`/stats` と既存2人ゲームのURLは削除しない
- 子どもはルート、地形、報酬傾向、帰還タイミングを選ぶ。問題難度そのものは直接選ばせない
- 既定起動面となる探索では、Study と共通の算数 planner が Due、weak、maintenance、表現フォロー、現在レベル、解放済み +1 レベルを選び、3問の連問区間へ供給する
- 連問区間はrunの正解step `0〜2 / 3〜5 / 6〜7` の3区間とし、区間の最初のgateが確定した時点で、区間内の自動routeを実nodeへ投影して全slotの完全なProblemと学習assignmentを単一snapshot・1回のplanner call・同一transactionで先に予約する。区間途中の正解でプロフィールがunlock / level-upしても既存slotを差し替えず、次区間だけ最新プロフィールから再計画する
- 誤答は同じstep slotに留まり、1回目は同じProblem、2回目以降は支援assignmentを別attemptとして使う。支援assignmentもcheckpoint CASと完全なProblemを一緒に予約し、再読込時にfresh profileから再生成しない。支援問題を出しても次slotを消費・再計画せず、未回答Dueを回答済みにしない
- 探索の学習対象回答は、planner が予約した実出題 skill と source を保存境界で照合できた場合だけ SRS 対象にする。近傍レベルへの表示 fallback や未対応入力の代替問題を、学習進捗へ混ぜない
- 探索の1回答は、探索イベント、run 集計、既存回答ログ、MemoryState、プロフィール内の直近履歴・学習日・メインレベル回答窓を、同一の冪等 transaction で保存する
- active探索runは、新規runを作る前に同一プロフィールのversion付きcheckpointを検索して自動復帰する。checkpointはroute、energy、finds、attempt境界、完全なpending Problem、opening experience ID、確認済みdiscovery cursorを保持し、入力途中の数字は保持しない。回答eventだけがcheckpointより1件先行した場合は、保存済みreceiptを同じpending gateへ1回だけ適用して復旧し、複数tailや照合不一致を推測で進めない
- 予約済み連問区間はindexを増やさないrun行のoptional dataとして保存し、step、gate、node、Problem、assignment、計画時プロフィール境界を照合して再開する。旧active runが区間途中で区間dataを持たない場合は、完了済みstepを変更せず残りslotだけを一度予約する
- 旧active runが既にpending full Problemを表示している場合は、そのProblemとassignmentを現在slotの正本として入力解禁前にsegmentへ取り込み、同じsnapshotで残りslotを予約する。現在問の回答によるunlockを次slotの再計画へ混ぜない
- 各slotの完全なProblemを保存値の正本とし、fresh profileとseedからの再生成で置き換えない。保存値はsegment ID、絶対step、slot順、planner / generator versionも持ち、review capは既存assignmentと同じsegmentで計画済みのslotを含めて候補ごとに再判定する
- Exploreで新しいbase segment slotまたはrepresentation retryを予約するときは、すべてのplanner sourceを計画時 `mathMaxUnlocked` 内へ制限し、生成済みProblemをrapid-loop適格性で判定する。適格条件は単一のnumber入力、正規化済み非負数、答え入力3操作以内かつ決定込み4操作以内、筆算 / `algorithm` 面でなく、`application` / `number-advanced` の高認知負荷familyでないこととする
- 不適格なDue等はassignment化せず、別identityのrapid-safe `game-only-fallback / affectsSrs = false` で不足slotだけを埋める。除外した学習候補をfallbackへ偽装せず、`logs`、MemoryState、recentAttempts、Due状態、プロフィール回答窓を変更しない
- rapid-loop適格性は未保存の新規予約時だけ適用する。保存済みsegment / assignment / retryと、旧runから現在slotへ採用したfull Problemは新規則で再評価・差替えせず、旧runで同時に新規生成する残りslotだけ現行規則を通す
- ランの最初の3問は、学習問題の意味を変えず、`解く → 即世界反応`を2回積み重ね、3問目に同じ身体規則から読めるオチへ到達するcold-openとする。1・2問目は追加0タップ・submitから650ms以内に次問を操作可能にし、誤答はsubmitから550ms以内に同じ問題へ戻す
- 1ラン8問の体験順は `Q1〜3 cold-open → Q3後の道選択 → Q4〜6 主調査の手掛かり → Q7 大発見1回 → Q8 持ち帰り → 帰還要約 → 再出発` とする。cold-openは主調査ページへ特徴を付与せず、通常標本とレア標本は希少度だけを理由に操作を止めない。明示的に止める報酬は意味づけされた大発見だけとし、8問完了時は「基地へ もちかえる」を唯一の主操作にする
- delivery / feature-flag ID `snap-root-v1` のcold-open visual candidate `dig-pop-carry-bloom-v3` は、後続と同じ黄色い葉帽子のポッコ、シアンの空、黄土の地面、コーラルの根生物、同じ横cameraを保ち、commit済み正解数だけを `ready → dig-one → dig-two → popped` へ写す。相棒は根生物の身体や葉ではなく中央の同じ土だけを掘る。一つの土塊が飛ぶ、根生物が持ち上がって両足が見える、全身でぽんと抜ける、という三段変化の最後に、相棒が安全に尻もちをつき、柔らかい土塊が葉帽子へ載る。1・2問目の途中発見はtoastを出さず、3問目も説明モーダルや追加CTAを挟まない。先読みが期限に間に合わない場合、正解後は通常plannerへ戻し、誤答後は先読みをabortして同じ問題を操作可能にする。blocking discoveryを越えて次問を先読みしない。旧v2のruntime視覚点とthroughput点はv3へ継承しない
- production defaultは `snap-root-v1` とする。`classic-v1` は旧マキモドンから後続の別rendererへ切り替わる実機FAILのためrollback先として使わない。旧 `ready → tug → tumble → landed`、編み根、`nest-squash | nest-tip`、一本葉を引くBloom版、水やり版、`dig-pop-painted-v1`、`dig-pop-painted-v2`、`root-pull-v1` / `root-pull-v2` は非採用のままとする。default変更を `dig-pop-carry-bloom-v3` や後続v5のformal visual承認、Gate B通過、過去候補の点数継承とみなさない。保存済みactive runのopening IDは途中で差し替えず、新規runから現行defaultを使う
- 絵主導のcold-openは、`視覚的磁力`、`無文字の因果理解と安全`、`runtime整合` を別々の非補償ゲートとして判定し、総合点へ平均しない。視覚的磁力は承認済み絵本調benchmark **52 / 60以上かつ6軸すべて8 / 10以上**、無文字テストは未説明の5人中4人以上が同じ主動詞とpayoffを説明し4人以上が続きを望み、危険解釈0件を必須とする。runtimeは1・2問目の正解から次問入力までP95 650ms以内、誤答から再入力までP95 550ms以内、追加0タップ、answer leak 0件、旧高速学習と同一固定問題で同等以上のthroughput、およびmobile / tablet・入力・reduced motion・asset・PWA検証の通過を必須とする。三ゲートすべてを実runtimeで通るまで最終visual承認を出さない。現在defaultがmandatory gateを実機で明確にFAILした場合は、既知FAILをrollback先に残さず、最小の同一lineage候補へcontainmentし、その未通過gateをHOLDとして明記する
- Gate Cの同一問題比較にはDEV限定fixture `cold-open-fixed-ten-v1` を使う。Studyは非記録session、Exploreは8問の実runを帰還・summary・再出発した後に別runで2問を解き、Exploreの全回答を `game-only-fallback / affectsSrs = false` とする。10反復all-correctの未丸め中央値で `Explore回答数/分 ÷ Study回答数/分 >= 1.000` を必須とする。Q4 / Q8誤答はStudyが訂正表示から明示Nextで次問へ進み、Exploreが同じ問題へ戻るため、相互のthroughput合否へ混ぜず回復時間・正答率・操作中断の別証拠にする。このfixtureは通常plannerの同一skill上限を意図的に外す表示throughput検証であり、planner / SRS真正性は既存の実planner 3問grayboxで別に確認する
- 全問足し算の固定10問はroot-tangleの引き算遭遇を偽装せず、Q7では3手掛かりをつなぐ中立の調査ページpayoffだけを開く。Explore中断は `Q3後の道選択 / Q7大発見 / Q8後に持ち帰る / 帰還要約から再出発` の4件へ固定し、Q1〜2、Q4〜6、Q8〜10はblocking表示0件とする。root固有の動作・観察provenanceは、実plannerが対応引き算を割り当てるroot-tangle E2Eで別に検証する

### 1.5 モチベーション（再プレイしたくなる探索）

- 岩を開く手触り、発見、分岐、帰還判断を反復の動機にする
- 1ランの主調査を「1つの調査ページ」として扱い、算数アクションで性質を見つけ、発見順がそのラン固有の小さな物語になる。最初の3問は操作と身体規則を教える短いcold-openとして主調査ページの前に完結してよいが、HOLD中のvisual candidateを生態メモや永続図鑑ページには混ぜない
- 未発見の手掛かりは同時に1件だけ示し、チェックリスト消化ではなく「次は何が起きる？」を残す
- 複数の性質がつながったときだけ短い「大発見」のピークを作り、通常発見との山と谷を明確にする
- 「谷」は低彩度で無表情な待機画面を意味しない。通常遭遇にも、対象固有の極端な輪郭、相棒との視線・重心の関係、一つの読める因果を置き、静止時点だけでも触りたくなる状態を保つ
- 「山」は全要素を同時に派手にすることではない。色、縮尺、表情、素材、密度、動勢のうち、その発見に必要な2〜3軸だけを強める
- Golden Discovery Page の最初の縦切りでは、通常発見で3つの手掛かりを集めた後、receipt確定済みのQ7 finaleだけが最終特徴「花のまんなかに 四滴」を開く。通常調査は、四滴を葉帽子で運ぶ、一つのでこぼこで安全に尻もちをつく、五枚花が開く、四滴が花の中心へ収まってポッコが帽子を片目にかぶったまま笑う、という一続きの因果にする。対応引き算なら `root-tangle` 固有の動作と観察provenanceを付け、非対応skillなら問題の意味を変えず中立のページpayoffにする。4件目という順番、正答数、希少度だけでは大発見にしない
- 現行MVPの調査特徴はrun内の一時進捗であり、rootを選ばず帰還した未完成ページが次runへ持ち越されるとは表現しない。run横断の特徴永続化はMVP-2bで扱う
- ランごとに予測可能だが読み切れない変化を入れる
- 学習上は子どもを責めず、ゲーム上は短期的で回復可能な失敗を許可する
- 図鑑登録済みの重要発見、学習履歴、恒久進行は失敗で没収しない
- 「見つけた」と「身についた」を分離し、発見表示だけで習熟認定しない。習熟はMVP-2以降も学習ログとSRSを正とする
- 外部ランキング、課金圧力、未達ノルマは導入しない
- 音は任意でOFFにできる

## 2. コンセプト（設計思想）と体験フロー

### 2.0 ブランドと画面全体の一貫性

- 正式名は **「ぽこもこと不思議な島」**、アイコン下の短縮名・Appleホーム画面名は **「ぽこもこ」** とする（2026-09-08ユーザー採用）。ブラウザー、初回画面、印刷物は正式名を使う。設定・記録・共通ナビ・島の操作面は、採用したくまと布の素材、静止したシンプルな水玉と幻想的な配色を軸に統一する。風景画やアニメーションでファンタジーを足さない。背景は方向検討中で、単色紫・細かい黒い点・大きなパステル水玉だけの案は最終採用しない。黄色を画面全体や主操作の基調にしない。既存の探索モード内のキャラクター「ポッコ」と、その物語・ゲーム名は改名しない。
- アプリアイコンは、紫の背景にクリーム／青の顔、水玉の丸耳、黄色い縫い目を持つパッチワークのくまを使う。正方形の元画像からfavicon・Apple touch・PWA各サイズを出力し、目鼻・口をmaskableの中心安全領域に保つ。共通画面の見た目はUI仕様07に従い、学習・島の挙動・保存キーを保持する。
- 色の骨格は、明るい空のシアン、土の黄土、根のコーラル、葉の緑、濃い青緑の輪郭、紙のクリームで全画面をつなぐ。
- 探索問題は手触りのある絵本調、マップと基地は同じ役者・色・素材を簡略化した地図／切り紙調、記録・設定・保護者画面は同じ世界の「探検ノート」調とする。描画密度は変えてよいが、別作品のパステルガラスUIへ戻さない。
- 起動から通常問題、大発見、帰還、再出発、探検基地までの現行visual lineageを `pokko-field-v1` とする。同じ黄色い豆型の身体、広い緑の葉帽子、小さな黒い手足、単純な顔をポッコの不変silhouetteとし、白い長耳、クリーム色の猫、リボン触角の洋梨型、旧マキモドンを同じrunへ混ぜない。visual modeは `world-painted / world-live / observation / field-book / archive / route-map / base-map / legacy` に正規化する。各critical surfaceはlineage ID、surface candidate ID、visual modeをDOMへ出し、差が意図した編集工程だと検証できること。
- `dig-pop-carry-bloom-v3` はcold-open固有のsurface candidateであり、後続surfaceの承認を兼ねない。後続Q4〜Q8の検証候補は `firefly-stumble-bloom-painted-v5`、中立Q7は `firefly-q7-stumble-bloom-v5`、帰還図鑑は `firefly-field-book-painted-v5` とする。大遭遇、Q7、帰還、基地はそれぞれ同一ポッコと直前の因果を保ち、actual app target・同一buildのcritical-path contact sheetで混在0件を確認する。mixed visible lineage 1件以上はrelease FAILとする。
- 起動、オンボーディング、共通ナビ、通常学習、記録、設定のいずれから入っても、表示名、相棒、色、紙面、言葉の調子から同じアプリだと分かることを必須にする。
- 通常学習と探索の問題入力は、視覚統合のために問題数、入力数、確認操作、待ち時間を増やさない。ブランド変更より既存の高速回答テンポを優先する。

### 2.1 目指す体験

**算数で道がひらき、発見と判断が「もう一回」を生むゲーム**

- **即開始：** 通常起動と初回設定完了後は探索ランを直接開き、説明CTAやゲーム選択を挟まない
- **連問優先：** 世界演出は問題の背後で同時進行させ、通常の正解から次問までを追加0タップ・目標650ms以内にする
- **表示と学習の分離：** cold-openの変化段階は保存済みの正解回数から決め、式の答え、演算、planner assignment、`Problem.categoryId` を演出都合で変えない
- **意味のある判断：** 道、発見傾向、資源、帰還タイミングを自分で選ぶ
- **発見：** 毎回少し違う出来事が起こり、そのランの物語が残る
- **回復可能な失敗：** 短期ボーナスや未確定素材を失っても、能力や恒久進行は否定されない
- **学習の保全：** 問題順と復習優先度を Study と共通の学習エンジンが守り、探索演出の都合で別 skill へ差し替えない
- **再挑戦：** 失敗後の待ち時間や長い説明を置かず、すぐ次のランへ進める

### 2.2 設計原則

| 原則 | 説明 |
|------|------|
| Fun First | 最初に「もう一回遊びたいか」を見る |
| 意味のない判断を減らす | 開始前の設定や説明は減らし、ラン中の道・資源・帰還判断を増やす |
| 学習とゲームの失敗を分ける | 不正解は能力評価にしない。ゲーム上の短期結果は持たせてよい |
| 予測できる驚き | 地形ごとの傾向を示しつつ、中身は完全には読めないようにする |
| 山と谷 | 平常時は読みやすく、発見や連鎖では短く強い演出を使う |
| 学習の完全性 | MVP-2以降は、SRS、Due、weak、解放、3問束を探索の裏側で維持する |
| 再開より再挑戦 | 恒久進行は守りつつ、短い失敗からもう一度試したくなる構造にする |

### 2.3 やらないこと（禁止事項）

| 禁止事項 | 理由 |
|----------|------|
| 外部ランキング・課金圧力 | 比較や支払いで継続を強制しない |
| 能力や人格を責める表現 | 自己効力感を傷つけない |
| 恒久的な学習進行の没収 | ゲーム失敗と学習成果を混同しない |
| 長い敗北・待ち時間 | すぐ再挑戦できることを守る |
| ホラー、死、血、敵撃破中心 | 明るい地底の発見世界を守る |
| 常時うるさい演出 | ピークの価値と問題の読みやすさを守る |
| 図形・文章題 | 現行の計算力中心スコープを維持する |
| 保護者向け評価の子どもUI混在 | ゲーム中の羞恥や監視感を避ける |

### 2.4 体験フロー

**Island初回導線（2026-09-07採用）**


**初回起動時の初期化ロジック**
1. **学年基準**: 学年値から算数の基準レベルを決める。`-2: 0`、`-1: 2`、`0: 8`、`1: 10`、`2: 11`、`3: 13`、`4: 14`、`5: 15`、`6: 16` とし、未知の値は `8` を使う。
2. **到達目安**: 全学年に数の基礎〜速さの12択を提示する。従来5択は `q_count: -6`、`q_add: -3`、`q_sub: -1`、`q_col: +1`、`q_mul: +4` を基準レベルへ加え、選択範囲の末尾（順に7/9/10/11/14）を上限とする。九九より先は学年補正を使わず、補遺Cの範囲末尾を使う。算数を選ばない場合は基準レベルのみを使う。
3. **スタートレベル決定**:
   - `mathStartLevel`: 上記の値を **1〜28** にクランプして設定する。学年だけを理由に選択範囲より先を初期retiredにしない。初回/従来初回/プロフィール追加で同じ計算を使い、保存済みプロフィールは再計算しない。

4. **解放状態の適用**:
   - 決定した `mathStartLevel` 以下の算数スキルは **`status = "retired"`** として初期投入する（詳細は 5.6 参照）。
   - `mathMainLevel` と `mathMaxUnlocked` は `min(28, mathStartLevel + 1)` とする。
   - `vocabMainLevel` と `vocabMaxUnlocked` は `vocabStartLevel` とする。
   - `subjectMode`: ユーザー選択に従う（デフォルト "mix"）。

## 4. 操作仕様（入力・スキップ・PC操作）

### 4.1 プロフィール切り替え

- 端末内に複数プロフィールを保持
- 通常起動は最後に使用したプロフィールで探索開始画面を開く
- 切替は **≡ → 設定 → プロフィール管理**

**切替時の挙動（確定）**
- 切替操作を行った瞬間に **現在の問題は破棄**し、即座に新プロフィールの学習対象へ切り替える
- 履歴・記憶状態・統計はプロフィールごとに保持

### 4.2 基本操作

| 操作 | アクション | 結果 |
|------|------------|------|
| タップ | 選択肢 or 数字 | 回答・正誤判定 |
| 左スワイプ | 問題カード | スキップ・答え表示（主にスマホ） |
| ボタン | Skip | スキップ・答え表示（PC代替） |
| キー | `S` | スキップ・答え表示（PC代替）。Escは解答記録を変更しない |
| キー | `0-9` | 数字入力（算数） |
| キー | `Backspace` | 1文字けす（←） |
| キー | `Delete` | クリア（C） |
| キー | `Enter` | 決定（OK） |
| キー | `←` / `→` | フォーカス移動（複数入力時） |
| キー | `1-4` | 4択の選択（英単語） |

### 4.3 回答方式（UI切替）

Study・島の算数は、[02の自動採点](02_math_skills.md#自動採点と確定キー)に従い、整数・小数・分数・商と余りの各欄を桁ごとのマスで示し、最後のマスが埋まった瞬間に正誤を問わず採点する。教材による1桁入力の手動/自動の混在をなくす。筆算も現在段の必要マスが埋まると採点する。通常練習はテンポを優先し、マス数と小数点位置を学習上の足場として提示する。正答一致や入力停止時間では確定しない。桁数・小数点位置そのものの独力判断を測る証拠とはしない。

確定が必要なときは、入力がそろうと同じ位置のEnterボタンが明るい面と二重枠で主操作になる。最初は周囲の光だけをゆっくり2回動かし、その端末で一度手動確定を使った後は静止した強調だけにする。説明文を追加せず、自動採点時のEnterは薄い非操作状態とする。筆算ではEnterと画面上の左右キーを空き領域に置き換え、数字キーの位置を動かさない。保存失敗時の再送は例外として有効にする。動きを減らす設定では最初から静止表示とする。

筆算の誤答は[06の多桁の筆算](06_screen_specs.md#多桁の筆算)に従って部分訂正する。行全体の採点後、正しく入力した数字を残して誤ったマスだけを空け、次の空欄へ自動移動する。誤答・支援の履歴は維持し、段の途中に演出用の固定待ち時間を追加しない。

| 問題タイプ | 方式 | UI |
|------|------|-----|
| 英単語 | 4択タップ | 大きなボタン4つ |
| 算数（単一入力） | 数字入力 | 0-9テンキー + 決定 |
| 算数（複数入力） | 数字入力 | マス + 専用パッド + 決定 |
| 算数（choice） | ボタン選択 | 例：`＜ ＝ ＞` |

（推奨）問題カード内に **科目バッジ（算/英）** を表示。

### 4.4 英単語（4択）の操作ルール（最小）

- タップまたはキー `1-4` で回答

### 4.5.1 問題の定義（Problem）

* **1問（Problem）**: 1回の解答入力（または一連の入力完了）で完結する最小単位。
* 計算の途中経過や、位ごとの分割入力は、それ全体で「1問」とみなす。
* Studyの通常問題は都度生成し、教材リストとして永続保存しない。Exploreのactive runでは、中断再開とimmutable segmentのため、完全なProblemをrun行のcheckpoint / segmentへ一時永続し、run外の教材リストへ昇格しない。

### 4.6 算数：複数入力（あまり・分数・帯分数）の入力仕様（専用パッド）

算数は原則「数字入力（0-9テンキー + 決定）」だが、**入力欄が2つ以上**になる回答形式では、
迷わない入力のため **回答形式に合わせた専用パッド**と **マス（1桁セル）**を用いる。

**用語**
- マス：数字1桁分の入力セル（[□]）
- フィールド：マスのまとまり（商/余り、分子/分母 など）
- フォーカス：現在入力対象のマス（視覚的に明確）
- 専用パッド：0-9、←、C、OK、フィールド切替 など

**共通ルール（必須）**
1. フォーカスは常に視覚的に分かる（太枠／淡い背景／カーソル点滅 等）
2. 数字入力で **次のマスへ自動遷移**する
3. 自動遷移に加え、専用パッドに **手動切替ボタン（←/→）**を併設する
4. マス数は **問題が決まった時点で自動決定**する（原則：正解の桁数から算出）
5. 削除（←）は直感的であること

**A) マス数の自動決定（推奨：正解の桁数から算出）**
- あまりあり割り算（商＋余り）
  - 商：Q = 桁数(商)
  - 余り：R = max(1, 桁数(余り))（余り=0でも1マス）
  - 例：150 ÷ 4 = [□][□] あまり [□]
- 分数（分子＋分母）
  - 分子：N = max(1, 桁数(分子))
  - 分母：D = max(1, 桁数(分母))
- 帯分数（整数＋分子＋分母）
  - 整数：W = max(1, 桁数(整数))
  - 分子：N = max(1, 桁数(分子))
  - 分母：D = max(1, 桁数(分母))

**B) フォーカスと自動遷移**
- 初期フォーカス：先頭フィールドの先頭マス
- フィールド内最終マスまで埋まったら次フィールドへ自動移動
- 最終フィールド最終マスまで埋まったらOK待ち

**C) 手動切替（専用パッド必須）**
- 直ジャンプ切替を用意（例：商へ/余りへ、分子へ/分母へ…）
- 各フィールドをタップしてフォーカス移動できる（推奨）

**D) 削除（← / C）**
- ←：現在マスが埋まっていれば空にする。空なら1つ前へ戻って空にする
- C：全マスを空にし、フォーカスを先頭へ戻す

**E) OK（決定）**
- 未入力マスがある場合：不足マスを強調して進めない
- 全マスが埋まっている場合：組み立てて判定

**F) 出題上限（推奨）**
- 商：最大3桁／余り：最大2桁
- 分子/分母：最大3桁（レベル別に調整）

### 4.7 スキップの扱い

* UI: 問題カードを左スワイプ、またはPCならスキップボタン/キー。
* **制限**: **1問につき1回だけ** 可能（答えを見て次へ進む）。
* **評価**: **不正解（Incorrect）** として扱う。
* **学習への影響**:
  * `strength = 1`（リセット）
  * `nextReview = 今日`（直近で再出題されやすくする）
* **ガード**: 同一項目のスキップが **連続3回** 起きた場合は、当日は出題停止（翌日に回す）。

## 5. 学習ロジック

### 5.0 基本方針（ロジックの分離）

* **科目ごとの最適化**: 算数（運動スキル的）と英語（暗記的）は学習性質が異なるため、**内部ロジックを分離**して管理する。
* **体験の分離**: 初期探索は算数のみとし、英語は既存 `/study` または将来の別ゲームで扱う。
* **用語の統一**: 「復習」「要復習」などの用語は共通化するが、その挙動（強い強制力か、優先度調整か）は科目ごとに定義する。

### 5.0.1 探索ゲームとの境界

- 子どもが選ぶのはルート、地形、報酬傾向、ゲーム上のリスクであり、問題難度そのものではない
- 探索アダプターは Study と共通の算数 planner と既存問題生成を呼び、Due、weak、maintenance、レベル配分、表現フォロー、3問区間を守る
- `due | weak | maintenance | followup | main | plus-one | representation-retry` の全sourceは、Exploreで新しく予約する前に既知curriculum levelが計画時 `mathMaxUnlocked` 以下であることを共通guardで確認する。未知skillと無条件 `count_10` fallbackはfail-closedとし、guardを迂回しない
- planner が run に予約した assignment と実出題 skill が一致した回答だけを、回答ログ、SRS、解放・昇格・苦手判定へ算入する
- 未予約問題、未対応入力の代替、生成失敗時の安全 fallback は `affectsSrs = false` とし、探索イベントだけへ残す
- 学習上の正誤と、ゲーム上の成功・失敗・報酬を別の状態として扱う
- 探索固有の正誤・ペナルティ・問題ゲートは [11_learning_integration_spec.md](11_learning_integration_spec.md) を正とする

### 5.1 用語・概念定義

UIに露出しない内部用語でも、仕様上の基準として定義する。

**用語定義一覧（共通）**

| 用語 | 対象 | 意味 | UI表示 |
|---|---|---|---|
| **wordId** | 英語 | 英単語1語を表す識別子 | 非表示 |
| **skillId** | 算数 | 算数スキル1種を表す識別子 | 非表示 |
| **strength** | 共通 | 記憶・習熟の安定度（1〜5） | 非表示 |
| **nextReview** | 共通 | 次に優先出題される日付 | 非表示 |
| **要復習（Due）** | 共通 | `nextReview <= 今日` の状態 | UIでは「復習」 |
| **overdueDays** | 共通 | 復習期限を超過した日数 | 非表示 |

**strength（忘却曲線）**

| strength | 次回出題間隔 |
|---|---|
| 1 | 1日後 |
| 2 | 3日後 |
| 3 | 7日後 |
| 4 | 14日後 |
| 5 | 30日後 |

**strength 更新ルール（共通）**

| 事象 | 処理 |
|---|---|
| 初回正解 | strength = 1、翌学習日に再確認 |
| 復習期限以降、かつ前回正解と別の学習日の正解 | strength +1（最大5） |
| 同一学習日／期限前の正解 | strengthを維持し、予定済みの復習を先送りしない |
| 不正解／スキップ | strength = 1 |
| 算数 retired | 裏で strength / nextReview は更新継続 |

### 5.2 段階的解放

**解放条件（次レベルを解放）**
* 判定対象：各科目メインレベルの「復習以外」直近20問
* 閾値：正答率85%以上
* 解放成立：最大解放レベルが+1

自動解放で新しく開いた次レベルは、算数・英語とも同時に有効にする。既に解放済みで保護者が無効にしたレベルを、この処理で再有効化しない。

**メイン昇格（有効な次レベル → メイン化）**
* 対象は **有効かつ解放済みのメイン+1** のみ。保護者が無効にした範囲や離れた最大解放レベルへ自動昇格しない。
* **英語**：対象レベルの単語の70%以上で独力の正解が1回以上ある場合に昇格。誤答・スキップだけの語は数えない。
* **算数**：対象レベルで復習以外・スキップ以外の回答が30問以上あり、復習以外の直近20問（スキップを含む）が85%以上正解の場合に昇格。
* 既存のレベル・解放・記録は保持し、条件は今後の自動判定へ適用する。詳細は [29_learning_progression_spec.md](29_learning_progression_spec.md)。

**不変条件（共通）**
1. 解放 (`unlocked`) されていないレベルは有効 (`enabled`) にできない
2. メインレベルは常に `unlocked=true` かつ `enabled=true`
3. すべてOFFになった場合は、メインレベルを自動でONに戻す

### 5.3 出題ロジック（ブロック生成フロー）

島のmixモードは[仕様28の教科切り替え](28_mystic_island_spec.md#教科の切り替え)に従い、固定交互をやめる。3〜6問の予約ごとに、新しい内容の短い継続・有効な復習の必要量・次の一区間への本人の希望を使う。以下の10問ブロックは通常Studyの契約とする。

**基本方針**
* **10問 = 1ブロック** として出題
* ロジックは科目ごとに完全に分離する
* **出し過ぎ防止（共通ガード）**: 1ブロック内で同一 wordId / skillId は最大2回まで。
* 対象範囲の候補数 × 2 がブロック問題数に満たず上限を守れない場合は、出題不能や先頭IDへの集中を避け、出題回数が最少のIDから選んで偏りを最小化する。

**ブロック決定フロー**

1. **英語の復習チェック**（最優先）
   * 条件：英語の「要復習」単語が存在 AND 直近40問中の復習比率 < 50%
   * 判定：YESなら **「英語復習ブロック」** を生成

2. **通常ブロック生成**
   * 算数か英語かを決定（直近40問のバランスを見て不足している方、差がなければランダム）
   * 決定した科目のロジックで「通常ブロック」を生成

### 5.3.3 復習出題時の補助表示（Visual Feedback）

* 復習スキルや以前間違えた問題が出題される際、**問題表示直後に一瞬だけ** 補助ラベルを表示する。
* **目的**: 「なぜ簡単な問題が出るのか」への納得感を与える。
* **仕様**:
  * 文言: 🔁「まえに やったところ」「もういちど やってみよ」
  * 挙動: 0.5秒フェードなどでさりげなく表示し、消える。
  * 頻度: 毎回ではなく、久しぶりの出題や正答率低下時などに限定してもよい。

### 5.4 科目別ロジック詳細

#### A) 英語ロジック（暗記重視）

**英語 出題ロジック（要点）**

| 項目 | 内容 |
|---|---|
| 管理単位 | wordId |
| 復習 | Due を**復習ブロック**で出題（強制力あり） |
| 優先 | overdueDays が大きいもの |
| 通常配分 | 例：メイン50% / -1 25% / -2 15% / -3 10% |
| 選択肢 | 同レベル優先、同訳除外、誤答クールダウン |

解放済みの次レベルがある場合、通常10問のうち最大3問をメイン+1へ割り当て、残りは上記配分で選ぶ。次レベルでは独力の正解がない語を優先し、正解済み語70%による昇格へ自然に進める。未解放・無効のレベルは選ばない。復習ブロックの優先と上限は維持する。島・遊園地の短い区間も同じ対象範囲・正解実績を使い、区間の切り詰めで+1が集中しない上限を設ける（詳細は29）。

旧実装で次レベルが解放済み・無効のまま残る場合は、設定の学習欄で「英語 Lv.Nの練習を始める」を案内する。保護者がメインレベルを戻した状態と区別できないため、無効設定を黙って書き換えず、操作した次レベルだけを有効にする。メインレベル・解放上限・学習履歴はその操作では変更しない。
英語の自動解放で新しく開く次レベルは、同時に `enabled=true` にする。保護者が後から無効にしたレベルは、自動で再有効化しない。

**英語に status がない理由**

| 観点 | 方針 |
|---|---|
| 学習性質 | 記憶・想起（忘却前提） |
| 卒業概念 | 持たない（事故の元） |
| 出題停止 | nextReview による自然低下に任せる |
| 復活 | 間違えたら strength=1 で自動復帰 |

#### B) 算数ロジック（スキル重視）

**算数 status（算数専用）**

| status | 意味 | 出題扱い |
|---|---|---|
| **active** | 現在学習中 | 通常出題 |
| **maintenance** | 忘却防止の維持 | 低頻度出題 |
| **retired** | 十分安定し卒業 | 原則出題しない |

**status と weak の関係**

| status | weak 判定 |
|---|---|
| active | あり |
| maintenance | なし |
| retired | なし |

**status 遷移（想定）**

| from | 条件 | to |
|---|---|---|
| active | 30問以上＆直近10問90%以上＆日を空けた復習でstrength 4以上 | retired |
| retired | 維持確認時のみ | maintenance |
| maintenance | 失敗が続く（将来拡張） | active |

**算数 出題ロジック（要点）**

| 項目 | 内容 |
|---|---|
| 管理単位 | skillId |
| ブロック | 10問＝1ブロック |
| 復習 | **専用ブロックなし**（通常に混入） |
| 優先順位 | Due → 未調整（未出/低Strength） → レベル配分 |
| レベル配分 | +1レベルは**最大30%（上限）** |
| maintenance | retired から低頻度（例：1%） |

通常・+1・自動の表現フォローでは、解放・当日停止・表示対応の条件を満たす `active` または未学習の候補を先に使い、卒業済み候補を混ぜない。同じ範囲にその候補が1つも残らない場合だけ、範囲内の独力の定着練習を通常枠で続ける。これは最終レベルや既習範囲への戻りで出題停止／別レベルへの置換を避ける例外で、回答は通常学習として記録する。1%の維持確認抽選は別枠として `isMaintenanceCheck` を保持する。明示的な誤答直後の支援は必要な表現へ戻せる。

#### B-1) 算数ブロックの中身（教材としての組み方）

算数は英語と違い、**同じ skillId を繰り返すだけでは伸びにくい**。
通常ブロックの中で、`新しい内容` `橋渡し` `復習` `手順理解` を混ぜる。

| 要素 | 目安 | 役割 | 備考 |
|---|---|---|---|
| 新規 / 現在レベル | 40〜60% | いま進めたい本体 | 現在の mainLevel と +1 レベル上限の範囲 |
| 橋渡し / 別表現 | 20〜30% | 絵・表・数直線・逆向きで理解を支える | `Bridge`, `Reverse`, `Strategy` 系 |
| 復習 / weak / Due | 10〜30% | 忘却防止と穴埋め | ただし 1セッション全体で 60% 上限 |
| 手順確認 | 0〜20% | 筆算や途中の考え方を確認 | `Algorithm` の途中手順系 |

補足:

- ここでいう「橋渡し」は、同じ答え領域を別表現で見る問題を指す。
- `手順確認` は毎回必須ではないが、筆算系・誤答多発時は優先する。
- 同一 block 内で、同じ skill family だけに偏りすぎないようにする。

#### B-2) ミニレッスン束（算数専用）

算数では、必要に応じて **3問を1束** とみなす。

| 問 | 役割 | 例 |
|---|---|---|
| 1問目 | Concrete / Bridge | 絵、数直線、表、位取り |
| 2問目 | Symbol / Reverse | 式、穴埋め、対応づけ |
| 3問目 | Mental / Algorithm | 暗算、筆算、途中手順 |

生成ルール:

- 1ブロックに最大2束まで入れてよい。
- 新スキルの初回導入時は、可能なら1束を優先する。
- `weak` な skillId がある場合も、単純再出題より束を優先してよい。
- 束内では同じ概念を扱うが、**同じ見た目の問題を連打しない**。

#### B-3) 失敗時の戻し先（算数専用）

算数の復習は「同じ問題をもう一度」ではなく、**つまずいた種類に応じて戻し先を変える**。

| 失敗パターン | 優先して戻す先 |
|---|---|
| 記号問題で崩れた | `Bridge` 系（絵、表、数直線、位取り） |
| 比較で崩れた | 数直線、位取り、表 |
| 割合・比・速さで崩れた | 対応表、テープ図、逆向き問題 |
| 暗算で崩れた | `Strategy` 系（10づくり、分ける、近い九九） |
| 筆算で崩れた | 途中手順系（くり上がり位置、借り先、部分積、商の位置） |
| 余りで崩れた | `Concrete` / `Bridge` 系（配る、何こずつ） |

戻し方:

- 直後の1問を `representation_retry` にしてよい。
- 同一セッション中に同じ失敗が続く場合は、`mini_lesson_review` を1束入れてよい。
- `Due` より軽い失敗でも、理解不足が明確なら別表現への寄り道を許可する。

#### B-4) 算数専用の再出題ガード

- 同じ `skillId` をそのまま連続で出すのは原則避ける。
- ただし `ミニレッスン束` の中では、同じ概念 family の連続出題を許可する。
- `calc_error_check` などの誤答診断問題は、元問題の直後または2問以内に出すと効果が高い。
- `representation_retry` は、元問題と答えの難度を大きく変えすぎない。

### 5.5 苦手（weak）判定と混入

**weak（苦手）**

| 項目 | 内容 |
|---|---|
| 定義 | 直近成績が不安定な学習対象（内部状態） |
| 目的 | 出題優先度の調整（評価ラベルではない） |
| 判定条件 | 最低5回以上回答 ＋ 直近10回の正答率が低い（<60%） |
| 解除条件 | 直近10回の正答率が回復（>=80%） |
| 混入上限 | 通常ブロックの最大30% |
| UI表示 | しない |

**weak の科目差**

| | 英語 | 算数 |
|---|---|---|
| 管理単位 | wordId | skillId |
| 出題方法 | 復習／通常で優先 | 通常に自然混入 |
| 専用ブロック | あり（復習時） | なし |
| 出題圧 | 強め | 弱め |

### 5.6 初期レベル設定ロジック（Start Level Logic）

初回起動時にユーザーに最適なレベルを提供するためのロジック。

#### A) 算数：到達目安と学年による初期設定

**1. 基準レベル（Base Level）**
* 学年ごとに「基準となる算数レベルID」を内部定義する（補遺C参照）。
* 例：小学2年生 → Lv.X（足し算筆算付近）

**2. 補正（Adjustment）**
* 初回質問「どこまでやった？」の従来5択は、学年基準に補遺Cの補正を加え、選んだ範囲の末尾で上限を設ける。
* わり算・小数・分数・割合/平均/比・速さは、学年にかかわらず補遺Cの範囲末尾を使う。小2でも先取りした範囲を選択でき、小6の九九選択だけで小数を既習扱いにしない。

**3. スタートレベル適用（Impose）**
* 補正後のレベルを `mathStartLevel` とする。
* **解放ロジック**:
  * Level 1 〜 `mathStartLevel` まではすべて `unlocked=true` とする。
  * `mathStartLevel` の1つ上を `mainLevel`（現在の学習対象）とする。
  * `maxUnlockedLevel` も `mainLevel` と同じにする。
* 「簡単すぎて退屈」という離脱要因を防ぐため、既知の範囲はスキップさせる（ただしいつでも戻れる）。

#### C) 安全装置（Safety Net: 内部仕様）

自己申告は過大評価になりやすいため、**初期設定直後の一定期間** は以下の比率で下位レベルを混在させる（UIでの説明は行わない）。

* **混入比率（目安）**
  * `mathStartLevel` : 90%
  * `-1 Level` : 5%
  * `-2 Level` : 5%
* **解除**: 正答率が安定して高い状態が続けば、自然にメインレベルのみに収束させる（通常の苦手判定ロジックに委ねる）。

#### B) 英語：簡易推定

* 英語は算数ほど細かく刻まない。
* 学年（中学生判定など）と「経験有無」のクロスで、初期単語レベル（Lv.1 or Lv.5 or Lv.10程度）を決定する。
* 基本は Lv.1 からの積み上げを推奨するが、経験者のために多少のスキップを許容する。

## 6. テスト・復習機能（定期テスト・にがて復習）

※ 詳細は **[06_screen_specs.md](06_screen_specs.md)** を参照のこと。

### 6.1 概要

従来の「ちからチェック」「特別ちからチェック」「紙テスト」は、**名称を「定期テスト」に統一**し、役割ベースで再編する。
**測定（テスト）** と **準備（にがて復習）** を明確に分離する。

| 機能 | 目的 | 問題数 | 位置づけ |
|---|---|---|---|
| **にがて復習** | **準備** | 10問 | テスト前の練習。思い出すことが目的。 |
| **定期テスト** | **測定** | 20問 | 正式な確認。アプリ（オンライン）でも紙（オフライン）でも同一内容。 |

### 6.2 にがて復習（新設）

- **位置づけ**: 定期テスト前に行う準備用の復習モード。
- **目的**: 理解度測定ではなく、「一度触った」「思い出した」状態を作ること。
- **問題数**: 10問固定。
- **出題範囲**: 定期テストと同一（現在のメインレベルに属するスキル集合）。
- **優先順位**: `weak`（苦手） > `strength`低 > テスト範囲内の重要スキル。
- 算数・英語とも、範囲外のDue／maintenance／表現フォローを混入しない。当日の3連続スキップによる停止を守り、対象不足を別レベルで埋めない。
- 自動テストが受験待ちなら保存済みテストのレベルを優先する。候補が少ないときは最少出題の項目から10問を組む。全候補が当日停止なら出題せず記録へ戻る。途中で3回目の連続スキップに達した項目は残りの予約から外し、その回の復習を短縮して終了する。
- **評価**: 点数・合否なし。時間計測なし。スキップ可。
- **データ影響**: `weak` 判定・復習優先度の更新は行う。

### 6.3 定期テスト（アプリ内・PDF）

**位置づけ**: 学校の定期テストに近い正式な測定。
**目的**: 子ども・保護者が「できているか」を納得できる確認手段。
**問題数**: 20問固定。
**出題内容**: 範囲内から偏りなく均等またはランダムに出題（`weak` 等の重み付けはしない）。
**実施方法**:
    - **オンライン（アプリ内）**: 時間計測あり、正誤結果確認あり。
    - **オフライン（PDF出力）**: 家庭での印刷用。オンラインと **同一テスト内容** を出力。
**結果表示**: 実施後に **点数（正解数/20・スコア）と所要時間** を表示する。

**家庭用印刷（2026-09-07改善）**:
- 設定のテスト欄から20問をプレビューし、ブラウザーの印刷／PDF保存を使う。問題のみ・解答のみ・両方を選べ、A4で問題途中を分断しない。
- 算数の図・空欄・複数回答の意味と英語の4択を保持する。数える問題を「りんご3こ」のような答え入り説明へ置換しない。
- 採点待ちは教科ごとに1件。完全な問題集合をプロフィール所有のsnapshotとして保存し、レベル変更やアプリ受験の後でも同じ内容を再印刷できる。旧データでsnapshotがない場合は内容を推測して再印刷せず、点数入力または明示的な取り消しを案内する。
- 作成／再印刷だけではSRS・Due・進級・回答数を変更しない。採点は最新プロフィールに対して1回だけ記録し、別の設定・学習結果を上書きしない。取り消しは紙の採点待ちだけを外し、学習履歴を変更しない。
- 自動出現中のテストを紙で作成した場合は `auto` として保存する。採点時に同一の問題snapshotがまだ自動受験待ちなら、その待ちを解消して7日のクールダウンへ移る。別の新しいテストの待ちは解除しない。採点した現在の問題集合は次回作成で更新できるように解放する。

#### 6.3.1 出現モード（トリガー）

**A. 自動出現モード（システム判定）**
- **教科別**: 算数・英語で独立して判定。
- **クールダウン**: 同一教科で自動出現した場合、7日間は再出現しない。
- **出題範囲**: 原則「現在レベル」。※レベルアップ同時出現時は「旧レベル」。

**[算数トリガー]** (OR判定)
1. **Pre-LevelUp**: 現在レベル達成率 90%以上
2. **滞留 (Slow)**: 同一レベル14日以上滞在 OR 累計200問以上
3. **苦戦 (Struggle)**: 直近14日で120問以上学習 かつ 達成率70%未満

**[英語トリガー]** (OR判定)
1. **Pre-LevelUp**: 現在レベル達成率 85%以上
2. **滞留 (Slow)**: 同一レベル14日以上滞在 OR 累計150問以上
3. **苦戦 (Struggle)**: 直近14日で100問以上学習 かつ 達成率65%未満

**B. 手動出現モード（保護者操作）**
- **目的**: 任意のタイミングでの確認。
- **制限**: 回数制限なし、クールダウン無視。
- **出題範囲**: 原則「現在レベル」。レベルアップ直後の場合は「直前レベル（旧）」を選択可能（実装依存）。

#### 6.3.2 評価・記録仕様

スコア（点数）は保存するが、**レベルアップ条件には使用しない**（あくまで「評価履歴」）。

**保存項目（必須）**:
- 実施日時
- 教科（算数／英語）
- 出題範囲ID（レベルID）
- 実施モード（自動／手動）
- 実施方法（オンライン／紙）
- 正解数 / 20問
- スコア（点数）
- 所要時間

## 7. データ構造（ローカル保存）

### 7.1 方針

* **完全ローカル（Local Only）**: 全データは端末内 IndexedDB に保存。
* **アカウント不要**: ログイン機能は持たない。
* **同期なし**: 複数端末間の同期は行わない（将来検討）。
* **バックアップ/復元は扱わない**: 仕様上の機能対象外とする。
* **探索学習接続**: run に予約した planner assignment を持つ回答だけ、既存プロフィール・学習ログ・SRSへ原子的に反映する。未予約 fallback は探索イベントだけを保存する。
* **探索正式導入**: 探索ラン、発見、イベント、設定は `UserProfile` へ大量追加せず、Dexie version 5以降の専用テーブルへ分離する。
* **移行安全性**: 既存プロフィールと学習ログを破壊する移行を禁止し、詳細は [13_data_storage_migration_spec.md](13_data_storage_migration_spec.md) に従う。
* **学習記憶の正本**: skill / word 単位のSRS状態は `memoryMath` / `memoryVocab` を正本とする。`UserProfile.mathSkills` / `vocabWords` は互換用ミラーであり、プロフィール取得時に正本テーブルの同一IDで上書きして問題生成へ渡す。
* **回答保存の原子性**: 探索の1回答では `exploreRunEvents`、run集計、`logs`、SRS MemoryState、プロフィール内の直近履歴・連続日数・メインレベル回答窓を同一Dexieトランザクションで保存する。保存できない場合は問題を進めず、同じ回答・同じattempt keyから再試行できるようにする。
* **weak移行**: `isWeak` はMemoryStateへIN/OUTヒステリシス状態として逐次保存する。旧行は最初の参照時に全履歴から一度だけ復元し、回答書き込みと競合しないトランザクションで正本へ反映する。
* **削除**: プロフィール削除時は、そのIDのプロフィール、回答ログ、算数・英語MemoryStateを同一トランザクションで削除し、同IDのいきもの状態・図鑑も端末保存から除く。「全データをリセット」は全プロフィールへ適用する。

### 7.1.1 初期化（プロフィール作成時）
* 2.4「初回起動時の初期化」に従う。
* `schemaVersion` はアップデート時に段階移行できるように保持する。

### 7.1.3 ログ保存方針（Logging Policy）

* **Problem（個々の問題）**: Studyでは都度生成して教材リストとして永続保存しない。Exploreのactive runに限り、checkpoint / immutable segment / retryの正本としてrun行へ一時永続し、完了済みrun外の再利用問題集にはしない。
* **SkillStats（累積統計）**: `memoryMath` / `memoryVocab` で永続保持する。
* **AttemptLog（全回答履歴）**: `logs` に保存し、SRS・統計・旧weak状態の復元に使う。
* **RecentAttempt（直近履歴）**: `UserProfile.recentAttempts` に **直近300件** をリングバッファで保持し、出題クールダウンや直近判定に使う。
* **Islandの前向きな観測（2026-09-08採用、次段階の実装契約）**: 既存のIsland学習操作eventへ、具体的な予約問題・筆算途中段/全体完了・操作直前の保存済み支援・実際に観測できたDOM表示と要求受理時刻を任意情報として添える。正誤・scopeは保存側の実slotと採点から作り、観測値を採点/SRSの正本にしない。旧行・他経路・未観測はunknownで、独力や定着を推定しない。新table/schema、汎用AttemptLog、SRS・Due・日次・streak・進級・報酬の計算を変えず、観測時計を既存計算へ渡さない。同一要求の再送は最初のaction/観測snapshotを保持し、実保存例外の原子rollbackを維持する。詳細と検証境界は [島仕様の観測契約](28_mystic_island_spec.md#prospective-island-observation) に従う。

### 8.1 PWA更新契約

- 更新識別子 `version` はコミットの `revision` と分離し、同じコミット・異なる公開設定の再ビルドも識別するためbuildごとに一意とする。`version.json` とアプリに埋め込む版は同じ値を使う。オンライン復帰・安全なcheckpointで新しい版を自動適用し、利用者による更新確認やキャッシュ削除を要求しない。
- 起動中のPWAは、起動時、復帰時、再接続時、フォーカス時、SPA内の画面遷移時、および表示中は最大60秒間隔で新しいbuildとService Workerを確認し、手動キャッシュ削除なしで新しいbuildへ移る。オフライン中に確認できなかった更新は、次の再接続・復帰・フォーカス・画面遷移のいずれかで再確認する。
- Service Workerの通信が遅れても版確認を止めない。版確認は10秒で打ち切り、次の確認契機で再試行する。通常のSW更新では、新しいService Workerがページを制御してから再読込する。
- 版の差だけが残った場合は、オンラインかつ表示中に更新用URLのHTMLを取得できることを確認し、安全なcheckpointでネットワークから再読込する。更新用URLは古いapp shellへのnavigation fallbackから除外し、復旧のために既存Service Workerやoffline cacheを削除しない。同じ版への復旧再読込はタブ内で1回に制限し、不整合な配信による連続reloadを防ぐ。
- `/onboarding`、`/study`、`/explore`、`/park`、`/island`、`/battle/play` はpointer/key操作後の同一進行中セッションだけ更新reloadから保護する。各画面の初回表示から最初の操作までは更新を適用できる。
- 更新を進行中セッションで検出した場合は即時reloadせず、保護対象外の画面へ移る、別の保護対象セッションを開く、または同一画面の結果・休憩を確認して「もう一回」「続ける」「cancel」を選んだ安全なcheckpointで一度だけreloadする。結果・報酬画面が表示されただけではreloadしない。React RouterのSPA遷移はnative `hashchange` に依存せず観測する。
- 安全なcheckpointは、そのrun・テスト・プロフィール更新など中断できない保存が完了した後にだけ公開する。reload後はcheckpointの行き先または同一画面を保ち、子どもに終えた操作を繰り返させない。
- 回答、テスト結果、探索runなどのcritical persistenceが1件でも進行中なら、保護対象外または別routeへ移っても更新reloadを解禁しない。必要な保存がすべてsettleした後に更新判定を再開する。
- PWA更新処理はIndexedDB、localStorage、ユーザーデータ用cacheを削除しない。回復処理で削除できるのはアプリが管理するService Worker cacheだけとする。
