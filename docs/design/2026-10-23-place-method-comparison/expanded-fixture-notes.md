## 比較できることと、広さに左右されること

[構築方針](../../product/island-construction-strategy.md)は、native-05 の全島美術を通常のゲームで編集・育成できることを目標としつつ、小さい島も一つの景色として成立させると定めている。[今回の契約](README.md)も、初期島に多数の家や森を増やすことを要求していない。

したがって、30セルと native-05 の地区数・家や森の総密度・移動距離は直接比較できない。一方、岸が一律の箱に見えないこと、使える上面と低地の大小、登り口の分かる斜面、物の接地、主役と空いた場所の関係は、初期島でも比較できる。面積不足を理由に、この局所の美術条件を免除しない。

参考自体の [README](../2026-10-10-island-final-3d/README.md) は、15軒はゲームの戸数上限でも合体レシピでもないと明記している。また、過去案は面積や樹種を増やしても同型反復が残ったため、大きな形と素材を作り替えた。現在の方式に土地を足せば参考へ届く、という根拠にはならない。

## 一つだけ追加する診断入力

49 の状態を本人の保存から分離した in-memory fixture にコピーし、通常の拡張 command を east → west → south の3回実行する。現行 `landBounds` では x=-3..8、z=0..7 の96セルになる。通常取得・通貨・学習・DB保存の成功証拠には使わない。banner に診断であることと reload でリセットされることを明示する。

既存の所有 ID、配置、成熟、住人、旧30セルの高さは変更しない。花とベンチを増やさず、家の尺度も変えない。新しい土地だけに次の形を作り、「高い庭 → 幅のある斜面 → 低い水際」が一つの景色になるかを見る。

| 新しい土地の範囲 | 高さ | 役割 |
| --- | --- | --- |
| x=0..2, z=5..6 | +3 | 既存の高庭につながる広い上面 |
| x=-1 と 3, z=5..6、および x=0..2, z=7 | +2 | 上面から下る肩 |
| x=-2 と 4, z=5..6 | +1 | 広い裾 |
| x=5..7, z=4..7 | 0のまま | 高庭の横に残す低い余白 |
| x=8, z=4..6 | -1 | 低地から海へ開く水際 |

個々の command が支持・通行の理由で拒否された場合は、その事実を記録し、検査を迂回して高さを注入しない。上表は美術上の入力仮説で、合法性を事前に保証した recipe ではない。

A / F / H に同じ拡張入力を与え、光・カメラ・品の尺度を一致させた全景を比較する。一つの診断用比較画像に3方式を並べ、旧30セル部分は同じ家の見かけの尺度で確認できる crop も添える。全景を fit した結果、家が小さくなったことを地形の改善と数えない。新しい土地も彫るため、これは広さを与えたときの表現能力の診断であり、面積だけを変えた厳密な因果テストではない。

## この一試行で投資先を決める

- 広さを与えても箱台・長い壁・同型のうねりが残る場合、土地追加や係数調整を継続しない。次の制作単位を「使える上面、登り口、裾、岸を一緒に持つ場所」へ変え、描画・支持・経路がその共有床を使う設計を比較する。
- 広い入力で大小の場所と連続した登り口が成立し、旧30セルだけで窮屈になる場合、必要な幅を作れる道具と初期島の使える余白を検討する。初期島の美術未達は残す。
- 地形は成立しても空の台地にしかならない場合、次の不足は物量ではなく、所有物の配置から場所がまとまる規則である。小物や家を増やして判定を通さない。

試作の +3 は約0.54mの高さに限られる。native-05 の大きな上下関係が届かない原因は、面積不足とは別に高さ範囲・造形単位にもあり得る。今回の広さの試験だけで方式全体の能力を断定しない。正本に従い、試作の3段を製品の完成上限として固定しない。
