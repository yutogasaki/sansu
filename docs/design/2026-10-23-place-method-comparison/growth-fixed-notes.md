# 固定 cardinal 基底の拡張診断

2026-10-22 21:19 UTC。比較候補 `fixed-cardinal-grid-v1`。製品sourceと既存F2は変更していない。`growthFixedFieldTransform` を既存 `terrainMethodTransform` の後へ適用する。ブラウザは `growthField=fixed`、Nodeは `{alwaysFixed:true}`。取得の一列初期化は別の `growthTrial=inherit` として併用した。形状の切替をrevisionへ含める。

## 原因と変更

F2は外周で元のA補間を使い、内部では平らな上面を作るcardinal補間を使う。外周の判定が現在のland boundsなので、同じ保存値・同じ座標でも取得後に補間方法が切り替わる。また現在外周の三角形だけを旧6gridに合わせる処理も、取得後に外周でなくなると外れる。

この候補では、全ての座標に同じ `.30〜.70` cardinal基底を使い、三角形も常に12gridにする。取得時の隣接一列継承によって、旧端の外半セルに使われる係数の延長を保つ。初期島だけを特別に固定する処理はない。保存データ・owner配置を見て基底を曲げない。

## 結果

コマンド：`fnm exec --using=22.23.3 node docs/design/2026-10-23-place-method-comparison/growth-fixed-check.mjs`。実UI入力33のコピーに明示的な試験残高100000を与え、通常expandを実行した。保存33・各sourceのSHA256と日時はJSON内。UI購入・学習経済の証明ではない。

| 取得順 | F2＋一列継承：旧dry喪失数 | 固定基底＋一列継承 | 旧到達点喪失 |
| --- | --- | --- | --- |
| 西→東→南 | 3 / 21 / 11 | 0 / 0 / 0 | F2は `0,3.5` と `5,2.5`、固定基底は0 |
| 東→西→南 | 8 / 10 / 11 | 0 / 0 / 0 | F2は `5,2.5` と `0,3.5`、固定基底は0 |

測定は旧取得矩形の外半セルまで、0.1間隔。花・ベンチ・p1の支持は全段階で成立し、旧Undo/Redoと入力stateは不変。純粋なoffsetの旧範囲差は0。固定基底では南取得後の旧サンプル床差も0だった。

西・東の取得には最大0.185117496mの上昇が残る。初回拡張で有効になる基面と、現在桟橋位置に依存するfoundation maskが別の原因。今回の固定基底を「どの取得でも完全に床不変」とは呼ばない。

## 採用できない点・未完の点

**初期F2からの切替は同じ地形にならない。** 広域サンプルの最大床差は0.242546705m。所有矩形外で新しくdryになった点が4、失われた点が18あった。新dry例は `(6,2.7)` 高さ−0.343438111m、`(-1,3.3)` 高さ−0.352712397m。0.1grid上の点数であり正確な面積ではない。初期F2の外周を維持する制約に反するため、そのまま採用する候補ではない。

負の開口では、明示fixture `(0,3),(0,4)=-4` を西取得し、旧開口0〜−0.5と新隣接一列はwetを維持した。ただしx=−1.2でdryに戻り、新二・三列目を横切って海へ続く保証はない。所有物を除いた反例fixtureであり通常UIで作れた状態という主張ではない。この問題は固定基底では解決しない。

現在の取得外基面は西へ向けて高くなるため、全新列へ同じ負offsetをコピーするだけでも、必ず海面以下になるとは限らない。取得時に「入口をどこまで延長するか」を設計し、同じ保存offset範囲で実現できない場合を明示する必要がある。固定支持を削る、旧入力を無断変更する、裏で水面を描くだけで済ませる、という修正はしない。
