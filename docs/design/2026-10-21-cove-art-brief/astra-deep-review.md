# 一角の再検討：部品の移植から、使える場所の制作へ

2026-10-21 JST。「もっと深く検討して」に対する追加レビュー。[前回](astra-review.md)を履歴として残し、以下を今回の推奨とする。親仕様の変更・美術の採用・本体実装ではない。

**前回の配置図を、そのまま次の完成案として制作することは勧めない。native05の再利用は維持するが、制作単位を「家と六本の木」から「木陰から玄関前を通り、同じ岸へ歩ける場所」へ変える。** 素材を選ぶ問題と、場所を成立させる問題を分ける必要がある。

今回行ったのは、既存の製品契約・実装との再照合、前回の配置を実キットで描く12画角の診断、高さ操作の数値検討。この診断はアプリでも次の遊べる候補でもない。地形編集、経路、児童理解、再訪を新たにPASSとしていない。

## 1. 前回から変える判断

| 前回の提案 | 再検討後 |
| --- | --- |
| キット＋同じ高さ場から地面・支持・経路を作る | 方向は維持。ただし本体には既にキット、共有world、複数の床がある。別の高さ場を新設する話にしない。欠けている場所の構成を、その世界へ戻せる形で制作する |
| 図の座標で家・六本・湾を置く | **対照配置へ格下げ**。投影上ぽこもこが見えることは確認できたが、木陰と玄関前の関係まで成立した証拠ではない |
| 帰路を切る編集は事前拒否 | **一律の規則としては撤回**。支持を壊す危険と、直せる不通を分ける。現在いる相棒を危険な状態にしない条件は残す |
| 一段を `.14〜.18` 程度へ小さくする | **既定の推奨値としては撤回**。歩く斜面の勾配と、海を露出させる操作の手応えを別に調整する |
| 近景では顔・両耳が必ず見える | 観察中は横顔でもよい。**相棒→対象の向きが読めること**を優先し、顔の発見性は別の場面で確認する |
| 一角が通ってから次へ進む | 今回の制作単位として維持。ただし一角の合格は、全島・成長・別配置への適用可能性を証明しない |

この訂正は消極化ではない。強い岸の変形、木陰を通る行動、本人が直す余地を残すために、禁止と微調整へ寄りすぎた部分を戻す。

[前回の配置図](astra-evidence/corner-plan.png)の家・六本・尺度・向きを、実native05 meshと既存ぽこもこで描いた。所有保存からの復元ではなく、明示した診断用配置である。

- 390×844と768×1024。canvasはそれぞれ390×570、768×780、DPR 1。
- 俯瞰37°／近景32°、方位0°・30°・60°。光と素材と配置は共通。
- 俯瞰は地面と部品のboundsを収める診断用fit、近景の水平幅は3.1。アプリのcamera実装ではない。

ここから判断を三つに分ける。

**人物の発見性について、前案は捨てるほど悪くない。** 調べた方位では木に隠れず、近景も作れる。「現物で試すと必ず隠れる」といった反論は支持されなかった。ただし全周や移動中、服の差、UIを含む評価ではない。

**画素の最低値は、構図の合否を代行できない。** 近景0°では人物は74pxあるが、家の一部が画面左で切れ、相棒は湾へ向く横顔になる。30°は家と相棒を一緒に見やすい。方位60°では対岸の木と岸が重なり、全景の湾の見え方が変わる。大きさ・顔・対象・帰る方向を別々に確認する必要がある。観察中に正面顔を強制すると、見ている対象との関係をかえって壊す。

**この診断は、前案の完成美術を評価するものではない。** 丘や地面の仕上げを省いた自分の診断画像を根拠に、「native05では足りない」「前案の丘も無効」とは言えない。一方、部品の置換だけで、樹冠の下の居場所や生活の道まで移植されるわけではないことは見える。次は省いていた地形・木陰・玄関前を、飾りではなく同じ場所の構造として作る必要がある。

## 3. 目標画像の魅力は、どこに宿っているか

[native05原本](../2026-10-10-island-final-3d/whole-island-render.png)には、少なくとも三つの異なる尺度がある。小さい家と人物、家々を包む木陰や水庭、島全体を特徴づける大樹や入り江である。普通の家と普通の樹種だけを抜き出すと、最初の二つの接続も、最後の固有性も自動では付いてこない。

見た目の部品より、次の関係を転写したい。

| 原本から残す関係 | 一軒・六本での最小形 | 代用しても届かないもの |
| --- | --- | --- |
| 大きな自然の下に小さな暮らしがある | 家の片側と玄関前が同じ木陰に属し、冠の下を抜けられる | 家の周囲に等間隔で六本を置くこと |
| 空いている場所に役割がある | 入口の前庭、通る帯、水を眺める岸を区別できる | 空地の全面を草・石・花で埋めること |
| 手前と奥で別の行き先が見える | 低い水際と奥の木立が、同じ道からつながる | 背面を一様に高くすること |
| 材料が違えば光の受け方も違う | 葉の量感、丸い幹、家の縁、水の滑らかさ、湿った岸の差 | 全面へ同じノイズや発光を掛けること |
| 景色が自分の行為を受け止める | 自分が作った岸が残り、同じ相棒がその場所を使う | 編集ごとに鳥や光が一律に出ること |

一軒・六本という制約は、**小さい所有量で場所を作れるか**を見るにはよい。しかし「扇の大樹・鉱石泉・透ける殻を含む全島の幻想性」の縮小合格試験にはならない。ここを混同すると、小さな庭へ大樹の装飾を足すか、大樹のない庭を永遠に不合格にするかの二択になる。

今回の庭は「木陰と家と水際がつながる局所」を評価する。全島の固有性は別に残る。なお、[実装のcompact grove](../../../src/components/island/growing/native/nativePlaceGrove.ts)は、authored世界・成熟したP02 cluster・ちょうど四つの実所有木・整数2×2・支持床などの条件を持つ。六本あるという理由だけで扇葉と空洞幹を追加できない。条件を満たす別配置の比較は将来可能だが、今回の絵を華やかにするための無償の主景にはしない。

同じように、キットの材質を使えば原本の照明も移るわけではない。[原本のexport](../2026-10-10-island-final-3d/build-final-scene.py)はcameraとlightを含めていない。今回の光も診断用であり、色の見え方の差をmeshだけの責任にはしない。まず同じ昼の光で形と接地を比較し、その後で接触影と素材差を詰める。

## 4. 制作方法の選択を、既存実装に合わせて具体化する

**既存キットを核に、岸・根元・玄関前・通行空間を一体で設計する方法を選ぶ。** これは既存の[島構築方針](../../product/island-construction-strategy.md)を、一角で具体化する判断であり、新しい全島生成器の提案ではない。

本体の[sceneLayout](../../../src/components/island/growing/sceneLayout.ts)は既にworldの床とanchorを参照し、[worldFloorGeometry](../../../src/components/island/growing/worldFloorGeometry.ts)は評価済み床の頂点と面を描いている。前回の「同じ地表を使う」は必要条件の再確認にすぎず、未実装機能を発見したことにはならない。

さらに、**共有するのは一つの世界定義であって、島中を一つの高さ関数にすることではない。** 入り江の地面にはheightfieldを使えても、回廊・橋・空洞の上下には別の床と接続が必要になる。床の存在と所有anchorも同じではない。表示用にy座標を取得できるだけで、そこへ立てると判断しない。

| 工程 | 今回残すもの | 追加・修正を限定するもの |
| --- | --- | --- |
| 木と家 | 原本mesh・材質・比例。適用時はIDから決まる樹種、本人の色、成長を保持 | 根元と地面の接合、玄関前の支持。元mesh全体を非等方に伸ばして地形へ押し込まない |
| 岸 | 編集できる地表と一定の海面、同じ床判定 | 低い岸へ降りる斜面、土の厚み、上面と側面の連続。制作した断面を実床へ反映する |
| 木陰 | 元の幹と成熟に基づく樹冠 | 幹・枝・冠の関係と、その下の通れる空間。枝を足しただけで床や利用実績を作らない |
| 場所 | 家前→木陰の縁→水際という関係 | 通行を塞がない空き、入口から外へ出る向き、相棒が止まる支持面 |
| 光 | 最初は全比較で同じ昼の設定 | 原本の見た目を失う接触影・材質差を局所で修正。夕景で問題を覆わない |

現在のkitは材質ごとにmeshをまとめている。柳の「曲がる枝だけ」を安全に調整できる接続点が、そのまま編集可能な部品として露出しているとは限らない。必要ならBlenderで元の形を保つ派生部品を作り、根・枝・冠の接続点と許容範囲を付ける。ただし**診断前から汎用パーツ体系を大量制作しない**。最初の実画面で、どの接合が本当に足りないかを一つに絞る。

## 5. 自由編集と、美しい景色を両立させる範囲

任意の子どもの配置を許し、毎回同じ完成構図を保証することはできない。保証したいのは、選択の結果が消されず、物が同じ物として残り、原因と回復手段が読めることである。本人の好みと異なる配置を、作者の美術点のために修正してはいけない。

前回の「帰路切断を拒否」は、この線を越えやすい。[憲法§3.1](../../../CONSTITUTION.md)は通れない・届かない配置を許し、理由と直す手段を求めている。現試作にも、届かない場合に道をつなぎ直す案内があり、[小島の森の実験](../2026-10-21-island-shape-experiments/README.md)は分離と再接続を扱っている。

| 状態 | 次の一角での扱い |
| --- | --- |
| 家の基礎・木の根・現在の足の支持を失う | 初期の試作では予告時に止める。必要な支持域を見せ、移動や別位置の編集で解けることを示す |
| 無人の行き先への道が切れる | 直せる状態として残せる。到達不能な行動を開始しない。道を戻す／編集を戻す手段を使える状態に保つ |
| 相棒がいる陸から家への帰路だけが切れる | 一律許可もしない。安全な滞在と、そこで使える確実な回復手段を先に成立させる。それがない初期候補では、この場合を限定して拒否する |
| 木が入口を隠す・見た目が不格好になる | 見た目だけを理由に編集を拒否しない。本人が選べる画角・移動で直す。カメラも所有物も勝手に整列しない |
| 共同形の条件を失う | 個体の所有・成熟を保持し、成立する通常形へ戻す。報酬や住人を取り上げない |

「次の三つの撮影用編集は帰路を残す」ことと、「全ての編集で帰路を強制する」ことは別である。E1〜E3は正常系の比較として残せるが、禁止の多い試作を自由編集の成立と呼ばない。

Undoにも同じ区別が必要だ。全地形を戻す前に歩いて家へ帰る案は、すでに道が切れていたら使えない。安全な立ち位置を含めた復元順序、または明示した回復手段を決める必要がある。家前への瞬間復帰を黙って行い、自然な生活の演技が成立したことにはしない。

また、現行契約は取得済み床を海へ取り上げない。自由掘削を本体へ入れるなら「所有権は残るが床は水になる」を許すかという別の製品判断がある。今回の隔離試作は、その判断を済ませたものではない。

## 6. 地形操作の手応えを弱めない

[実コード](../2026-10-21-living-cove/terrain.mjs)では、level 0→1の高さ差は`.9`、1以上の一段は`.57`である。前回の説明は後者に偏っていた。水位は`.08`、平地は約`.42`。ここを一律`.14 / .16 / .18`ずつ下げる仮定なら、水面より低くなるまでそれぞれ3 / 3 / 2回かかる。

一方、間隔`.7`のsmoothstep補間は、表示を細かくしても緩い坂にはならない。一方向の孤立した段差を計算すると、中央から`.13`離れた足の検査点との高低差は、上段`.57`で約`.151`、海岸`.9`で約`.239`。現試作の支持許容`<.13`を超える。これは単純化した断面の計算で、島の全経路の測定ではない。[計算条件と結果](astra-deep-evidence/height-analysis.json)

ここから導くのは「全てを低く、滑らかにする」ではない。

- **歩く帯**は、実rigの幅と支持判定に合う斜面・平場にする。
- **削った岸**は、歩けない断面を含んでよい。陸と海が変わったことを読ませる。
- **盛る／掘る操作**は、予告した範囲と結果を一操作で確定できることを先に試す。小さな高さ差や広いbrushのどちらがよいかは、その操作結果で決める。
- 海につながる岸の露出と、陸の内側の穴は区別して検討する。一枚の海面が見えたことだけで、「水が流れ込んだ」「池が生まれる規則」を実証したことにはしない。

次の初手は前案E1の「湾奥を掘る」でよい。ただし受入は段数ではなく、入力した同じ場所に、指せるほどの岸の変化が残ること。斜面を作るための整地操作を後から何度も要求するなら、その負担自体を問題として扱う。

## 7. 次に制作する一角と、最小の行動

次の推奨は**片岸を家と木陰のまとまりにし、反対側を低く開いた入り江**。家・六本・相棒という材料制約は維持する。前案の座標は対照として保存し、移動は制作中の明示fixtureで行う。本人の所有配置を変更する提案ではない。

家の入口と観察点を先に固定し、その間に必要な乾いた歩行空間を置く。次に、二〜三本の冠が家の片側を包み、幹の間から岸が見える関係を作る。残りの木は対岸と奥の厚みを担うが、六本全てを等しく目立たせない。近景で冠の上が切れてもよく、入口・足元・見ている水際を優先する。俯瞰で全体へ戻れることは維持する。

ただし、これも未制作の推奨である。正面の庭、片岸の木陰、湾を両岸で包む庭という三つの構成が未決なら、同じ材料・同じ光・同じcropの粗い比較で選ぶ。仕上げる一角は一つに絞り、多数の完成島や細部制作へ広げない。今回の12画角は前案のcamera診断であり、この三構成を比較済みという意味ではない。

動作の中心は、前回の「掘る→見に来る」を少し厳密にする。

**「自分が変えた岸が残る。その岸へ同じ相棒を呼べる。自分でもう一度変えたり、戻したりできる。」**

一回の呼出で、道の先に行き、対象へ向き、足を止める。この連続が成立してから、小さな前傾を足す。歩行の最後まで等速で、到着時だけ角度を切り替えると、体の演技を増やしても機械的に見えやすい。減速・向き・接地の接続を優先する。

波紋は必須の報酬にしない。土と水際の変化だけでは場所が伝わりにくい場合に、その水域に収まる短い応答として足す。陸を盛った時にも同じ波紋、編集を拒否した時にも成功演技、離れた水へ関係なく向く動作は、因果を弱める。

相棒を呼ぶために毎回編集を止める、呼出が毎回長い、歩行完了まで次の入力を受けないなら、景色が良くても遊びの流れは弱い。連続編集中は結果を短く返し、観察を本人が選ぶ時に演技を使う。単発の10秒動画だけで、この繰り返しの良し悪しは判断できない。

## 8. 次の比較で、何を反証できればよいか

次案の実装前に全ての将来ケースを増やす必要はない。前回の正常系E1→E2→E3→Undo/Redoと、以下の境界を同じ候補で確かめる。

| 問い | 反例の作り方 | 失敗した時に変えるもの |
| --- | --- | --- |
| 本当に部品が場所になったか | 390の俯瞰で、コピーなしに玄関・木陰・水際の関係を見る。原本の該当局所と並べる | 位置関係・冠の塊・岸の高低。装飾の個数を増やさない |
| 編集の結果を使えるか | 編集で岸をずらし、以前の地点でなく今の岸へ呼ぶ | 目的地の導出・支持・経路。固定の演技位置でごまかさない |
| 直せる不通を残せるか | 相棒が家側にいる間に無人の行き先を分離し、再接続する | 不通の表示と回復。全ての切断を禁止しない |
| 相棒の安全とUndoが両立するか | 編集で生まれた地面へ相棒を呼び、その編集を戻す | 支持を含む復元順序。無言の位置飛びを通常演技にしない |
| 繰り返しても煩わしくないか | 数回連続で編集し、途中で呼出・取消・再編集を行う | 中断・応答時間・演技の頻度。演技の種類を増やさない |
| cameraの一点だけで成立していないか | 390/768、全景/近景、別方位を比較する | 対象と入口を含むfocus、幹と冠の重なり。人物だけを拡大しない |

美術、無説明理解・安全、runtimeは引き続き別判定。スキルの各8/10・独立4/5というゲートは制作判断の運用基準であり、統計的な人気や翌日の再訪を証明する値ではない。作者の採点と観察者の発言は混ぜない。「続けたい」と答えたことと、実際に別の岸を試す行動、日をまたいで戻る行動も分けて記録する。今回は児童N=0のまま。

前回の22px/56pxはcamera校正の補助値に留める。今回それ以上でも関係の読み取りには別の問題が残った。全周で常に顔を正面に見せること、全ての冠を近景に収めること、全ての形を美しく保つことは受入条件にしない。

完成対象は一つの編集できる場所である。そこで原本の局所的な魅力が保てないなら、次の葉や小物へ進まず、岸・冠・玄関・道を一緒に作る工程へ戻る。そこを通過しても、全島構成、大型形、本人保存への接続、配布は別の未完として残す。
