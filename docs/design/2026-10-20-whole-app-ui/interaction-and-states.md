# 操作と状態の契約

本案の操作変更を実装するときは、ルーティング・保存・PWAの現行保護を保ち、該当する製品仕様を先に更新する。以下は実装前に判断をそろえる設計で、アプリが既にこの通り動くという記述ではない。

## 1 カメラの初期値と復帰

現行 `frameCamera` は正射影で、全島の描画形状から求めた `fit` を `view.zoom` で割って表示する。内部zoomの既存範囲1〜4を維持する。単にCSSでcanvasを拡大したり、島の所有boundsを小さく偽装したりしない。

### 新しく島を表示するとき

1. 実際の3D viewportと、情報・操作で覆われない可視領域を確定する。
2. 最初の候補は内部zoom1.5。小さい島では家の周囲の暮らしが見える構図にする。初回に全景を強制してから寄る演出は足さない。
3. 取得範囲が広い場合は、実際のぽこもこの家の描画中心へ `panToFocus` 相当で寄せる。初期表示の主役を全所有地の中央に固定しない。
4. 家の実meshをfit時に投影し、1.5で主な家が100〜160pxに入れば1.5を使う。それより小さい場合は120pxを目安に必要倍率を求め、1〜4へclampする。投影がまだ求まらない間は1.5を候補にして、描画準備後一度だけ初期構図を計算する。
5. 住人48〜64px高は同じ画面で比較する視認性目安。全住人をこのサイズに保証せず、身体比率や位置を捏造しない。上限4でも魅力が弱い大島は限界として記録し、別の仕様判断なしに上限や所有地を変えない。
6. 初期化後はユーザーの操作を優先し、成長や住人の移動で勝手にcameraを追従させない。

上記の120pxは試作の第一候補で、美術の合格値ではない。実画面で住人・家・操作を一緒に見て採用する。

### 視点の扱い

| きっかけ | 視点 |
| --- | --- |
| メニュー・対象情報の開閉 | 同じzoom・azimuth・panを保持 |
| 学習・家・記録・設定との往復 | 同じ本人・同じ島ならsession内の視点へ戻る |
| 同じ本人の別の島へ移動 | その島のsession視点。初表示なら魅力的な既定 |
| 本人切替 | 本人×島で分離。別人の視点や選択を流用しない |
| きょうだい訪問 | 訪問用の視点。帰還時は自分の島の視点へ |
| 再読込・アプリ再起動 | 魅力的な既定構図。camera用の新しいDB保存は足さない |
| 画面回転・サイズ変更 | 世界の注視点とzoom・azimuthを保ち、可視領域外の補正だけ行う |
| しま全体 | 現在方位で全所有地と実描画形状の境界中心にfit、zoom1。相対panを0にする。既存の岸・高さも含める |
| 現地へ・住人へ | 本人が押した対象の実座標へ。目的物のない場所へ偽focusしない |

連続的なcamera操作に強い慣性を追加しない。reduced motionでは自動の補間移動を止めて即座に対象を示す。視点を戻しただけではゲーム状態を書き換えない。

`pan=0` を世界座標の原点と同一視しない。`frameCamera` がその方位で計算した全所有地・実描画境界の中心を基準にし、その中心からの相対panを0へ戻す。海や遠くの未到着船をboundsへ含めて島を縮めない。

## 2 ジェスチャーの優先順位

UI面の操作、既存modal、編集、世界の順に判定する。既存の7pxの移動閾値、住人のpick可否・drop・cancelCarryの規則を今回の見た目変更で変更しない。

| 開始場所・入力 | 通常の島 | 品物の仮置き中 |
| --- | --- | --- |
| UI上のpointer | そのUIだけ | 確定・取消等、そのUIだけ |
| 世界の静止タップ | 見えている対象を選ぶ／既存の反応 | 実際の地面の仮位置を選ぶ |
| 空白からの一本指drag | 既存のpan | pan。drag終端で配置位置を確定しない |
| 住人からのdrag | 既存のcarry成立条件で運ぶ | carryは開始せず、仮置きの操作を優先 |
| 二本指pinch | 既存の連続zoom | ghostを保って連続zoom |
| 二本指twist | 既存の回転 | ghostを保って既存の回転 |
| wheel・trackpad | 世界上だけ既存の拡縮 | 世界上だけ既存の拡縮 |
| ながめの＋／− | 同じ範囲で1.15倍刻み | 提供時はghostを保ち同じ範囲 |
| ながめの左右 | 既存の30度刻み | 同じ規則。カメラの回転を物の回転にしない |

二本目のpointerが入ったらその系列の対象タップ候補を破棄する。carryしていれば既存の安全なcancelを完了してから同じ系列をcamera操作へ移し、住人のdrop・位置確定・配置・clickを発火しない。住人を勝手に家へteleportさせない。確定前のghostと所有データは保持する。最終pointerが離れるまで系列を終端せず、その系列由来のclickを捨てる。時間だけで抑止して次の独立したタップを落とさない。

pointercancel、画面回転、アプリ背景化、描画context喪失ではcarryを安全に戻し、確定commandを発火しない。戻ったあと別のgestureとして再開する。既存の小さな住人のfinger targetを保ち、隣の花や建物の見えるhitを透明hitが奪わない。

キーボードや補助技術では既存のDOMの入口と拡縮buttonへ到達できることを確認する。住人運搬のdrag代替は、本人の選択シートに任意の「はこぶ」、現行で利用できる実ベンチ・ブランコ等の名前付き一覧、対象選択、同じpick・drop規則への接続とする。通常の世界上のcarryには手順を追加しない。利用可能な対象が無ければ理由を示して戻れる。これは入力手段の提案で、別のゲーム規則・報酬・保存形式を追加しない。既存の安全判定へ接続できることを実装時の受入条件にし、文書だけで代替操作が実装済み・合格とは扱わない。

## 3 パネルと背景の操作

一度に操作する主パネルは一つ。例外は既存の確認dialogで、その親の選択・編集文脈を保持して重ねる場合。重ねた親を同時に操作させない。

| 面 | 意味・背景 | 外側タップ | 初期focus・復帰 |
| --- | --- | --- | --- |
| 島の補助menu | 非modalのsection、背後の世界は見える。canvasのpointerを遮断 | 最初のtapは閉じるだけ。drag/carry/選択へ通さない | 見出しまたは閉じる。trapなし。閉じるとmenu trigger |
| ながめ | 小さな操作section。世界のgestureを使える | 閉じる専用hitを世界全体へ広げない | 見出し／閉じる。元triggerへ |
| カタログ・図鑑・目標等 | 既存のsection/dialogの意味を保つ。canvasのpointerは遮断 | 未保存の編集を黙って破棄しない。既存の外側閉じ契約が無ければ追加しない | 見出しまたは選択tab。戻り元が残ればそこへ |
| 任意詳細 | 同じ親パネル内の状態 | 親と同じ | 見出し。戻ると選択元タイルとscroll |
| 仮置き | 世界上の編集。cameraとghostのみ操作可 | 終了しない | 操作説明へ。取消後は元一覧または元対象 |
| 家menu・海図・名前等の既存modal | `aria-modal`、背景inert、focus trapを保つ | それぞれの既存規則。保存中は保護 | 見出しまたは安全な操作。閉じると有効な起点 |
| 確認dialog | 編集文脈を保ち背景inert | 確認を無視して確定しない | 安全な取消または見出し。閉じると発火元 |

非modal menu中は背後の島の操作をpointer・キーボード双方で無効にする。Tabで明示的に利用可能な通常ナビへ移ることは許容し、ナビを選んだらmenuを閉じ、既存のnavigation ownerを通して移動する。focus trapは設けず、閉じると有効な起点へ復帰する。

`Escape` は最前面の状態で一回だけ処理する。日本語変換中のEscを面の閉じるに使わない。dialogと親が同じEscで二重に閉じない。閉じた後に切断済みDOMへfocusせず、元triggerが無ければ戻り先見出しへ。

## 4 戻ると取り消し

「もどる」は今の詳細から一段前、「とじる」は今の主パネルを閉じて島または部屋へ。ブラウザBackは既存URLの意味とnavigation ownerを優先し、戻り先や履歴を独自の二重stackにしない。追加する一時詳細のBackを処理する場合も同じownerで管理する。

| 元の状態 | 戻る／Esc | 明示の閉じる・取消 |
| --- | --- | --- |
| menu | 島へ | 島へ |
| 一覧の任意詳細 | 同じ一覧へ | パネル全体を閉じる |
| 目標帳のfoldout | 既存の本の戻り契約 | 本を閉じて島へ |
| 新規品・収納品の仮置き | 現行の編集保護を通して取消 | 元tab・分類・scrollの一覧へ |
| 配置済み個体の移動 | 現行の編集保護を通して取消 | 元の個体と選択面へ |
| 家の記念・お知らせ | 家の中へ | 現在の退出labelに従う |
| 学習 | 既存の予約・保存保護を通り開始元へ | 同じ。新規予約や報酬受取にしない |
| 訪問先 | `かえる`と同じ自分の島へ | 自分の島と視点へ |
| 未保存の編集を失う遷移 | 必要な既存の確認パターン | `編集をつづける／変更をやめる`。単なるcamera・scrollは確認不要 |

元一覧の記憶は本人×島×panelのsession状態。廃止されたitemやカテゴリを再現しない。対象がなくなれば有効な親一覧とその説明へ復帰する。

## 5 未処理操作と会話

保存失敗・編集中の説明を一般の会話へ混ぜない。未処理のつぼみ・船と、ただの挨拶も分ける。

| 種類 | 表示位置・寿命 | 編集・menu中 |
| --- | --- | --- |
| 保存・編集の問題 | 当該操作の近く。解決または本人が取消するまで残る | 操作の面に残す |
| 未処理のつぼみ・到着 | 対象の手掛かりと文字付きaction chip。実状態が残る限り到達経路も残る | 背後から押せなくする。閉じれば戻る |
| 短い住人の返事 | 同時に一つ。実行した対象を優先し4秒程度で静かに消える | 遮らず待つ。保存失敗を上書きしない |
| 成長・発見の演技 | 実際の結果の近くで短く、次の操作を止めない | 編集・学習を中断させない |
| 任意目標 | 小さな絵とヒントの入口 | 通常面で再表示。選択の催促にしない |
| 拡張 | 独立した小入口、実条件・費用 | 通常面で再表示。機能をmenuの奥だけへ隠さない |

複数の会話は同じ意味をまとめ、古い挨拶を順番に強制再生しない。未処理の権利は会話を閉じても消さない。`open-all` と個別の開く・下船を連打しても同じIDを二度処理しない。

## 6 共通の状態表示

| 状態 | 読める内容と次の安全な操作 | かわいさの扱い |
| --- | --- | --- |
| 読込中 | 何を準備中か。操作可能な退出は残す | 一つの小さな絵。存在しない進捗率や演出の最低待ち時間を追加しない |
| 0件 | ここに何が残るかと現在ある戻り・入口 | 空の棚・写真枠等一つ。寂しい相棒で行動を迫らない |
| 未解放 | 必要条件を文字でも読める。現在の取得権を保持 | 中立の輪郭・「これから」。失敗の印にしない |
| 購入不可の旧品 | 所有・収納の実状態。現行の無料再配置 | 売り物の価格札や新規購入buttonを付けない |
| 残高不足 | 正規費用・残高・不足、選び直す／閉じる | 絵や文字を極端に薄めず、学習へ強制誘導しない |
| 保存中 | 何を保存しているか。二重確定を止める | 局所の処理表示。全画面の無意味な紙吹雪は出さない |
| 保存失敗 | 何が未確定か。同じ入力で再試行／安全な取消 | 優しいが具体的な文。成功色・接地済みの確定表示を先出ししない |
| 競合・別タブの変更 | 現行の読直し・writer保護に従う。新旧のどちらが確定かを区別 | 上書きで直ったように演出しない |
| WebGL失敗 | 既存の再試行・軽い描画・学習への入口 | 黒いcanvasを完成画面として出さない |
| 音声不可 | テキスト・図を保ち再生状態を明示 | 音が必須の状態合図にしない |
| オフライン | 端末内DBとキャッシュが使える機能は通常動作 | 接続なしだけで保存失敗の警告を出さない |
| 未cacheの読込失敗 | 何を読めないか、再試行・戻る | 所有消失と誤認する表現をしない |
| PWA更新待ち | 現行の安全な更新案内 | 作業中・保存中に自動reloadや更新を強制しない |

保存成功と一時的なpreviewをDOMのstatusでも区別する。通常状態はpolite、操作失敗は当該alert一つ。会話や人数を毎frame読み上げない。

## 7 非同期と本人の境界

保存・購入・島作成・贈り物等のcommandは現在のrepositoryと識別子を使う。保存再試行では、存在する元の操作ID・対象ID・処理状態を引き継ぎ、新規操作として二重実行しない。成功・失敗・未確定を区別し、結果が不明なら既存の確定状態との照合を先に行う。UI再試行で新しい所有IDやrequestを無闇に作らない。操作IDを持たない既存commandへ、未実装のtransaction機構があると仮定しない。現行の原子性・状態照合で守れることを検証し、変更が必要なら保存の独立した実装範囲とする。完了後に旧本人のPromiseが返っても、新しい本人の画面やDBを更新しない。

保存中に本人切替、航行、再読込が起きる場合は現行のロックと復旧契約を保つ。閲覧できる面まで一律停止する必要はないが、書込の競合を発生させない。未知versionの保存を上書きせず、旧writer・移行・復旧は仕様13を守る。

画像・実物thumbnailの生成はゲーム保存と分ける。失敗しても取得物が消えた扱いにせず、同じ品名と既存の代替絵を出す。メニュー画像のために世界のcameraやcanvas寸法、保存状態を変更しない。所有状態・衣装・成熟をkeyにキャッシュし、UI画像用のWebGL contextを品物数だけ増やさない。

## 8 アクセシビリティと端末対応

意味のある文字は通常4.5:1、大文字3:1、操作境界・focusは適用される基準を実際の合成背景で確認する。48pxの主要hit、可視ラベル、選択印と名前を維持。色のみ、音のみ、動きのみの意味を作らない。

文字200%・長い名前・大残高・日本語変換・soft keyboardでも、閉じると主操作に届く。文字拡大時は列数と内部scrollで受け、文字やhitを縮めない。canvasを拡縮してもページ全体の拡大機能を一括で禁止しない。

音OFFと動き少なめは、playの結果・現在地・成功・失敗の意味を残す。英語の発音・手紙の音声・効果音の優先と退出停止を確認する。端末別の合格範囲は [受入条件](review-and-acceptance.md) に残す。
