# Sansu 全画面UIの具体設計案

2026-10-20。島、メニュー、品物、配置、家、学習、記録までを、同じ世界の手触りで使えるようにする設計案。子どもが住人に会いたくなり、品物を置いて試したくなり、学習から気持ちよく帰島できることを目指す。

**位置づけは実装前の設計提案。アプリへの反映、美術候補の採用、実機操作・子どもの理解と再訪の合格は含まない。** ユーザーが示した「魅力的な初期倍率と自由な拡大縮小」は本案の前提とする。他の数値は最初に作る候補を一つに絞ったもので、実画面で検証してから製品仕様へ反映する。

## 実装

利用者「UIいっきに実装」により、[実装内容と検証範囲](implementation.md)へ進めた。以下の設計相談時の「未実装」は当時の位置づけであり、現行の実装・検証はこの記録を参照する。実機と児童の理解・再訪、美術HOLDは技術検査と分ける。

## 設計の結論

- 島は暮らしが見える近さから始め、自由に拡縮する。既存の二本指回転、住人をつまんで運ぶ遊びも保つ。
- メニューは実住人と6つの絵付き入口が並ぶ、小さな道具箱。現在の構造を使い、絵・文字・押し反応の質を上げる。
- 新しい品は実物を見て選び、1回押すと仮置きへ。収納品は本人の個体を大切に扱い、旧品と記念品も保つ。
- 家は自分の部屋、図鑑は花の標本帳、写真はアルバム。共通の操作を使いながら、画面ごとに主役と構図を変える。
- 学習は問題と入力の明快さ、ぽこもこの演技、短い反応で楽しくする。開始前・連問間・報酬に新しい必須操作を加えない。
- 編集、未処理の出来事、短い会話は別の役割として表示する。保存失敗や不足でも次の操作が分かる。

効く柱は「くふう・にぎわい・ふしぎ・愛着」。弱める柱はない。新しい成長規則、課金、日課、学習義務、ランキングを追加する提案ではない。

## 守る現行契約

製品の正本は [憲法](../../../CONSTITUTION.md)、[親仕様01](../../product/01_app_spec.md)、[画面レイアウト44](../../product/44_display_layout_spec.md)、[UIガイド07](../../product/07_ui_design_guideline.md)。本案はそれらを自動で上書きしない。実装着手時に変更箇所を特定し、挙動変更は先に該当する正本へ反映する。

成長は [52](../../product/52_growing_island_game_spec.md) と [育成規則](../../product/island-system/growth-rules.md)、初回は [初回の島と学習設定](../../product/island-first-play-onboarding.md)、保存は [13](../../product/13_data_storage_migration_spec.md)、検証は [変更別matrix](../../ai/verification_matrix.md) に従う。学習の出題・採点・SRS・独力と支援の区別をUIの都合で変更しない。
