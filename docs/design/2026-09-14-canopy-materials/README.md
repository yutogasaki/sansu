# C3の木肌を3D世界へ移す素材検討

状態: 制作中の素材候補。実装・採用・本番配信・視覚合格を意味しない。

対象は背景の巨大な枝だけ。既存の住民、顔、耳、頭身、色、布、家具の輪郭、学習入力、歩行、自由配置、保存は対象外。C3の生成キャラを設定画へ転用しない。

| 要素 | 移す特徴 | 移さないもの |
| --- | --- | --- |
| 大きな枝 | 暖かい黄褐色、緩やかに流れる木肌、幅の異なる大きな筋、素材固有の粗さ | 現在の規則的な縞、金属光沢、縄のようなねじれ、傷や黒い亀裂の過密さ |
| 空間 | 明るい場所と根元の局所的な青緑の陰の差 | 全面の暗さや紫染め、素材画像に焼き込んだ一方向の照明 |
| 住民 | 既存モデルが読める余白と接地 | 新しい顔・配色・布・身体の設計 |
| 操作 | 実3Dの自由な画角、同じ地面と当たり判定 | C3をそのまま固定背景にすること |

既存の枝は頂点色による周期的な縞が主で、C3の素材感が弱い。背景の枝専用の木肌mapと独立した粗さ/陰影を検討し、ほかの素材へ同じtextureを広げない。木肌mapは照明を焼き込まないalbedo候補として作る。曲がった枝への貼り方と実画面の小さな縮尺で評価し、色見本だけで完成判定しない。

世界の方向自体はC3で合意済み。今回の比較対象は質感の実装方法であり、地形やカメラの固定契約を新設しない。通常/近景/配置と両幅をC3に並べ、視覚・無文字理解/安全・runtime整合を別判定にする。現行の視覚HOLDとHuman N=0は解除していない。

## 素材候補1と描画方式の診断

[木肌albedo候補1](bark-albedo-candidate-1.png) はimagegenで生成。C3の木肌だけを参考に、横方向に流れる暖かい木目、控えめな凹凸、照明を焼き込まない正面の素材面を指定した。生成元は `exec-623b79f4-70c2-4179-85e6-a16715096ebf.png`。繰り返しの継ぎ目や実機容量は未検証で、publicやprecacheには入れていない。

[比較1](geometry-comparison-1.png) では、現行のbatch処理が無地の枝のUVを捨てていたため、描画後にmapを設定しても模様が出なかった。[比較2](geometry-comparison-2.png) は**比較用だけ**、batchより前にmapを指定してUVを保持し、元の周期的な頂点色を一定の木肌色/奥の青緑へ置き換えたもの。実装済みの枝/住民/家/家具の同じ形状と画角を使った独立した3D描画であり、アプリの採用画面ではない。albedoを仮のbumpにも使い、振幅は0.025とした。

比較2では細い周期縞より木肌が読めるが、橙が強く、縮小時には筋が密に見える。枝の端の切れ方、草地と海の大きな色面、局所陰と奥行きの不足は残っている。素材だけでC3へ到達したとは評価しない。次は彩度/筋の尺度と枝の終端を実画面の縮尺で調整し、UV保持の仕組みとtexture所有/破棄を実装するか判断する。現在は素材案HOLD、Human N=0、アプリruntimeの新しいPASS主張なし。

## 素材候補2

[候補2](bark-albedo-candidate-2.png) は候補1のimagegen編集。横方向の大きな流れを維持し、橙の彩度を抑え、細かい尖った筋を減らして幅の広い木肌にした。生成元は `exec-ddb0134d-15ac-4a7d-aaae-2a9ba2889401.png`。[比較3](geometry-comparison-3.png) は比較2と同じUV保持/形状/照明/画角で画像だけを入れ替えた。

**次の試作には候補2を選ぶが、まだ採用しない。** 候補1より大きな流れが静かに読める一方、C3の奥行きや局所陰は素材単体で戻っていない。枝の終端、遠近の層、地面と海のつながりを同時に見直す必要がある。候補2の原画像は1,542,339 bytesあり、そのまま現行precacheへ追加すると12MiBの上限を超えるため、配信形式/容量の検証も先に行う。人物の変形・配色変更で不足を補わない。

## 比較の再現

`tools/preview-island-canopy-material.mjs` はこのフォルダーの固定QA状態を実装済みsceneへ渡し、528×596の2画面を同じ画角で比較する。DEVから取得したcanopy moduleの**比較用コピーだけ**でbatchより前にmapを設定し、UVが残っていることを検査する。ファイルのアプリ実装は変更せず、UIや保存経路も検証しない。

5223のDEVが起動した状態で、新しいPNG出力先を指定する。`SANSU_CANOPY_PREVIEW_URL` で別のDEVを指定できる。

```bash
SANSU_CANOPY_PREVIEW_OUTPUT=/tmp/canopy-new.png node tools/preview-island-canopy-material.mjs
```

eslintと実行がPASS。公開した比較3と、この再現スクリプトの出力SHA-256はともに `96bdc988e03d779122d1bb625cc498c8b62f94a003ad86b29b12f77de6f668d0`。アプリsourceはX3の `74514aaad4483288a65ec4e85e8c576a832fcf64d813fad4e2762c37fea6bfec` のまま。[素材と手順の出所](provenance.json) を保持する。

続く[DEV実画面の試作](runtime-study.md)では、候補2のmapと枝の終端を独立worktreeで検査した。上記は素材比較時点のsourceであり、実画面試作のsource/判定は別記する。視覚HOLD・Human N=0は継続。
