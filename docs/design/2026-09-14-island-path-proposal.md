# 道路を要求しない島の配置案

## 検討後の採用判断

## 結論

道路を敷く・つなぐ・空きマスを一列確保することを、島づくりの前提にしない。子どもは花や家具を置き、住人は見える隙間を自動で歩く。道を追加するなら任意の地面装飾とし、利用・成長・報酬・地区解放の条件にしない。

ただし、経路判定だけを削除する変更は採らない。実際に家具へ到着して使う暮らしを維持するため、配置用マスと歩行用の障害物を分けることを本命とする。

## 現状と問題

- `src/domain/islandLife/space.ts` の `usablePlacement` は、配置後の全品について家の前から利用位置へ到達できることを要求する。固定道路の予約ではない。
- 同ファイルの `blocksWalking` は花のアーチ以外の配置品を歩行障害にする。花や灯りも配置マス全体が障害になる。見た目の隙間と通れる範囲が一致しない。
- ベンチ・ブランコは新規配置で前面利用、施設は専用入口、アーチは通過という違いがある。単に「入口だけ空ける」では、途中を囲った場合の到達性を保証できない。
- 住人の到達・利用はひかりや活動に接続する。配置を許すだけでは、説明なく使われなくなる品が生まれる。
- 添付画面は通り道を空ける案内を示すが、ビルドは未特定。現在の作業ツリーには経路の点表示・対象名の案内を追加する既存差分がある。これは制約を説明する改善であり、配置の自由度そのものは変えない。

## 比較

| 案 | 子どもの体験 | 評価 |
|---|---|---|
| 現行の空きマス経路を可視化 | 理由は見えるが、花を並べる時も経路設計が必要 | 当面の説明改善に限定 |
| 到達性チェックだけ廃止 | 置けるが、住人が利用できない物ができる | 不採用を推奨 |
| 配置マスと歩行範囲を分離 | 隣り合う物の間を住人が歩き、配置が暮らしにつながる | 本命 |

## 提案する規則

### 1. 置く場所と歩く場所

所有物の配置座標と地区の隣接判定は既存の整数マスを維持する。歩行は別の細かい領域で計算し、モデルの足元の形と住人の身体幅を考慮する。細分化の解像度は実装時に実モデルで決め、見た目に通れない隙間を数値上だけ通れることにしない。

| 対象 | 歩行と配置の扱い |
|---|---|
| 花・灯りなど小物 | マス全体を塞がず、実物の周囲を通れる。花の中心や灯りの柱をすり抜けない |
| ベンチ・ブランコ | 本体と利用動作に必要な範囲を確保する。前面1マス丸ごとの空白要求を、見える接近・利用領域へ置き換える |
| 家・図書館など建物 | 本体は通れない。入口と接近領域を配置中に見せる |
| 花のアーチ | 開口部を通れる。支柱は通り抜けない |
| 敷石など地面装飾 | 歩行を強制も阻害もしない。敷いていない草地も歩ける |

購入直後と最大成長時で必要な歩行余白を保証し、花が咲いたことで突然通れなくならないようにする。成長途中で所有物を自動移動・収納しない。

### 2. 配置を止める条件

未開放の土地・海にはみ出す、本体同士が重なる、入口や利用動作の領域を塞ぐ、実際の歩行範囲を完全に分断する場合に限る。最後の条件は残すが、細かな隙間で経路が成立するなら拒否しない。住人が一時的に立っている位置や座席の混雑は恒久的な配置不可条件にしない。

配置中は選択品の本体と必要な利用領域を実景に重ねる。不可の場合は衝突箇所・影響を受ける対象を形と短い言葉で示す。「いりぐちを あけよう」「ベンチの まえを あけよう」など、具体的な場所へ案内する。経路線は困った時の補助とし、通常は道路づくりを促さない。

### 3. 歩行と暮らし

配置確定後は、その時の住人の位置から行き先まで経路を計算する。移動中の経路が塞がれば到達可能な行き先へ選び直す。家具を突き抜ける、消えて移動する、到着していないのに利用・ひかりを成立させる挙動は認めない。利用中の品の移設・収納では既存の安全な活動終了契約を保持する。

道路の有無・長さで歩行速度、ひかり、成長、発見率を有利不利にしない。49の「4歩以内」等の関係距離は細分化したノード数に直結させず、従来の1マス相当の距離へ換算する。隣接する花による花壇・花畑の判定は変えない。

## 保存と導入の境界

既存の購入品、配置座標、成長、残高、地区解放、学習記録、写真を保持する。保存履歴から世界を再現する構造のため、歩行規則を全履歴へ遡及適用して過去の到着・活動報酬を再計算してはならない。切替時点と歩行規則の版を持つ方式などを、実装前に保存契約として確定する。

新規配置だけ細かい判定にして描画や保存は旧経路のまま、という中間状態を公開しない。プレビュー、保存時の再検証、自発行動、移動描画、施設間の活動を同じ規則にそろえる。今回の検討は既存作業ツリーの変更を修正・撤回するものではない。

## 採用時の受け入れ条件

1. 花を2×3で並べた花畑、隣接する花とベンチ、花と灯りを、1マス幅の道路なしで配置でき、住人の接近・実利用を確認できる。
2. 家や施設の入口を塞ぐ時は、確定前にその場所が分かる。理由の読み上げ・キーボード操作・reduced motionでも同じ判断ができる。
3. 建物による完全な囲い込みは検出する。一時的な住人の混雑だけでは配置を断らない。
4. 花の開花、移動中の再配置、利用中の移設・収納後も、すり抜け・瞬間移動・架空の利用報酬が起きない。
5. 旧保存を開いても所有物・通貨・成長・学習と過去の報酬が変わらず、再読込・オフライン・保存再試行でも同じ配置になる。
6. phone/tabletの同一ビルドの実画面で、配置→歩行→利用を確認する。見た目の魅力、説明なしの理解、安全な実動作を別々に判定する。子どもの理解は未観察のまま合格扱いにしない。

## 次の実装単位

まず実モデルの花・ベンチ・灯りで隙間歩行を試作し、上記1と4を確認する。その後、施設・アーチ・保存版切替へ広げる。道路の装飾編集は別機能として後回しにできる。

採用時は親仕様01と現行仕様48の到達性・前面利用・保存契約を更新し、49の距離条件と50の配置比較に整合させる。今回は未採用案を記録したため、それらの現行規則とプロダクト用のdurable memoryは変更しない。
