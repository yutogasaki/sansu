# 目標へ届く島の制作方法を選ぶ

2026-10-22 JST。状態：公開情報調査・コード読解・比較実験の設計。新しい美術候補の完成、方式採用、本体への接続を示さない。

追補（2026-10-23）：[ベンチマーク監査と再現テスト](../2026-10-22-benchmark-method-audit/README.md)で、作者の追加資料、Townscaper実操作、材質の順序依存と段差の反例を確認。A/Bの方式採用は引き続き未判定。比較には、同じ所有物から作る異なる場所の美術に加え、住人の実利用・操作の可逆性・保存再開を含める。

追補（2026-10-24、09:17〜12:17 JSTの再開枠）：[現在の実画面比較](../2026-10-23-place-brush-trial/current-review.html)と[実装・失敗・検証の記録](../2026-10-23-place-brush-trial/platform-notes.md)。家具を置く平面と方向付きの坂、通常移動・実利用・試作専用DBの保存再開を対象旅程で確認。再計算で古い坂が混ざる欠陥を修正した。海岸4案は全景の美術未達で、複数場所の共存と海岸輪郭の比較を続けている。通常製品・全島美術の採用には昇格していない。

「他作品の情報を集め、作り方を探さないと細かな積み重ねだけでは目標へ届かない」という依頼に対応する。効かせる柱は、本人の編集が景色と使い道を変える「くふう」、育てた物が続く「愛着」。学習・所有・人口・成長の規則は変えない。

## 何を変えるか

**現試作の局所修正を主工程から外し、同じ目標を異なる作り方で実現する比較へ移る。** 一角は研究する単位であり、最終目標の縮小ではない。岸を丸める、木を動かす、検査を増やすだけで完了にしない。

今回の最有力仮説は「形を設計した岸・段差の部品を、編集状態に合わせて変形・接続する方式」。ただしこれを先に勝者にせず、「連続した地表を数式で作る方式」と同じ条件で比較する。どちらにも、家・木陰・水辺・経路の関係を扱う規則が必要である。

[承認済み全島参考](../2026-10-10-island-final-3d/whole-island-render.png)は到達方向、[岸編集v2](../2026-10-21-cove-mechanism-v2/README.md)は現状対照。全島参考の物量を家1軒・木6本の試験へ求めない。昼の厚み、高低差、大中小、材質差、重なり、歩いて使う意味を取り出す。

## 今回見つかった判断上の差

1. **高さ場を捨てる根拠はまだない。** v2の `terrain.mjs` は陸の初期高さが最大0.42へ飽和する形で、その上に編集差分を加える。広い平面はこの設計でも生じる。高さ場そのものの失敗とは分ける。ただし同じ水平位置に複数の床を置く回廊・洞・張り出しは、単一高さ場だけでは表せない。
2. **部品があるだけではつながらない。** native05の木や家を再利用しても、岸の断面・接合境界・歩く余白の設計がなければ、現在と同じ散在した景色になり得る。Bで制作するのは完成地区の差替えではなく、岸/段差の接続可能な形。
3. **公開コードは研究材料。** S9の `IrregularHexGrid.build` は三角形の結合→四角形への分割→緩和を行う。既定以外の3つの分岐に `tthis` という参照があり、未変更で使えばその分岐は失敗する可能性がある。コード読解による指摘で、今回は実行再現していない。
4. **GPUで見た目だけを曲げない。** S9の `TrilinearLatticeMaterial.js` は頂点シェーダーの位置を書き換える。このファイル単独ではCPU側の床・hit更新を確認できない。試作ではCPUで変形後の頂点を確定して描画と支持へ渡す案を優先し、本体統合時は既存[共通world契約](../../product/island-world-contract.md)へ戻す。
5. **格子と地形方式を同時に変えると原因が分からない。** 最初は同じ格子・高さ・水位でA/Bを比較し、不規則格子はその後の独立変数とする。Bが未完成の部品で負けた場合も、方式全体の限界と断定しない。

## 比較する作り方

| 候補 | 具体的に作るもの | 得たい差 | 主な失敗条件 |
| --- | --- | --- | --- |
| 現行v2 | 変更せず対照として残す | 目標との差を見失わない | 作者の自己採点を達成へ戻さない |
| A：連続地表＋設計した断面 | 同じ編集データから上面・低岸・斜面を連続生成。段の肩や裾を断面で設計 | 平らな板から、厚みと奥行きのある地形へ | 起伏追加だけで家と岸の関係が変わらない／膨らみが同じ形へ収束 |
| B：造形済みの部品を接続 | 低岸・凸岸・凹岸・段の接合を、周囲の高さ・陸水から選び変形 | 自由編集でも意図した岸と段の造形が残る | 継ぎ目、形の急変、足場との不一致、編集のたびに専用部品が必要 |
| C：関係から形を作る共通層 | 木陰、玄関前、乾いた経路、水辺の関係を判定し、必要な接合と開口を導出 | 所有物が別々に置かれた景色から、使える場所へ | 自動整列・無根拠な道・枝の衝突・形がちらつく |

CはA/Bと競合する第三の地形方式ではない。最初はA/Bを同じ空間構成の評価条件で比べ、Cによる形の自動生成は後続の別試験にする。共通にするのは判定規則・設定で、異なる実形状へ同じ経路結果を強制することではない。家・木の所有ID、位置・向き・尺度・成熟を保ち、派生形を認める範囲を事前に定める。現段階で枝の自動変形を必須機能にしない。

## 次の比較試作の実施条件

これは未実施の実験計画。各方式を一度で完成させる約束ではなく、次に投資する方式を選ぶための診断である。

- 同じ家1軒・木6本・ぽこもこ1体、同じモデル/尺度/成熟、水位・昼の光・材質設定・390/768幅・全景/近景カメラを使う。各方式の外側に物を追加して密度で勝たせない。
- 同一の初期高さ/陸水データと編集履歴を入力する。比較対象の方式だけで生まれる支持差・不成立も結果として残す。無理にすべての操作を成功させない。
- 三配置は「元配置」「木1本を別の合法地点へ移した配置」「家と岸の距離を変えた合法配置」。制作前にfixtureを固定し、各編集中は所有物を移動しない。
- 同じ編集列で湾を掘る→岬を盛る→手前を削る→帰宅→Undo/Redo。加えて既存のE1〜E3以外の編集箇所を事前指定し、画面を見てから試験座標を調整しない。
- 地形だけの中立色表示と、同じ資産を載せた昼の表示を切り替え、幾何と色・光の寄与を分離する。美術の最終判断は昼の通常表示で行う。
- 出力は固定カメラの配置×方式の比較、編集前後のcontact sheet、操作の連続動画、支持・経路の結果。候補・入力hash・日時・実装/調整時間・未対応ケースを記録する。
- 最初の比較は枝生成などのC全体を作り込まず、家前→木陰→岸の通れる余白を同じ規則で評価する。Cが効くという証拠がなければ、地形方式の採用後にC有無を比較し、曖昧な原因を残さない。

**継続条件：** 明るい全景でも厚み/高低差/余白の関係が目標に近づき、別配置と未調整の編集箇所でも使える岸が残る。制作に要した手作業と未対応条件を含め、次に埋める差が具体的に分かる。

**棄却・再設計条件：** 一つの撮影配置だけ成立する、目標との差が色や細部しか縮まらない、家や木の移動で取り繕う、床を偽装する、局所編集で島全体を並べ直す。実装不備で比較できなかった場合は「方式不成立」ではなく「判定不能」。両方届かなければ低い方から勝者を選ばず、地形・主景の設計からやり直す。

児童の無説明理解・再訪、正式美術採用、本体保存・更新・実機性能はこの診断の外。自動検査数で埋めない。

### Bの最小接合条件と、逃げない追加ケース

初回は低岸・凸岸・凹岸・一段接合の4族を設計する。「4族」は4枚のmeshですべての組合せを表せるという意味ではない。高さ差・向き・境界状態の対応表を持ち、未対応入力は未対応と表示する。

| 接合条件 | 次の制作への要求 |
| --- | --- |
| 位置 | 同じ格子辺の端点と境界サンプルを正本として共有。片側だけ細分して隙間が出る接合、重複面、裏面の露出を残さない |
| 法線 | 実形状から求める。滑らかな岸の継ぎ目を見せず、意図した崖の硬い角は平均して潰さない |
| 材質 | 草・土・水際の対応位置と遷移を共通化。意図した地層境界以外でUV/色が急変しない |
| 支持・hit | 変形後の実頂点/三角形を確定して、描画・支持・raycast・経路へ共用。地形の連結だけで足幅の通行を保証しない |
| 編集・復元 | 同じrevisionで形・接合・支持を確定。形の生成に失敗したら直前の有効状態を保つ。通行不能と生成失敗は区別し、単に道が切れたことを理由に全編集を拒否する規則へ変更しない |

追加の未調整ケースは、①対角だけで陸が接する境界、②幅1セル相当の細い接続とその切断、③一地点から二方向に高さが変わる段差。A/Bで同じ入力を使う。B四族で足りなければ、追加部品の必要数と制作負担を明記し、その入力を別の形へ丸めない。

## チャッピーとの協議・検証

[相談先：土地拡張案を比較](https://chatgpt.com/g/g-p-6ad58d0857b881918e46e346350848e7-hokomoko/c/6ad7354d-f4f4-83e8-a296-b462d76d7d72)。同じぽこもこプロジェクトで、既存5画像と今回の公開情報・比較案を使い、2往復の送信と回答完了を確認した。consult-chatgptスキルによる協議。新しい画像やソース全文の送付はない。

- 初回回答はB+Cを有力仮説、A+Cを対抗案とし、全景・接合・編集・制作負担を別判定する提案。Aが同等ならAを優先し、両方届かなければHOLDとした。
- こちらから、初期地形の平坦さを高さ場の限界と決めないこと、同一格子で変数をそろえること、描画だけの変形を採らないこと、C全体の先行実装を避けることを補正した。
- 2回目回答は補正を受け、接合条件と三つの追加ケースを具体化。一方、同じ規則的格子の比較だけではBと不規則格子の組合せの価値やCの効果は分からないと指摘した。この限界を採用する。
- 「失敗時に全体を拒否」は不正なmesh/接合の生成に限定して解釈する。到達不能な配置を直せる遊びまで拒否する製品変更は採らない。
- 以上は公開根拠・既存画像・要約からの設計提案。チャッピーとの合意で方式採用や美術合格にはしない。

製品正本は変更不要：今回の成果は制作方式の調査と比較設計で、採用・挙動変更ではない。検査は文書の読合せと `npm run docs:check`。本体のテスト・美術合格を新たに主張しない。
