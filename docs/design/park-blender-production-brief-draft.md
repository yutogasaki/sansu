## 1. 依頼の要約

幼児〜小学3年生程度の子どもが、遊具を並べ替えて人形を遊ばせる「ちいさな遊園地」の美術を制作したい。

目指すのは、**机の上に自分で組み立てた、手で触って動かしたくなる小さな玩具の遊園地**。形の厚み、素材ごとの触感、人形の表情と身体の動きで魅力を作る。静止している初期画面から「遊ばせたい」と感じられ、動かすと配置の違いが分かることを重視する。

最初の依頼範囲は、人形1体、すべり台、トランポリン、シャボンゲート、小さな台座による美術試作。まず完成イメージ1枚と編集可能な `.blend` を作り、スマートフォンの画面に当てて方向を評価する。全6種・全ポーズの量産は、その評価と素材合成の試験後に進める。

本書を仕様へ発展させる際は、見た目の形容だけでなく、カメラ、寸法、配置、動作、分割素材、合成方法、納品物、受入条件まで具体化してほしい。必要な判断は末尾の「要決定事項」に残す。

## 2. 背景と今回直したいこと

現在のアプリには、配置・学習・保存まで動くMVPがある。一方、美術は簡単なSVG図形による試作で、ユーザーから見た目への強い不満が出ている。

| 現状の弱さ | 今回の制作で目指す変化 |
|---|---|
| 人形が小さく、記号に見える | 顔・重心・ポーズが読み取れ、動きを見守りたくなる |
| 遊具が説明用アイコンに見える | 厚み、接地、素材差があり、手元に集めたくなる |
| 広い背景に対してコースが細い帯 | 遊具と動く人形が画面の主役になり、空きがジャンプの空間として働く |
| 背景・ボタン・部品棚が別々に見える | 玩具の舞台と操作面の関係を整え、遊ぶ場所を一目で見つけられる |
| 成功時の装飾に頼りやすい | 遊具の働きと人形の反応自体が見どころになる |

現行画像は問題点と機能配置を確認する資料であり、模倣すべき美術の基準ではない。

## 3. ゲームの固定条件

製品の正本は [22：教科共通ゲーム仕様](../product/22_shared_subject_build_and_play_spec.md)。以下は美術制作に必要な抜粋であり、ゲーム規則を独自に変更しない。

- 最初は横に3つの設置位置。すべり台とトランポリンを1個ずつ持ち、学習前に完成済みコースを試遊できる。
- 子どもは部品を選び、置き場所をタップする。精密なドラッグを必須にしない。
- 最大3コース、各6位置。個体として持つ部品を配置する。編集と再演は無料で繰り返せる。
- 動きは配置から決まる。正誤、回答速度、抽選でジャンプの結果を変えない。
- 学習側が予約した短い課題区間を終えると、選んだ部品を1個制作できる。支援を使っても制作を進められる。
- 学習画面では問題と全入力を主役にし、遊園地の動きを止める。問題文や答えを美術素材へ焼き込まない。
- スキップ・中断・誤答で、人形を痛がらせたり、所持部品を壊したりしない。

算数は単純な一桁入力に限定しない。分数・複数欄・筆算もある。英語は既存の中学生向け単語4択で、幼児向け英語教材を用意済みという意味ではない。

22仕様のMVPでは3Dは対象外とされている。本書では「Blenderによる素材制作と画像への書き出し」を検討する。素材制作としての採用範囲は仕様確定時に22へ明記する。リアルタイム3D、カメラ回転、3D物理演算への拡張は別の仕様判断とする。

## 4. 美術の方向案

### 基本案：木と色付き樹脂の玩具

| 要素 | 提案する表現 | 避けたい表現 |
|---|---|---|
| 形 | 太さと丸みがあり、側面・縁・底面で厚みが読める | 細い線だけの形、角を丸めただけの箱の集合 |
| 人形 | 一つの特徴が記憶に残る輪郭。顔の位置と体の重心を大切にする | 大きな目・赤い頬だけで個性を代用する、既存キャラの写し |
| 木 | 台座・支柱などを支える、控えめな木目と柔らかい反射 | 全面に強い木目ノイズを貼る |
| 樹脂 | すべり面や枠の丸いハイライト、色の厚み | 全素材を同じ艶にする、光沢で顔が消える |
| ゴム・布 | トランポリンの面やマットの沈み込みで柔らかさを見せる | 危険に見える鋭いばね、硬い着地 |
| 泡 | 輪郭と少数の反射で薄膜を見せ、顔が透けて読める | 白く濁って顔を隠す、ガラス球のように重い、閉じ込めに見える |
| 色 | 大きな主調色、主役色、少数のアクセントに役割を持たせる | 全面を淡くして焦点を失う、全部品を虹色にする |
| 照明 | 柔らかい一方向の主光源、接地する短い影 | 黒く深い影、全体を覆う発光、素材ごとに違う光源 |
| 背景 | 玩具が乗る場所と奥行きが読める簡潔な舞台 | 生活小物を大量に置いた部屋、空きの埋め草としての装飾 |

木・樹脂の組合せは第一候補であり確定ではない。まだ方向を選べない場合は、同じ3位置・同じカメラで「木と樹脂」「やわらかい粘土」「成形されたカラフルな玩具」の小さな見た目比較を3案作る。3案とも完成モデル一式へ仕上げる必要はない。選んだ1案だけを最初の完成イメージへ進める。

既存画面から引き継ぐのは、左から右へ進む分かりやすさ、部品による結果の差、自由な再演。現在の線画、背景の比率、小さな人形、均一な素材感は引き継がない。

## 5. 最初に作るもの／採用後に増やすもの

| ID | 最初の美術試作 | 見るポイント | 採用後に必要な状態 |
|---|---|---|---|
| `actor` | 人形1体・基本ポーズ | 64px程度の小さな表示でも輪郭と顔が読める | 待機、歩き、登る、すべる、踏み込み、小跳ね、高いジャンプ、着地、落ち着く |
| `slide` | すべり台1個 | 入口・すべり面・出口が見え、人形と寸法が合う | 人形が支柱・手すりへめり込まず通れる |
| `trampoline` | トランポリン1個 | 踏む面と柔らかさが分かる | 通常、沈む、戻る。弱い跳ねと高い跳躍を区別 |
| `bubble-gate` | シャボンゲート1個 | 通る入口があり、人形の全身が収まる | 通常、通過反応。泡の前後面とは別素材 |
| `stage` | 3位置の小さな台座 | 地面と設置面、スタートと安全な終点が分かる | 空き位置、4〜6位置への拡張、配置用の接地基準 |
| `bubble-fx` | 見た目を決める代表の泡 | 泡付き人形が読める | 付く、持続、着地ではじける、色付き泡 |

最初の完成イメージは「すべり台 → シャボンゲート → トランポリン」の制作後コースを提案する。ゲームの初期状態は従来どおり「すべり台 → トランポリン → 空き」であり、混同しない。初期状態も同じモデルを非表示・再配置して確認する。

採用後に追加する機能部品は次の3種。初回から全種を作る工数には含めない。

| 部品 | 機能を伝える見た目 |
|---|---|
| 減速マット | 踏むと柔らかく沈み、人形の歩みが緩む |
| ベル | 地上で触れると揺れて鳴る。飛び越すと鳴らない。無音でも差が見える |
| 色ゲート | 通ると人形の色が変わり、その後のゲートで付く泡にも色が付く |

人形の最終デザイン、名前、色数、リグの方式は要決定。ポッコや現在の黄色い人形をそのまま使う義務はない。

## 6. カメラ・画面構成

### カメラ案

横から少し見下ろす固定視点を第一候補にする。平行投影を使い、左右へ部品を移しても同じ大きさに見せる。制作ファイル内では、進行方向をX、奥行きをY、高さをZとする案を採る。X方向が画面上の左右と揃うようにし、床が少し見える傾きから比較する。平行投影の性質は [Blenderのカメラ説明](https://docs.blender.org/manual/en/4.3/render/cameras.html) を参照。

- **固定条件**：人形の地上通過とゲートの飛び越しを見分けられる。飛び上がった先と着地場所が画面内にある。
- **提案**：俯角10〜20度程度を比較用の出発点とする。見た目のために深い俯瞰へ振り、ジャンプを小さくしない。
- **要決定**：投影方式、最終角度、カメラ位置、平行投影のスケール、床の位置、光源を一つの設定として固定する。

### 画面での確認

- 基準は390×844と768×1024の縦画面。静止画だけでなく、実表示の大きさまで縮小して見る。
- 3位置の試遊では、コース・人形・跳躍空間を含む舞台に画面高の45〜60%程度を使う案から検討する。上限・下限は未検証の仮値。
- 人形は顔が読める大きさを優先する。まず表示高64〜80px程度を試し、遊具の寸法と跳躍の余裕を併せて決める。
- ヘッダー、再演／停止ボタン、部品棚の領域も当てて確認する。ジャンプの頂点、着地、人形の顔を操作面で隠さない。
- 6位置では単純な全体縮小で人形を読めなくしない。舞台内の横移動・追従表示等の候補を別途比較し、見失わない方式を決める。複雑な自由カメラ操作を増やさない。
- 学習中は静かな問題画面へ移り、制作対象の小さな部品表示のみを残す案とする。算数・英語・支援表示・全入力の領域を先に確保する。

## 7. 動作として見せるべき因果

最重要の比較は、**同じ部品を並べ替えると、泡の付き方とジャンプの結果が変わる**こと。

| 配置・条件 | 見せる順序 | 変えてはいけない結果 |
|---|---|---|
| すべり台 → トランポリン → ゲート | すべる → 強く踏み込む → ゲートを越す → 安全に着地 | 空中で通り越したゲートでは泡が付かない |
| すべり台 → ゲート → トランポリン | すべる → 地上で泡が付く → 泡と跳ぶ → 着地ではじける | 空中では泡を保ち、着地してからはじける |
| 勢いが弱い状態でトランポリン | 踏む → その場で小さく跳ねる → 着地 | 隣の位置へ移動しない。泡があれば着地ではじける |
| 高く跳んだ先に別の部品 | 着地 → その位置の部品に反応 | 飛び越した位置の反応を再生しない |
| 最後の位置から高く跳ぶ | 画面内の終点へ跳ぶ → 柔らかく着地 | 場外へ落ちたり、危険に見える落下をしない |
| 泡を付けたまま地上を進み終点へ | 歩く → 泡のまま止まる | ジャンプしていない泡を、都合のよい場面で勝手にはじかせない |

演技は「予備動作 → 接触 → 反応 → 収まり」が読めるようにする。泡が付いたときは見上げる、着地したら膝や胴が少し沈むなど、原因のある反応を優先する。全身の上下移動だけで全動作を済ませない。

動きの長さは次の段階で決める。既存MVPの再生時間を制作フレーム数の根拠にせず、まず動作見本を評価する。実装時はゲーム側の「踏み切り」「着地」「泡が消える」時点とアニメーションを合わせる。

初回の静止画採用後に、上記2配置の短い無音動画と、踏み切り／頂点／着地／収まりの代表静止画を作る。動画は動作の見本であり、任意の配置を再生する本番素材の代用ではない。

## 8. アプリへ組み込むための素材設計案

現時点の第一候補は、**Blenderで立体を作り、固定カメラで書き出した画像をアプリ側で配置・アニメーションする構成**。既存の配置・学習・保存の仕組みを使いながら美術を差し替える。

### 一枚絵と部品素材の両方を用意する

完成イメージは、一枚として陰影・構図を評価する。採用後は同じ見た目を次のような再利用可能な素材へ分ける。

1. 背景・空の台座。
2. 遊具の奥側、接地影、必要に応じた手前側。
3. 人形の状態別画像または連番、動きに追従する影。
4. 泡の後ろ側・前側・破裂の反応。
5. 部品棚・制作目標・作品サムネイル用の見え方。

重なり順は全動作で固定と決めつけない。ゲート内を歩く人形は手前の柱より奥、ゲートの上を跳ぶ人形は空中に見える必要がある。まず「ゲート通過」と「ゲート飛び越し」の2場面を素材から再合成し、必要な前後レイヤー・切替時点を決める。

### 合成で失わないための条件

- カメラ、照明、色の表示設定、床の高さ、モデルの縮尺を全素材で揃える。
- 配置用の基準点を各素材に記録する。部品は設置面中心、人形は足元等を候補とする。切り抜きの余白を変えても基準点が飛ばないこと。
- 人形の全ポーズで同じ座標基準を使う。フレームごとの自動切り詰めを使う場合は、元キャンバスからの位置情報を添える。
- 遊具が隣へ落とす影や反射を、特定の並び方のまま素材へ固定しない。部品を入れ替えた2配置で検証する。
- 人形の影は地面側へ置く。ジャンプ中に足へ貼り付いた影が一緒に浮かないこと。
- 泡は任意の背景と人形へ重ねるため、透過PNGだけで完成と判断しない。明暗の違う背景、通常／色付き人形、前後レイヤーで試す。必要なら反射・輪郭中心の表現へ調整する。
- 素材へ分けた結果、厚み・質感・接地・演技が失われる場合は、レイヤー構成や描画方式を再検討する。

平行投影、基準点、床位置等の具体値は最初の合成試験で確定する。現行SVGの寸法や原点に、新モデルを無理に合わせる必要はない。モデルの見た目と接触位置を保つ変換を実装担当が用意する。

## 9. 納品物と制作データ

### 段階A：最初の見た目の判断

- 編集可能な `.blend` 1式。人形・各遊具・台座・カメラ・照明を区別できる名前にする。
- 制作後コースの完成イメージPNG 1枚。390×844の画面に置く舞台の比率を意識する。UI文字やボタンは焼き込まない。
- 使用したカメラ、照明、色の表示設定、Blenderバージョン、外部素材の有無を短く記したメモ。

初回はリグ完成、全アニメーション、全6部品、GLB、全端末画像を必須にしない。

### 段階B：採用した方向の組み込み試験

- 初期／制作後の同カメラ画像、2配置の動作見本、主要ポーズ。
- 人形・初期3部品・泡・台座の分割素材と、基準点・重なり順の説明。
- 素材から再合成した画像。元の完成イメージと同じ縮尺で比較する。
- 色付き人形と泡は、外見の全バリエーションを量産する前に1例で合成を試す。

### 段階C：仕様確定後の量産

- 全6部品の必要な状態、人形の採用動作、部品棚・サムネイル表示。
- フレーム範囲、再生時間、繰り返す動作、着地・反応時点、基準点を記録した素材一覧。
- 再書き出しできる `.blend`、必要なテクスチャと依存ファイル。第三者の絶対パスだけで成立する納品にしない。外部素材があれば出典と利用条件を添える。

### 書き出しの提案値

| 項目 | たたき台 |
|---|---|
| 静止画・連番 | 透過が必要なものはPNG RGBA。完成見本と透過素材を区別 |
| 大きさ | 想定表示の約2倍を出発点にする。全素材へ一律4Kを要求しない。量産前に画素数と総容量を確定 |
| 動作見本 | MP4。24fpsを比較用の出発点とし、アプリ納品の連番fpsとは別に決定 |
| 色 | 全素材の表示変換と露出を統一。アプリに読み込んだ色と完成見本を見比べる |
| ファイル名 | `park-<candidate>-<asset>-<state>-<frame>.png`。候補・部品・状態を識別可能にする |
| 素材一覧 | ファイル、用途、寸法、基準点、前後関係、尺、イベント時点、版、容量 |
| アプリ配信用 | 実装側で必要に応じ圧縮形式やアトラスへ変換し、透明縁と画質を再確認 |

BlenderのFilm設定は背景の透過に、出力設定のRGBAはアルファチャンネルの保存に関係する。両方を確認する。使用バージョンで名称を確認し、明暗2色の下地に重ねて納品を点検する。[Film公式説明](https://docs.blender.org/manual/en/4.4/render/cycles/render_settings/film.html) / [RGBA公式説明](https://docs.blender.org/manual/id/4.4/render/output/properties/output.html)。参照は設定概念の確認用で、Blenderの使用版を指定するものではない。

## 10. 受入条件

美術、理解、実装の判定を別々に記録する。テストが通っても美術がよい証拠にはせず、魅力的なレンダーだけでアプリ組み込み完了としない。

| 判定 | 最初の確認内容 | 完了を判断する証拠 |
|---|---|---|
| 美術 | 静止時から人形に目が向く。素材差と厚みがあり、触りたくなる | 選んだ参考と候補の同縮尺比較。画面上の実寸、64px輪郭、複数ポーズ。企画者の選定理由 |
| 理解・安全 | すべる、通る、跳ぶ、着地するが読める。怖さや痛さがない | 説明を見せていない観察者の反応。作者の解説だけで合格にしない |
| 素材の成立 | 配置を変えても接地・前後・透過が破綻しない | 一枚の完成見本と、分割素材からの2配置の再合成比較 |
| アプリ内の成立 | 人形・着地点・操作が隠れず、任意の配置を再演できる | 390×844と768×1024の実画面・録画。無音／動きを減らす設定の確認 |
| 配信の成立 | ユーザーが開くアプリに新候補が表示される | 対象URL、build revision、delivery flag、実際のcandidate ID、キャッシュ／PWA更新状態 |

子どもの観察では、2配置を説明なしで見てもらい、「何が起きた？」「並べ替えるとどうなると思う？」「もう一度やってみたい？」を確認する。自分から置き替える行動も記録する。理解の確認と、学習を挟んでも遊び続けるかの確認は別に行う。22仕様の年齢層別観察と採否条件を参照する。

最初の美術試作の合格は、量産方向を選ぶための判断。独立観察や実機確認、公開可否の判断を実施済みと扱わない。既存探索の画像スコア・主人公・連問タイミングを、この新モードの美術承認として転用しない。

## 11. 担当の分担案

| 担当 | 受け持つ内容 |

| 企画者 | 狙う感触、参考、キャラクター、制作範囲、採否、予算・日程、未決事項の確定 |
| Blender制作者 | 造形、材質、照明、固定カメラ、ポーズ・動作、再利用できる制作データと書き出し |
| UI／実装担当 | 画面内の占有率、部品棚、配置操作、素材の座標変換、前後関係、ゲーム状態と動作の同期、最適化、端末検証 |

制作前にカメラ・基準点・納品画像の比率を共同で確認し、量産前に「ゲートを通る／飛び越す」を共同で合成する。接地や遮蔽の問題を最終納品時まで持ち越さない。

## 13. 仕様策定者に返してほしいもの

1. 完成像を一文で表した制作方針と、具体的な参考画像。
2. 固定条件に対する不足・矛盾の指摘と、要決定事項を埋めた決定表。
3. 段階Aで実際に依頼する造形・カメラ・完成イメージの範囲。
4. 段階B以降の素材一覧、必要ポーズ、合成試験、納品条件。
5. 390×844の画面配置案と、制作・試遊・学習の画面のつながり。
6. 見た目、無文字理解、アプリ内の成立を分けた受入条件。

「かわいく」「高品質に」だけで終わらせず、制作者が造形と画角を選び、実装者が素材を組み込める具体性まで詰める。一方で、まだ見ていない美術候補や子どもの反応を確定事項にしない。
