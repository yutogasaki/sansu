# 観察の拒否理由と保存障害を分ける

園芸の観察中に「しまの きろくを たしかめられなかったよ」が残った[実取得検査](../2026-09-14-facility-production/README.md)を調査した。最初の同じ所有者での診断は利用中案内だけとなり、問題を再現しなかった（`initial-diagnostic/`）。図書室へ実際に到着するのを待ってから園芸小屋を呼び先にすると、歩行中の対象選択で再現した（`walking-diagnostic/`）。

後者の捕捉例外は `いまは みちを とおっているよ。`。これは `applyRelationObservation` が歩行を中断/瞬間移動させないための拒否であり、保存確認の失敗ではなかった。共通のメッセージ変換が既知の拒否まで未知の保存例外へまとめていた。診断は元の実60問/購入済み隔離ブラウザを使用し、DB注入や時計変更はない。ただしCDPのcaught exception一時停止を使ったため、その時刻/操作速度を通常E2Eの証拠にはしない。React等の内部で捕捉される例外も収録され、全てを未処理のアプリ障害とは扱わない。

変更は既知の歩行中・別利用中・対象不在の3理由だけを、再選択の案内へ対応させるもの。未知の保存障害/不明なpayloadを画面へ流さず、既存の確認/再試行案内を保持する。操作の拒否条件・保存・重複排除・PWA hold・住民の行動は変更しない。

実ドメインの歩行拒否を通す回帰検査は修正前RED、修正後は対象29テストPASS。coreは411ファイル/3962テスト。実画面の対象はlocalhost:5308、Island/Life/Discovery=true、Life preview/BuildPlay=false、moon-garden / mystic-island-shore-garden-v18。親revision `bd9f9dd`、app source `d594fd9d6751c0308a654d62c688e8a8c9f9e0f8bf8bcf21393092758ed27194`。外部デプロイではない。

通常ブラウザ検査は未完了。1回目は歩行中の短い拒否区間を捕捉できず、2回目は地面の投影位置から小屋のメニューを開くハーネスが失敗した。失敗結果とハーネスを保存した。修正後の同一debugger診断も相手が利用中の分岐となり、修正した歩行案内を再現しなかった。従って両幅の歩行案内、到着後の明示再選択、offlineまでをPASSとはしない。既知の歩行拒否から案内への変換は実ドメイン回帰テストで検証した。

- 視覚: レイアウト/美術を変更していない。C3はHOLD。
- 無文字理解/安全: 移動を中断せず再選択を案内する。実利用者による理解は未検証（N=0）。
- runtime: core/build PASS。上記の通常ブラウザの未検証区間を残す。全release PASSではない。
