# 本体接続の範囲と仕様同期

主目的は、低い殻・入口・共有岸を同じ所有物の場所として描画し、配置予告・確定・歩行・利用で同じ世界を使うこと。現在は明示DEV候補で、通常の本人保存への切替ではない。

`authoredWorldFrame` は不変の基礎worldから水庭、殻の支持床、最終placeを順に計算する。実際の家のstyle／成熟、あそびば、水供給、配置、局所床が監査済みprofileに合う場合だけ殻を組み立てる。配置や成立条件が変われば、殻と追加床／歩行点／辺を一緒に消す。すでに追加床を含むworldを次の基礎として使わず、追加床だけで成立条件を満たす循環を拒否する。

殻はSHAを照合した原本派生GLBの19 primitive／79,384 trianglesを使う。元の法線と4素材、入れ子のtransformを保持し、一度だけ共通座標へ移す。床はWorldDefinitionから一度描くため、床を含む確認用GLBはruntimeへ重ねない。共同形の選択先は元のp9で、新しい所有IDを作らない。

予告では将来のworldを別に計算する。現在のactor・pointer支持床・所有物は確定worldを保つ。変化する殻だけ一時非表示にし、取り消すと同じgeometry／material／rootを戻す。初期previewを伴う再構築で衝突判定が消える不具合は、表示上の一時非表示と確定worldの物理可視性を分けて修正した。無効な配置や取消しで予告床を残さない。

歩行判定は花庭と殻の実三角形を同じactorの部位別余白へ照合する。殻だけの場所でも働き、通行・利用・退出・drop／cancel／床の消失による退避に適用する。全ownerへの接近、実あそびばへの歩行／利用receipt／退出、予告と確定の同じ床・transformはfocused検査を備える。ブラウザの全旅程は別の証拠として検証する。

## Review

独立したコード確認は、previewを保持して全景へ戻った後に殻のguardが抜けるP2を1件検出した。修正前の実テストで0 triangles、修正後は79,384 trianglesを記録し、取消後も安全な床へ戻る。その他の確認対象にP0–P2は認められなかった。レビューだけで本体全旅程や美術採用を保証する判定ではない。

c2の全旅程で、許可された移動先 `(4,-4)` が主路を占有して24 ownerへの接近を断つことを確認した。移動前後で水庭と床は同じで、元位置に戻すと接近が回復する。driverを安全な `(12,-9)` と実geometryの事前検査へ修正し、両方の移動先をlife回帰で保持した。c3では復元期待値を検査用JSONから再構築したことによるプロパティ順の指紋差を確定した。保護対象の値が初期stateと同一であることを確認して初期stateを期待値に使うようdriverだけを直した。アプリの指紋規則は変更していない。c4で選択・取消・移動・収納・復元と回転／両幅の全旅程が通り、各失敗の生記録も保存した。

現在の実形状guardは花庭と殻を対象とする。[全native樹木とl14の入口の調査](../2026-10-12-authored-whole-massing/l14-approach-audit/README.md)で見つかった候補探索とguard対象の不足は、次の中央肩／森の制作で扱う。今回のPASSを全樹木・全施設の自然利用へ拡張しない。
