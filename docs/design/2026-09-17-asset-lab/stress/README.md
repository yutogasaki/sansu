# 島の配置数・素材種類数の負荷試験

2026-09-17。candidate: island-stress-v1、delivery: isolated synthetic production build。対象は localhost:5245/output/playwright/island-stress/index.html（終了後停止）。アプリ本体・保存データ・Meshyは変更なし。追加クレジット0。

[生データとrevision/source hash](report.json)、[描画環境](gpu-environment.json)、[30/100/300個の画面](placements.jpg)。

同じ起動設定で試験後に照会した描画環境はANGLE/SwiftShader（ソフトウェア描画）。フレーム時間を実スマホGPUのfps判定に使わない。

## 配置数の増加

|配置数|総転送量|画像展開推定|全景の描画回数：通常→区画一括|近接の描画回数：通常→区画一括|
|---|---:|---:|---:|---:|
|30|12.82 MB|56.01 MB|80→59|49→43|
|100|12.82 MB|56.01 MB|150→77|40→33|
|300|12.82 MB|56.01 MB|350→125|33→18|

3種類を共有すれば300個でも画像とモデルの転送量は増えない。ただし描く形状は増える。300個の全景では両方式とも2,482,260三角形を提出。一括描画だけでは頂点処理を減らせない。

区画一括は近接で余分な形状も描く。区画の一部が見えた場合、区画内インスタンスをまとめて描くため。この区画サイズを最適解として採用しない。

## 独立した素材種類数の増加

配置は30個に固定。同じGLBを別URLから取得して独立に保持した模擬試験。実際の異なる新しいアートではない。

|種類相当|総転送量|画像展開推定|
|---|---:|---:|
|3|12.82 MB|56.01 MB|
|6|25.44 MB|106.34 MB|
|12|50.67 MB|207.01 MB|

画像展開はRGBA8＋mipmapの推定で、共通背景を含む。実GPU使用量ではなく、ドライバー・render targetの領域を含まない。種類増加は12種類までに限定し、100/300種類は実際に読み込んでいない。

## フレーム時間（ソフトウェア描画の参考値）

|配置数／方式|全景中央値|近接中央値|移動中央値|

|30／通常|93.4 ms|66.6 ms|66.7 ms|
|30／区画一括|93.5 ms|67.1 ms|80.0 ms|
|100／通常|266.8 ms|67.2 ms|79.9 ms|
|100／区画一括|266.7 ms|93.4 ms|106.4 ms|
|300／通常|766.3 ms|93.5 ms|105.6 ms|
|300／区画一括|760.4 ms|133.3 ms|133.4 ms|

一括描画によるfps改善は確認できなかった。全景向けの遠距離LODと、近接での区画粒度が次の検証対象。300個で影の毎フレーム更新も診断したが、通常移動の続きの位置から測定したため、同位置比較の改善率・悪化率は算出しない。

- 8条件完走、JS例外・WebGL描画エラー0。3種類共有の全条件で転送量と画像推定が一定。両方式の全景三角形数一致を検査。
- 各条件1回、45フレーム／視点、先頭11を除外。ローカル通信・キャッシュ無効・390×844／DPR1.5。

- 視界外の描画削減は確認。区画の非同期ロード／アンロード・長時間メモリ解放・住人や物理の増加・スマホ実機は未検証。

## 判断

素材の共有は採用する。未圧縮1K画像を種類ごとに増やす量産は進めない。先にGPU画像圧縮、全景用LOD、区画粒度を試して同じ負荷シーンで比較する。実機の上限個数は今回の結果から決めない。
