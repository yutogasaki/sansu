## 見た目

静止した全体・各素材拡大の比較は合格。色・シルエット・ドット・ベンチの配色を維持。1Kでは木の細かい凹凸や岩の表面が少し滑らかになるが、通常の島内サイズで主な特徴は読める。生成素材は既存の家より丸く、塗りの質感が強い。大量に増やす前にアート方向の統一は必要。

## 無文字理解・安全

素材は木・岩・ベンチとして目視で識別可能。ラボは開発者向け。子どもの操作理解を観察したテストは未実施で、本番UX承認は未判定。ベンチは静的モデルであり、座る位置や住人との接触判定はまだ実装していない。

## 実行整合性

PC幅1280・幅390で2解像度×全体/木/岩/ベンチ、横はみ出しなし、読込エラー表示、再試行、再読込を確認。WebGL警告のうち描画失敗を示すものも検査し0件。reduced-motion環境で自動運動なし。スマホ実機のGPU・発熱・メモリ・通信速度は未検証。

ローカル比較では初回描画込み読込はPC 2K 211ms/1K 72ms、幅390は218ms/56ms。キャッシュ条件が同一でないため速度向上率は採用根拠にしない。描画呼出CPU平均は0.24–0.28msで、GPUフレーム時間ではない。描画call 52・全シーン95,708三角形は両版同じ。まず減らせたのは転送量とテクスチャ画素数である。

`verify:core`成功（426ファイル、4,041テスト）。既存lint警告1件と文書期限警告あり。後続の小修正は対象lint・typecheckとブラウザ再検証済み。

## 検出した問題と再利用した対策

- Blender再書出しで木の頂点が2個増えた → 縮小した画像だけを元GLBへ移植し、形状属性hash一致を必須化。
- 初回描画時にshadow map未作成で背景モデルが消えた → 初回描画前に更新要求。スクリーンショット目視とWebGL warning検査を併用。
- 今後は素材ごとの高さ・地面接触・座席位置・衝突形状をrecipeに持ち、実機メモリ予算を決める。KTX2等の圧縮は別検証として扱う。
