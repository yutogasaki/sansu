## 具体的な所見

### 1. 長く遊ぶ理由が序盤で尽きる

家具は6種、3択の組合せは4周期。2区間で土地、4区間でキツネ、6区間で灯台が増え、その後の成長はない。6区間は3/6問換算で18〜36問相当であり、誤答や支援操作の回数は別である。何日遊べるかは利用者のペース次第だが、世界側の新規コンテンツは短い。

根拠: `src/domain/island/catalog.ts:3`、同`:22`、`src/components/island/three/runtime.ts:159`、`src/pages/Island.tsx:118`。

家具選択と自由配置は有意味で、住民の通路・到達可否も変える。しかし自由遊びは主に「物を選ぶ→住民が歩く→決まった動作」。住民同士・家具同士の組合せで結果が変わる層はない。現在の仕様は回答に別の攻略ルールを求めないので、追加の算数パズルを強制する必要はない。既存の家具を並べ替えると住民の遊び方が変わるような、学習外の小さな発見が有望な設計案になる。

根拠: `src/components/island/three/residentInteraction.ts:31`、`src/components/island/three/runtime.ts:276`、`src/components/island/three/animals.ts:88`。

### 2. 遊びの主操作をUIが弱めている

[自由遊びのphone画面](screens/phone-play.png) で、最も強い黄色のボタンは学習へ戻る「ひかりを とどける」。実際の遊びの選択肢はその下に並ぶ。遊びを始めた子の現在の目的と強調の順が合っていない。

[配置画面](screens/phone-placement.png) では、初期候補のベンチがカワウソの背後へ隠れた。対象の全体・向き・接地位置が読みにくい。輪郭や住民との分離で改善すべきで、説明を増やしても位置は見えるようにならない。

[tabletで遊びから学習へ戻った画面](screens/tablet-next-learning.png) では、灯りへ移動したウサギの耳と頭上部がstage上端に切れた。初期位置の住民が収まることだけでは、遊んだ後のカメラを保証できない。今回観測した状態の指摘であり、全問題で切れるという意味ではない。

既存 [phoneの図形選択](../2026-09-07-production-release/screens/phone-learning.png) には、見本側の選択図形と押せる回答側の図形が重複している。問題の意味を保ちつつ、見本と回答先を一目で区別できる構成が必要。

### 3. 説明を減らす対象は「同じ意味の繰り返し」

ホームで「きょうは、なにが ふえるかな」「ひかりを とどけよう」「ひとつ とくと…」「ひかりを とどける」が同じ誘いを繰り返す。学習の支援でも「いっしょに たしかめよう」が上部と下部に重なる。現状は長いルール説明が問題なのではなく、読まなくても操作できる補足が常設されていることが負担。

一方、学習の問いやヒントは削るべき装飾ではない。重複する世界説明を減らし、問題文・短い考え方・必要な操作指示を残す。配置できない原因も、通れない場所を画面で示す方が文言追加より目的に合う。

### 4. 支援を「答えの入力」から理解へ進めたい

[今回の3+2の支援](screens/phone-support.png) は「3から2こすすんで、かぞえよう」に続いて即座に答え5を表示する。方略を読まずに写すこともできる。「わからない」も同じ問題の支援を開き、最終正解の入力までは次問へ進まない。支援を受けることが独力記録へ混入しない点は良いが、理解を生む体験としては弱い。

根拠: `src/components/island/IslandLearningSupport.tsx:24`、`src/components/island/IslandLearningPanel.tsx:42`、`src/domain/island/commit.ts:49`。

数を一つずつ動かす、繰上がる場所だけ確認する等の短い支援を、必要な時だけ使える形が候補。通常の連問へ操作を増やさず、支援後の別問題で独力回答できるかを評価する。これは改善案であり、効果を実証したものではない。

### 5. 演習量・当日の成功と定着を分ける

SRSは同日かどうかを問わず正解ごとに強度が上がる。次レベルの解放には20回答85%以上の条件があるが、解放済みの次レベルを主練習へ移す段階は誤答も含む30回答である。いずれも仕様一致で、今回バグと判定していない。ただし定着や理解の評価として十分かは再検討に値する。

根拠: `src/domain/algorithms/srs.ts:20`、`src/domain/learningAttemptWriter.ts:123`、同`:142`。別問題での再確認は `src/domain/island/learningChecks.ts:37`、苦手と通常Dueの調整は `src/domain/island/repository.ts:85`。

自動入力の速さは子どもの流暢さではない。理解確認・翌日以降の独力回答・自発的な再訪を別々に観察したい。

## 速さの証拠

[直近配布の正式固定10問](../2026-09-07-production-release/throughput-retry.json) は両画面各10反復、PASS・eligible=true。今回再計測した値ではない。

| 画面 | 正解→入力可能P95 | 誤答→再入力P95 |
|---|---:|---:|
| 390×844 | 262.3ms | 385.0ms |
| 768×1024 | 368.4ms | 324.6ms |

計測は同sourceのDEV5398、固定fixture、自動keyboard、音off、reduced motion。通常問題間の追加0操作、650/550ms以内を確認している。Study側は非記録fixture、Island側は保存を行う条件差があるため、速度比を子どもの学習効率へ換算しない。今回の実操作でも連問、訂正、支援後の回答、次区間の入力を確認。物理的なモバイル端末の速度は未測定。

## 独立した判定

- **視覚の魅力: 改善余地あり。** 6軸の参考診断はhome 36/60、learning 32/60。順に「入りたい世界」7/5、「愛着」5/6、「素材」5/4、「構図」7/6、「色」8/7、「出来事の期待・結果」4/4。2026-09-07、同候補・両viewportの既存実画面による専門家評価、確信度は中。旧探索cold-openの52/60を島の合否基準へ転用していない。
- **無文字理解・安全: 独立観察待ち。** 文言と失敗処理には配慮がある。一方、配置対象の遮蔽と、遊び後の住民のcropを実見。子どもに未説明で通じることは実証していない。
- **Runtime integrity: 今回の限定操作とfocused testsは確認済み。** 既存の同revision release検証はPASS。今回のconsole errorは0、Three.jsの影方式の非推奨warningが2件。全PWA/全形式/実機を今回再検証したとは扱わない。
- **全体の連続性: 島内の造形・配色は連続するが要改善。** 初回準備はutilityへの意図した切替として扱う。遊びから学習へ移る際のカメラと住民位置の整合に具体的な残課題がある。

## 改善順

1. 配置対象の視認性、遊び画面の主操作、戻った学習画面の住民cropを修正する。
2. 既存家具の配置・組合せで異なる出来事が起きる遊びを一つ作り、もう一度配置を変えたくなるか観察する。
3. 重複する世界説明と図形提示を減らし、必要な問い・ヒント・操作だけを主役にする。
4. 支援を段階化し、別問題と時間を空けた独力回答を観察する。SRS・進級条件の変更は別途仕様と学習検証を伴う。

アプリコードの変更なし。評価記録と実画面のみ追加。学力向上や自発的再遊びの実証は未完了として明記する。
