## 優先する3件

### P1：室内の触れる物と結果を読み取れるようにする

**画像で確認＋コード照合、初見の理解は仮説。** overviewの案内は床歩行が中心で、実物のアルバム・掲示板・机・壁模様・棚と遷移先の対応は画面から読み取りにくい。物タップ自体は実装済みであり、新設する必要はない。窓は写真表示で、タップ入口ではない。

候補：実際に押せる物に短い名称・操作後の反応を添える。必要時の小さな案内にとどめ、常時のラベルや点滅で部屋を覆わない。文字付きの既存の入口も保持する。

受入条件：床歩行と実物タップが競合しない。実物を触る前に結果を予想できるか、初見の子どもに観察する。窓など非操作物を押せるように見せない。

### P1：机の表示と「学習を始める」挙動を一致させる

**コードで確認、誤操作の発生は未観察。** `applyDesk` は当日実績なしでは「ここから まなぶ」、実績ありでは「きょう まなんだ」と描く。しかし両者の机タップは `desk → begin()` で学習を開始・再開する。後者は記録閲覧に見える可能性がある。

候補：直接開始の既存契約を保ち、当日の内容とともに「まなぶ／つづきから」の操作意図が読み取れる表示を比較する。タップごとに確認画面を増やす案は必須にしない。

受入条件：未学習・当日実績あり・再開予約ありで、表示と実行内容が一致する。同じ学習予約と家への復帰を保つ。開始前に本人が学習開始を予想できるかは別途観察する。

**画像＋コードで入口の並存を確認、混乱は仮説。** アルバム・写真・まなびの記念・かざりと記憶・おしらせ・手紙は異なる実データと機能を持つ。似た言葉だけでは行き先を覚えにくい可能性がある。

| 入口 | 現在の意味 | 整理の候補 |
|---|---|---|
| アルバム | 島の過去と現在の比較 | 島の変化を見ると伝える |
| しゃしん | 自分で撮った写真の棚 | 写真を見ると撮影を区別する |
| まなびの きねん | 区切り回数で得る証書・トロフィーと展示 | 何を飾る面か伝える |
| かざりと きおく | 学習1区切り後に出る既存の別画面 | 内容を調べて役割を説明する。保存統合はしない |
| おしらせ | `pendingRewards` のおくりもの案内 | 運営情報と誤読させない名前・補足を検討 |

受入条件：新規と1区切り完了後で各入口の意味と出現条件を説明できる。既存の閲覧・展示・取得・撮影・戻り先を保持し、データや機能を削らない。
