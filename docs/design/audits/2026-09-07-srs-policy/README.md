## 解釈と最小の次案

- 親01 §5.1は正解ごとにstrength+1を要求し、遅延や期限後かどうかを条件にしていない。1〜3は仕様との一致であり、実装バグとは扱わない。同日反復と期限後の成功を同じ強度として扱うことが確認できた再検討点である。遅延成功を重くする等の新しい基準は採用も数値提案もしていない。
- 04:00境界と暦日間隔の組合せにより「1日後」が実経過1分になる条件が存在する。最低24時間と同義ではない。変更するなら間隔の意味を親仕様で決める必要があり、時計の受け渡しだけを直してもこの結果は変わらない。
- writerは明示timestampをログ・updatedAtへ使う一方、SRS期限と日次集計は内部の現在時計を読む。今回の測定では両方を揃えたため、混在時計の不一致は測定していない。当初はイベント日時へ時計を揃える案を検討したが、独立レビューで前日分の遅着が日次件数/streakを巻き戻す可能性を確認した。観測時刻の追加と日次/SRS時計の変更を分け、遅着をどう集計するかを決めるまで現行時計を維持する。混在時計の不一致や遅着そのものを、この12ケースで測定したとは扱わない。
- 親01 §5.2は最大解放レベルの非復習30問でメイン昇格する。6〜11は両実装の一致を確認した。0/30正解での昇格は現行方針上起こり得るため、到達の意味を再検討する材料になる。正答率条件の追加や数値閾値は別の仕様判断が必要。ここではすでに解放されたLv9を明示fixtureとして使い、誤答で新規解放できるとは主張しない。
- 将来の観測は、実在する問題/slot・提示回・訂正か新問題か・実際に開いた支援・回答日時・期限計算の基準日時を対応づける最小の記録から始められる。支援を開かなかったことだけで独立した想起と断定しない。古い汎用ログにない事実はunknownのまま残し、推測によるバックフィルをしない。
- 1人ずつでも、日を空けた別問題で支援なしに解けるか、同問訂正とどう違うかを新しい観察として集められる。本プローブの12PASSは、その人の学習成功を代替しない。
