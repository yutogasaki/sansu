# 成長後の操作数と重なり

ユーザーのiPhone画像では、動物のパネルに配置済み全道具のボタンを並べ、「もとの ながめ」がその上へ重なっていた。前回の退出/保存復帰の確認では、この増加を扱えていなかった。[仕様43](../../../product/43_island_navigation_spec.md)・[仕様44](../../../product/44_display_layout_spec.md)を更新し、同じ画面内へ全件リストを増設しない操作に変更した。

[実画面一覧](review.html)・[コンタクトシート](contact-sheet.png)。変更前はmain `45d62a9` の別buildであり、変更後の証拠には数えない。成熟の道具は合法配置を使った明示native fixture。家/学習の写真は別プロフィールの実初回3問からの経路であり、一つの獲得履歴として扱わない。

## 実装

- 動物選択は短い案内と「えから えらぶ」。1/9/16個で2ボタン・同じ高さ。SSRでは100個でも同じ出力を確認。実3Dをタップして、その動物と道具で遊ぶ。庭のお花も動物選択中は遊びに使える。
- 操作領域を3Dの外へ分け、ホームのもちもの/メニュー列と置き換える。眺めメニューは排他で開き、リセットや成長案内を操作に重ねない。低い横画面は左右配置。
- 絵の一覧は本文だけをスクロールし、景色と退出を固定。選択後は案内へ戻し、通り道が塞がったときの移動操作をその直後へ出す。島が画面外へスクロールして遊びの処理まで停止する状態を解消。
- 遊びを続ける間は選んだ動物を保持。退出/再読込では持ち越さない。WebGL context lossでも直接操作の退出と一覧入口を残す。保存スキーマと獲得条件は変更しない。

- v5のunitは329ファイル / 3,555件通過。
- [browser-reports.json](browser-reports.json)：Chromiumの390×844 / 320×568 / 768×1024 / 844×390とWebKitの390×844で、合法1/9/16配置、閉じる/選ぶ操作の全体表示・44px・上中下の実hit、眺めとの排他、閲覧/取消の7store不変、空の配置、実3D/一覧の選択を確認した。

## 最初の失敗と検証の限界

[diagnostic-history.json](diagnostic-history.json)に失敗したrunの分類と元の保存先を記録。初期fixtureの追加家具IDが正式なIDでなく、読込検証に拒否されたため修正した。カメラの最小倍率で縮小を押す前提や、混雑して隠れるラベル・動物に遮られた花をタップする前提も修正した。tabletは実カメラを回し、見える花をタップする。これらをアプリ成功に数えない。

実際のアプリ側の問題は、増えるリスト/リセットの重なり、庭の花の選択分岐、混雑時の移動操作の埋没、横画面で一覧を選ぶと景色が画面外へ出て処理が停止する構造だった。最終候補ではこれらを確認した。

- 視覚：同じ候補の画面で操作領域の分離と景色の可視性を確認。変更前のcaptureには旧canvasの水色矩形も残るが、今回の合否はリスト数・重なりと操作に限定し、その描画問題の解決とは主張しない。既存アートHOLDは解除しない。
- 無説明理解/安全：操作の到達性と保存保持は確認。子どもの観察N=0、魅力や継続意欲の実証なし。
- Runtime：この変更の局所回帰。実取得による全島成熟、PWA二版更新、学習throughput、実iPhone/Android、全機能の公開ゲートは今回の再検査外。Git mainへの反映は本番配布済みの確認とは別。
