# Little Habitats：操作から地形の作り方を推定する

2026-10-22 JST。ユーザー依頼「必要なら触ったりしながら、手法を推定してよ」への調査。[画像で読む結果](index.html)。対象は [Little Habitats公開版](https://little-habitats.vercel.app/)、入口は [Wavedash](https://wavedash.com/games/little-habitats)。Sansuの実装変更ではない。

## 結論

最有力の説明は **区画ごとの段階的な高さ・材質 → 隣接関係に応じた連続輪郭 → 厚みのある断面 → 草・土・石・水際の描き分け**。固定の丸い柱を並べるだけでは観察結果を説明できない。一方、格子と段階的な高さを捨てて、全面を滑らかな丘へ変える必要性も、この参考作からは導けない。

これは外から観察した挙動に合うモデルであり、内部ソースの確定ではない。Marching Squares、輪郭スプライン、隣接マスクで選ぶ変形部品、滑らかな距離場などは、同じ見た目を作り得る。今回、実際の格子構造・アルゴリズム名・更新範囲・三角形数・CPU/GPU分担は確定していない。

## 作り方の推定を、実装可能な形へ落とす

以下は **Sansuで試すための候補**。Little Habitatsの実コードを復元したものではない。

1. 編集データを `地点ID / 高さの段 / 材質` として保持する。見える輪郭を四角い編集枠そのものにしない。
2. 高さの段ごとに隣接する陸を判定する。境界を「直線・凸角・凹角・対角・内周」に分け、共有端点と接線を揃えてつなぐ。Marching Squares相当の判定か部品表で実現できるが、対角の扱いは明示する。
3. つながった輪郭に対して上面の肩、土の胴、裾を生成する。上面と側面の境界は草が少し覆い、土の層は側面にふくらみを持つ。全面を平均化して足場を細らせる処理とは分ける。
4. 同じ輪郭から海岸の砂・浅瀬・水際の帯を生成する。実際の水表現の方式は未確認なので、観察できた帯の追従を再現目標にする。
5. 小さな表面変化は地点・境界に固定し、編集やUndoで周辺の模様を不必要に引き直さない。これは安定した見た目を得る設計提案であり、参考作の乱数仕様の確認ではない。
6. Sansuでは完成した実三角形を支持・歩行にも使う。参考作でキャラクター歩行の整合を実測したわけではなく、こちらの製品要件。

不規則格子は選択肢だが、今回の見た目だけから必須とはしない。[有機的格子の作者による解説](https://andersource.dev/2020/11/06/organic-grid.html)は別実装の方法で、Little Habitats採用の証拠ではない。[TownBuilder](https://github.com/eliemichel/TownBuilder)もTownscaperの教育的再現であり、参考作本体のソースではない。両ページを今回再読した。

## 直前の7案から変える判断

- 「段階高さや格子だから角張る」は説明として不十分。参考作も段階的に編集でき、丸い輪郭・草の縁・土の厚み・水際が同時に成立する。
- B4の対角分離は一つの方針であり、参考作に近いという根拠にはならない。今回見えた対角接続は、全対角を分けるB4と異なる。逆向きも調べるまでB3の固定対角を正解とも扱わない。
- 7案のB3/B4はすでに曲線輪郭を持つ。新たな名称だけでは前進にならない。次の候補では **参考作と同じ単独・隣接・L字・対角入力の輪郭、草の縁の厚み、断面の層とふくらみ、内外の水際** を直接照合する。
- 家や木の密度を増やす前に、この小さな無装飾地形で近づくか判断する。影・ぼかしだけで輪郭不足を隠さない。歩行・支持の合格は美術の合格と分ける。

次の試作の合格条件は、同じ4入力を固定画角で並べて輪郭と断面の差を説明でき、編集後も岸が連続し、木・家の足場とUndoが保たれること。現段階では候補の実装・美術合格を宣言しない。
