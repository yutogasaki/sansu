## 結論

前回の「Switchらしい作り込み → 立体の玩具盤面」という解釈を改める。参考の軸は、明快な面色、濃い輪郭、太い見出し、入力に直接参加するキャラクター、画面と音が段階的に発展する構成。質感を増やす方向へ進んだため、この軸から離れた。

次は参考のグラフィックのルールをもっと直接取り入れる。ぽこもこの顔・頭身・耳・布・配色は保持し、操作面を平面的で輪郭の強いポップな表現へ再設計する。静止画の色替えだけで終わらず、音付きの短い一連の動作を先に検討する。

## 1. 古く見える原因を分ける

| 観点 | 参考の実画面／公開CSS | Sansu v4で見える差 | 検討する変更 |
|---|---|---|---|
| 色 | 明るい紙色、濃い紺、澄んだ青・ピンク・黄・ミント。アクセントは面として見える | 生成り・ベージュ・茶の影が広く、青い光沢レールだけが強い | 茶の陰影を外し、明るい下地＋紺の輪郭＋鮮明なアクセントへ |
| 形・影 | 問題面・キー・カウンター・見出しが、共通の濃い輪郭と硬い短い影を持つ | 二重の縁、ベベル、ぼけた影、光沢部品、布のキャラが競合 | 枠と影のルールを統一。素材感は元のぽこもこに集中させる |
| 文字 | 普段の操作は丸い文字、節目は横に太い見出し。数字が前景へ出る | 大きい問題文字と、小さい補助表示の差が中心。節目の主役が小さい | 大見出し用の字形を別途設計。節目は短い数語・大きい数字 |
| 構図 | 問題面の上がキャラの舞台。キー・問題・舞台が動作でつながる | レールが問題面内の上部を占有。キャラと答えの間に距離がある | レールをやめ、問題の縁を舞台に。問題と入力の空間を返す |
| 統一感 | 背景、キャラ、数字、粒子まで同じ輪郭と色の言葉を使う | 実写的な光沢、ぬいぐるみ、淡いUI、線画アイコンが混在 | UIは面と輪郭、キャラは既存の布。その二つの役割を明確にする |

生成り自体が古さの原因ではない。参考も `#fff8ec` を使っている。違いは、茶色い陰影を何層も重ねるか、濃い輪郭と明るい色面を使うかにある。「古い」は今回の比較に対するデザイン判断で、普遍的な年代分類ではない。

公開CSSの基準色は紺 `#1b1d4d`、紙 `#fff8ec`、青 `#3b6bff`、ピンク `#ff7ab6`、黄 `#ffd23f`、ミント `#3fdcb0`。見出しはDela Gothic One、通常文字はZen Maru Gothic。値は[公開CSS](https://github.com/grmchn/dopa-drill/blob/0720ddfe37334628bab61ba5b3a9282bd6bfb31c/app/style.css#L1-L20)から取得し、圧縮動画の画素から測った値ではない。

参考にも小さいHUD文字はある。小さい文字の多さまで追従せず、Sansuでは主な進行1つ、連続数、必要な操作へ絞る。問題形式が違うため、単純な「問題欄の高さの比率」は比較しない。筆算や分数にも必要な広さを確保する。

## 2. 元動画の構成

| 元動画の位置 | 見える変化 | 持ち帰る設計 |
|---|---|---|

| 約17.5秒 | 色違いの観客、紙吹雪、累積数が重なる | キャラ周辺だけでなく舞台全体が発展する |

| 約30.5秒 | エクストラで観客・光・数字が増える | 特別状態は背景・音楽・演技がまとめて変わる |

上の時刻は観察フレームの位置で、効果開始の厳密な計測値ではない。元動画の後半には問題に重なる効果もある。画面占有率をそのまま移さず、次の解答欄とキーの読みやすさを守る。

## 3. キャラを「操作に参加」させる

参考は **キー → キャラの手 → 解答欄**。Sansu v4は **解答欄 → 青い光 → キャラ**。後者は入力後の飾りとして見えやすく、前者は「キャラと一緒に数字を置いた」という物理的な因果になる。

公開版は視線、体の傾き、手、数字の弧、着地を順序づけている。通常範囲のE=0.08〜1では手を伸ばす約80〜117ms、運ぶ約150〜187ms、戻す150ms。左右の手を使い分ける。[carryの実装](https://github.com/grmchn/dopa-drill/blob/0720ddfe37334628bab61ba5b3a9282bd6bfb31c/app/js/dopakichi.js#L346-L373)。これは公開版の設定値で、動画計測値ではない。

ぽこもこでは顔・体の形を改変せず、「押した数字を前足で弾く／受け渡して解答欄へ送る」をまず検討する。伸びる腕を採用する必要はない。数字を受理する処理は即時で、キャラの演技待ちや拍待ちを作らない。画像のポーズ数を増やす前に、この移動経路と接点を決める。

## 4. 連続正解だけでは発展しない

公開版の基本演出強度は `E = 0.08 + 0.92 × (問題位置 / (問題数−1))^1.3`。主な盛り上がりは**問題を進めた量**から生まれ、コンボとは別軸。[applyLevel](https://github.com/grmchn/dopa-drill/blob/0720ddfe37334628bab61ba5b3a9282bd6bfb31c/app/js/main.js#L237-L248)。元動画でもミス1の表示を残したまま演出が強まっている。

Sansuへの案は次の二つを分ける。

- **学習の進行**：舞台の色・旗・応援役・音楽の層が段階的に増える。誤答で全部を静かな状態へ戻さない。
- **連続正解**：3連続・5連続で短い特別演技や音のフレーズを追加する。既存の獲得物と学習判定を変えず、連続数が途切れても進行による舞台の発展は残す。

参考の数字の無限膨張、時間制限、後半の全面的な効果密度は、最初の「ここまでドーパミンを出したいわけではない」という要望から、そのまま採用しない。ピークの強さは通常との差で作る。

## 5. 音の分解 — 公開版ソースで確認した構造

音の情報源は[音源実装](https://github.com/grmchn/dopa-drill/blob/0720ddfe37334628bab61ba5b3a9282bd6bfb31c/app/js/audio.js)。音色の呼称はコードの楽器名・合成方式であり、実際に聴いた印象ではない。

| 層 | 公開版の仕組み | Sansu v4との差 |
|---|---|---|
| 曲の発展 | マリンバ風の音・シェーカー・パッドに、L1キック、L2ベース、L3クラップ、L4ハット、L5アルペジオ、L6和音の短音、L8旋律、L9コーラスを加える。初期のマリンバは薄くなる | 連続数や進行で編成が変わる学習BGMがない |
| テンポ・調 | 基本はEに応じて約113.28→128 BPM。終盤とextraで転調。extraは134+tier×5 BPM | correct/clear等の既存固定ファイルを選ぶ |
| 入力の触感 | keyTap、grab、placeが別音。キー音はその時の曲の和音と連続段数から音程を選ぶ | キャラの受取・跳躍・着地と一組の音が設計されていない |
| 正解 | ベルを0/60/120msで重ね、強度に応じて高音・硬貨音・クラッシュを足す | 同じcorrect、特別時にclearへ切替 |
| 予兆→解放 | リーチでBGMの高域を絞り、ロールと上昇音。到達で低音・和音・高域を戻す | 「あと1つ」の文字と点の変化が中心 |
| 拍との同期 | 音楽のキックと拍を画面へ渡す。体や背景の動きと音が共通の拍を持つ | 動きと既存効果音が独立 |
| 音の整理 | 音楽とSEの系統を分け、コンプレッサー・リミッター・一時的なBGM抑制を使う | 効果音を足すだけでは同時発音が混み合う |

参考の音作りの中心は、音量を上げることより、編成・音程・間・拍・低音と高音の役割を変えることにある、というのが実装からの解釈。

Sansuへの最初の提案は、通常は短い音のBGM、3連続でベースとクラップ、5連続で短い上昇フレーズと和音、区切りで小さな終止形。通常の押下音を即時に返し、着地音を絵の接触と合わせる。SEは曲の和音へ合わせる。音量の増加と高速化を主な報酬にしない。音offの設定を継承し、誤答に大きな失敗音を使わない。

## 6. 真似るもの・変換するもの

| そのまま設計の基準にする | ぽこもこへ変換する／今回は採らない |
|---|---|
| 鮮明な面色、濃い輪郭、短い硬い影 | 茶のベベル、光沢レール、縁の多重化は外す案 |
| 通常文字と巨大な見出しの使い分け | 小さいHUD文字の量は減らす |
| キーから答えへ数字が動く、視線と手が追う | ぽこもこの元の体・顔・配色を保つ |
| 通常→発展→予兆→ピーク→落ち着く流れ | 常時大量の紙吹雪、全面の点滅は採らない |
| 進行で育つ舞台＋連続正解の短い特別演技 | 無限桁の通貨や制限時間は採らない |
| 効果音とBGMを同じ音楽として設計 | 既存音に無関係なSEを順次追加する方法をやめる |

## 7. 次に検討する成果物

1. **参考と並べる一つの方向**：通常、入力、3連続、5連続の4画面。今回は発散する玩具案を増やさず、面色・太線・大見出しを忠実に試す。
2. **音付き12〜15秒の絵コンテ動画**：押す→数字を送る→正解→3連続→5連続。入力・接触・着地・BGMの変化を同時に確認する。新しい音色の聞き比べもここで行う。
3. **比較後に実装判断**：通常時点で新しい配色・形の方向が伝わるか、節目の構図が変わるか、音付きで操作の触感が増すかを見て決める。今回の分析だけで採用・楽しさ・子どもの評価をPASSにはしない。

仕様変更は保留。現行の盤面・音維持の規定を、検討資料だけで新方針へ置き換えない。コード・保存・ルーティング・PWAは無変更。検証対象は資料のリンクと比較ページの表示・区間再生操作のみ。
