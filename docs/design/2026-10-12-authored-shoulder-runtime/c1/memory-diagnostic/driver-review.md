## Cache semantics and cost

The c1 outer key was JSON of a structured clone excluding `applied` and `placeProgress`. Domain also excludes only those two fields, and additionally keys water/cove options, shoulder drawing revision, and cove profile revision. In this driver the immutable base, options, and loaded profiles are fixed. Delegating therefore preserves the intended state distinctions, including drops/nextId and future/committed states, while allowing the domain's actual LRU3 to refresh on every hit. A recomputed frame can have different object identity after eviction, but the driver compares revision/data, not frame object identity. No test currently requires the original frame object to survive eviction.

An outer LRU3 is less reliable as the fix. Both outer and domain caches could retain different sets because an outer hit bypasses the domain refresh. For example, calls A,B,C,A,D give outer order C,A,D versus domain B,C,D: four distinct frames remain. Two capacities of three do not prove a global three-frame bound. The exact maximum across cache layers and live locals was not established.

Direct calls have extra hit cost. `authoredWorldFrame` computes the state JSON and calls `authoredShoulderProfileDrawingRevision` before looking up the domain cache. The latter JSON-stringifies and scans the entire profile, with no memoization. The gzip profile expands to 6,808,883 bytes on disk, so this is an O(profile-size) temporary allocation and scan per call, not an O(1) lookup. The frozen default cove profile revision is already WeakMap-cached. On a domain hit, shoulder/world composition, derivePlaces, and world compilation are skipped. The exact hit time and peak allocation were not measured here. This cost is preferable to knowingly retaining unlimited worlds; it does not justify reintroducing a second world cache. If later evidence requires a profile-revision optimization, its immutability contract needs separate review rather than silently trusting a mutable profile identity.

The domain also has a separate water-frame cache with three entries. It returns hits without refreshing insertion order (FIFO-like), unlike authoredWorldFrame's LRU. Composed land extensions and caller-held worlds also exist. Thus even the direct-delegation change cannot be described as 'only three worlds live in the process.'

## Remaining live references

`acquisition()` assigns the full `checkSettled` result to `initial`, whose `.projected` field references the baseline compiled world. It is only needed immediately to derive `oldPlaces` and `geometryHash`; it is not used later in the journey. A runtime may collect a value after its last use, but source structure should not be treated as a guarantee that the async activation released it. A follow-up scoped helper could return only the derived place records and geometry digest, leaving no full checked result in the long-running acquisition scope. `DerivedPlace` contains cells/routes/IDs, not an IslandWorld reference.

`fixedEdits()` similarly holds `initial = frame(baseline)` across awaits and later uses only `initial.revision`, after computing rights and the first canPlace check. A future narrowing could retain the revision string, rights data, and floor/edge digest instead of the full frame. The per-purchase `current.projected` is intentionally needed through the pure applyIntent oracle; that reference should not be dropped before its last use. Per-check/capture results can also remain live across their own awaits. No reference narrowing has been implemented by this review.

## What the diagnostic actually modeled

Attempt 02 used the unchanged real domain caches, plus an outer cache set to LRU3 or unbounded. Its outer-LRU hit logic refreshes only the outer cache; it does not call domain on a hit. All 12 measured calls were misses, so that divergence was never triggered. The sequence did not reproduce the real driver's repeated reads/captures, the long-lived acquisition/fixed-edit initial results, all placement scans, browser allocations, or the new direct-delegation repair. Its finding is extra retained heap from the unbounded Map on identical frame states; it does not prove a full-driver memory ceiling.

The single bounded sequence completed growth, milestone synchronization, and mature projection, but the unbounded half stopped after four of eight planned states at the safety reserve. The original full acquisition OOM remains a failure. No more diagnostic process, browser, build, or heavy test was run for this review. A new same-source frozen candidate and the complete original assertions are still needed for acceptance; heap expansion or reduced assertions would not address that requirement.
