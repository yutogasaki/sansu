# 育成ペースの30日仮計算

2026-10-19。v0.4協議の設計診断。本人のデータは使わず、架空入力で既存の純粋ドメインを実行した。**候補仕様の受入試験や、子どもの楽しさの実証ではない。**

## 前提と再実行

1日6件/20件の有効完了を2セッションに分け、30日間。これは比較用の入力であり、日課や達成ノルマではない。各完了は現行どおり2しずく/2まち時間。初回家の無料特例、家/畑40、船、夜明け、建築、論理セルでの実到達、時間銀行を既存処理で判定する。

- 家優先：空き住居を1枠先に用意し、供給が尽きたら畑を買い、すみごこちが上がる場合だけベンチを買う。
- 庭優先：各セッションで先に花または木を1個、最大20しずくで買い、その後は家優先と同じ方針。資金不足で家を後回しにしてよい。
- 2島：7日ごとに交代。共通財布、独立の島状態と時計、各島の初回無料家。海図repositoryの保存transactionは通さず、設計上の時間配分だけを比較する。

現行と候補は同じ購入方針。候補はプロセス内だけで家成長のすみごこち/Lv条件と土地4/5のLv条件を外し、A/B資格と購入終了を設定する。アプリのソースや通常保存は変更しない。**新しい場所形状/自然/W移行はモデルに含めない。**

```sh
fnm exec --using=22 node_modules/.bin/vite-node docs/design/2026-10-19-island-system-spec/pace-probe.ts
```

実行用[ソース](pace-probe.ts)、全ケース/1・7・30日/人口節目の[生データ](pace-results.json)。Node 22.23.3、終了0。生成日時はJSONに保持する。

## この結果から選ぶこと

- 家優先の30日人口は両条件で現行と同じ。この固定方針では、家の成長緩和だけから急増は起きなかった。少量条件では候補の家が1軒少なく、同じ人数に必要な投資先は変わった。価格/容量を今変更する根拠にはしない。
- 庭優先は装飾との予算競合と配置で人口が遅れる。20件/日の現行では後の配置が畑の経路を塞ぎ、現在供給が2まで下がった。既存4人は残り、時間銀行も保持する。候補との差を家成長だけの効果として扱わない。
- 2島合計18人と1島16人の差は現行にもある。独立の船と無料家があるので、人口総数が同じになる必要はない。島追加税/共通船/追加学習を新設せず、人口以外の構想と所有の違いも見る。
- 庭の人口が少ないことを失敗にしない。到達を妨げる配置は、届かない場所と無料で直す方法を分かるようにする。子どもが実際に理解できるかは未確認。

## 診断の限界

両規則の購入方針とも畑だけを買い、旧パン/市場/鉢を選ばない。したがって**食料カタログ統合の因果効果を分離できない**。水を買う戦略、旧施設持込、全購入順の探索、最適化も未実施。論理セル配置の固定方針は子どもの行動モデルではなく、3Dの床/全身/干渉の試験でもない。

自然は既存ロジックを実行し、新親の自生を実装していない。独立状態での2島配分は保存競合・SW更新・復旧を検査しない。新W/装い/新場所/見える物流/実行動の魅力/理解/翌日再訪も対象外。モデルで良い数値が出たことを採用・公開の合格にしない。
