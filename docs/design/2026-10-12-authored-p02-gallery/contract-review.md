# P02 authored gallery: narrow contract review

2026-10-12. Read-only code review; no world compilation, mesh measurement, tests, browser, render, or app/source edits. Current live code is the reference, not a new candidate approval. Previous source inventory is `/private/tmp/sansu-next-forest-research.md`. Existing native gallery width ~0.320 and stairs ~0.297 at the fixed 0.45 source scale are narrower than the supplied ~0.568 actor-clearance corridor. Those measurements are reused, not repeated here.

## Conclusion

The current floor sampler can query overlapping ground/deck triangles, but the public walking graph and ordinary support/placement contract cannot independently represent two walkable levels at the same logical XZ. Merely adding the gallery to ordinary `world.floors` is unsafe: unqualified sampling selects the highest dry floor, including for existing owner support and ground walking. The smallest useful addition is an explicit, owner-bound **use-floor + physical route** attached to the same authored world/frame, while leaving the ordinary ground graph and rights unchanged. This is a new narrow contract, not an already implemented gallery. A freely navigable multi-level world would require a larger ref/layer-aware graph change.

This matches `docs/product/island-construction-strategy.md:211`: upper floors must not be mixed into default ground; the authored interior/stairs/shared gallery remain unimplemented.

## Minimum proposed production boundary

1. **Author one real supported assembly.** Preserve original benchmark bytes, trunk/crown pivot and relative pose; author a separately identified derived interior floor, entry and stair/ramp/gallery with closed structural thickness and connections to the four-owner assembly. Its walk surface must clear the supplied actual actor envelope (~0.568 width here), including turning/landings, walls/rails, ceiling/headroom and animated parts. A wider mesh without source support, an invisible ramp over disconnected stairs, or dropping obstructing triangles is insufficient. A smooth visible ramp is compatible with existing linear pose travel; discrete treads need explicit step/contact travel and a test that feet do not interpolate through risers or float between treads.
2. **Add a pure owner-use plan after ordinary place derivation.** Derive compact-place applicability and supported ground entrance from the final shoulder→water→cove world, then transform the source profile into owner-use floor triangles plus route/entry binding. Keep the result on the same immutable authored frame/world context, but explicitly excluded from default `floorAt`, ground support, grants, joins and planting hits. This avoids `derivePlaces → frame → derivePlaces` recursion. Current frame integration point: `authoredWorldFrame.ts:44–64`; current gallery insertion point: `places.ts:177–184`. Either attach use targets in a second pure pass or consume the already derived plan explicitly; do not re-enter frame construction from `placeGalleryRoute`.
3. **Give route samples surface identity.** Recommend an explicit proposed `role: owner-use` collection, with namespaced IDs such as `P02:p3:gallery:floor:interior` / `:ascent` / `:bough` (example IDs, not implemented fields). Each plan binds ownerIds/placeId/placeRevision, source hash and pivot/scale/transform, these use-floor IDs, triangle-based support, an actual reachable ground WorldSiteRef, ordered physical XYZ route with per-segment floorId and a designated use/return segment. Use-floor physical/inverse queries must require that identity and fail closed: never fall back to default ground or nearest owner cell. They are isolated from ordinary floorAt, sample defaults, planting siteAt and ground pointer planes. A floor/segment identity is essential when a spiral crosses the same XZ at different heights. Render its source triangles once; the support payload and visible mesh must be numerically identical. Preserve positions/indices, normal/material lineage and source transform; do not put both a model deck and duplicated commonfloor top on screen. Ground owner selection remains `siteAt`; gallery-use hits carry owner/place/use-floor identity and use physical inverse on that floor. A tap requests travel to the actual validated entrance; it cannot snap the actor to ground beneath the hit and count a gallery receipt. Receipt eligibility should name the reached use segment, replacing the legacy height-above-ground heuristic for this authored plan.
4. **Extend physical validation only for this use route.** Validate the full swept actual-actor corridor against its explicit supporting triangles, then against native trunk/crown, new stair/support/walls/rails and neighboring structures. Reuse real actor envelope/triangle index machinery, not the ground-height box. Separate valid sole contact with a walk face from collision with its riser/underside/rail; do not exclude the entire gallery from collision. Runtime pose guard remains the last check. Ground approaches for all owners must remain safe below/around the new structure. Preserve current grounds/rights/records and the existing water/cove/flower use paths.
5. **Share committed/preview plan and explicit lifecycle.** Same source matrix must drive render, route/support, hit and obstruction. Future ghost geometry cannot become physical floor. On move/store/separate or lost prerequisites: invalidate owner-use plan and receipts, evacuate to an existing safe entrance before removing it; restore/rejoin recreates the same source-bound plan. Wider ordinary forests must retain their current separate trees and must not acquire the compact model/route by membership alone.

The full general alternative would require changing site identity, cell-keyed open sets, graph APIs, active floor selection, pointer mapping and actor locations to carry a layer/floor/ref throughout. That is unnecessary for the first bounded entrance→gallery→same entrance P02 interaction and should be a separate product/world contract decision.

## Critical tests for a later implementation (not run here)

- Same physical/logical XZ ground + upper-use deck: old owner anchors/support/hits, ground route and rights remain byte/semantically unchanged; explicit upper-floor query/hit selects only that level. Include a mapped district and quarter turn, not only identity-XZ native05.
- Real GLB/profile parity under the actual four-owner source matrix: top triangles rendered once; closed support joints and all full-width route/landing support; passage clear of trunk/crown/rails/ceiling with actual animated actor bands. New source normals/materials remain source-provenanced.
- Real actor entrance→stairs/ramp→interior/gallery→return, both reduced motion and ordinary motion, frame delta crossing segment boundaries; continuous obstruction plus actual pose/sole contact, correct use receipt only after visible valid use. Gallery hit must not grant planting rights or teleport to an upper level.
- Real commands/preview/cancel/commit/store/restore/separate during ascent: committed physical route survives ghost preview, invalidation evacuates safely, no invisible floor, restored same owners reconnect. Preserve all existing owner approaches and other place uses. Existing `authoredGroveLife.test.ts:200` and `placeTerrain.ts:42` currently assert no authored gallery; change that expectation only when actual support exists.

Existing tests useful as partial mechanisms, not native completion evidence: `worldFloorIndex.test.ts:103` (highest/nearest-Y queries), `authoredSceneLayout.test.ts:9` (absolute gallery Y only), `authoredPlaceSurfaces.test.ts:86` (explicitly synthetic renderer route, no authored deck support), `placeGeometry.test.ts:172` (legacy gallery travel/removal). No current test/source evidence establishes an actual native walkable interior.
