## 東回りの最初の測定

[東案v1の原記録](east-v1/archive-proof.json)では、同じ入口から前側の内床を訪ね、同じ開口を通って東へ昇り、元のgalleryの局所高さへ向かう一続きの経路を測定した。既存の家の屋根と扉への接触は消え、内床の到達点は25点すべてが元床上にあった。galleryの該当面はY=2.997417450で、内床からの差は1.316007376、最大標本勾配は0.681617。西側の低い位置を東側へ流用していない。

339標本中30点が保守的な箱に接触した。相手は足元の道、入口の枝と幹であり、箱との接触を実身体の貫通とは断定しない。地面との継ぎ目も未設計のため、選択案はnull、HOLDを維持する。次は入口を開口の正面へ揃え、元の地形断面へ接する可視の入口と、余裕幅を確保した東側の枝道を粗形にする。

測定はCPU2・11.338秒・最大観測RSS772,407,296 bytesで終了。継承したsupervisorは子PIDとUTC開始終了を記録していないため、[root記録](east-v1/runs/01-east-survey/root-execution-note.json)は04:36:00.957〜04:36:12.295 UTCというファイル時刻の範囲と、終了待ちのexit 0／背景processが残っていない観測を区別する。8入力・コード・固定meshは前後一致し、build・render・本体変更はない。

## 東回りv4の判定と実階段への変更

v3ではMANIFOLDによる5入力・4接合の閉体検査が通ったが、最初の支持枝が幹へ届かず停止した。その後の保存データの分析で、入力した道の17面に折り返しがあると分かった。v4は曲率が連続する経路へ変え、入力上面の折り返しと投影上の重なりを解消した。低い支持は地形へ接する根に、高い5本は実幹へ届く枝に分けて準備した。

[v4 build](east-v4-curvature-build/archive-proof.json)は、5入力と4接合の閉体・正体積検査を通過し、出力上面／下面の対応検査で停止した。上面15・下面10三角形の不一致には、境界外の標本、約2×10⁻⁷の面差、向きが反転した微小面3枚が含まれる。すべてを単なる誤差と扱わず、支持枝・手すり・身体検査は未到達と記録する。検査を通すために面を消したり、途中で許容差を緩めたりしていない。

同じ失敗sceneから[全景と入口近景](east-v4-failed-shape-view/archive-proof.json)を描画し、[v2・完成像と並べて作者が判定](east-v4-review.html)した。大きな滑らかな帯、支えのない外観、暗く狭く見える内側が残り、source美術はHOLD。描画成功は形の採用を意味しない。入口左の黒い切れ込みなどは元source・撮影・影の影響を切り分けておらず、新しい床の欠陥とは断定しない。

次の候補は、共有頂点から踏面と蹴上げを造形する実階段にする。幅0.64、4所有木、元幹と扇葉、家と扉、主要な始終点を保つ。段数は住人の左右の足、向き、歩行姿勢を使って決める。旧案の最小run 0.114833はsmoothstepの中心線間隔であり、内側の踏面幅ではない。中立姿勢の足長だけから18段を不可とは判断しない。本体統合では利用床IDと3D経路を明示し、通常の地上支持・配置権・通行を上階へ置き換えない。

[足接地の実装境界の調査](contact-step-review.md)では、現在のgalleryは全体の高さ補正と左右の足の回転だけで、別々の踏面へ接地する動作を持たないと確認した。実階段には経路に同期した左右の接地・遊脚が必要。足を個別に動かせることと、脚や体から離れず段を越えられることを分け、元の顔・体形・geometryを保った実poseで検証する。調査段階であり、API実装や実際の昇降の合格ではない。
