# 遊んでいる島の地形編集

通常のGrowing画面へ地形編集を接続する。本人が島を掘る・盛る、持ち物を移すと、描画と同じ床から水・配置・通行・場所利用を導き、保存して続きを遊べることが今回の実装範囲。全島の美術採用、子どもの無説明理解、実機性能、公開の判定は分離する。

- 契約：[仕様52 §1.1](../../product/52_growing_island_game_spec.md#11-遊んでいる島の地形編集2026-10-22-実装契約)、[保存13](../../product/13_data_storage_migration_spec.md#ゲーム内の地形編集の保存境界2026-10-22)。
- 実画面：[旅程の比較](index.html)。本体ローカルpreviewは `http://127.0.0.1:5495/#/island`。
- 対象：通常Island=true / NatureTown=false、delivery `snap-root-v1`、candidate `editable-lived-island-v1`、floor `editable-common-floor-v1`。
- [入力manifest](evidence/input-manifest.json)はsource/distのSHAを持つ。先行旅程は[経路修正前manifest](evidence/input-manifest-before-path-fix.json)へ帰属。DEVや独立viewerの画像は本体の証拠に混ぜない。
- 画面操作はCUAで実施。[時刻付きDOM旅程](evidence/journeys.json)に実際の高さ、画面、候補、版を保存。DB注入・残高付与・成熟時計の加速はしていない。

## 実装

「メニュー → じめんを かえる」で取得済みの土地を選び、0.18ずつ上げ下げする。周囲を滑らかにつなぎ、海面より低い地面は水になる。水になった土地も所有したままで、再び盛れる。地形と同じ三角形を表示・タップ・配置・足裏・経路に使う。

編集画面では住人を止め、足元を消す操作を保存前に拒否する。家や物を支えられる小さな高さ変更は可能だが、傾き・水没で支持を失う操作は拒否する。主人公の家、桟橋、橋の支点は高さを固定する。歩行中に先の道が変わった場合は、現在地を保って道を再計算し、通れなければ待つ。回廊に滞在中はその床の経路形状も保存時に保護する。

地形の差分と64操作の履歴を保存する。undo/redoは現在の家・住人・床を再検査し、後から取得・移動した物や学習を巻き戻さない。保存6/schema14で古いwriterを分離する。初回体験から本人設定へ進んでも同じ島を保持する。

## 仮説と反例のループ

| 発見した問題 | 修正と再検証 |
|---|---|
| 地形を変えると元の草や岩が全部消える | 同じ床で群れ全体を支持できる装飾だけ残し、根元を実床へ接地。 |
| 移した家の入口を静的な草が隠す | 配置範囲と重なる群れだけ除外。移動・収納でも再生成し、収納で元の装飾へ戻る。 |
| 足の中心だけ接地させると斜面で足裏が浮く | 実モデルの足裏頂点から接地高さを求める。世界のXZ座標は動かさない。 |
| 画面が小さいと編集地点が選びにくい | 近景/全体の切替を編集パネルへ追加。320/390幅で実タップと44px以上のボタンを確認。 |
| 最新の地形・履歴と表示がずれる | 形と履歴のrevisionを照合して拒否し、保存済みの島を読み直す。 |
| 場所の形が変わると旧処理が住人を入口へ移す | 現在の足場を保持して旧目的地を解除。道が切れた実walkerの反例を追加。 |
| 回廊の外の道を切るだけで滞在中の床が消えうる | 現在使用中の回廊のID・経路XYZをコマンドへ添え、保存時に同じ実床が残るか検証。 |
| 回した全景で盛土した岸が欠ける／水面下まで収めると島が小さすぎる | 編集済みの実形状で画角を計算し、水面下の土台だけは画角計算から除外。表示は保持。16回転×3画面幅で乾いた実床が収まり、画面の90%まで使うことを検査。 |
| 位置保持を広く適用すると、移動した家の中に住人が残る | 地形の実支持に加えて同じ所有物の占有判定を使用。合法な分数位置は保ち、配置物との衝突は実際に乾いた通路のある足場へ退避。 |

## 本体の実操作

1. 新しいローカルoriginで最初の島を開く。通常の無料の家を(0,2)へ置き、うさこを迎える。
2. (0,4)を3回下げ、水辺を作る。undoで−2、redoで−3へ復元。
3. 住人の家を(0,1)へ移す。入口と装飾の非交差を目視。家を動かした後の地形undo/redoでも家はその位置を保つ。
4. 家の下を1段下げる変更は支持範囲内で成立。2段目は「ものの 足もとだよ」と拒否。住人が移ってきた後のundoも「なかまが いるよ」と拒否し、履歴と現在地を保持。
5. 初回学習設定を通常操作で済ませ、実問題3問に回答。帰島時に同じ岸・家・住人が残り、しずく0→6。
6. 390幅で水面の取得地を選択して盛り、undoで水へ戻す。320幅でも横overflowなし、編集ボタンは44px以上。
7. previewサーバーを停止し、接続不能を確認した状態で再読込。キャッシュから島が開き、同じ地形・家・しずく6を保持。
8. 同じ学習予約(1+2、1/6)を再開し1問回答。帰島時にしずく8。同じサーバー停止中に(5,0)を3段盛って保存し再読込。
9. 修正版の別buildを同じoriginへ配信し、通常reloadで版が `b1e9356e-…` から `528caebb-…` へ切り替わることを確認。3地点の高さとしずく8を保持。
10. 修正版でベンチを(3,3)から岸近くの(1,3)へ通常移動。更新前の盛土履歴をundoで3→2、redoで2→3へ戻し、後から移したベンチは保持。

11. 自然に歩いたうさこが移動後のベンチへ座ることを実画面で確認。最終版でも主人公が同じベンチを利用。
12. 最終版 `7854d428-6f2a-4891-ad97-7f90dee5ba83` へ通常reload。全景を回して見える岸の収まりを確認し、390/320幅の編集・近景/全体と履歴を再検査。
13. 最終版のサーバーも停止。キャッシュ再読込で同じ地形・しずく8、学習の同予約2/6を保持。停止中に盛土undoを保存、再読込後のredoで3段へ戻した。

サーバー停止は対象originへの通信不能の検査であり、OSの機内モード・別端末の実PWA・全旧配布版からの更新を検証したことにはしない。人物の利用は実画面とruntime検査を区別する。自然な数日の成長、未調整の大規模配置、実参加者の理解/再訪は未確認。
