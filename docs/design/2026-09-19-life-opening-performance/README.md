# 島を開く際の経路計算の重複削減

公開版の「しま」が開くまで長いという報告に対するCPU診断。新しいGLB素材は公開版の既定flagでは無効であり、素材容量と断定しない。利用者の実際の保存データ・端末・URLでは未測定。

`node tools/benchmark-life-opening.mjs /tmp/life-opening.json` はユーザーDBを触らず、6家具と3住人の合成状態を1時間・24時間・7日進める。CPU profileでは `walkingSpace.meshFor` が最大の自己時間を占め、変わらない家具配置を毎回JSON化していた。

## 変更

直前の配置を値のコピーで保持し、土地・家具種別・座標が一致する間は既存の経路meshを再利用する。オブジェクト参照の一致だけには依存せず、再生中のin-place変更も検出する。既存8配置/各512経路の上限は保持。経路検索のキーも座標から作り、毎回のJSON化を避ける。経路探索順・行動・成長・報酬・学習・保存形式は変更しない。

## 計測

同じPC/Node/Vite SSRの合成CPU計測1回ずつ。ネットワーク、WebGL、実機の画面表示時間を含まない。

| 再計算する期間 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 1時間 | 74.5ms | 62.4ms |
| 24時間 | 645.7ms | 296.7ms |
| 7日 | 4374.0ms | 1963.9ms |

7日分は約55%短縮。全3条件で最終LifeState全体のSHA-256が一致。[変更前](before.json)・[変更後](after.json)。実際の公開版の遅延原因がこれだけと確定したものではなく、長期間の再生そのものは残る。

## 検証

配置・種類・格納・土地のin-place変更、別の島との切替、回避点、呼出側による返却pathの変更を回帰テスト。focusedは4 files / 22 tests PASS。固定した別ディレクトリーで `verify:core` は433 files / 4,071 tests、docs/lint/typecheck/build/asset budget PASS。`e2e:smoke` は31項目 PASS。

初回の共有作業ツリーでは、旧moduleを読み込んだテストと更新済みの追加テストが混在して1件失敗し、別作業のHTML更新によるHMRで画面テストも1件中断した。最終ソースを外部ディレクトリーへ固定して全体検証をやり直した。最終計測の前後で状態hashが一致。再計測中のVite終了時に依存scan警告が出たため、CPU診断では不要な依存scanを無効にした。
