# 算数テンキーの配列比較

2026-09-08。ユーザーからの「iPhoneや電卓を参考に検討」への調査・提案。採用済み仕様やリリース判定を置き換えない。アプリ実装は変更していない。

## 結論

現行の電卓型 `789 / 456 / 123 / 0` は妥当な選択であり、電話型に変えれば子どもが使いやすくなると断定できる証拠は得られていない。数字配列は暫定維持し、消去・訂正・確定の理解を優先して改善することを提案する。

新しい子どもに説明なしで使ってもらい、数字探しで止まる、上下を押し間違えるといった現象が出るなら、同じ寸法・機能の電話型と比較する。大人のスマホへの慣れを、子どもの慣れと同一視しない。

## 参考にした方式

| 方式 | 数字の配置 | Sansuに取り入れる点・注意点 |
|---|---|---|
| 電話・iPhoneの電話型数値入力 | 上から123、456、789、下に0 | 左上から小さい数字を探せる候補。子どもが既に使い慣れているとは限らない |
| iPhoneの計算機・一般的な電卓 | 上から789、456、123、下段に0 | 現行の数字配列と同系統。電卓固有の演算・メモリー機能まで移す必要はない |
| PCの数値テンキー | 電卓型 | 外部キーボードとの一致。物理キーの触覚や多指操作の利点はタッチ画面にそのまま移らない |
| 0〜9を横一列 | 昇順 | 狭い画面で10個の十分なタップ領域を確保しにくく、共通の通常入力には勧めない |

数字の上下と、キーの大きさ・間隔・補助操作の位置は別々に評価する。比較試作では数字配列だけを変え、0と操作キーの位置をそろえた。

## 調査で分かったこと

- Armandほか（2014）は成人57人にPCの数値キーパッドで10桁を入力させた。電話型の配列の記憶は良好だったが、入力の正確さは電卓型が良好で、通常数値を電話型で入力すると反応が遅いという交互作用もあった。「覚えやすさ」と「実際の入力性能」は一致しない。[論文抄録](https://pubmed.ncbi.nlm.nih.gov/24315462/)
- Marteniukほか（1996）は24人、4配列、3課題を比較し、0が下にある配列で入力が速く、配列間の誤り率に有意差を認めなかった。[論文抄録](https://www.sciencedirect.com/science/article/pii/0003687096000245)
- これらはSansuの子どもの算数回答やiPhoneでのタッチ入力を直接比較した研究ではない。今回確認した資料だけで、子どもに対する一方の優位性や学習効果を主張しない。
- Appleの計算機は1桁削除、入力した数の消去C、式全体の消去ACを区別する。Sansuは計算機と異なり答えを入力するので、機能名をそのまま模倣せず、操作対象が分かる表現にする。[Appleの計算機ガイド](https://support.apple.com/ja-jp/guide/iphone/iph1ac0b5cc/ios)
- Appleのボタンガイドは基本的なヒット領域として44×44pt以上を示す。Webでの寸法は実端末でも確認する。Sansuの既存44px以上の契約を維持し、必要なら大きくする。[Appleのボタンガイド](https://developer.apple.com/jp/design/human-interface-guidelines/buttons)

その他の参照：[Appleの電話ガイド](https://support.apple.com/ja-jp/guide/iphone/-iph3c993cbc/ios)、[Appleのキーボード種別](https://developer.apple.com/documentation/uikit/uikeyboardtype)、[CASIO実務電卓の製品サポート](https://www.casio.com/jp/basic-calculators/support.JS-20WKA-BK/)。

## 優先して検討する改善

1. **全消去と1字削除を見分けられるようにする。** Cを「ぜんぶ けす」、削除をアイコン＋短い操作名で示す案を試す。全消去を長押しだけに隠さず、分数等では実際に消す対象に合わせて文言を決める。
2. **必要な確定操作を理解できるようにする。** 手動確定時のチェックに「こたえる」を添える案を、既存の強調と比較する。自動採点時の非操作状態と区別する。誤り防止の効果は子どもの観察で確認する。
3. **不要な記号を減らし、数字の位置を固定する。** 小数点は必要な教材に出し、非表示でも残りのキーを詰め直さない。0、訂正、確定の位置は問題・教科・画面幅で変えない。分数・筆算の欄移動を消さない。
4. **電話型の3列構成は高さも比較する。** 幅が広くなる利点はあるが、確定や全消去を別段に出すと背が高くなる。現行224pxで問題と入力が収まる契約を崩してまで採用しない。

## 比較の進め方

- まず計算を含まない転記（例：7、17、208、3.5）で、数字探し・誤タップ・訂正の理解を観察する。続いて実際の一桁・可変桁・小数・分数・筆算で確認する。
- 同じキー寸法・間隔・操作名で、電卓型と電話型を比較する。提示順を参加者間で入れ替え、初見と短い練習後を分ける。
- 完了時間だけでなく、上下の押し間違い、Cと削除の取り違え、確定で止まった回数、助けが必要だった場面を記録する。子どもには速度競争や得点として見せない。
- 少人数での観察は問題発見に使う。統計的優位を証明した扱いにはしない。
- 差が明確でなければ現行配列を保つ。変更する場合も、問題ごとの切替・毎回の配列選択を増やさない。既に現行に慣れた利用者への影響を確認する。
