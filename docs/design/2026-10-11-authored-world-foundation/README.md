## 実装した土台

`WorldDefinition` に地区の固定原点、実床の三角形、配置地点、細かな歩行点、接続口、歩行/結合/通水の辺を持つ。床の補間・逆hit・配置権・経路がこの定義を読む。囲むboundsや描かれた地面を理由に、海や未取得地点へ配置権を足さない。取得地点と歩行点は別の権利を持つ。

現行の `GrowingWorld` の床と足元は、既存土地から作る互換地区の同じ三角形を使う。全既得セル、既存の座標と斜面、見晴らし橋を保持する。本人保存4/schema5、価格、成長、学習は変更していない。現行の道・暮らしと次期の明示グラフの統合はM1で継続する。

## 原本から作った次期の入力

[world-manifest.json](world-manifest.json) は原本SHA、変換、原本の八つの床、生成入力と配布bytesを記録する。[native05-world.json.gz](native05-world.json.gz) はその共通世界定義。

- 元の岸・丘・段丘の上向きの **89,488三角形**を保持する。矩形、凸包、別の高さ関数へ置換しない。
- 原本の家の幅を一つの配置単位にする尺度 `.45`。全地形へ同じ原点と尺度を適用し、所有物別の位置補正は使わない。
- **73配置地点と1,990歩行点、3,865辺**。配置地点73個すべてが、ぽこもこの玄関地点から実床上で到達できる。
- 細い岸の歩行点には配置・材料の結合・通水の権利を付けない。材料の結合と通水の辺は整数の配置地点だけに持つ。
- 配置範囲の9点と、各歩行辺の中央/両側の足の帯を実床へ照合する。床のない辺と、別地区の離れた実床をつなぐ辺を拒否する。

この入力は明示した制作診断で、本人の取得地や実績ではない。床の準備ができたことと、家・樹冠・泉・屋根・住人を同じ配置と利用で動かすM1の完成を分ける。

この段階の入力は、原本の地形と共有広場の八つの床を抽出している。泉の水面や橋・回廊の接続床は、M1で実所有と成熟に対応する形から導き、描画と歩行の共通定義へ接続する。

## 最初の診断と変更した理由

[配置マスだけの診断](history/placement-grid-v1/world-manifest.json)は同じ床で73配置地点中20地点しか到達できなかった。狭い岸が大きいマスの間に落ちるため。元の地形を膨らませず、配置権を持たない細かな歩行点と、実床に沿う辺を追加した。初回の尺度 `.34` では玄関地点の配置帯が岸を外れたため、原本の家幅から全体の尺度を定め直した。

履歴の定義と入力SHAは、その時の診断であり現行候補へ読み替えない。

## 検証と残る工程

専用回帰は、入り江の欠け/水、配置権、床と逆hit、歩行/結合/通水の分離、地区追加、離れた床、旧全取得地、橋、原本SHAと実rayを扱う。水面より低い地面を歩ける床と認めず、呼出側のopen集合に床外の点が混ざっても経路として受け入れない。

[変更前後の描画buffer照合](legacy-geometry-comparison.json)は、基準 `2861a0e0f177316c0274a205ca05295ceda3f625` と現行コードを別々に評価した。初期/湾/森/庭/橋×linear/curvedの10組で、**所有地の床のposition・normal・color・indexはbyte一致**。装飾の岸と岩には浮動小数点の丸め差があり、最大はnormalの `3.159046173095703e-6`、indexの差は0。全描画bufferがbyte一致するとは扱わない。
