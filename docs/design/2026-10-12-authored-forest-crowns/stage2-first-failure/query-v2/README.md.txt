`ray_query64.py` computes all ray/triangle intersections from the same original point. Binary64 interval arithmetic uses `math.nextafter` to round every interval operation outward. Ray/AABB rejection and Möller–Trumbore determinant, barycentric and distance predicates carry those bounds. A crossing counts only when its barycentric coordinates are strictly inside a triangle and its distance interval is strictly positive, within 100 and disjoint from every other crossing. We do not merge equal distances or move a ray origin. Edge/vertex hits, overlapping distance intervals, unresolved parallel/coplanar or degenerate triangles and endpoint ambiguity raise `QueryHold`. This intentionally favors unresolved results over false inside results.

The same two normalized directions and 128-hit limit remain. `volume_adapter.py` subclasses the original `Volume` and overrides only `inside`: inherited construction uses the exact same mathutils world vertices, triangle order, 7-decimal query weld, closure test and BVH; nearest-distance, overlap-ball radius, search guesses, connector caps and leaf/repair conditions remain inherited and unchanged. The existing builder does not import this adapter. Every `RayQuery64.ray` call now derives a conservative AABB exit-parameter interval from its actual origin and supplied direction, including float32 normalization error. It HOLDs unless a forward miss is proved or the entire possible forward AABB crossing ends strictly before parameter 100. An outside origin whose first hit or final exit lies beyond 100 also HOLDs. This guard is in the query kernel, not only the comparison script.
