# b1 を層のある森林へ進める次の source 粗形

**静的制作案。まだ生成・接合診断・描画していない。** 初回3案はすべて HOLD。b1 は出発点だけで、美術採用、runtime 接続、全島完成を意味しない。独立観察 N=0。c2 browser 中は Blender、Node projection、重い geometry を動かさない。

## 変える一つの構図

4本をそれぞれ横長にする初回の方法から、**奥の高い柳、そこへ上がる白樺の中層、手前へ返る小さな冠**という非対称な断面にする。葉塊の輪郭を重ね、幹の間に明るい空間が見える森林の内部を作る。元の丸み・垂れ葉・尖冠と原材料を使う。平たい円盤、簡易 primitive、木や装飾の量産に置き換えない。

- **上層 l14**：5つの元 lobe を一律に潰さない。後方 lobe を高く奥へ、東の lobe を横へ張り、南の lobe を少し低く手前へ返す。材の違いと厚みを持つ柳の輪郭を残す。全89冠/茎/葉は共通の滑らかな空間変形場を通すので、垂れ茎と葉を別々に散らさない。
- **中層 l15**：東の白樺枝＋冠だけを上へ伸ばし、柳下端の前へ重ねる。西と南の2組は別の高さに残す。3枝＋3冠が同じ高さの「雲の棚」に戻らない構成にする。
- **前から内へ上がる l29**：内向きの元枝＋冠を左上へ伸ばして l15 の東冠と重なる候補にする。外向きと南向きの冠は小さく低い返りにとどめる。前景の bench l30 と庭の空を塞ぐ一枚屋根にしない。
- **外周 l28**：軸と4tier の高さは原形のまま、中間tier の幅だけ変える。小さな垂直の縁として柳/白樺の大きい面を締める。最高大樹の代わりになる塔へ成長させない。

最高主景 l10–l13 は元形・最高高さを保つ。肩 l33/l34/l35 と実根元も固定。P03 周辺まで枝を渡して構造的に一体化する案ではなく、既存の主景・bench court・左群が全景の前後でつながって読めるかを見る。4本で全島の空白すべてが埋まるとは扱わない。

## 元データから分かる制約

元 POSITION accessor の box を確定 c1 の同じ owner matrix へ通した包絡値では、l14 冠の下端は約 y2.79、l15 の上端は約 y2.73、l29 の上端は約 y2.15。これは実三角形の tight bounds や葉接触ではないが、全体を横へ拡大するだけでは高さの層が噛み合いにくい。次案では白樺の一部を上げ、柳は厚みを残し、上下に重なる葉塊を作る。

原本の node 役割は分離済み。元4木の128 node のうち、幹・根・樹皮23 node は位置/index/NORMAL/matrix を固定する。柳89 node、白樺の各6 node、尖冠4 node の計105だけが変形対象。旧 target tree は context から外してあるので、旧冠との二重描画は禁止のまま。両白樺は同じ原本をそれぞれの owner matrix / native pivot で使い、冠単位の recenter はしない。

## 2つの異なる入口

1. **前の明るい口**：l15/l29 の内側の葉が頭上で重なり、その下から既存 bench l30 (4,-2) の庭へ光が抜ける。正面の大きな空洞を目標にする。前の低冠と垂れ葉をカーテン状に一直線で下げない。
2. **西の横口**：l28/l14 の外縁に、正面より狭く向きの違う側面の抜けを残す。尖冠の低tierを大きく膨らませて通り道を潰さない。

これは構図上の入口候補で、新 nav anchor や支持床を宣言するものではない。座標を自由に生やさず、後続で実 c1 world の既存 safe approach / graph を参照し、actor の全幅・高さを新しい実冠と実枝で再検査する。元 support/land/owner/成長は一切変えない。既存35 owner の入口、P02/P04、肩3木、家、水庭、花庭の空間を保つ。

## 木質接合と材質を同じ source で扱う

枝と冠の recipe anchor 一致は、実meshの継ぎ目を保証しない。初回の「柳5lobeに実幹表面が入った」という点の内外判定だけでは、次の枝冠構成を閉じた構造とは呼べない。

次に実行を許可されたら、柳5lobeと元幹の実体、14垂れ茎の上端と葉冠、白樺6枝の開始部と元幹・6終端と葉冠を確認する。必要な差分枝は同じ owner の元幹/元主枝の実表面から、実冠内へ届く短い閉じた taper/湾曲木質体にする。両端は円の中心点だけでなく断面が内包するだけの重なりを確認する。接続がないまま元枝を遠くへ移し、葉だけで隠すことはしない。幹を削る、別 owner へ構造を渡す、自由 anchor を増やすこともしない。

元材質10種の raw PBR/spec は proposal に保持する。元material slot、baseColorFactor、roughness、metalness、doubleSided を保持し、混色や新しい葉色で面をまとめない。選択原材の texture 参照0は抽出の事実で、欠けた画像を mock する許可ではない。柳差分木質は実元幹材、白樺補修は実元主枝材を使う。変形部の原 split NORMAL は Jacobian の逆転置、差分枝は作者法線と実接合で扱う。全島の材や法線を変えない。

## 次の実行順と停止条件

- root の次の連続制作枠まで待つ。再抽出が必要ない限り、固定 `extraction-attempt02` を使用する。新出力は `stage2/attempt-01/`。初回3案・原本は上書きしない。
- metadata 計画と役割対応を確定後、同じ128 role / 23固定node・source hash・owner行列・原材を検査する薄い stage2 builder を用意する。まだ用意していない実行コードや、接合修復を実行済みとは扱わない。
- 実頂点を変形し、法線と閉じた必要枝を生成する。最初の折れ/接合/干渉失敗は保存する。枝は独立の owner 差分manifestへ記録し、移動・収納・youngで残る背景にはしない。
- 同じカメラ/光/1280/Cycles CPU16samplesの全景を**まず1枚**作り、初回b1・benchmark・c1 actualと比べる。役割ごとの厚みと2つの抜けが読めなければ近景に進まない。新案の得点を事前に付けない。
- 形の方向が良ければ実mesh入口/材質/NORMAL/所有/固定parityを監査する。原図の影響範囲に新しい木が生えたように見えないことも確認する。runtime未接続の境界を守る。

stage1 の静的exportの黒い道の点は既知の描画差として残す。c1 actualには無い。隠すpixel retouchや材変更をせず、比較時の限界として明記する。住人/生活感、Blender光・海・透過/rippleとの差から都合よく加点しない。
