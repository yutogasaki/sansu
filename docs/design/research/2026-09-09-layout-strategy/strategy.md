## 提案の核

**島では暮らしを大きく、学習では問題と入力を近く、編集では作品と道具を隣に置く。** すべての画面を「同じヘッダー＋島＋カード＋タブ」に揃えるのをやめ、目的ごとに面積配分を決める。共通にするのは文字、色、ボタン、戻り方である。

今の違和感は、タブの高さだけでは解消しない。スマホのホームは島の下にカメラ・地区・育成状況・8機能の入口・全体ナビが連続する。縦長の島枠にも海が多く、住民の顔は小さい。持ち物は選ぶ品より先に島が大きく出る。横向き学習では小さい問題と答えが遠い。目的と画面の重心が一致していない。

推奨は、**島を基底面にして、選んだ対象の操作だけを下または横に開く構成**。中央の「まなぶ」は明示的な開始操作として残す。トップや「しま」を開くことでは問題を始めない。

## 何を比べたか

## 3つの構成を比較した結論

| 構成 | 良い点 | 弱い点 | 判断 |
| --- | --- | --- | --- |
| 今の構成のまま圧縮 | 移行が小さい。入口の位置をほぼ保てる | 5段の操作帯と、画面ごとの主役の不一致が残る | 読めない戻るボタンなど、応急修正だけに使う |
| **島＋必要時の操作パネル** | 島に面積を渡し、学習・編集では集中できる。スマホと横画面で展開方法を変えられる | 隠した道具を発見できる、ラベル付き入口が必要 | **推奨** |
| 機能ハブ・カード一覧 | 多機能を見渡しやすい。保護者の管理には合う | 島がサムネイル化し、訪れたい場所になりにくい | 設定・教材選択に限定 |

## 6つのレイアウト

### 1. 島で過ごす

住民、家、現在育てている場所を画面の主役にする。島の表示面は端まで使い、上下のUIを先に確保して残りをカメラの有効範囲にする。既定は「暮らしが見える距離」へ寄せ、全島を俯瞰する操作を別に持つ。島を切って単純拡大するだけでは、顔や家が欠けるので不十分。

上端は現在の場所と設定などの少数操作。下端は「しま｜まなぶ｜きろく」。島の上には育成状況を一つ、道具を開くラベル付き入口を一つ置く案から試す。カメラの5ボタンは専用の「ながめ」操作から開く。ピンチやドラッグだけを唯一の手段にしない。

家や住民を触ると、その対象の短い操作パネルを開く。同じ操作へ到達できる一覧も「しまのメニュー」から用意する。写真、もちもの、きせかえ、しまづくり等を横スクロールの奥に隠したままにしない。単なる「どうぐ」では遊びや思い出まで入っていると予測しにくいため、入口名は「しまのメニュー」を第一候補とする。パネル内は「あそぶ」「ととのえる」「おもいで」のまとまりにし、各機能には絵＋短い言葉を残す。

| 現在の入口 | 対象を触る経路の案 | メニュー内の代替入口 |
| --- | --- | --- |
| あそぶ | 住民を選ぶ | あそぶ → どうぶつとあそぶ |
| みつける | 発見対象を選ぶ | あそぶ → みつける |
| もちもの | 置いてある物を選ぶ | ととのえる → もちもの。収納中の物もここから |
| きせかえ | 対象の実景を選ぶ | ととのえる → きせかえ |
| しまづくり | 現在の対象を選ぶ | ととのえる → しまづくり |
| いえ | 家の扉を選ぶ | あそぶ → いえ |
| アルバム | 撮影や展示から関連する記録へ | おもいで → アルバム・しゃしん |
| ほかのあそび | 既存の別モード入口を保持 | あそぶ → ほかのあそび |

これは入口の対応案で、既存のviewや保存処理を統合するものではない。メニュー経由は開く操作が一つ増えるため、直接タップの発見性と併せて比較する。初期／成熟した島の両方で、「遊ぶ・収納中の物・写真・別モード」を説明なしで見つけられるかを確認する。

### 2. 学ぶ

「まなぶ」で全体ナビを閉じ、同じ学習予約を開く。前置きの画面や毎回の教科選択は増やさない。上端は閉じる、進み具合、必要な音操作。島名の大きな見出しや装飾背景は問題の面積を奪わない範囲に収める。

問題と答えを隣接するまとまりにする。簡単な3択は中央付近で問題と選択肢を近づけ、画面全体を均等に埋めようとしない。数値入力は問題＋筆算領域と固定テンキーを分ける。横向きの2列も、左右端まで引き離さず最大幅と間隔を定める。ヒント、わからない、全テンキー行はスクロールの外に残す。

### 3. 選ぶ・探す

もちもの、家具、育てる場所、案内は、候補と現在の選択状態を先に見せる。一覧へ入っても画面上半分に無関係な島を繰り返さない。選んだ品のプレビューが必要なときだけ表示する。未取得、所有、試用、設置済みを色だけで区別しない。

スマホは十分な大きさの2列一覧とフィルタ。広い画面は一覧＋選択詳細。戻る操作は画面上端に固定して、タイトルの長さによって1文字幅に縮ませない。

### 4. 編集する

配置・きせかえ・工作・身支度は、変更対象の実景と今使う道具を見せる。スマホは上に実景、下に段階のある操作パネル。広い画面は実景の横に道具を置く。操作パネルが被写体の顔や配置点を隠さないよう、カメラの可視範囲にも連動させる。

未確定の編集では全体ナビを閉じる。上端に取消と確定の異なる操作を置く。ラベルは「ここにおく」「きがえる」など実際の結果に合わせる。工作のUndoや部分工程など、各機能固有の契約を一律の保存ボタンへ変えない。確定失敗では編集内容を残して再試行できる。

### 5. 思い出を見る

アルバム、写真、発見、家の展示は、本人の作品と変化を大きく見せる。一覧は作品、詳細は一枚または一場面。成長の比較はスマホで切り替えまたは小さな比較を選べるようにし、横画面では並べて見る。今のように分類を何段も積んでから作品を見せない。

現在の「きろく」は学習統計、島のアルバムは思い出で役割が異なる。今回の提案で同じデータや新しいタブへ無条件に統合しない。将来は子どもの記録から作品にも行ける導線を比較するが、統計の保護者向け詳細との区別を先に定める。

### 6. 読む・管理する

設定、学習設定、保護者、詳細統計は、見出し＋まとまった行の構成にする。島の3Dや大きな装飾の余白は不要。1項目ごとの厚い独立カードを減らして、現在値と変更先を読みやすく揃える。設定一覧の第一画面から、全データリセットは詳細管理へ移す。

タブレットの設定は左にカテゴリ、右に内容。統計は意味のあるまとまりを2列まで広げられる。情報がないときは「ゼロのカードを増やす」より、どんな記録がここに残るかと次の行動を示す。

## 下部ナビと戻り方

「しま｜まなぶ｜きろく」の位置は保つ。中央の「まなぶ」は行き先の選択状態ではなく、集中状態を開く開始ボタンである。「しま」を選択中でも「まなぶ」は押せるが、二つのタブが同時選択されたような色分けにはしない。

[AppleのTab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)はタブを行き先として説明し、[Androidのレイアウトとナビ](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns?hl=en)も主要な行き先と操作を区別する。したがって、Sansuの3項目全体を同格のtablistとして扱うのではなく、2つの行き先と1つの明示的な開始操作として設計・アクセシビリティ実装する提案である。

| 操作 | タブ | 終了後 |
| --- | --- | --- |
| トップ／しまへ移動 | 表示 | 島に滞在。学習は自動開始しない |
| まなぶを押す | 非表示 | 閉じると出発した画面へ。同一プロフィールの問題と下書きを保持 |
| 持ち物などの一覧へ入る | 表示 | 戻ると所属先へ。学習から閉じた場合は元の一覧へ |
| 対象の短い説明を開く | 表示 | 閉じても島の場所や対象を見失わない |
| 配置等の未確定編集 | 非表示 | 取消は変更前、確定はその機能の既定の戻り先へ |
| 写真等を拡大して見る | 写真一枚表示の非表示は現行を維持。他の鑑賞への拡張は提案 | 明示的な閉じるで一覧へ。操作を隠しても復帰手段を残す |
| 設定・記録の詳細 | 表示 | 戻るは一階層上。学習の閉じるは開始元へ |

通常のタブ選択時に先頭へ戻す現行仕様は、今回変更していない。「集中画面から出発元へ復帰する」と「通常タブを選び直す」は別の操作である。ブラウザ履歴、再読み込み、直リンクのfallbackは既存43仕様を引き継ぐ。リサイズを画面遷移のきっかけにしない。

## サイズを決める順番

次の値はプロトタイプで比較する**開始値**であり、競合から測った最適値ではない。

1. 最小の有効画面で、安全領域と常設操作を確保する。スマホの下部帯はまず56〜64 CSS px＋safe area、上部は48〜56 pxを検討。タップ範囲は原則44 px以上を確保し、図柄だけを小さくする。
2. 島ホームで世界が見える面を概ね75〜85%にする案を試す。分母はブラウザの内容viewportからsafe areaを除いた矩形の面積で、アプリのヘッダーと下部ナビの領域は分母に含む。分子はその矩形内の実際に見える世界の面積とし、重なった不透明パネルや操作帯を除く。同じ端末・同じパネル開閉状態で比較し、画面領域の比率だけでは合格にしない。
3. 同じ島状態で、住民の顔・家・育成対象の見えるサイズを比較する。視覚評価のため、現在比約1.3倍・1.6倍の構図を比較候補にする。欠けや遮蔽が増えるなら倍率だけを採用しない。
4. 道具を開いたときの有効範囲をカメラに渡す。重要な対象をパネル下へ置かない。
5. 390×844だけでなく360×640、768×1024、1024×640、1024×768と実機safe areaで確認する。フォント拡大も別に確認する。

600や768という幅だけで機械的にモードを切り替えず、内容と入力の必要幅・高さで決める。横に余裕があるときは道具を横に逃がす。中央の開始操作を端末回転のたびに違う場所へ飛ばす構成は避ける。

## 実装順序

| 順序 | 変更単位 | 完了条件 |
| --- | --- | --- |
| 0 | 読めない戻る／閉じる、記録の空振りボタンを修正 | 長いタイトルでも横書きで読める。「もっと見る」が実際の追加内容を開くか、内容がなければ出ない |
| 1 | 島ホームの面積配分と入口の再編 | 小型スマホ・縦横タブレットで主な入口がスクロール不要。近景と全景を実画面で比較 |
| 2 | 持ち物・配置を一組で変更 | 一覧で品を選びやすく、編集で対象と確定操作が同時に見える。取消／保存／再開を検証 |
| 3 | 学習の問題タイプ別配置 | 小さい3択と筆算の双方で問題・入力が近い。全キーと支援が見え、追加タップを増やさない |
| 4 | アルバム・記録・設定を整理 | 子どもの作品、学習の事実、保護者の管理がそれぞれ読み取れる |

一度に全画面を作り直さず、各段階で実行画面を比較してから次へ進める。配置の図や美しいモックだけで採用しない。実装時は01/07/43と対象機能のSSOTを先に更新する。

## 合格条件と未検証

**見た目と触りたさ。** 同じ成長状態・同じviewport・同じ候補版で、顔、家、今できることが読めるかを並べて比較する。世界の広さだけではなく、そこに居たいかを評価する。今回の監査は初期の島のみ。成熟した4地区、展示が増えた状態は未評価。

**説明なしの理解と安全。** 子どもが「島を眺める」「学ぶ」「閉じて戻る」「ものを置いて取り消す」を説明なしでできるかを別に観察する。今回の独立参加者は0人。作者・エージェントが知っている意図は理解成功の証拠にしない。退出の罰、失点の煽り、支援を使う羞恥を加えない。

**動作とデータ。** 学習予約・下書き・プロフィール・写真・配置保存・PWA更新は従来の保護契約を維持する。非表示の島は操作・音・観察処理を止め、復帰しても二重保存しない。ルート／共有UIの変更後はverification_matrixに従う。今回の調査では回答保存、故障、PWA、実機Safari、キーボード全操作、コントラスト比を新たに検証していない。

3つの判定は独立に行う。テストが通ったことを理由に、世界が小さい・道具が見つからないという画面の問題を合格にしない。
