# 2026-10-11 美術と遊びが同じ地形・場所を組み立てる制作方針

- Date: 2026-10-11
- Status: Accepted as production strategy; world contract, migration and runtime replacement pending

- Related task: [幻想の庭 — 最初の遊べる一周](../tasks/active/2026-09-27-living-fantasy-first-playable.md)

## Context

利用者が全島の拡張実装に「完成像に近づきそうにない」、改善の説明に「寄せるとかじゃなくて方針が必要」と指摘した。採用native-05と本体の差は、部品や光だけの問題ではない。自由anchorで構成した美術と、矩形取得セルを連続変形して個体を置く本体では、地形・密度・共有空間を作る仕組みが異なる。

以前にも「場所から作る」「全島の美術を先に作る」と定めたが、その美術を実際の配置・歩行と共有することが最初の成果物になっていなかった。大規模な診断と技術検査は、この分離を解消していない。

## Decision

1. 美術で設計した地形と場所の形・接続規則を、子どもの土地選択・配置・成熟から組み立てる方式を採る。許容する形と支持・入口・床を美術で作り、自動処理は形の選択・継ぎ目・配置適応を担う。
2. 美術表示・本体・配置予告・実際の移動と利用が、一つの世界定義を読む。完成模型の後に別の床や簡易プリミティブを再制作する工程を置かない。
3. 次期の土地表現を、安定した局所座標・取得範囲・床・水・接続口を持つ地区へ改める方針とする。矩形boundsの内部をすべて土地とすることは、次期世界の固定制約にしない。具体の取得規則と保存形式は52・13で先に確定する。
4. 最初の実制作は、一つの島全体を同じ地形・配置・歩行で成立させる。その後に同材料の三配置、成長と編集、別地区への拡張、保存・配布の統合へ進む。制作順は[構築方針§12](../product/island-construction-strategy.md#12-作る順序を変える)に集約する。
5. 所有・成熟・住人・土地・学習・写真・履歴・ぽこもこのidentityを保つ。旧配置を勝手に整列せず、既得床を削らない。地区と人口に完成上限を設けない。

これは[2026-10-10の場所を育てる判断](2026-10-10-place-first-island-strategy.md)を具体化し、同ADRのDecision 6にある「木の一系列から全体へ」の制作順を置き換える。北極星と四つの柱、現行runtimeの有効な検証結果を変更しない。

## Alternatives Considered

| 方式 | 判断 |
| --- | --- |
| 現在の床写像と個別モデルを調整し続ける | 接地・hitの整合には有効だが、地形と場所の構成を作る責任が足りない。最終美術の制作方式として固定しない |
| 完成全島を固定背景として載せる | 一例の景色を表示できても、本人の配置・所有・成長と編集が成立しない |
| 配置から任意の建築・地形を全面自動生成する | 造形の品質と自由度の両方を最初から保証できない。美術で形と接続を設計する範囲を設ける |
| 作家が設計した場所を配置から組み立てる | 制作する形と成長段階が増えるが、採用美術と子どもの選択を同じ構造で扱えるため選ぶ |

## Consequences

全島の品質を先に成立させるため、16／32軒の追加や新しい品の量産を次工程にしない。一つの全島でも自由anchorでしか成立しなければ、地形・配置の契約を修正してから進む。全配置を同じ完成模型へ誘導せず、共同形が成立しない配置も遊べる単独の形を用意する。

次期の地区表現は保存・土地購入・到達の変更を伴い得る。このADRだけでschemaや価格を変更せず、M0とM5で仕様・旧保存互換・更新復旧を検証する。今の純粋な所有／成長／場所の計算、原本部品、共有床の保証を再利用する。別の島ホームを作らない。

## Verification

今回の成果物は文書のみで、docs checkerと正本間の制作順・状態・リンクを確認する。アプリの入力・画像・3D・保存・配信は変更しない。新方針の美術、子どもの独立理解／安全、runtimeは未検証。

次工程の証拠は、同じ世界定義から描いた本体の全景・近景と実際の選択／配置／歩行。配置差、成長、編集、拡張前後を同じ所有・成熟・尺度で比較する。美術・理解／安全・runtimeを別ゲートにし、以前の試験数や完成モデル数を通過証拠へ転用しない。
