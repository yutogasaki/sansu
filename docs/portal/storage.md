# 大量資料の原文・検索・復旧

正本は既存の仕様・仕事・素材・判断記録。`portal/` は内部閲覧用の生成物で、編集元や公開出力ではない。生成は `npm run agent:index`、確認は `npm run agent:index:check`。使用中の固定vendorは変更せず、固有の `tools/portal-storage.mjs` を最後に合成する。

## 読む・探す・原文へ戻る

通常の検索は既存のページ検索。分類・種類・語句を組み合わせる詳細検索は `portal/filters.html`。人向けの初期結果から操作コード・style・反復ナビを除き、必要なとき「操作定義・ナビ等の原文も含める」で戻す。表示件数と原文の母数を分ける。原文の詳細は選んだ項目の分割ファイルだけを読む。

`portal/data/unification.json` はページ・資料・資源と分割台帳。全文・識別子・属性・未知フィールドは `itemStorage.shards` の順に、gzipを格納した `data/records/*.js` に保持する。従来のフラットJSONが必要な場合は `portal/records.html` から端末内で復元・書出しできる。file/HTTPのどちらもscript transportで読み、外部送信しない。

Nodeの読取は `tools/portal-registry.mjs`、Pythonは `tools/portal-registry.py`。各分割のhash/件数と復元全体のhashを検査する。索引は全文の代わりではなく、原文へ到達するための別投影。生成途中は固定部品へ従来の完全なモデルを渡し、最後に保存形式を分割する。

画像・音声・3D・添付は `portal/assets.html`。元mapと同じ素材集合と現行英語教材public/foundationを個別登録し、元パス・容量・hash・出典/使用先の確認状況を保つ。保存元をコピーせず参照する。過去の画像・未採用の案を現行の採用・配布可能と表示しない。元ファイルがない6参照は一覧に明示し、別版で補完しない。

## 保存メモと旧URL

元7画面・原資料・教材操作・旧URLを保持する。新しい内部ナビで製品アプリを書き換えない。図鑑の比較メモはfileとHTTPで保存先が違う。元画面の「判断メモを書き出す」でJSONを得て、統合図鑑の明示した読込で版・件数・競合を確認し、既存優先または明示した上書きを選ぶ。原本の保存は消さない。読込失敗・quota・別タブ更新では再確認/再試行し、書出した原本も保持する。自動のorigin移行や外部送信は行わない。

## 容量とGit

`/portal/` はignoreし、Gitでは生成元を管理する。2026-10-26の[Git整理](../maintenance/2026-10-26-repository-cleanup.md)で、現存する全出力の復旧archiveとSHA256往復一致を確認して既追跡を解除する。ローカル出力は保持し、歴史資料の欠損を復元済みとは扱わない。PBUILD-001時点の追跡/現物の容量は `qa/evidence/PBUILD-001/` に保持する。docs/design・qaの唯一の素材・判断・失敗/受入履歴をまとめてignore/削除しない。

outputは実行用build/cachesと唯一の試行証拠を含む。今回一括削除せず、所在・役割・復元可能性で分類する。新規証拠は小さい要約/manifestと代表撮影を基本とし、全件対応表の巨大な反復は明示オプションでだけ生成する。

## 実仕事の改善循環と限界

今回の実仕事は[ポータルの軽量化と復旧](../tasks/active/2026-10-21-portal-storage.md)。開始の現物は321,361,977 bytes、全件JSONは104,772,437 bytes、検索用JSは12,766,634 bytes。これは未commitの開始ツリーの実測で、Git indexのblob合計やOSの占有容量と区別する。

観測：レコードで出典/検証状態/全文を反復し、起動時に全件原文を展開していた。仮説：検索用の投影と原文保存を分け、原文を必要時に読めば出力と初回展開量を減らせる。担当AIの技術判断として可逆な分割を採用し、hash復元・初回生成・既存操作・容量を同じ仕事で確認する。人の採用や理解の結果は生成しない。

後続の実使用は、同じ仕事の素材全件棚卸しと旧URL/メモ移行の検査で、この分割読取を実際に使う。証拠は `qa/evidence/PBUILD-001/`。ここでの成功を別案件の能力向上や児童の学習価値へ一般化しない。後続の別仕事での能力向上、人の理解・判断負担、実機性能は未実証。新しい形式の破損・読込失敗が増える場合は、台帳とhashから従来の完全モデルへ戻して比較する。

## 復旧

Gitの正本・固定vendor/lockと、宣言したGit外の素材を揃えて `npm run agent:index`。空の出力から一度で生成し、通常verifyと全文復元hashを確認する。Git外の開始差分はrepo専用の既存ローカル保管 `../.portal-recovery/PI-001-SANSU/pbuild-20261021/` を参照する。使用中のファイルへ復元する前に現在の差分を別名保全し、対象path/hashを照合する。欠損6件の完全復元は未達で、全体受入は別判定。
