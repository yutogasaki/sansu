`tools/portal-originals.mjs` は既存の6つの `.agents/` HTMLと `docs/index.html` を読み、`portal/original/` に全要素・直接の文章・全属性・CSS・scriptを保存する。相対URLだけを同じ元資料、または取り込んだ対応ページへ張り直す。S-004では原形表示を常時展開した。PI-001では整理した内容を先に読めるよう専用の開閉内へ置き、同じページのiframeで元のCSS/JS・横幅・検索を保持する。元URLの通常入口は残す。画像や音声の元バイナリ、個人設定や本人の保存はコピーしない。ポータル全体は内部ローカル閲覧用で、公開・hub集約を本作業で実行しない。

棚卸しは `portal/data/original-inventory.json`。要素・属性・空でない直接の文章・CSS・scriptを別々に数え、S-002のCSSルール150・メディア条件9・操作定義8も個別に残す。S-002の5,495件は構造5,328件とこの167件の合計。S-003の5,328件は構造だけの報告で、167件の削除ではない。今回の細分化した総件数とは数え方を区別する。

`npm run portal:verify` に全棚卸しの一致、全 `.agents/` HTMLの対象漏れ、全文章・CSS・script・属性・リンク先とアンカーの保存、同じページ内の表示入口の検査を含める。欠落・配色改変・script改変の異常系を検査する。実表示と操作は `node tools/qa-portal-originals.mjs` で別に確認する。独立headless Chromium、1440×900 / 390×844、DPR 1、100%で、元ページと新ページ内の原形表示を比較し、主要な節と図・画像を含む対応場面（現入力では両幅計94場面）を左右に保存する。全要素の計算後スタイルと寸法、検索・絞込・折り畳み・ナビも検査する。出力既定は `/tmp/codex/S-004/side-by-side/`。同等性に達していなければ元ページを入口のまま残す。

判断カードの同倍率撮り直しと原形比較はbrowser検査の対象とし、ブラウザ起動に失敗したら画像取得済みと記載しない。確認条件カードは元記録を保持したまま、次の確認を短い3手順で示す。S-003の正規入力未配置による通常verify失敗と、明示した代替入力による検査結果を区別する。


## 第一画面・比較・確認カード（S-005）

新入口は、要約 → 画像つき利用先・成果カード → 紫枠の元ポータル入口 → 既存の流れ要約、の順に生成する。判断カードは長い流れの詳細より先に置き、選択肢ごとの次の作業、推奨理由、採用後に進む制作と別途必要な保存・公開承認を常時表示する。端末・参加者の確認条件は回答依頼と分け、全カードを「確認済み → 残り → 次」の同じ順で並べる。原文は同じカードの詳細に残す。未対応の確認条件は確認済みと推測せず、要約未確認と表示する。

判断欄の二枚は過去の四角い岸／丸い岸の実画面であり、現在の二本の腕の入り江とは区別する。最新の判断資料は同じカードからページ内で開ける。`tools/prepare-portal-comparison.py`（Python 3・Pillow）はcommit済みの元画像と撮影記録を照合し、同じ正投影倍率・向き・画面原点を確認して、両方から同じ座標・660×440の枠を切り出す。拡大縮小・修整なし。生成先は `docs/portal/comparison/`、入力と出力のSHA・カメラ・切り出し座標は `comparison.json`。`python3 tools/prepare-portal-comparison.py --check` で再現一致を検査し、通常の `portal:verify` にも組み込む。

新入口と新しい節の本文・画像説明・補助ラベル・開いた詳細に、生IDや英語ログを出さない。`tools/check-portal-entry.mjs` が確認し、`npm run test:run -- tools/portal-entry.test.mjs` は混入時・判断内容を隠した時の拒否も検査する。原形コピーの歴史的なIDや試行記録は変更せず、この検査の対象文書と分ける。

実画面の再確認は、独立したheadless Chromiumを起動できる環境で次を実行する（外部の利用先へはアクセスしない）。新しい地形の撮影は不要で、既存記録の切り出しのみを生成する。

```sh
python3 tools/prepare-portal-comparison.py --check
npm run portal:build
npm run test:run -- tools/portal-entry.test.mjs
SANSU_PORTAL_QA_REPORT=/tmp/codex/S-005/browser.json SANSU_PORTAL_QA_SCREENSHOTS=/tmp/codex/S-005/screenshots node tools/qa-integrated-portal.mjs
```

最後の検査は320・390・768・1440幅、DPR 1。390×844で要約→利用先・成果→元入口が画面内に収まること、比較画像の枠寸法、判断文の可視性、横はみ出し、検索・キーボード・資料のページ内表示を確認する。`entry-*`、`decision-*`、`confirmations-*` のPNGを保存する。失敗時も取得できた画面と生の起動エラーを残す。元7ページの左右比較は従来の `node tools/qa-portal-originals.mjs` を使う。OS権限などで起動できない時は実画面未確認と記録し、静的合格を見た目の審査合格へ読み替えない。
