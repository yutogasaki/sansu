# 忘却・復習・レベル分けによる学習強化の分析

実装への追補: この分析後の「実装」により[学習強化34](../product/34_learning_reinforcement_spec.md)を採用。以下は変更前の診断記録として保持する。

調査日: 2026-09-08。対象はHEAD `9300ea0b5e965a4ca4d6679fc3cf85ba9ec10aa5`を基にした作業ツリー。UI・音声・島の並行変更があり、診断した学習ソースは各証拠のSHA-256で識別する。

これは分析と未採用の改善案である。現行契約は[仕様29](../product/29_learning_progression_spec.md)、単元比較は[仕様31](../product/31_learning_units_spec.md)。今回、出題・SRS・昇格・実プロフィールは変更していない。実学習者のログ・翌週成績は分析しておらず、定着率の改善量や最適な閾値は未測定。

## 判断

優先するのは、失敗した既習内容を確実に復習へ戻すこと、初回正解と訂正成功を分けること、単元別の到達と現在の定着を分けること。その後に個人・教材別の間隔調整を比較する。固定間隔を別の数字に置き換えるだけでは、出題漏れや誤った習得判定を解消できない。

現状には、同日の反復だけでSRSの段階を上げない、別問題・表現・支援を記録する、保存済み問題を差し替えないという良い基盤がある。ただし「期限がある」「正解数がある」「一度確認できた」だけでは、現在の想起能力を表せない。

### 復習量と支援後の間隔も独立した問題

通常Studyの算数は直近最大20出題の復習枠が60%上限。島の算数は6問中最大3問、3問中最大1問。島・遊園地の英語は1区間に明示的なDueが最大1語で、Dueが入る区間はweakを追加しない。期限を過ぎた語が増えても、この比率自体は増えない。[blockGenerators.ts](../../src/hooks/blockGenerators.ts) 637行、[park/learning.ts](../../src/domain/park/learning.ts) 88行、[english/planner.ts](../../src/domain/english/planner.ts) 45–50行。

例えば、現在のmain/+1以外に期限超過の英語60語があると、明示Dueとして一巡するだけで少なくとも60英語区間が必要になる。これはキュー容量の計算で、実利用者の滞留を測定した値ではない。通常Studyの英語では、直近40回答の教科横断の復習率も優先条件に使うため、算数の復習が多い時の英語滞留を別に確認する必要がある。[useStudySession.ts](../../src/hooks/useStudySession.ts) 261行、[blockGenerators.ts](../../src/hooks/blockGenerators.ts) 659行。

島の支援後の独力再確認は、当日にも解除できる。支援を開くこと自体では既存strengthを下げないので、元のstrengthが4〜5なら、その場の独力成功の後に14〜30日先へ戻り得る。誤答を伴わない支援と、その場の回復と、後日の再確認は別に扱うべきである。支援だけを一律の失敗へ変換する提案ではない。[island/commit.ts](../../src/domain/island/commit.ts) 16行、[learningChecks.ts](../../src/domain/island/learningChecks.ts) 38行、[srs.ts](../../src/domain/algorithms/srs.ts) 45行。

さらに算数のmaintenance/weakは復習予算に数える一方、`isReview=false`で、対象レベルなら非復習の昇格回答へ入り得る。英語weakは`isReview=true`。出題枠の消費、復習の種類、昇格へ使える証拠を一つのフラグへまとめないことも必要。[math/planner.ts](../../src/domain/math/planner.ts) 232行、[english/planner.ts](../../src/domain/english/planner.ts) 57行。

## 研究から使える原則と限界

| 一次資料 | 読み取れること | このアプリへの判断 |
| --- | --- | --- |
| [Cepeda et al., 2008](https://escholarship.org/uc/item/0kp5q19x) | 事実学習の実験では、覚えておく期間に応じて有利な学習間隔が変わった | 全員・全教材に一つの「正しい忘却曲線」を当てない。特定の1/3/7日列の最適性は示していない |
| [Roediger & Karpicke, 2006](https://pubmed.ncbi.nlm.nih.gov/16507066/) | 文章を再読する条件と比べ、想起テストを行う条件で2日後・1週後の保持が高かった | 答えを見る・訂正する・後日自力で答えるを区別。子どもの算数で同じ効果量が出るとはしない |
| [Rawson & Dunlosky, 2011](https://pubmed.ncbi.nlm.nih.gov/21707204/) | 概念の想起練習で初期正解数と後日の再学習を比較し、後日の再学習が長期保持へ寄与した | 初日に正解数だけを積むより再訪時の確認を設計。論文の3回正解は、本アプリの「異なる算数3問＋24時間1回」と同じ条件ではない |
| [Rohrer et al., 2020](https://files.eric.ed.gov/fulltext/ED595322.pdf) | 中学1年相当の54学級の試験で、解法を選ぶ混合練習が後日の試験成績を改善した | 習った型を混ぜる候補は有望。導入前から全種類を無作為に混ぜる、幼児にも同じ比率にする根拠ではない |
| [Settles & Meeder, 2016](https://aclanthology.org/P16-1174/) | 言語学習の履歴から教材・学習者に応じた想起確率を予測するモデルを検証した | 個別間隔は候補。ただし大規模な語学データでの結果を、少人数の算数や四択へそのまま移植しない |

これらから「時間を空けた想起、後日の再学習、適切な混合」を推奨する。一方、最適な合格率、段階数、復習比率をこの研究だけで固定しない。今回の主張は製品への設計上の推論である。

## 忘却と再学習の設計案

### 最初は、復習の予定と実績を正確にする

1. 卒業後の誤答・支援を`再確認が必要`として扱い、必要な復習に期限を付ける。学習者のレベルや島の獲得物は下げない。
2. 答えを確認して解き直す回と、少し後の別問題の初回回答を分離する。訂正自体は学習として価値があり、翌日にも適切な確認を予約する。
3. `初回正解日時`、`同概念に最後に触れた日時`、`後日の確認日時`、`次回確認期限`を混ぜない。音声開始や画面表示は接触の可能性であって、本人の理解の証明ではない。
4. 欠席後は期限超過を罰にせず、既習内容の短い確認から再開する。復習の滞留に応じて新規量を抑え、復習だけで区間を埋め続けない。3/6問の保存区間と学習目標の完了は別の単位とする。

### その後、想起確率を比較する

候補モデルの一例は`R(t)=2^(-t/h)`。`t`は経過時間、`h`は学習者・教材条件ごとの推定半減期で、strengthそのものではない。HLR論文のモデル形を使った説明例であり、本製品に当てはめた推定値はまだない。[モデル原論文](https://aclanthology.org/P16-1174.pdf)

| 仮の半減期h | 7日後のR（計算例） |
| --- | --- |
| 3日 | 約20% |
| 10日 | 約62% |
| 30日 | 約85% |

同じ7日後でも、推定する記憶の安定性によって予約判断が変わることを示す例。四択の正答確率、概念の理解度、学力をこのRと同一視しない。新規・少数データでは教科/型ごとの共通初期値へ寄せ、不確かな個人推定で極端な間隔を作らない。まず固定SRSを基準に読み取り比較し、後日の初回正答について校正と予測誤差を調べる。正解確率の目標値も、復習量と後日成績の両方から選ぶ。

## レベル分けの設計案

一つのレベル番号に、内容の難しさ・現在の解け方・記憶の古さを詰め込まない。

| 軸 | 持たせる情報 | 例 |
| --- | --- | --- |
| 内容と前提 | 系統、概念単元、必要な前提、問題の型 | 加法/減法、2桁、繰上/繰下、位取り |
| 適用の証拠 | 支援付き、初回独力、必要な型の網羅、別形式 | 式では独力、筆算手順は練習中 |
| 定着と再確認 | 過去の確認日時、実経過時間、次回確認、未確認 | 1週前に確認済み、今日は再確認の対象 |

算数Lv11の7単元はよい試作範囲だが、全単元が同時に完成しないと先へ進めない新しい関門にはしない。次の単元に本当に必要な前提を確認し、未実装の位取り単元はplannedのまま必須条件へしない。独立した系統は並行して学べるようにする。無補助の式・筆算・暗算・図は一律の一本道にせず、証拠を分ける。

3つの内容キーの違いは、重要な問題構造を網羅した証明ではない。例えば21+3、31+3、41+3だけでは数値は異なるが、幅広い加法場面を確認したとは言えない。まず繰上/繰下、桁境界、ゼロ、未知数の位置など、対象単元で必要な型を決め、その型を覆う少数問題を選ぶ。

英語の20レベルは教材の配置目安とし、語義×課題形式で証拠を分ける。四択で正解経験のある語率70%は、後日想起率や会話能力ではない。音声・絵の課題を加える時は、新しい能力の記録から始める。綴りを表示して読み上げた問題を、音声だけの聞き取りと同じ条件にしない。

## 出題と効果測定

ここでの初回独力は、記録範囲内で訂正・アプリ内支援がなく問題全体へ初回回答したことを指す。家庭内の助言や本人の注意・理解までは認定しない。履歴が欠ける場合は未確認とする。

初学時は短いお手本と同型の問題で操作と考え方を理解し、独力の成功が見えたら既習の異なる型を混ぜる。誤答時は必要な支援へ戻し、支援後の別問題と後日の確認で効果を見る。最初から「復習20%・新規80%」のような比率を最適値として固定しない。

算数の生成幅は正解数で広がるため、正答率が下がっても忘れたとは限らない。入力方式・数範囲・型・支援条件を揃えて比較する。英語は選択肢の紛らわしさ、文字表示、回答前の読み上げも条件になる。並行追加中の読み上げには、再生要求/開始/失敗と回答の関係を記録する余地がある。再生回数をそのまま支援ペナルティへ変換しない。

| 測るもの | 分母・条件 | 意思決定 |
| --- | --- | --- |
| 初回独力の正答 | 条件が分かる問題全体への初回回答。訂正・お手本を分離 | 導入の幅と次の型 |
| 後日の正答 | 予定より実経過時間を使い、同概念の直前接触を併記。例として1日/7日/30日の窓 | 間隔と再学習の必要性 |
| 別の問題への適用 | 同じ目的の未出数値・必要な型。英語は同じ語でも選択肢条件を別記 | 丸覚えや偏りの確認 |
| 支援後の回復 | 支援→別問題の初回回答→後日確認 | 支援内容の有効性 |
| 復習の負担 | 期限超過数、最も古い未確認、再確認までの出題機会、新規量 | 再訪時に復習が集中しないか |
| 継続と体験 | 自発的再訪、途中終了、スキップ、操作負担 | 正答率を上げるために遊び続ける意欲を損なっていないか |

未回答・来訪なし・音声失敗を誤答へ変換しない。難しい問題を出さなくなっただけでも正答率は上がるので、同じ内容構成で比較する。入力の速さは補助指標とし、筆算・音声待ち・休憩・保存待ちの時間を学力に換算しない。

評価は次の順序で行う。

1. 合成ケースで保存・選択・判定の取りこぼしを検査する。初心者、片方の演算だけ得意、同問反復、訂正、30日休止、古い予約を含める。
2. 同じ履歴へ旧判定と候補を当て、食い違いと理由を出す。候補判定を真の習得ラベルとみなさない。予測時点より後の回答を使わない。
3. 実利用の再訪時に、練習前の少数の確認を観測する。年齢/教科/型/初期状態を分け、回答数だけでなく学習者数、再訪率、欠測を示す。
4. 比較する出題方針と主要指標を先に決める。個人内の反復は独立サンプルと数えず、少人数なら事例比較として扱う。後日正答・復習負担・自発的継続を合わせて判断する。旧方針のログだけでは、出さなかった問題への新方針の因果効果は分からない。

## 実装する順序と受入条件

| 順序 | 変更の候補 | 受入条件 |
| --- | --- | --- |
| 1 | 卒業後の誤答を期限付き再確認へ戻す | 期限後に抽選へ依存せず対象となる。支援・連続誤答・大量Due・保護者範囲・再開を検査。獲得済み進行は下げない |
| 2 | 初回/訂正と、過去の確認/現在の再確認を分ける | 訂正だけで独力coverageが増えない。時間経過で確認期限は到来するが、過去の成功は消えない。別表現の直前練習を追跡 |
| 3 | Lv11の単元・必要な型で選択を比較する | 足し算だけで減法を確認済みにしない。苦手な型へ戻り、未実装前提で停止せず、別系統を必要以上に止めない |
| 4 | 復習予算と間隔を適応化する | 固定SRSに対し後日予測が校正される。定着だけでなく復習量・再訪を比較し、少数データ時は保守的な既定方式へ戻せる |
| 5 | 英語の音声/絵・想起と算数の転用課題を増やす | 課題の成立、教材品質、offline、支援条件、後日成績を個別に確認。認識の記録を新能力へコピーしない |

最初の実装単位は1と、その再発を防ぐ結合テストが適切。全面のレベル再採番や大規模な学習モデル導入より、改善の意味を確かめやすい。
