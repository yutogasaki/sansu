# Little Habitatsから考える、ぽこもこの幻想性

2026-09-27。世界観・デザイン・発見体験の分析と方向案。**提案段階であり、ユーザーの採用決定、仕様変更、実装、公開を意味しない。**

同日の追加依頼で、既存のデザイン・世界観・仕様も見直す検討へ範囲を広げた。[現在の方向比較](../design/2026-09-27-world-direction-rethink/README.md)を参照。本稿の「既存の色・キャラクターを保持する」は前段の提案であり、今回の検討を制限しない。

## 推奨する方向

**自分が育てた庭に暮らしが生まれ、その場所ならではの不思議に、ぽこもこと出会う。**

普段の景色にも形・素材・奥行きの魅力を持たせ、植物、水、灯りの関係から短い魔法が現れる方向を推奨する。幻想性を一部のレア演出だけに任せず、日常の美術、試して分かる小さな不思議、特別な出会いの三層で作る。

学習は既存の材料選びと成長につながる。何をどこへ置くかは本人が決め、魔法の基本条件は繰り返し確かめられる。思い出には実際に見えた出来事を残す。「正解ごとに精霊を抽選する」方向にはしない。

## 参考作で観察できることと、その解釈

| 観察した表現 | 魅力を生む理由の仮説 | ぽこもこへの翻訳 |
|---|---|---|
| 青い夜の庭に暖色の灯りが点在する | 暗さが灯りの居場所を際立たせ、安心と未知を同時に感じられる | 家の窓や灯りの近くを暖かく、木陰・水辺を涼しくする。顔と足場は見える |
| 光の鹿・鳥が、雪の庭や灯台のある風景に現れる | 日常の物との尺度・素材の差が、珍しい存在の印象を強くする | 布のぽこもこ、木、陶器の質感を残し、魔法だけに透過や光の軌跡を使う |
| 水面の灯り、空へ上がるランタン、灯台の光の向きが変わる | 空間の上下と奥行きに出来事があり、視線を運ぶ | 地面・水面・樹冠のどこに起きる魔法かを決める。画面全面へ均等に粒子を撒かない |
| 草花、池、ベンチ、建物が近接して小さなまとまりを作る | 道具の集合を、暮らしのある場所として読める | 花とベンチ、水ばちと灯りなど既存の関係を、景観のつながりとして表す |
| 春夏秋冬で同じ島の植物や色が変わる | 同じ場所を知っているため、変化が思い出になる | まず同じ一画の昼と薄明かりを比較する。四季の全実装は後段で検討 |
| 小さな土地から地形・植物・生き物へ発展する紹介 | 自分の行為が世界を豊かにするという期待がある | 保存済みの学習参加と既存成長を、帰島時に見つけられる変化へ結びつける |

これは観察からの設計上の解釈であり、利用者への効果を検証した結論ではない。

幻想性の核は、**親しめる場所、現実と少し違う現象、見つける余白**の組み合わせにあると考える。夜や発光だけでは十分ではない。昼の庭が魅力的で、その場所を覚えられることが、特別な出来事の前提になる。

動画は短時間に見せ場を連続させている。これを通常画面の密度や発生頻度へそのまま移すと、静かな日常と発見の差がなくなる。精霊は種類数より、訪れる場所と固有の振る舞いを重視したい。

## 現在のぽこもことの比較

比較画像は[食料の運搬](../design/2026-09-27-island-food-loop/README.md)と[みずみち](../design/2026-09-27-island-water-channel/README.md)。390×844 / 768×1024のローカルDEV記録で、development-local、delivery mystic-island-v1、現行島candidate mystic-island-shore-garden-v18。水路記録のLife visual candidateはmoon-garden-v1。音なし・動き抑制・明示fixtureであり、公開版の視覚認定ではない。

参考動画は物の多い完成例、こちらは機能検証用の疎な配置である。植物の量や賑わいだけで優劣を結論づけない。一方、この画像で見える広い均質な床、硬めの影、島の縁と青い背景、家・家具・住人の画面内の位置関係は、次の比較で調べるべき具体的な論点になる。

### 既に強いもの

- ぽこもこの布の身体、色瓦の家、紫の木に、自然色の庭とは違う固有性がある。
- 暮らしの用途がある。歩く、座る、運ぶ、食べることを、新しい精霊のために作り直す必要はない。
- [発見判定](../../src/domain/islandLife/discovery.ts)には、植物のまとまり、ベンチと花、水ばちと灯りなどの関係がある。
- [水面の魔法](../../src/components/island/life/waterMagic.ts)、[植物の魔法](../../src/components/island/life/plantMagic.ts)、[灯りの範囲](../../src/components/island/life/lanternLight.ts)が既にある。魔法ゼロからの出発ではない。
- [発見帳](../../src/domain/islandLife/discoveryJournal.ts)と再演の仕組みがある。条件成立と実際の表示を分ける方針を使える。

### 伸ばしたいところ

1. **家具の関係を、場所の景色として見せる。** 土・草・水・陰のつながりで、水ばちがある場所を小さな水辺として感じられるようにする。購入前から大量の無料家具を描いたり、配置による影響を偽ったりしない。
2. **全景と住人の距離を使い分ける。** 全景は配置と島への愛着、近景は表情と不思議な現象に使う。今あるカメラ操作を土台にし、演出で勝手に操作中のカメラを奪わない。
3. **光が届く相手を見せる。** 発光物だけでなく、近くの葉、水の縁、ぽこもこの顔へ何が届くかを作る。重い全面エフェクトの採用は見た目と実機負荷を確認してから決める。
4. **物単体の魔法を、同じ庭の出来事として読ませる。** 水面の星は専用の[観察表示](https://github.com/yutogasaki/sansu/blob/6acabf8a885a35ec80ba337f272e5d8d31f696a0/src/components/island/life/WaterObservationView.tsx)に実装されている。庭・灯り・住人との関係を一画面で見せる案には、別途描画と表示記録の設計が要る。

[既存のC3参考画像](../design/references/2026-09-13-canopy-dots/README.md)には、前景の葉、巨木、木陰、家の暖色、海まで続く奥行きがすでにある。これは生成された参考でありruntimeではないが、Little Habitatsの自然色へ全面変更するより、既存の[デザイン憲章](../product/design-charter.md)を具体化する接点として強い。

## 方向の選択肢

| 方向 | 中心になる体験 | 利点 | 弱点・判断 |
|---|---|---|---|
| A：日常の庭に不思議が訪れる | 育てる、暮らしを眺める、特別な場面に出会う | 愛着、成長記録、住人の存在がつながる | 待つだけにならないよう、小さく再現できる不思議を持たせる。推奨の主軸 |
| B：常に夢の中のような世界 | 巨大植物、浮遊、色と光の非日常をいつでも眺める | 一枚の絵として強い | 全部を特別にすると魔法の差が弱まり、操作と状態の読み取りが難しくなる。巨大植物・空間の美術は借りる |
| C：組み合わせで魔法を発見する | 近づける、離す、比べる、法則を見つける | 既存v3の再現可能な発見とよく合う | 条件集めや攻略表が主役になると、暮らしが薄れる。Aを支える遊びとして採用候補 |

**提案はAを主軸に、Bの空間的な魅力とCの再現できる因果を組み合わせる。** 三案を別モードとして増やす意味ではない。

## 幻想性を作る三層

### 1. いつもの庭：何も起きていなくても入りたい

ミントの地面、紫の植物、色瓦、布の住人を出発点とする。明るい庭・涼しい陰・暖かい窓の関係を作り、前景から家の奥へ視線が続くようにする。細部は居場所の周辺へ集め、住人が歩く場所は読みやすく残す。

昼が魅力的であることを先に確認する。薄明かりの案では、全面を暗くせず、手前の顔と足場を読めるようにする。夜の色見本を作ることと、実時間の昼夜システムを導入することは分ける。

### 2. 小さな不思議：自分で見つけ、もう一度試せる

水面に星が見える、花びらが上へ舞う、灯りの中で足跡が光るといった既存の素材を、場所と行動に結び付ける。同じ条件で繰り返せる。最初から完成図やレシピ一覧を提示せず、反応と穏やかな手掛かりから気付けるようにする。

基本条件を乱数、正答率、連続学習日数に依存させない。学習は材料や成長を支え、置き方と触れ方で不思議を試す。参加と独力習得の記録は引き続き分ける。

### 3. 特別な出会い：その庭の思い出になる

将来案として、整えた水辺や木陰を訪れる一種類の精霊から始める。同じ形を色違いで増やす前に、「どこから来て、何に応え、ぽこもこがどう見送るか」を定める。既存の住人を発光キャラへ置換しない。

基本法則を壊さず、来訪の仕草や見せ方に変化を作る。出会いを長時間滞在・深夜ログイン・課題の大量反復に依存させない。実装する場合は条件、再会、見逃したときの扱いを仕様化する。未表示の来訪を「見た思い出」として自動保存しない。

## 最初の試作案：水ばちに、小さな星空が宿る

既存M4（水ばちと灯り）の体験を育てる案を推奨する。初回から精霊の新規造形、季節システム、自由な地形編集をまとめて作らない。

1. **舞台を整える。** 既存の家・住人・配置を使い、水ばちと灯りを一画に収める。少量の植物、地面のまとまり、木陰で居場所を作る。新しい正解配置をユーザーへ強制するための見本ではなく、制作上の検証シーンとする。
2. **原因を見せる。** 灯りが近いと水面に暖色が映る案を比較する。照り返しは条件の手掛かりにする。現行の灯りの描画は地面の色面であり、物理的な反射が既に実装されているわけではない。
3. **水面で発見する。** 水面に触れると波紋が広がり、そこに星が現れる。既存の5秒の水魔法を最初の比較基準とし、同じ島の中で水ばちと原因の灯りを見せる。現行の別観察表示からの変更は提案段階。
4. **関係を確かめる。** 灯りを離した場合は通常の波紋、戻せば同じ魔法を試せる。無料移動と現在の配置条件を使う。失敗画面や不正解判定にはしない。
5. **一緒に見た気持ちを作る。** ぽこもこが実際に近くにいる場合だけ、水面へ顔を向ける案を第二段階で試す。瞬間移動や既存の運搬・行き先の取消しをしない。住人が不在でも基本の魔法は試せる。
6. **思い出に残す。** 可視になった実場面を既存の発見記録へつなぐ。「あのとき」と現在を分け、保存や鑑賞を学習復帰の必須操作にしない。

初回の比較では昼と薄明かりの固定照明を用意し、どちらでも水面・住人・操作が読めるかを見る。時間経過による自動の昼夜移行は、この試作の前提にしない。

この一画で、場所の魅力、光、再現できる魔法、ぽこもことの関係、思い出を同時に検討できる。魅力が弱ければ精霊の種類を足す前に、構図と素材と因果の見え方を直す。

## 判断のための比較と検証

最初に同一配置・同一画角・同じ住人を使って現行と候補を比較する。物量やカメラだけを変えて照明の効果を主張しない。少ない所有物の庭と、発展した庭の両方を見て、育てる前から居心地があるか確認する。

| 独立して判断する項目 | 確かめること | 今回の状態 |
|---|---|---|
| 視覚的魅力 | 魔法なしでも入りたいか。素材・奥行き・一つの焦点があるか。魔法の結果がスマホで見えるか | 仮説のみ。新候補の画像・runtime未制作、採点なし |
| 無文字理解・安全 | 説明前に「水が変わった」「灯りが関係しそう」と気付けるか。自分で再試行できるか。怖さや急がされる感じがないか | 実参加者未観察 |
| Runtime整合 | 390×844 / 768×1024、学習往復、配置・保存・再読込、音なし・動き抑制、実機負荷と更新後の継続 | 今回は実行なし。既存の技術検証を新案の合格に流用しない |
| 画面の連続性 | 島→家→学習→島で同じ世界に感じられ、学習の入力とテンポを守れるか | 新案は未検証 |

案を制作するときは、実対象・build revision・delivery flag・visual candidate・cache状態を残し、現在と候補の重要な画面を並べる。リリース審査は[検証仕様](../ai/verification_matrix.md)に従う。今回の方向検討に合格点やリリース判定は付けない。
