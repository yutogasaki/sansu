# 7作品から抽出する遊び・気持ちよさ・成長のベンチマーク

確認日：2026-09-08。**104項目を18の観点で整理した調査・提案資料**。採用済み仕様ではない。

ユーザー指定の作品から、公式資料で確認できる仕組みを抽出し、「なぜ触りたい・見たい・続けたいと思えるのか」とSansuへの応用を分けて記録した。全シリーズ・全バージョンの全機能を調べ尽くした一覧ではなく、製品設計で比較すべき観点を広く覆うカタログである。

「よっしーの不思議な」は『ヨッシーとフカシギの図鑑』、Forestは集中して木を育てるアプリと仮定。ポケモン本編はSV、どうぶつの森は『あつまれ どうぶつの森』を代表とする。SimCityは2013版を中心とし、BuildItの3項目を区別した。Minecraftは本編を扱い、モード・版に限定される機能を明記した。

## まず取り出したい核

**学ぶ → 同じ世界が育つ → 住民の暮らしが変わる → 新しいことに気づく → 自分で試す → また育てたくなる。**

Sansuでは、このつながりを強くする候補を優先したい。報酬の数だけでなく、育った物の使い道、住民の反応、自分だけの配置、発見の記憶に成果を変える、という提案である。

**「確認した仕組み」は公式資料の内容。「気持ちよさ」は設計上の解釈。「Sansu候補」は新しい提案または既存体験を磨く案。** 後ろ2列は原作の事実や効果検証を主張しない。

通常の島に追加する案、長期拡張、独立した算数遊びの案が含まれる。数える・分ける・積むことを回答操作にする案は、既存の通常入力を置き換える決定ではない。

| 自分で決めた | 名前や配置、行く場所に本人の選択が残る | YO08、AC09、PK06 |
| 役に立った | 作った物を住民が使い、仲間の仕事も見える | PA07、SC08 |
| 眺めていたい | 急かされず、生活や小さな動きを見届けられる | PK10、FO09–10 |

「毎回派手な祝福」で全てを表そうとしない。一問では短い手応え、区間では確かな蓄積、節目では輪郭と用途の変化、帰島では暮らしを見る、という役割分担がSansuに合うと考える。

## デザインで比較する10項目

見た目の具体的な測定は今回行っていない。ヨッシーの色・形・材質・演技については、既存の[公式画像の分析](../design/research-library-2026-07-19/benchmark-yoshi-fukashigi.md)も参照する。以下は今後の制作・比較の観点であり、7作品全てに同じ表現があるという主張ではない。

| 観点 | 比較する問い | Sansuで試す方向 |
|---|---|---|
| 1. 輪郭 | 小さく見ても対象や成長段階を見分けられるか | 花・樹冠・家のシルエットそのものを変える |
| 2. 材質 | 木、石、水、生き物の触れ心地を想像できるか | 全部を同じ光沢・同じ質感へ揃えず、反応と音も変える |
| 3. 色の焦点 | 今見てほしい物と、背景の役割が分かれるか | 場所ごとの主色と、小さな焦点色を決める |
| 4. 縮尺と画角 | 育つ前後の差や、住民の行為が読めるか | 成長比較は同じ倍率。全景と暮らしを見る画角を使い分ける |
| 5. 身体の演技 | 説明文なしで、誰が何をしてどう返されたか分かるか | 視線、体の向き、触れる位置、相手の返しを揃える |
| 6. 置いた後の生活 | 完成品がただの飾りで終わっていないか | 座る、渡る、分け合う、休む行動までを一つの機能とする |
| 7. 音の役割 | 入力、結果、材質、環境、節目が聞き分けられるか | 短い操作音と環境音を分け、声や問題の理解を妨げない |
| 8. 動きの緩急 | 日常と大発見が同じ強さになっていないか | 平常は少数の動き、節目は短く大きい変化 |
| 9. 情報の順序 | 景色の変化より通知や達成率が先に目に入らないか | 世界で起きたことを先に、詳細記録は任意の図鑑へ |
| 10. 操作の確かさ | 選択・配置・取消・次の操作が分かるか | 置く前の影、届く範囲、戻す操作、音に依存しない状態表示 |

借りたいのは色コードやキャラクターの形そのものではなく、「何に目が向き、何が起きたと分かり、もう一度触りたくなるか」という関係である。

## 成長は8軸を別々に持てる

| 成長の軸 | 具体例 | 主な着想 |
|---|---|---|
| 量が増える | 木、発見、図鑑の棚が増える | Forest、ポケモン |
| 姿が変わる | つぼみ→花、小屋→屋根窓のある家 | ポケモン、SimCity |
| 用途が増える | 座れる、渡れる、運べる、照らせる | ぽこあ、Minecraft |
| 空間が広がる | 橋、新しい水辺、別の探索先 | SimCity、どうぶつの森 |
| 理解が深まる | 初めて知る→別条件でも性質を使える | ヨッシー、Minecraft |
| 関係が育つ | 好みが分かる、頼ってもらう、一緒に過ごす | ぽこあ、どうぶつの森、ポケモン |
| 表現が豊かになる | 選べる配置、音、名前、テーマが増える | Minecraft、どうぶつの森 |
| 本人が上達する | 独力で解ける、日を空けてもできる、別表現へ使える | Sansuの学習設計で別に確認 |

**島の成長、滞在時間、コレクション数を、本人の習得の証拠へ読み替えない。** Forestが可視化する集中時間と、Sansuが確認する独力正解・後日の再確認は意味が違う。学習判定は[学習曲線](../product/29_learning_progression_spec.md)と[単元・習得証拠](../product/31_learning_units_spec.md)に従う。

## 運・未知・発見を分ける

| 種類 | 例・着想 | Sansuでの扱いの提案 |
|---|---|---|
| 抽選による珍しさ | ポケモンの色違い、Minecraftの釣りの希少品 | 能力差のない色・模様などへ使う |
| 条件で傾向を変える | 生息地、季節、場所、準備 | 子どもが出会いの種類をある程度選べるようにする |
| 世界のバリエーション | Minecraftの開始地点・生成される地形 | 同じ難しさで、配置や景色を変えて再訪を新鮮にする |
| 中身がまだ分からない | ぽこあの落とし物、あつ森の化石鑑定 | 正体判明を楽しみにする。未知であることと抽選は別 |
| 組合せの意外性 | ヨッシーの生き物×場所、Minecraftの装置 | 原因を再現できる発見として扱う。ランダムと呼ばない |
| 暮らしの小さな揺らぎ | 来訪、仕草、自然の表情 | 重要な進行を止めず、毎回少し違う様子を作る |

Sansuへの追加案としては、**基本の成長は必ず得られ、周辺の小さな発見が変わり、自分で出会いの条件も試せる**形を優先したい。

- 同じ発見でも、違う仕草や展示の用途があるようにする。
- 必須の物は抽選だけに依存させず、条件達成でも得られるようにする。
- 記録済みの発見をもう一度試す時は、抽選の当たり待ちを要求しない。
- 未発見へ出会いやすくする補正や一定回数での保証は検討候補。ただし、これは原作で確認した共通機能ではなくSansu向けの新規案。
- 外観の珍しさを独力正解・速度・連続正解の優劣へ結び付けない。

具体的な抽選率、保証回数、出会いの頻度は未提案・未検証。ぽこあの鑑定の抽選方式や、ヨッシーの各発見が確率で起きるとは確認していない。

## Sansuで優先して比べたい12候補

[育つ島の仕様](../product/30_living_island_growth_spec.md)との関係を整理した。ここでの「仕様にある」は実装監査・実画面での合格を意味しない。追加候補を採用する場合は、対応する親・子仕様で別途決定する。

| 順 | 候補 | 今の仕様との関係 | 良くなったと判断する観察 |
|---|---|---|---|
| 1 | 同じ場所が、一目で分かるほど育つ | 仕様にある。輪郭・大きさ・暮らしの変化を磨く | 子どもが変わった場所を自分で指せる |
| 2 | 作った物を住民が実際に使う | 仕様にある。単独利用と組合せ行動を磨く | 完成後に住民を見に行く |
| 3 | 普段の一問と、大きな完成の気持ちよさを分ける | 仕様にある。連問を止めず強弱を磨く | 入力を続けつつ、節目も分かる |
| 4 | 対象×場所を試して性質を発見する | 一部の距離・向きによる反応は仕様にある。拡張候補 | 別の場所でも自発的に試す |
| 5 | 図鑑から発見の場所へ戻り、再現できる | 発見記録と再演は仕様にある。案内を磨く | 記録を見た後に再び遊ぶ |
| 6 | 昔と今を同じ視点で比べる | 仕様にある。節目と意味のある比較を磨く | 数字を読まずに成長を説明できる |
| 7 | 並べ直しても獲得した成長を失わない | 移動・収納・過去の姿は仕様にある | 失う不安なく模様替えをする |
| 8 | 次に育つものの姿と用途が想像できる | 芽や育成先選択を土台にする候補 | 自分の言葉で次の楽しみを示せる |
| 9 | 仲間の好み・得意な仕事が違う | 既存の興味・行動を広げる候補 | 名前や動きから仲間を選びたくなる |
| 10 | 能力差のない珍しい訪問・外観 | 追加候補。基本成長から独立させる | 普段の成果も喜び、珍しい時は人に話したくなる |
| 11 | 題材を選んで作る、おためしの場所 | 新しい任意創作の候補 | 指示を増やさず本人が配置を試せる |
| 12 | 季節・環境音・小さな来訪で再訪を新鮮にする | 長期候補。実時刻に拘束しない | 義務感からでなく景色を見に戻る |

最初は1〜7のつながりを実画面で確かめたい。現在の島は4つの居場所と有限の持ち物を育てる仕様なので、毎区間の大量アイテム配布や、未設計の無限拡張へ変更する根拠にはしない。

採用時に調整が必要な点は次の通り。

- **Forestの中断ペナルティ**：現行公式ではモードによって条件が異なる。Deep FocusやPlant Togetherの枯死・連帯責任は、Sansuの中断しても進捗を失わない方針へ移さない。[Forest公式FAQ](https://www.forestapp.cc/)
- **BuildItの回収操作**：手応えの参考にはなるが、通常学習の区切りに受取を必須化しない。
- **都市の破壊や維持費**：風景の変化や因果だけを取り出し、学習の誤答で育てた島を壊す仕組みにしない。
- **交換・オンライン協力**：交流の価値は参考にできる。現在はローカル保存のため、家族に同じ端末で見せる体験から検討する。
- **ゲーム内のヒント通貨**：発見の余白には参考になるが、算数で困っている時の支援は通貨や希少品に依存させない。

## 調査の範囲と確認

- 公式サイト、公式ガイド、開発元のストア掲載、2013版の公式マニュアルを使用。各行から根拠へ移動できる。
- 104件は比較のために分解した項目数。同じ機能を「入手」「使う」「記録する」など別の設計責任へ分けたものを含み、104個の独立システムが必要という意味ではない。
- 公式資料の仕組みと、こちらの体験解釈・Sansu案を列で分離した。原作の継続率、学習効果、操作遅延、音の強度、対象年齢ごとの効果は測定していない。
- ベンチマークの優先順位は現行のSansu仕様との適合からの提案。子どもの自発的な再遊びや無説明理解は未確認。
- 作品・版を限定して、主な設計領域を覆うことを調査の区切りとした。対戦大会、全課金要素、MOD・拡張作品、全ての細かなアクセシビリティ設定は対象外。
- 現在の製品仕様と実装はこの資料で変更しない。検証は文書の構造、出典と主張の対応、件数・ID、および `npm run docs:check`。
